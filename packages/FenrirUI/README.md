# FenrirUI

UI roots of elements (ADR-0063, ADR-0066), laid out by Yoga flexbox behind a layout bridge (ADR-0064) and painted every frame through FenrirPainter into each root's 2D target. The tree is retained: style resolution and layout run for what is dirty, and the draw list is made again every frame. Elements are FenrirUI's own, addressed by versioned `ElementId`s, not entities. It depends on FenrirPainter (and through it FenrirText, which lays out its elements' text), FenrirInput (each root is an input router), FenrirApp and FenrirAssets; a root on a window reads the window's size from FenrirWindow and submits to FenrirRenderer's overlay, both linked privately, and Yoga (the `libs/yoga` submodule, 3.2.2, static) is included by `src/LayoutBridge.cpp` alone, so no Yoga type is in a public header. It is built with `FENRIR_ENABLE_UI` (on by default), which needs `FENRIR_ENABLE_RENDERER`. This is the core of the FenrirUI spec (`.scratch/fenrir-ui/spec.md`), its stylesheets with transitions and keyframe animations, `:intro`, `:outro` and deferred removal, pointer and keyboard input with focus and UI events, and text on elements: gamepad navigation, controls, markup and stylesheet files come in later tickets.

## Installing

`UI::Install(app)`, after FenrirAssets' `Assets::Install`, installs the painter (`Painting::Install`), adds the `UIRoots` app resource and a sequential `PostUpdate` system that runs every root's frame. Destroying the owner removes the resource and every root. Without an asset store, or with a UI already installed, it logs why and its `IsValid()` is false.

## Roots

`UIRoots::CreateRoot(UIRootConfig)` makes a UI root; several coexist, drawn lowest `layer` first, then in the order they were made, and `DestroyRoot` ends one. A root names:

- **its target**: by default its `window`'s overlay on `layer` (ADR-0027), at the window's logical size and content scale; nothing is drawn until the renderer (which adds the overlay) and the window exist. A `UITarget` of the game's own (`FenrirUI/UITarget.hpp`) gives the size and takes each frame's `DrawList2D` instead, which is how the tests capture what a root draws.
- **its scale rule**: `ScaleRule::Height1080` (the default: 1080 UI units span the target's pixel height, so the scale is pixel height / 1080 / content scale logical units per UI unit, and a UI authored at 1080p keeps its proportions) or `ScaleRule::ContentScale` (one UI unit is one logical unit). `GetScale()` is the last frame's.
- **its blend space**: `Gamma` by default, as a UI on the window overlay blends (ADR-0065).
- **its input priority** (`inputPriority`, 0 by default): its input router's place among FenrirInput's routers, highest first; give a root drawn over another a higher one.
- **pixel snapping** (on by default): every edge of every laid-out rectangle is rounded to the target's nearest pixel, a half pixel up, so neighbours that share an edge share its pixel; the painter snaps what it draws too.

## Elements

A root starts with its root element (tag `root`), which fills the target and cannot be removed. `Create(parent, tag, index)` makes an element under a parent at an index (`UIRoot::End` for last); `Remove` takes it and everything under it away and their ids go stale: a call with a stale id does nothing and returns an empty value, and a slot used again gets a new version. By default the removal waits for its outro (ADR-0066): the element gets `:outro`, and goes after the first frame in which no transition runs on it or under it, so `.toast:outro { opacity: 0; }` with `transition: opacity 0.3s` fades it out; until then it is alive, laid out, painted and hit-tested (turn its `pointer-events` off for it not to be), and its id names it. `Remove(element, RemoveMode::Immediate)` removes it at once, cutting short an outro under way. Every element made by `Create` carries `:intro` until the first layout that includes it completes, and its first style starts no transitions, so `.panel:intro { opacity: 0; }` with a transition on opacity fades a panel in. `Reparent` and `Reorder` move an element and its subtree, keeping every list of children in order. Each element has a tag name, an id string (`FindById`), classes (`AddClass`, `RemoveClass`, `FindByClass`, in tree order), pseudo-class flags (`SetPseudoClass`), an inline style, a resolved style and its rectangles (`GetBoxes`: border, padding and content boxes and the clip its ancestors set, in UI units from the root's top-left, before transforms).

`Element` (`FenrirUI/Element.hpp`) is an element's behaviour, which custom elements subclass: `HasMeasure` and `Measure` size a leaf's content box from the space layout offers (`InvalidateMeasure` asks again), `Paint` draws its content through the painter after its box and before its children, and `OnInput` sees the inputs the root's router routes to it (below); returning `Consumed` skips the root's default action. `UIRoots::RegisterElement(tag, factory)` registers a subclass under a tag; creating an unregistered tag makes a plain `Element`, which paints its box only.

## Text

Any element carries text the same way: `SetText(element, utf8)` gives it a FenrirText paragraph (ADR-0062) in its text properties, kept on the element and laid out again when the text, those properties or its width change; `GetText` and `GetParagraph` read them back. A **label** is an element of tag `label` with text, and controls with a caption (ticket 12's button) reuse it. While the element has no children, layout measures its content box to the paragraph at the width offered (Yoga's measure function), so a label wraps at its parent's width, or its share of a flex row; each frame paints the paragraph at the content box's top-left through the painter's text draw, after the box and before the element's own `Paint`, under its `text-shadow`s (the first on top) and faded by its opacity. The paragraph is laid out in the target's pixels: its sizes are the style's times the root's scale and the target's content scale (`size * scale * pixelsPerUnit`), the exact pixel size its bitmaps are rasterised at, and its measured size is divided back into UI units. The fonts are the app's `FontLibrary` resource (`UIRoots::GetFonts()`), which `UI::Install` adds over the asset store when the app has none; register a family on it with `AddFace` for `font-family` to name (`@font-face` comes with stylesheet files, ticket 16). A family with no faces, and `default`, is FenrirText's embedded default face. A text-shadow's blur is kept and not drawn yet. A paragraph that changes size because the library's families changed under it is measured again on the next frame.

## Input, focus and UI events

Each root registers an input router with FenrirInput (ADR-0027) when it is made, or on its first frame once `Input::Install` has run, at its `inputPriority`, and it handles the input of its `window`. It hit-tests against the last frame's layout (`HitTest(position)` in UI units gives the same answer): the topmost element under the pointer that has `pointer-events: all` (ADR-0065), children before their parent, siblings by `z-index` then tree order, inside rounded corners, under transforms and within the padding boxes of ancestors that hide overflow. Elements take no pointer input until styled so, so a HUD is transparent to input; `:root { pointer-events: all; }` makes a whole menu opaque.

- **Pointer**: motion updates the hovered element (`GetHovered()`; `:hover` on it and its ancestors) and sends PointerLeave, PointerEnter or PointerMove; motion is always passed on, so the game's `Mouse` keeps the pointer's place. A button pressed over an element is consumed: `:active` goes on it and its ancestors while held, the root claims pointer capture, it is sent PointerPress, and its release (wherever the pointer is) PointerRelease and, when the pointer is still over it, Click, then DoubleClick for a second click on it within half a second and four UI units. A scroll over an element is consumed and sent Scroll. A press over nothing passes to the game. The root claims the pointer while something is hovered.
- **Focus**: elements are focusable once `SetFocusable(element, true)` (the controls make themselves so). A press focuses the nearest focusable element at or above what it hit, and blurs when there is none or it hit nothing; `Focus(element)` and `Blur()` do it from code; Tab and Shift+Tab move it through the displayed focusable elements in tree order, wrapping, while something has it. The focused element (`GetFocused()`) carries `:focus` and its ancestors `:focus-within`; it is sent Blur when it loses the focus and Focus when it takes it, and the root claims keyboard focus while it has it, which cancels the game's held keys. Removing the focused element takes the focus away, sending nothing.
- **Keys and text**: while an element has the focus, every key and text input in the window is its (KeyPress, KeyRelease, TextInput) and is consumed; with none, they pass to the game.
- **UI events**: `UIEvent` (`FenrirUI/UIEvent.hpp`) is an engine event, sent once at its target for each of these, naming the root (`GetId()`), the target, the kind, the pointer in UI units, the button, the key, a float and an integer as each kind says; systems read it through `EventReader<UIEvent>`. Change, Submit and DocumentReloaded are sent by the controls and hot reload, through `SendEvent`.
- **UI listeners**: `AddListener(element, kind, listener)` attaches C++ to an element for one kind; a UIEvent runs the listeners of its target, then of each ancestor up to the root element, each element's in the order added, until one calls `StopPropagation()` (its element's other listeners still run). The queue has the event once whatever its listeners do. `RemoveListener` detaches one; removing the element detaches its own.

`Element::OnInput` sees the routed input itself before its UIEvent is sent: presses, releases and scrolls at their element, motion at the pressed element or else the hovered one, keys and text at the focused one. Gamepad navigation and the virtual cursor, and the text-input claim, come with later tickets.

## Style

The inline style is a `StyleDeclarations` (`FenrirUI/Style.hpp`): some properties given, the rest not. Give them through the typed setters (`root.EditInlineStyle(id)->SetWidth(Fenrir::Length::Px(200)).SetFlexDirection(Fenrir::FlexDirection::Row)`), or by CSS longhand name and value (`root.SetStyleProperty(id, "margin-left", "10px")`), which logs and refuses an unknown property or a value it cannot read. The properties:

- **Layout**: `display` (flex, none), `position` (relative, absolute), `top`, `right`, `bottom`, `left`, `width`, `height`, `min-width`, `min-height`, `max-width`, `max-height`, `aspect-ratio`, the `margin-*`s, `padding-*`s and `border-*-width`s, `flex-direction`, `flex-wrap`, `flex-grow`, `flex-shrink`, `flex-basis`, `align-items`, `align-self`, `align-content`, `justify-content`, `row-gap`, `column-gap`. Lengths are `px` (UI units), `%` or `auto` (`none` for a maximum).
- **Visual**: `background-color`; `background-image` (`url(path)`, loaded from the asset store, `linear-gradient()` with an angle or `to` side, or `radial-gradient()`, an ellipse to the farthest corner) with `background-size` (stretch, cover, contain); `border-image-source` and `border-image-slice` for a nine-slice image over the border box; the `border-*-color`s and `border-*-radius`es; `box-shadow` (outset shadows, a list); `opacity`; `transform` (`translate()`, `translateX()`, `translateY()`, `scale()`, `scaleX()`, `scaleY()`, `rotate()`) with `transform-origin`; `overflow` (visible, hidden); `z-index`; `pointer-events` (none, all; none by default, ADR-0065); `cursor`.
- **Text**: `color` (black by default); `font-family` (one name, quoted or not; a list takes its first, since a FenrirText family has fallbacks of its own); `font-size` (`px`, 16 by default); `font-weight` (normal, bold, or 1 to 1000); `font-style` (normal, italic, oblique as italic); `text-align` (start, end, left, right, center); `line-height` (normal, a number or a percentage of the font-size, or `px`); `letter-spacing` (normal or `px`); `text-shadow` (offset-x offset-y [blur] [colour], a list); `white-space` (normal, nowrap); `text-overflow` (clip, ellipsis).
- Colours are `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, `hsl()`, `hsla()`, `transparent` or a CSS colour name, sRGB with straight alpha, kept linear as `Colour`.

`SetStyleProperty` also takes the shorthands a stylesheet does (below), setting all of a shorthand's longhands or, for a value it cannot read, none. An element's resolved style is the defaults, then the inherited properties (`pointer-events`, `cursor` and every text property) from its parent, then the matching stylesheet rules, then its inline style. The defaults are Yoga's, as in React Native and Unity's USS rather than the web: `flex-direction` column, `flex-shrink` 0, `align-content` flex-start, and every element a flex container.

## Stylesheets

`root.AddStylesheet(text, name)` parses a CSS subset (ADR-0064, `FenrirUI/Stylesheet.hpp`) and adds it after the root's other sheets; `RemoveStylesheet` takes it away and `GetStylesheet` reads it back as parsed. `Stylesheet::Parse` alone gives the parsed sheet: rules with nesting flattened, `@keyframes`, `@font-face` and `@import` (kept for the tickets that use them), and a diagnostic with its line for everything refused, which `AddStylesheet` logs with the sheet's name.

- **Selectors**: type, `.class`, `#id`, compounds of them, descendant (whitespace) and child (`>`) combinators, selector lists, and the pseudo-classes `:hover :active :focus :focus-within :disabled :checked :intro :outro` (the flags `SetPseudoClass` sets) and `:first-child :last-child :root` (from where the element is). Specificity is CSS's: ids, then classes and pseudo-classes, then types; at equal specificity the later rule wins, a later sheet after an earlier one; inline style wins over every rule. `!important`, `*`, `+`, `~`, attributes and pseudo-elements are not supported.
- **Nesting**: a rule inside a rule is CSS nesting: `&` is the outer selector (`&:hover`, `.dark &`), and a selector without `&` is relative to it (`> .title`, `label`). `&` weighs as `:is()` of the outer list: its highest specificity, for every selector of the list. The outer rule comes first, then each nested rule in order, and declarations written after a nested rule apply after it, as a rule of the outer selectors.
- **Shorthands**, expanded as CSS does: `margin`, `padding`, `border-width`, `border-color` and `border-radius` (one to four values), `border` (a width, a style and a colour; with the style `none`, `hidden` or none given the widths are 0, as CSS computes them, a style with no width is `medium`, 3px, and the colour starts black until the style has a `color`), `background` (one layer: colour, image, position and `/ size`, the rest reset), `flex` (`none`, `auto`, `initial`, and up to two numbers and a basis), `gap`, `transition` and `animation` (lists, each into their longhands).
- **Custom properties** (`--name: value`) inherit down the tree, a `var()` in one resolved on the element that declares it; in a property, `var(--name)` and `var(--name, fallback)` are replaced where the value is used, in a longhand or a shorthand. A `var()` that leaves nothing readable makes the property as if no rule declared it, as CSS does.
- **Values** are read as inline style reads them, `url()`s loaded from the asset store when the sheet is added. The filter and scrollbar properties and `background-position` are parsed and kept, and style nothing until the tickets that add them.
- **Transitions**: `transition-property` (names, a shorthand naming its longhands, `all`, or `none`), `-duration`, `-timing-function` (`ease`, `linear`, `ease-in`, `ease-out`, `ease-in-out`, `step-start`, `step-end`, `cubic-bezier()`, `steps()` with any jump position) and `-delay`, lists paired as CSS pairs them. When an element's cascaded value of a property its lists name changes, it runs from the value shown to the new one; a change mid-transition starts from where the running one had got to. Lengths of the same unit, numbers, colours (in sRGB, alpha premultiplied, as CSS), opacity, radii, shadow lists (the shorter padded with transparent shadows) and transform lists whose functions match step by step mix; everything else, `auto` against a length and px against % among it, is discrete and switches at the end, `display` and `pointer-events` too when `all` names them. An element's first style starts no transitions, having no value before it to run from; a transition on it starts with its first change, which `:intro` gives.
- **Animations**: `animation-name` naming a sheet's `@keyframes` (of several with one name, the last of the last sheet), `-duration`, `-timing-function` (easing each interval between keyframes, or a keyframe's own `animation-timing-function` for the interval it starts), `-delay`, `-iteration-count` (fractions and `infinite`), `-direction` and `-fill-mode`. They apply over the cascade, a property no keyframe at 0% or 100% gives taking its cascaded value there, and a transition of the same property shows over them. A name the lists keep keeps its time through restyles; `var()` and custom properties in keyframes are logged and skipped.
- **Errors**: a malformed declaration, an unknown property or a value that cannot be read skips the declaration; a malformed selector or an unknown pseudo-class skips the rule (and the rules nested in it); an unknown at-rule skips itself and its block; an unclosed block or comment ends at the end of the sheet. Each is logged with its line, and the rest of the sheet stands.

Rules are bucketed by their rightmost compound's id, else its first class, else its tag, so an element is tested only against the selectors that could match it.

## The frame

In `PostUpdate`, for each root in drawing order: its target's size and the scale (a target with no size ends the frame here, so its transitions and animations stand still); every running transition and animation moved on by FenrirTime's frame delta; the dirty styles resolved, the cascade before layout (a change of inline style marks the element and the path above it; a change of classes, id or pseudo-classes marks its subtree when a selector of the root's sheets has a combinator, else the element; a change of children marks the siblings when a selector uses `:first-child` or `:last-child`; adding or removing a sheet marks every element; a changed inherited value or custom property reaches the children), starting the transitions and animations their changes call for, then the shown style of each element whose motion moved, its animations and then its transitions over its cascaded style, each written into its Yoga node; a layout if any node is dirty (a clean root calls no layout, which `GetStats()` shows); the rectangles read back and snapped when it laid out or the pixel size changed; `:intro` cleared on the elements that layout included; then every element painted in tree order, the list submitted to the target, and last the elements whose outros have ended removed.

Each element paints, under its transform about its origin: its shadows (the first on top), its background colour and its background image, each a rounded rectangle over its border box, then its border, a third box draw (the painter has no draw that fills and borders a box at once), and its border image; then its content (`Element::Paint`) and its children sorted by `z-index` (equal ones in tree order), both inside its padding box with its inner radii when it hides overflow. An element whose opacity is under one and that has children draws all of that through an offscreen group (ADR-0060) over what it and its subtree cover, composited at its opacity; a leaf's colours are faded instead. An element that is `display: none` or fully transparent paints nothing.

`UIRoots::settings` holds the switches for every root: `offscreenGroups` (off, an element's subtree is faded box by box instead of through a group). The spec's anti-aliasing switch is not here yet: FenrirPainter has no way to draw without anti-aliasing, so that option has to come to the painter first.

## Tests

With `FENRIR_BUILD_TESTS`: `FenrirUITests`, headless (no window: each root draws into a capturing `UITarget`), lays out Yoga's generated conformance fixtures, converted to element trees with inline styles by `Tests/fixtures/convert-yoga-fixtures.py` (run it again when the submodule moves; fixtures using what the property set lacks, such as start and end edges, are left out, and so are five that test Yoga's own layout root, which has no containing block, where each fixture's root here is an absolute child of the root element), and checks absolute positioning, percentages, gaps, minimums and maximums, both scale rules at two target sizes, pixel snapping, the tree's ids, order and queries, what a frame re-does when a subtree is dirty and when nothing is, custom elements and their measures, inheritance, root order, the draw list of a nested tree (shadow, boxes, border, overflow clip and one opacity group, in tree order), opacity without groups, z-index, transforms and backgrounds; the stylesheet parser (every selector form and pseudo-class, each shorthand's expansion, each error kind with its line, nesting, `var()`, the at-rules); and the cascade (specificity, order, inline style, inheritance, custom properties, combinators, structural pseudo-classes, what a class or pseudo-class change restyles, and a sheet-styled tree laying out as the same tree styled inline); and input through FenrirInput's feed (what is consumed and what reaches the game's `Mouse` and `Keyboard`, rounded corners, overflow clips, transforms and z-index in hit testing, hover, press and click, double clicks, scrolls, the input claims, focus by click, Tab, Shift+Tab and code with `:focus` and `:focus-within`, keys and text to the focused element, and listeners bubbling with stop-propagation while the event is sent once); and motion over fixed frame deltas (a width transition under `linear`, `ease-in-out` and `steps(4)`, a colour transition in sRGB, a change mid-transition, keyframe animations looping, alternating and filling forwards, `:intro` on the first frame only, an outro keeping a removed element and its parent alive until its transition ends, and removal at once); and text (a label's size from its paragraph laid out in target pixels, wrapping at its parent's width and at its share of a flex row, `white-space: nowrap`, ellipsis at a fixed width, `text-align`, font-size inherited and overridden by a class, families registered from code, the text properties read and inherited, glyph quads inside the content box, and text-shadow drawn first).
