# FenrirUI

UI roots of elements (ADR-0063, ADR-0066), laid out by Yoga flexbox behind a layout bridge (ADR-0064) and painted every frame through FenrirPainter into each root's 2D target. The tree is retained: style resolution and layout run for what is dirty, and the draw list is made again every frame. Elements are FenrirUI's own, addressed by versioned `ElementId`s, not entities. It depends on FenrirPainter, FenrirInput, FenrirApp and FenrirAssets; a root on a window reads the window's size from FenrirWindow and submits to FenrirRenderer's overlay, both linked privately, and Yoga (the `libs/yoga` submodule, 3.2.2, static) is included by `src/LayoutBridge.cpp` alone, so no Yoga type is in a public header. It is built with `FENRIR_ENABLE_UI` (on by default), which needs `FENRIR_ENABLE_RENDERER`. This is the core of the FenrirUI spec (`.scratch/fenrir-ui/spec.md`) and its stylesheets: text, transitions, input and focus, controls, markup and stylesheet files come in later tickets.

## Installing

`UI::Install(app)`, after FenrirAssets' `Assets::Install`, installs the painter (`Painting::Install`), adds the `UIRoots` app resource and a sequential `PostUpdate` system that runs every root's frame. Destroying the owner removes the resource and every root. Without an asset store, or with a UI already installed, it logs why and its `IsValid()` is false.

## Roots

`UIRoots::CreateRoot(UIRootConfig)` makes a UI root; several coexist, drawn lowest `layer` first, then in the order they were made, and `DestroyRoot` ends one. A root names:

- **its target**: by default its `window`'s overlay on `layer` (ADR-0027), at the window's logical size and content scale; nothing is drawn until the renderer (which adds the overlay) and the window exist. A `UITarget` of the game's own (`FenrirUI/UITarget.hpp`) gives the size and takes each frame's `DrawList2D` instead, which is how the tests capture what a root draws.
- **its scale rule**: `ScaleRule::Height1080` (the default: 1080 UI units span the target's pixel height, so the scale is pixel height / 1080 / content scale logical units per UI unit, and a UI authored at 1080p keeps its proportions) or `ScaleRule::ContentScale` (one UI unit is one logical unit). `GetScale()` is the last frame's.
- **its blend space**: `Gamma` by default, as a UI on the window overlay blends (ADR-0065).
- **pixel snapping** (on by default): every edge of every laid-out rectangle is rounded to the target's nearest pixel, a half pixel up, so neighbours that share an edge share its pixel; the painter snaps what it draws too.

## Elements

A root starts with its root element (tag `root`), which fills the target and cannot be removed. `Create(parent, tag, index)` makes an element under a parent at an index (`UIRoot::End` for last); `Remove` takes it and everything under it away at once, and their ids go stale: a call with a stale id does nothing and returns an empty value, and a slot used again gets a new version. `Reparent` and `Reorder` move an element and its subtree, keeping every list of children in order. Each element has a tag name, an id string (`FindById`), classes (`AddClass`, `RemoveClass`, `FindByClass`, in tree order), pseudo-class flags (`SetPseudoClass`), an inline style, a resolved style and its rectangles (`GetBoxes`: border, padding and content boxes and the clip its ancestors set, in UI units from the root's top-left, before transforms).

`Element` (`FenrirUI/Element.hpp`) is an element's behaviour, which custom elements subclass: `HasMeasure` and `Measure` size a leaf's content box from the space layout offers (`InvalidateMeasure` asks again), `Paint` draws its content through the painter after its box and before its children, and `OnInput` is where the root's input router will route to it (nothing calls it yet). `UIRoots::RegisterElement(tag, factory)` registers a subclass under a tag; creating an unregistered tag makes a plain `Element`, which paints its box only.

## Style

The inline style is a `StyleDeclarations` (`FenrirUI/Style.hpp`): some properties given, the rest not. Give them through the typed setters (`root.EditInlineStyle(id)->SetWidth(Fenrir::Length::Px(200)).SetFlexDirection(Fenrir::FlexDirection::Row)`), or by CSS longhand name and value (`root.SetStyleProperty(id, "margin-left", "10px")`), which logs and refuses an unknown property or a value it cannot read. The properties:

- **Layout**: `display` (flex, none), `position` (relative, absolute), `top`, `right`, `bottom`, `left`, `width`, `height`, `min-width`, `min-height`, `max-width`, `max-height`, `aspect-ratio`, the `margin-*`s, `padding-*`s and `border-*-width`s, `flex-direction`, `flex-wrap`, `flex-grow`, `flex-shrink`, `flex-basis`, `align-items`, `align-self`, `align-content`, `justify-content`, `row-gap`, `column-gap`. Lengths are `px` (UI units), `%` or `auto` (`none` for a maximum).
- **Visual**: `background-color`; `background-image` (`url(path)`, loaded from the asset store, `linear-gradient()` with an angle or `to` side, or `radial-gradient()`, an ellipse to the farthest corner) with `background-size` (stretch, cover, contain); `border-image-source` and `border-image-slice` for a nine-slice image over the border box; the `border-*-color`s and `border-*-radius`es; `box-shadow` (outset shadows, a list); `opacity`; `transform` (`translate()`, `translateX()`, `translateY()`, `scale()`, `scaleX()`, `scaleY()`, `rotate()`) with `transform-origin`; `overflow` (visible, hidden); `z-index`; `pointer-events` (none, all; none by default, ADR-0065); `cursor`.
- Colours are `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, `hsl()`, `hsla()`, `transparent` or a CSS colour name, sRGB with straight alpha, kept linear as `Colour`.

`SetStyleProperty` also takes the shorthands a stylesheet does (below), setting all of a shorthand's longhands or, for a value it cannot read, none. An element's resolved style is the defaults, then the inherited properties (`pointer-events` and `cursor`; the text properties join them with text) from its parent, then the matching stylesheet rules, then its inline style. The defaults are Yoga's, as in React Native and Unity's USS rather than the web: `flex-direction` column, `flex-shrink` 0, `align-content` flex-start, and every element a flex container.

## Stylesheets

`root.AddStylesheet(text, name)` parses a CSS subset (ADR-0064, `FenrirUI/Stylesheet.hpp`) and adds it after the root's other sheets; `RemoveStylesheet` takes it away and `GetStylesheet` reads it back as parsed. `Stylesheet::Parse` alone gives the parsed sheet: rules with nesting flattened, `@keyframes`, `@font-face` and `@import` (kept for the tickets that use them), and a diagnostic with its line for everything refused, which `AddStylesheet` logs with the sheet's name.

- **Selectors**: type, `.class`, `#id`, compounds of them, descendant (whitespace) and child (`>`) combinators, selector lists, and the pseudo-classes `:hover :active :focus :focus-within :disabled :checked :intro :outro` (the flags `SetPseudoClass` sets) and `:first-child :last-child :root` (from where the element is). Specificity is CSS's: ids, then classes and pseudo-classes, then types; at equal specificity the later rule wins, a later sheet after an earlier one; inline style wins over every rule. `!important`, `*`, `+`, `~`, attributes and pseudo-elements are not supported.
- **Nesting**: a rule inside a rule is CSS nesting: `&` is the outer selector (`&:hover`, `.dark &`), and a selector without `&` is relative to it (`> .title`, `label`). The outer rule comes first, then each nested rule in order; an outer rule's declarations all belong to it, wherever they sit among its nested rules.
- **Shorthands**, expanded as CSS does: `margin`, `padding`, `border-width`, `border-color` and `border-radius` (one to four values), `border` (a width, a style and a colour; with the style `none`, `hidden` or none given the widths are 0, as CSS computes them, a style with no width is `medium`, 3px, and the colour starts black until the style has a `color`), `background` (one layer: colour, image, position and `/ size`, the rest reset), `flex` (`none`, `auto`, `initial`, and up to two numbers and a basis), `gap`, `transition` and `animation` (lists, each into their longhands).
- **Custom properties** (`--name: value`) inherit down the tree; `var(--name)` and `var(--name, fallback)` are replaced where the value is used, in a longhand or a shorthand. A `var()` that leaves nothing readable makes the property as if no rule declared it, as CSS does.
- **Values** are read as inline style reads them, `url()`s loaded from the asset store when the sheet is added. The text, transition, animation, filter and scrollbar properties and `background-position` are parsed and kept, and style nothing until the tickets that add them.
- **Errors**: a malformed declaration, an unknown property or a value that cannot be read skips the declaration; a malformed selector or an unknown pseudo-class skips the rule (and the rules nested in it); an unknown at-rule skips itself and its block; an unclosed block or comment ends at the end of the sheet. Each is logged with its line, and the rest of the sheet stands.

Rules are bucketed by their rightmost compound's id, else its first class, else its tag, so an element is tested only against the selectors that could match it.

## The frame

In `PostUpdate`, for each root in drawing order: its target's size and the scale; the dirty styles resolved, the cascade before layout (a change of inline style marks the element and the path above it; a change of classes, id or pseudo-classes marks its subtree when a selector of the root's sheets has a combinator, else the element; a change of children marks the siblings when a selector uses `:first-child` or `:last-child`; adding or removing a sheet marks every element; a changed inherited value or custom property reaches the children), each written into its Yoga node; a layout if any node is dirty (a clean root calls no layout, which `GetStats()` shows); the rectangles read back and snapped when it laid out or the pixel size changed; then every element painted in tree order, and the list submitted to the target.

Each element paints, under its transform about its origin: its shadows (the first on top), its background colour and its background image, each a rounded rectangle over its border box, then its border, a third box draw (the painter has no draw that fills and borders a box at once), and its border image; then its content (`Element::Paint`) and its children sorted by `z-index` (equal ones in tree order), both inside its padding box with its inner radii when it hides overflow. An element whose opacity is under one and that has children draws all of that through an offscreen group (ADR-0060) over what it and its subtree cover, composited at its opacity; a leaf's colours are faded instead. An element that is `display: none` or fully transparent paints nothing.

`UIRoots::settings` holds the switches for every root: `offscreenGroups` (off, an element's subtree is faded box by box instead of through a group). The spec's anti-aliasing switch is not here yet: FenrirPainter has no way to draw without anti-aliasing, so that option has to come to the painter first.

## Tests

With `FENRIR_BUILD_TESTS`: `FenrirUITests`, headless (no window: each root draws into a capturing `UITarget`), lays out Yoga's generated conformance fixtures, converted to element trees with inline styles by `Tests/fixtures/convert-yoga-fixtures.py` (run it again when the submodule moves; fixtures using what the property set lacks, such as start and end edges, are left out, and so are five that test Yoga's own layout root, which has no containing block, where each fixture's root here is an absolute child of the root element), and checks absolute positioning, percentages, gaps, minimums and maximums, both scale rules at two target sizes, pixel snapping, the tree's ids, order and queries, what a frame re-does when a subtree is dirty and when nothing is, custom elements and their measures, inheritance, root order, the draw list of a nested tree (shadow, boxes, border, overflow clip and one opacity group, in tree order), opacity without groups, z-index, transforms and backgrounds; the stylesheet parser (every selector form and pseudo-class, each shorthand's expansion, each error kind with its line, nesting, `var()`, the at-rules); and the cascade (specificity, order, inline style, inheritance, custom properties, combinators, structural pseudo-classes, what a class or pseudo-class change restyles, and a sheet-styled tree laying out as the same tree styled inline).
