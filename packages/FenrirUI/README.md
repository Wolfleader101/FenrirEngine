# FenrirUI

UI roots of elements (ADR-0063, ADR-0066), laid out by Yoga flexbox behind a layout bridge (ADR-0064) and painted every frame through FenrirPainter into each root's 2D target. The tree is retained: style resolution and layout run for what is dirty, and the draw list is made again every frame. Elements are FenrirUI's own, addressed by versioned `ElementId`s, not entities. It depends on FenrirPainter (and through it FenrirText, which lays out its elements' text), FenrirInput (each root is an input router), FenrirApp and FenrirAssets; a root on a window reads the window's size from FenrirWindow and submits to FenrirRenderer's overlay, both linked privately, and Yoga (the `libs/yoga` submodule, 3.2.2, static) is included by `src/LayoutBridge.cpp` alone, so no Yoga type is in a public header. It is built with `FENRIR_ENABLE_UI` (on by default), which needs `FENRIR_ENABLE_RENDERER`. This is the core of the FenrirUI spec (`.scratch/fenrir-ui/spec.md`), its stylesheets with transitions and keyframe animations, `:intro`, `:outro` and deferred removal, pointer and keyboard input with focus and UI events, text on elements, the controls with the default stylesheet and text entry, gamepad navigation with the virtual cursor, and markup documents and stylesheets loaded from strings or files, with `@import`, `@font-face` and hot reload.

## Installing

`UI::Install(app)`, after FenrirAssets' `Assets::Install`, installs the painter (`Painting::Install`), adds the `UIRoots` app resource and a sequential `PostUpdate` system that runs every root's frame. Destroying the owner removes the resource and every root. Without an asset store, or with a UI already installed, it logs why and its `IsValid()` is false.

## Roots

`UIRoots::CreateRoot(UIRootConfig)` makes a UI root; several coexist, drawn lowest `layer` first, then in the order they were made, and `DestroyRoot` ends one. A root names:

- **its target**: by default its `window`'s overlay on `layer` (ADR-0027), at the window's logical size and content scale; nothing is drawn until the renderer (which adds the overlay) and the window exist. A `UITarget` of the game's own (`FenrirUI/UITarget.hpp`) gives the size and takes each frame's `DrawList2D` instead, which is how the tests capture what a root draws.
- **its scale rule**: `ScaleRule::Height1080` (the default: 1080 UI units span the target's pixel height, so the scale is pixel height / 1080 / content scale logical units per UI unit, and a UI authored at 1080p keeps its proportions) or `ScaleRule::ContentScale` (one UI unit is one logical unit). `GetScale()` is the last frame's.
- **its blend space**: `Gamma` by default, as a UI on the window overlay blends (ADR-0065).
- **its input priority** (`inputPriority`, 0 by default): its input router's place among FenrirInput's routers, highest first; give a root drawn over another a higher one.
- **pixel snapping** (on by default): every edge of every laid-out rectangle is rounded to the target's nearest pixel, a half pixel up, so neighbours that share an edge share its pixel; the painter snaps what it draws too.

## Elements

A root starts with its root element (tag `root`), which fills the target and cannot be removed. `Create(parent, tag, index)` makes an element under a parent at an index (`UIRoot::End` for last); `Remove` takes it and everything under it away and their ids go stale: a call with a stale id does nothing and returns an empty value, and a slot used again gets a new version. By default the removal waits for its outro (ADR-0066): the element gets `:outro`, and goes after the first frame in which no transition runs on it or under it, so `.toast:outro { opacity: 0; }` with `transition: opacity 0.3s` fades it out; until then it is alive, laid out, painted and hit-tested (turn its `pointer-events` off for it not to be), and its id names it. `Remove(element, RemoveMode::Immediate)` removes it at once, cutting short an outro under way. Every element made by `Create` carries `:intro` until the first layout that includes it completes, and its first style starts no transitions, so `.panel:intro { opacity: 0; }` with a transition on opacity fades a panel in. `Reparent` and `Reorder` move an element and its subtree, keeping every list of children in order. Each element has a tag name, an id string (`FindById`), classes (`AddClass`, `RemoveClass`, `FindByClass`, in tree order), pseudo-class flags (`SetPseudoClass`), an inline style, a resolved style and its rectangles (`GetBoxes`: border, padding and content boxes and the clip its ancestors set, in UI units from the root's top-left, before transforms).

`Element` (`FenrirUI/Element.hpp`) is an element's behaviour, which custom elements subclass: `HasMeasure` and `Measure` size a leaf's content box from the space layout offers (`InvalidateMeasure` asks again), `Paint` draws its content through the painter after its box and before its children, and `OnInput` sees the inputs the root's router routes to it or to an element under it (below); returning `Consumed` stops the input there and skips the root's default action; `OnCreate` runs once at the end of `Create`, where a control makes its own children. `SetAttribute(name, value)` takes a markup document's attributes, which the element parses itself (below). `UIRoots::RegisterElement(tag, factory)` registers a subclass under a tag, and `IsRegistered(tag)` says whether one is; `panel` (a plain `Element`), `label` and the controls are registered from the start. Creating an unregistered tag makes a plain `Element`, which paints its box only; a markup document may name only registered tags.

## Text

Any element carries text the same way: `SetText(element, utf8)` gives it a FenrirText paragraph (ADR-0062) in its text properties, kept on the element and laid out again when the text, those properties or its width change; `GetText` and `GetParagraph` read them back. A **label** is an element of tag `label` with text, and a button's caption is its text the same way. While the element has no children, layout measures its content box to the paragraph at the width offered (Yoga's measure function), so a label wraps at its parent's width, or its share of a flex row; each frame paints the paragraph at the content box's top-left through the painter's text draw, after the box and before the element's own `Paint`, under its `text-shadow`s (the first on top) and faded by its opacity. The paragraph is laid out in the target's pixels: its sizes are the style's times the root's scale and the target's content scale (`size * scale * pixelsPerUnit`), the exact pixel size its bitmaps are rasterised at, and its measured size is divided back into UI units. The fonts are the app's `FontLibrary` resource (`UIRoots::GetFonts()`), which `UI::Install` adds over the asset store when the app has none; register a family on it with `AddFace`, or through `UIRoots::AddFontFace`, or from a stylesheet's `@font-face` (below), for `font-family` to name. A family with no faces, and `default`, is FenrirText's embedded default face. A text-shadow's blur is kept and not drawn yet. A paragraph that changes size because the library's families changed under it is measured again on the next frame.

## Input, focus and UI events

Each root registers an input router with FenrirInput (ADR-0027) when it is made, or on its first frame once `Input::Install` has run, at its `inputPriority`, and it handles the input of its `window`. It hit-tests against the last frame's layout (`HitTest(position)` in UI units gives the same answer): the topmost element under the pointer that has `pointer-events: all` (ADR-0065), children before their parent, siblings by `z-index` then tree order, inside rounded corners, under transforms and within the padding boxes of ancestors that hide overflow. Elements take no pointer input until styled so, so a HUD is transparent to input; `:root { pointer-events: all; }` makes a whole menu opaque.

- **Pointer**: motion updates the hovered element (`GetHovered()`; `:hover` on it and its ancestors) and sends PointerLeave, PointerEnter or PointerMove; motion is always passed on, so the game's `Mouse` keeps the pointer's place. A button pressed over an element is consumed: `:active` goes on it and its ancestors while held, the root claims pointer capture, it is sent PointerPress, and its release (wherever the pointer is) PointerRelease and, when the pointer is still over it, Click, then DoubleClick for a second click on it within half a second and four UI units. A scroll over an element is consumed and sent Scroll. A press over nothing passes to the game. The root claims the pointer while something is hovered.
- **Focus**: elements are focusable once `SetFocusable(element, true)` (the controls make themselves so). A press focuses the nearest focusable element at or above what it hit, and blurs when there is none or it hit nothing; `Focus(element)` and `Blur()` do it from code; Tab and Shift+Tab move it through the displayed focusable elements in tree order, wrapping, while something has it, and scroll each scroll view above the element they reach just far enough to show it. The focused element (`GetFocused()`) carries `:focus` and its ancestors `:focus-within`; it is sent Blur when it loses the focus and Focus when it takes it, and the root claims keyboard focus while it has it, which cancels the game's held keys. Removing the focused element takes the focus away, sending nothing.
- **Keys and text**: while an element has the focus, every key and text input in the window is its (KeyPress, KeyRelease, TextInput) and is consumed; with none, they pass to the game. While the focused element has a text caret (`Element::GetTextCaret`, a text entry's), the root also claims text input with that rectangle in the window's logical units, so FenrirWindow turns the window's text input on and the operating system places its input method there.
- **UI events**: `UIEvent` (`FenrirUI/UIEvent.hpp`) is an engine event, sent once at its target for each of these, naming the root (`GetId()`), the target, the kind, the pointer in UI units, the button, the key, a float and an integer as each kind says; systems read it through `EventReader<UIEvent>`. Change, Submit and DocumentReloaded are sent by the controls and hot reload, through `SendEvent`; Cancel by the gamepad's B (below).
- **UI listeners**: `AddListener(element, kind, listener)` attaches C++ to an element for one kind; a UIEvent runs the listeners of its target, then of each ancestor up to the root element, each element's in the order added, until one calls `StopPropagation()` (its element's other listeners still run). The queue has the event once whatever its listeners do. `RemoveListener` detaches one; removing the element detaches its own.

`Element::OnInput` sees the routed input itself before its UIEvent is sent: presses, releases and scrolls at their element, motion at the pressed element or else the hovered one, keys and text at the focused one, each offered to that element and then to its ancestors in turn until one returns `Consumed` (so a scroll view sees the wheel over its rows, and the arrows while a row of it has the focus). An element carrying `:disabled`, or under one, is still hit, so its press and scroll are consumed, but it is sent no OnInput and no press, release, click or scroll. `UIRoot::TakePress(element)` moves the held buttons to `element`, whose releases then send no click: a scroll view takes the press from a row when it starts dragging its content.

- **Gamepad navigation** (ADR-0065): while one of the root's elements has the focus, the D-pad, and the left stick past `UIRoot::NavigationDeadZone`, are directions. Each is offered first to the focused element alone, as a `GamepadButtonEvent` press of the D-pad button that way (a slider steps along its own axis and a focused scroll view scrolls, each until the end of its range), and when it does not take it the focus moves to the nearest focusable element that way, passing over one with focusable elements under it (a scroll view round a list). Nearest is Unity's and Godot's rule: of the elements whose centre lies past the focused one's far edge, the least distance along the direction plus twice the gap across it, less how much the two overlap across it, ties by tree order. A held direction repeats after `NavigationRepeatDelay` (0.4 s) every `NavigationRepeatInterval` (0.12 s). With no root of the app focused, the first direction focuses the root's first focusable element in tree order. A (South) is an Enter press at the focused element, so it activates a control as Enter does (a checkbox takes Enter as well as Space), and B (East) sends Cancel at it. A focus moved by a direction scrolls its scroll views to show it, as Tab does. The root consumes the D-pad, A, B and the left stick, and claims the gamepad, only while it has the focus or its virtual cursor is on; the rest, and all of it otherwise, reaches the game.
- **Virtual cursor**: `UIRootConfig::virtualCursor` or `SetVirtualCursor(true)` turns the left stick into pointer motion (past `VirtualCursorDeadZone`, up to `UIRootConfig::virtualCursorSpeed` UI units a second, kept inside the root), with hover, drags and the pointer claim as the mouse has them, and A into a left press and release at the pointer, so a click, which goes to the game, as the mouse's would, with no UI under the cursor, and does nothing while a mouse button is held; it starts at the root's centre. While on, the root keeps a `virtual-cursor` element under its root element at the pointer (`GetVirtualCursor()`), above everything and taking no pointer input (it is the root element's last child when made, so `:last-child` there sees it); the default stylesheet draws it as a ring. Off, the element goes at once and the stick is the game's.

## Style

The inline style is a `StyleDeclarations` (`FenrirUI/Style.hpp`): some properties given, the rest not. Give them through the typed setters (`root.EditInlineStyle(id)->SetWidth(Fenrir::Length::Px(200)).SetFlexDirection(Fenrir::FlexDirection::Row)`), or by CSS longhand name and value (`root.SetStyleProperty(id, "margin-left", "10px")`), which logs and refuses an unknown property or a value it cannot read. The properties:

- **Layout**: `display` (flex, none), `position` (relative, absolute), `top`, `right`, `bottom`, `left`, `width`, `height`, `min-width`, `min-height`, `max-width`, `max-height`, `aspect-ratio`, the `margin-*`s, `padding-*`s and `border-*-width`s, `flex-direction`, `flex-wrap`, `flex-grow`, `flex-shrink`, `flex-basis`, `align-items`, `align-self`, `align-content`, `justify-content`, `row-gap`, `column-gap`. Lengths are `px` (UI units), `%` or `auto` (`none` for a maximum).
- **Visual**: `background-color`; `background-image` (`url(path)`, loaded from the asset store, `linear-gradient()` with an angle or `to` side, or `radial-gradient()`, an ellipse to the farthest corner) with `background-size` (stretch, cover, contain); `border-image-source` and `border-image-slice` for a nine-slice image over the border box; the `border-*-color`s and `border-*-radius`es; `box-shadow` (outset shadows, a list); `opacity`; `transform` (`translate()`, `translateX()`, `translateY()`, `scale()`, `scaleX()`, `scaleY()`, `rotate()`) with `transform-origin`; `overflow` (visible, hidden, scroll: below); `z-index`; `pointer-events` (none, all; none by default, ADR-0065); `cursor`.
- **Text**: `color` (black by default); `font-family` (one name, quoted or not; a list takes its first, since a FenrirText family has fallbacks of its own); `font-size` (`px`, 16 by default); `font-weight` (normal, bold, or 1 to 1000); `font-style` (normal, italic, oblique as italic); `text-align` (start, end, left, right, center); `line-height` (normal, a number or a percentage of the font-size, or `px`); `letter-spacing` (normal or `px`); `text-shadow` (offset-x offset-y [blur] [colour], a list); `white-space` (normal, nowrap); `text-overflow` (clip, ellipsis).
- Colours are `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, `hsl()`, `hsla()`, `transparent` or a CSS colour name, sRGB with straight alpha, kept linear as `Colour`.

`SetStyleProperty` also takes the shorthands a stylesheet does (below), setting all of a shorthand's longhands or, for a value it cannot read, none. An element's resolved style is the defaults, then the inherited properties (`pointer-events`, `cursor` and every text property) from its parent, then the matching stylesheet rules, then its inline style. The defaults are Yoga's, as in React Native and Unity's USS rather than the web: `flex-direction` column, `flex-shrink` 0, `align-content` flex-start, and every element a flex container.

## Stylesheets

`root.AddStylesheet(text, name)` parses a CSS subset (ADR-0064, `FenrirUI/Stylesheet.hpp`) and adds it after the root's other sheets; `RemoveStylesheet` takes it away and `GetStylesheet` reads it back as parsed. `Stylesheet::Parse` alone gives the parsed sheet: rules with nesting flattened, `@keyframes`, `@font-face` and `@import` as written, and a diagnostic with its line for everything refused, which `AddStylesheet` logs with the sheet's name.

A sheet's `@font-face` rules register their faces when the sheet is added (`UIRoots::AddFontFace`, which calls the font library's `AddFace` and records the face in `GetFontFaces()`): `font-family` and `src: url(path)` (a font asset's path relative to the asset root, as every `url()` of a sheet is; a `format()` after it is allowed) are needed, `font-weight` and `font-style` take the property values, and `font-rendering: bitmap | sdf` chooses the face's mode (ADR-0062), passed to `AddFace`: an SDF face's labels are laid out and drawn in FenrirText's SDF mode, scaling without blur, beside bitmap labels in the same root. An unknown descriptor, a value that does not read and a font that does not load are errors with their lines, and the face is not registered.

- **Selectors**: type, `.class`, `#id`, compounds of them, descendant (whitespace) and child (`>`) combinators, selector lists, and the pseudo-classes `:hover :active :focus :focus-within :disabled :checked :intro :outro` (the flags `SetPseudoClass` sets) and `:first-child :last-child :root` (from where the element is). Specificity is CSS's: ids, then classes and pseudo-classes, then types; at equal specificity the later rule wins, a later sheet after an earlier one; inline style wins over every rule. A selector may end in a scroll view's pseudo-elements, `::scrollbar` (a bar's track: its `width` is the bar's thickness and its padding the thumb's inset) and `::scrollbar-thumb`, or a text entry's, `::selection` (its selected text: `background-color` behind it, `color` for it) and `::placeholder`, which match their element's selector and count as a type (`GetPseudoElementStyle` reads them resolved); the compound before one may be empty (`::scrollbar`, `:hover::scrollbar-thumb`). `!important`, `*`, `+`, `~`, attributes and other pseudo-elements are not supported.
- **Nesting**: a rule inside a rule is CSS nesting: `&` is the outer selector (`&:hover`, `.dark &`), and a selector without `&` is relative to it (`> .title`, `label`). `&` weighs as `:is()` of the outer list: its highest specificity, for every selector of the list. The outer rule comes first, then each nested rule in order, and declarations written after a nested rule apply after it, as a rule of the outer selectors.
- **Shorthands**, expanded as CSS does: `margin`, `padding`, `border-width`, `border-color` and `border-radius` (one to four values), `border` (a width, a style and a colour; with the style `none`, `hidden` or none given the widths are 0, as CSS computes them, a style with no width is `medium`, 3px, and the colour starts black until the style has a `color`), `background` (one layer: colour, image, position and `/ size`, the rest reset), `flex` (`none`, `auto`, `initial`, and up to two numbers and a basis), `gap`, `transition` and `animation` (lists, each into their longhands).
- **Custom properties** (`--name: value`) inherit down the tree, a `var()` in one resolved on the element that declares it; in a property, `var(--name)` and `var(--name, fallback)` are replaced where the value is used, in a longhand or a shorthand. A `var()` that leaves nothing readable makes the property as if no rule declared it, as CSS does.
- **Values** are read as inline style reads them, `url()`s loaded from the asset store when the sheet is added. `filter`, `scrollbar-color`, `scrollbar-width` and `background-position` are parsed and kept, and style nothing until the tickets that add them. `backdrop-filter: blur(r)` blurs what is drawn under the element's border box before it paints, as a square-cornered rectangle whatever its border radius: the renderer's backdrop composite takes no mask.
- **Transitions**: `transition-property` (names, a shorthand naming its longhands, `all`, or `none`), `-duration`, `-timing-function` (`ease`, `linear`, `ease-in`, `ease-out`, `ease-in-out`, `step-start`, `step-end`, `cubic-bezier()`, `steps()` with any jump position) and `-delay`, lists paired as CSS pairs them. When an element's cascaded value of a property its lists name changes, it runs from the value shown to the new one; a change mid-transition starts from where the running one had got to. Lengths of the same unit, numbers, colours (in sRGB, alpha premultiplied, as CSS), opacity, radii, shadow lists (the shorter padded with transparent shadows) and transform lists whose functions match step by step mix; everything else, `auto` against a length and px against % among it, is discrete and switches at the end, `display` and `pointer-events` too when `all` names them. An element's first style starts no transitions, having no value before it to run from; a transition on it starts with its first change, which `:intro` gives.
- **Animations**: `animation-name` naming a sheet's `@keyframes` (of several with one name, the last of the last sheet), `-duration`, `-timing-function` (easing each interval between keyframes, or a keyframe's own `animation-timing-function` for the interval it starts), `-delay`, `-iteration-count` (fractions and `infinite`), `-direction` and `-fill-mode`. They apply over the cascade, a property no keyframe at 0% or 100% gives taking its cascaded value there, and a transition of the same property shows over them. A name the lists keep keeps its time through restyles; `var()` and custom properties in keyframes are logged and skipped.
- **Errors**: a malformed declaration, an unknown property or a value that cannot be read skips the declaration; a malformed selector or an unknown pseudo-class skips the rule (and the rules nested in it); an unknown at-rule skips itself and its block; an unclosed block or comment ends at the end of the sheet. Each is logged with its line, and the rest of the sheet stands.

Rules are bucketed by their rightmost compound's id, else its first class, else its tag, so an element is tested only against the selectors that could match it.

## Markup documents

`UIRoot::LoadMarkup(parent, text, name, resolver)` loads a markup document (ADR-0064), UTF-8 text, under `parent`, after its children, and returns a `MarkupLoad` (`FenrirUI/Markup.hpp`): `element`, the first element at the document's top level, `elements`, all of them, `stylesheets`, the sheets its style blocks attached, and `errors`, each a `MarkupError` with its file (the document's name, or an include's or sheet's src), line and message, in document order, logged as warnings too. A document with errors loads what it could, and each load makes elements of its own. The parser is FenrirUI's own:

- Tags are the registered element tags, made through their factories as `Create` makes them; `<tag/>` holds nothing. Names are case-sensitive.
- Attributes are `name="value"` (or single quotes), or a bare name for an empty value. `id`, `class` (split on whitespace), `style` (inline declarations, read as `SetStyleProperty` reads them) and `focusable` (`true` or `false`, applied after the rest, so it wins over `disabled`) are every element's; the rest go to `Element::SetAttribute`. A `label` and a `button` take `text`; a control takes `disabled`; a `checkbox` `checked`; a `slider` `min`, `max`, `step`, `value` and `orientation` (`horizontal`, `vertical`) and a `progress` `min`, `max` and `value`, in any order; an `image` `src` (an image asset's path, loaded from the asset store as written) and `fit` (`stretch`, `contain`, `cover`); a `textentry` `value`, `placeholder`, `password` and `maxlength`. A boolean is `true`, `false` or bare for true.
- Text content between tags, trimmed at its ends, is the element's `text` attribute.
- `<include src="...">` loads the document the resolver gives for its src in its place; an include back into a document being loaded is one error. `<style>` holds CSS, kept as written up to `</style>`, and `<style src="...">` names a sheet by the resolver; each is parsed and added after the root's sheets, its errors the load's at their own lines. The resolver is a function from src to text, which also serves the sheets' `@import`s.
- `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, `&#N;` and `&#xN;` decode in text and attribute values; `<!-- -->` comments are skipped.

Unknown tags (with what is in them), unknown attributes and values an element refuses, text in an element that takes none or that has a `text` attribute, bad entities, tags left open, closing tags that close none, unquoted values, repeated attributes, attributes with no whitespace between them, an empty `<style>`, and namespaces, processing instructions, DTDs and CDATA are errors, never skipped quietly.

## Files and hot reload

`root.LoadDocument(parent, path)` loads a markup document from a file as `LoadMarkup` loads one, and `root.LoadStylesheet(path)` adds a sheet from a file as `AddStylesheet` adds one. `path` is relative to the asset root (`AssetsConfig::root`) or absolute; an `<include src>` or `<style src>` is relative to the document it is written in, and an `@import` to its sheet. Errors name each file by that path. An `@import` loads the sheet it names in its place: its rules come before the importing sheet's rules written after it, so those win at equal specificity. An import of a sheet that is being loaded (a loop) is one error, and loads nothing more.

Hot reload is a switch per root (`UIRootConfig::hotReload`, `SetHotReload`), off by default. The root remembers every file it loaded, documents, includes, sheets and imports, with its modification time, and while the switch is on reads those times every `UIRoot::HotReloadInterval` (250 ms) of FenrirTime (`UIRootStats::filesPolled` counts them on the frame that polls). A changed sheet or import is parsed again in its sheet's place and every style is resolved again; its elements stay. A changed document or include loads its document again under the same parent at the same position: the elements and sheets it made before are removed at once, their ids going stale, and `DocumentReloaded` is sent at the new first element for the game to find its ids again. A version with any error, or a file that is gone, is not taken: the version before stays, the errors are logged, and the file is read again when it next changes. A document the game removed, and a sheet it removed, are not polled again. The polling is FenrirUI's own: FenrirAssets does not poll files.

## Scrolling

An element with `overflow: scroll` clips its children to its padding box as `hidden` does, and moves them up and left by its scroll offset (`GetScrollOffset`, `SetScrollOffset`): their rectangles, their painting and their hit tests are at the scrolled place. Its range (`GetScrollRange`) is how far its content, its children's border boxes and its padding past them, reaches past its padding box; the offset is clamped to it after each layout. A bar shows on each axis whose range is not zero, while its `::scrollbar` has a width, along the padding box's right or bottom edge over the children; its thumb is the track's share the view shows, no shorter than it is wide, and `GetScrollbars` gives where the tracks and thumbs are. A scroll view's bars are hit before its children when it takes pointer input. The scroll view control (below) is what scrolls it by input.

## Controls and the default stylesheet

The controls (`FenrirUI/Controls.hpp`) are elements with behaviour, which `UIRoots` registers under their tags; a game reads and sets their values through `GetElement` and a cast to their class, and a factory of its own under the tag replaces one. `Control` is the interactive ones' base: they make themselves focusable, and `SetDisabled` gives `:disabled`, takes the focus and stops their input.

- **`button`** (`Button`): its caption is its text (`SetText`). A press and release inside it is the root's Click; Enter and Space while it has the focus send a Click too.
- **`checkbox`** (`Checkbox`): `SetChecked`/`IsChecked`, with `:checked`; a click on it, and Space or Enter while it has the focus, toggle it and send Change (value 1 or 0). Its `checkbox-mark` child shows while checked.
- **`slider`** (`Slider`): `SetRange`, `SetStep` (0 for none), `SetValue`, `SetOrientation` (vertical sets the class `vertical`, min at the bottom); its `slider-fill` and `slider-thumb` children are placed by their inline style. A press sets the value under the pointer and drags it (the slider takes the press and the focus, so a scroll view round it does not drag); Left and Down step it down and Right and Up up, and so do the D-pad's directions along its axis until the end they step to, Home and End to the ends, and the wheel steps it while it has the focus (unfocused, the wheel passes on to a scroll view round it). Change carries the value, sent at each change and once more at a drag's release with `integer` 1.
- **`progress`** (`ProgressBar`): `SetRange` and `SetValue`; its `progress-fill` child's width is the fraction, `GetFraction()`.
- **`image`** (`ImageView`): `SetSource` (an image asset) and `SetFit` (stretch, contain, cover). It measures at the image's size, one UI unit a pixel, keeping its aspect ratio when one side is given or bounded, and draws in its content box by its fit. A covering image is drawn as its box filled with an image pattern, with no clip of its own, so an ancestor's rounded `overflow: hidden` still clips it (the painter evaluates only the innermost clip per pixel).
- **`scroll`** (`ScrollView`): `overflow: scroll` by the default stylesheet, with `GetOffset`/`SetOffset`. The wheel over it or over anything in it scrolls `ScrollStep` (40) units a notch; a press on a thumb drags it, one on a track jumps a page; a press on its content that moves past `DragThreshold` (8 units) drags the content, taking the press from the row it landed on so that row sends no click; while it, or something in it that does not take the key, has the focus, the arrows scroll a step, Page Up and Page Down a page, Home and End to the ends; focused itself, the D-pad scrolls a step, passing at the end of its range.
- **`textentry`** (`TextEntry`): one line of UTF-8 text, `SetValue`/`GetValue`, `SetPlaceholder`, `SetPassword` (a bullet shown for each grapheme, no words, nothing copied) and `SetMaxLength` (graphemes; 0 for none). Its caret and anchor (`GetCaret`, `GetAnchor`, `Select`, `SelectAll`) are byte offsets on grapheme boundaries. While it has the focus, typed text replaces the selection or goes in at the caret; Left and Right move a grapheme, or with Ctrl to the start of the word before or the end of the word after (FenrirText's UAX#29 `Words`); Home and End go to the ends; Shift extends the selection; Backspace and Delete take the selection or a grapheme (a word with Ctrl); Ctrl+A selects all; Ctrl+C, Ctrl+X and Ctrl+V go through FenrirWindow's clipboard; Enter sends Submit and Escape blurs. A press focuses it and places the caret at the character under the pointer, a drag selects, and a double click selects a word. Each edit sends Change. It paints its own text through its content box, scrolled across to keep the caret in view (`GetScroll`): the selection behind it in its `::selection` background colour (and the selected text in that style's colour), the caret, a `CaretWidth` bar a line tall in its colour, blinking every `BlinkSeconds` of FenrirTime from the last edit or move, and while empty its placeholder in its `::placeholder` style. While it has the focus, the root claims text input with its caret (`Element::GetTextCaret`), so the window takes text and places the IME there.

The **default stylesheet** (`Resources/default.css`, embedded at configure time and returned by `DefaultStylesheet()`) is plain: neutral greys, one accent blue, `font-family: sans-serif` (FenrirText's embedded default face until a game registers that family), a focus ring (`box-shadow`) on every focusable control, and hover, active, checked and disabled states for every control. Every root has it before its own sheets unless made with `UIRootConfig::defaultStylesheet` off, so a game's rule overrides one of it by specificity, or by coming later at equal specificity: `button { background-color: ... }` replaces the plain button's background, and a hovered button keeps the default's `button:hover` until the game writes its own. A text entry's selection and placeholder are its `textentry::selection` and `textentry::placeholder`. A control's own parts (`checkbox-mark`, `slider-fill`, `slider-thumb`, `progress-fill`) take no pointer input, so a press or click names the control. `virtual-cursor` is the virtual cursor's ring.

## The frame

In `PostUpdate`, for each root in drawing order: its target's size and the scale (a target with no size ends the frame here, so its transitions and animations stand still); every running transition and animation moved on by FenrirTime's frame delta; the dirty styles resolved, the cascade before layout (a change of inline style marks the element and the path above it; a change of classes, id or pseudo-classes marks its subtree when a compound before a combinator in the root's sheets names its tag, id or a class it has or had (or names none of them), else the element; a change of children marks the siblings when a selector uses `:first-child` or `:last-child`; adding or removing a sheet marks every element; a changed inherited value or custom property reaches the children), starting the transitions and animations their changes call for, then the shown style of each element whose motion moved, its animations and then its transitions over its cascaded style, each written into its Yoga node; a layout if any node is dirty (a clean root calls no layout, which `GetStats()` shows); the rectangles read back and snapped when it laid out, the pixel size changed or a scroll offset moved, each scroll view's range measured and its offset clamped to it; `:intro` cleared on the elements that layout included; then every element painted in tree order, the list submitted to the target, and last the elements whose outros have ended removed.

Each element paints, under its transform about its origin: its shadows (the first on top), its background colour and its background image, each a rounded rectangle over its border box, then its border, a third box draw (the painter has no draw that fills and borders a box at once), and its border image; then its content (`Element::Paint`) and its children sorted by `z-index` (equal ones in tree order), both inside its padding box with its inner radii when it hides or scrolls overflow, and last, over its children, a scroll view's scrollbars (each track's box, then its thumb's, from their pseudo-elements' styles). An element whose opacity is under one and that has children draws all of that through an offscreen group (ADR-0060) over what it and its subtree cover, composited at its opacity; a leaf's colours are faded instead. An element that is `display: none` or fully transparent paints nothing.

`UIRoots::settings` holds the switches for every root: `offscreenGroups` (off, an element's subtree is faded box by box instead of through a group) and `antiAliasing` (on, edges fade over one pixel; off, for a pixel-art UI, every root's painter draws with FenrirPainter's `PainterConfig::antiAliasing` off: paths and strokes without their fringe, and boxes, borders, shadows' boxes, circles and clips with hard edges, a pixel covered when its centre is inside; text keeps its glyphs' own coverage).
