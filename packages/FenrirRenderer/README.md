# FenrirRenderer

Draws the active scene's meshes through its cameras, every frame, over a private graphics device with an OpenGL 4.6 backend and a null backend (ADR-0016, ADR-0019, ADR-0022, ADR-0023, ADR-0024, ADR-0026, ADR-0047, ADR-0048). Game code draws the ECS way: a `MeshRenderer` on an entity, or an `InstancedMeshRenderer` drawing an instance list's many copies, a `Camera` on another, a `DirectionalLight`, any number of `PointLight`s, `SpotLight`s and `RectLight`s, and the `Sky` scene resource, which is also the scene's ambient light. No public header names GL, SDL or the shader compiler's libraries. Built with `FENRIR_ENABLE_RENDERER` (on by default).

```cpp
#include "FenrirAssets/Assets.hpp"
#include "FenrirRenderer/Renderer.hpp"
#include "FenrirWindow/Window.hpp"

Fenrir::App app(std::make_unique<Fenrir::ConsoleLogger>());
Fenrir::Window window = Fenrir::Window::Install(app);       // first: the renderer asks it for the window's surface
Fenrir::Assets assets = Fenrir::Assets::Install(app);
Fenrir::Renderer renderer = Fenrir::Renderer::Install(app); // OpenGL by default; check renderer.IsValid()

Fenrir::AssetStore& store = assets.Store();
auto mesh = store.Add<Fenrir::Mesh>(MakeCube(), Fenrir::AssetOwner::App());
auto lit = store.Load<Fenrir::Shader>("builtin:lit", Fenrir::AssetOwner::App()).handle;
auto material = store.CreateMaterial(lit, Fenrir::AssetOwner::App());
store.SetColour(material, "baseColour", Fenrir::Colour::FromSrgb(0xC08040FF));

Fenrir::EntityList& entities = app.GetActiveScene().GetEntityList();
entities.CreateEntity().AddComponent<Fenrir::MeshRenderer>(Fenrir::MeshRenderer{mesh, material});
Fenrir::Entity camera = entities.CreateEntity();
camera.GetComponent<Fenrir::Transform>().pos = {0.0f, 0.0f, 5.0f}; // looking along -Z
camera.AddComponent<Fenrir::Camera>();
entities.CreateEntity().AddComponent<Fenrir::DirectionalLight>();     // shining along its -Z
app.Run();
```

## Install and order

- `Renderer::Install(App&, RendererConfig)` returns the move-only `Renderer` owner of the renderer core and the graphics device, and adds the sequential `Render` system.
- **Install order:** FenrirWindow (for any backend but `Null`), then FenrirAssets, then the Renderer, all before the first frame. `Install` requests the main window's graphics surface (an OpenGL 4.6 core context, a debug one with `debugValidation`, and an sRGB backbuffer with no depth, stencil or MSAA), so the window is made then. It registers the built-in shaders in the asset store: `builtin:unlit`, `builtin:lit`, `builtin:fallback`, `builtin:background` (with a `CUBEMAP` variant for a cubemap `Sky`), `builtin:output` (with `MSAA`, `OCCLUSION`, `REFLECTIONS` and `ABERRATION` variants), the debug drawing programs `builtin:debug-lines`, `builtin:debug-triangles` and `builtin:debug-text`, `builtin:2d` for the overlay's 2D draw lists, `builtin:panorama`, which draws a panorama sky into its cube texture, and the sky's filtering programs `builtin:sky-irradiance`, `builtin:sky-specular` and `builtin:brdf-lut`, and the bloom's `builtin:bloom-downsample` (with `MSAA` and `HORIZONTAL` variants, the latter the anamorphic streaks') and `builtin:bloom-upsample` (with `HORIZONTAL` and `DIRT` variants, the latter the composites under lens dirt), and the lens flare's `builtin:lens-flare`, and `builtin:gtao`, the ambient occlusion's horizon search (with an `MSAA` variant) and its `DENOISE` blur, the reflections' `builtin:hi-z` (with `COPY` and `MSAA` variants) and `builtin:scene-history` (with `DOWNSAMPLE` and `MSAA` variants) and their trace `builtin:reflection-trace` (with an `MSAA` variant), and `builtin:skinning`, compute skinning's compute program, which no material can draw with. It adds the `Overlay` app resource, removed when the owner ends.
- **Teardown in reverse:** destroy the `Renderer` before the `Window`, the `Assets` and the `App`; declaring the owners in install order does this. It waits for the GPU, frees every GPU resource and releases the window's surface.
- **Failure:** without an `AssetStore`, without a valid `Window` (any backend but `Null`), or when the backend cannot start (no OpenGL 4.6 core context, with SDL's message), `Install` logs one error and returns an owner whose `IsValid()` is false. It adds no systems, and its calls do nothing. It never falls back to the null backend.
- The `Null` backend needs no window or GPU: it keeps every book a backend keeps and draws nothing, for tests and headless apps. With a window it follows the window's size, else a fixed 1280 x 720.

## RendererConfig

`backend` (`OpenGL`, or `Null`); `vsync` (`Off`, `On` default, `Adaptive`; changeable with `Renderer::SetVsync`, which returns the mode in effect, an unsupported one falling back to `On`, logged); `msaa` (samples per pixel of every view's `SceneColor` and `SceneDepth`, resolved in `Output`: 1 (off, the default), 2, 4 or 8; another count uses the largest of those below it, logged); `debugValidation` (on in Debug builds: GL's debug messages reach the app's logger); `framesInFlight` (2); `automaticInstancing` (on: consecutive `Opaque` and `Masked` items with the same pipeline, material and mesh draw as one instanced draw, ADR-0051; off draws each on its own, for comparison; changeable with `Renderer::SetAutomaticInstancing`); `computeSkinning` (on: each skinned mesh is skinned once a frame in compute and every pass draws the result rigidly, ADR-0050; off, every draw skins in its vertex stage under `SKINNED`; changeable with `Renderer::SetComputeSkinning`; see "Skinning"); `clusteredLights` (on: each camera's point, spot and rect lights are listed by a compute pass in the clusters of its frustum they reach, and each pixel loops over its cluster's only, ADR-0049; off, every pixel loops over every light, for comparison; changeable with `Renderer::SetClusteredLights`; see "Light clusters"); `gpuCulling` (on: each camera's cull pass drops the opaque and masked copies outside its frustum, ADR-0057; off, the pass keeps every candidate, for comparison, and only the coarse cull of whole entities on the CPU culls; changeable with `Renderer::SetGpuCulling`; see "GPU culling"); `lodErrorPixels` (1: each copy of a mesh with levels of detail draws at the coarsest level whose error, scaled by the copy's largest axis scale and projected at its distance from the camera, is under this many pixels, ADR-0057; with `gpuCulling` off every copy draws level 0; see "GPU culling") and `minProjectedPixels` (0: a copy whose bounding sphere's radius projects under this many pixels is dropped as if outside the camera; 0 drops none; both changeable with `Renderer::SetLodSelection`); `shadowCascades` (4: the `DirectionalLight`'s cascades per camera, 1 to 4), `shadowMapSize` (2048: each cascade's map's side in texels; a camera's maps sit side by side in one depth texture `shadowCascades` times as wide) and `shadowSplitLambda` (0.75: the practical split scheme's blend of even, 0, and logarithmic, 1, splits; see "Shadows"); `spotShadowBudget` (8: how many `SpotLight`s may cast shadows in a frame, the nearest to any camera; changeable with `Renderer::SetSpotShadowBudget`) and `spotShadowMapSize` (1024: each shadowed spot light's tile's side in texels; see "Shadows"), `pointShadowBudget` (4: how many `PointLight`s may cast shadows in a frame, the nearest to any camera; changeable with `Renderer::SetPointShadowBudget`) and `pointShadowMapSize` (512: each face of each shadowed point light's cube, in texels). There are no other tuning settings and no native escape hatch.

## Main-thread rule and the Render phase

- Everything the renderer does runs on the main thread, where the GL context is current: its one system is sequential, in the `Render` phase. Call `Renderer`'s functions from the main thread too, outside parallel systems.
- **`Render`-phase rule:** the renderer reads the scene in `Render`, after `PostUpdate`, so it sees the poses interpolated in `AfterTicks` and everything C++ and C# wrote in `Update` and `PostUpdate`, whatever order packages were installed in. Writing scene state in `Render` is unsupported.

## Each frame

All in `Render`, on the main thread (ADR-0019):

1. Read the main window's pixel size. A minimised or zero-sized window builds, submits and presents nothing, but the frame index still advances.
2. Read the active scene: every visible `MeshRenderer` and `InstancedMeshRenderer` (with `GetWorldMatrix` once each; an instance list is uploaded when it is new or its revision moved on), every enabled `Camera` as a view, the first `DirectionalLight` (more are warned about once), every `PointLight`, `SpotLight` and `RectLight` that can light anything, the `Sky` and any `SkyLight`, and the scene's `DebugDraw`, tessellated, when FenrirDebugDraw is installed. Inactive scenes are never read, and nothing is kept between frames but each reflecting camera's history colour and Hi-Z pyramids (step 4).
3. Prepare: upload each mesh, material and image that is new or has a new revision (an image with every mip level, made at upload; the `Sky`'s cubemap as a cube texture, each face with its mips, or its panorama as a 2D texture with its mips and an RGBA16F cube texture for it), and make each render target image's texture, keyed by asset handle and revision, and free the GPU side of each handle that went stale. Pipelines are made the first time a draw needs them (keyed by shader variant, blend mode, culling, vertex streams and sample count) and kept while their shader lives.
4. Build one render graph for every view: first, in the `Cull` stage, one `Cull` compute pass per view with opaque or masked items inside its frustum, dropping the copies outside it and choosing each kept copy's level of detail (ADR-0057; see "GPU culling"); then, in the `Prepare` stage, one `Panorama` pass per face and mip level of a panorama prepared since the last frame, each drawing that level from the panorama itself (four points a texel, from the panorama's mip as coarse as the level), after which the panorama's own texture is freed; in the first frame, `BrdfLut`, the split sum's 128 x 128 RG16F BRDF lookup table; and when the sky's source changes (a new cube texture, or a colour sky for a cube one), `SkyIrradiance`, its L2 spherical harmonics projected from its cube, and one `SkySpecular` pass per face and mip level of its prefiltered GGX cube (faces at most 128 wide, one roughness step a mip level), never for a new `intensity` or `rotation`; then, in the `Skinning` stage, when skinned meshes are drawn and compute skinning is on, one `Skinning` compute pass (see "Skinning"); then `SpotShadows`, in the `Shadow` stage, when spot lights within the budget cast and some item does, and per view `ShadowCascades`, there too, when the `DirectionalLight` casts and some item does (see "Shadows") → `DepthPrepass` (ADR-0049: the `Opaque` and `Masked` items in `Opaque`'s order, merged as `Opaque` merges them, each run one multi-draw of its commands from the view's cull pass, one per level of detail of its mesh (ADR-0057), through the item's own vertex stage and `builtin:depth-prepass`'s fragment stage, writing reversed-Z depth cleared to 0 and each pixel's view-space normal, octahedral (`Fenrir/Normals.glsl`), into an RG16F `SceneNormals` target cleared to 0, at the view's size and MSAA samples) → `LightClusters`, when there are point, spot or rect lights and clustering is on (a compute pass; see "Light clusters") → the ambient occlusion, when the camera's `ambientOcclusion` is on (`GtaoHorizons`, XeGTAO's horizon search over the prepass's depth and normals, sample 0 under MSAA, into R8 occlusion and edge targets at the view's size; then `GtaoDenoise`, its edge-aware 3 x 3 blur, into the view's R8 occlusion texture) → `HiZ`, when the camera's `reflections` are on (ADR-0056: one pass per level of the view's Hi-Z pyramid, an R32F texture at the view's size with a full mip chain that the camera keeps across frames; the first copies the prepass's depth into level 0, sample 0 under MSAA, and each later one draws a level from the one above, each texel the nearest depth of the texels it covers, the last row and column folded in where a level's side is odd; the camera keeps two pyramids and draws the other each frame, so last frame's is still there) → `ReflectionTrace`, after it (`builtin:reflection-trace`: each pixel's mirror ray about its prepass normal marched through the pyramid, at most 64 steps, into an RGBA16F hit target at the view's size: the hit's UV in last frame's view, its confidence and the ray's length; see "Screen-space reflections") → `Opaque` (the `Opaque` and `Masked` items sorted by pipeline, material and mesh, each run with the same three one instanced draw (ADR-0051) unless `RendererConfig::automaticInstancing` is off, drawn indirectly from the view's cull pass's commands for it, one per level of detail, as the prepass does (ADR-0057), each instance reading its own draw record through the view's indirection, testing the prepass's depth for equality without writing it, so each pixel is shaded once; it binds the view's occlusion texture, or the white one, at set 1 binding 1, and every other pass the white one) → `Background` (at depth 0, filling only what nothing drew: the camera's own colour, or the scene's `Sky`, a colour, or a cube texture sampled by the direction each pixel looks along, turned by the sky's `rotation` and scaled by its `intensity`) → `Transparent` (when there are `AlphaBlend` or `Additive` items inside the camera's frustum, each item tested by its world bounds, ADR-0057: one draw each, depth tested without writing it, back to front by the view-space depth of each item's world origin) → `Debug` (when the scene has debug drawing and the camera's `drawDebug` is on) → `SceneHistory`, first in `PostProcess`, when the camera's `reflections` are on (one pass per level of the view's history, an RGBA16F texture at the view's size with a full mip chain that the camera keeps across frames: the first copies SceneColor before bloom into level 0, the plain mean of its samples under MSAA, with infinities clamped and NaN left out as bloom's first level does, and each later one the 2 x 2 mean of the level above) → the bloom, in `PostProcess`, when the camera's `bloom.intensity` is over 0 and its viewport at least 2 pixels on a side (one `BloomDownsample` per level, SceneColor into half-size RGBA16F levels, one per halving of the viewport's shorter side up to six, with Jimenez's 13-tap filter and the Karis average on the first, which also clamps infinities to RGBA16F's largest value and leaves NaN out, so one bad pixel cannot blacken the bloom; `builtin:lit` clamps its colour there too; then one `BloomUpsample` per level from the second smallest up, each level below tent-filtered and blended over its own by `bloom.radius`; then `BloomComposite`, level 0 tent-filtered over SceneColor by `bloom.intensity`) → the anamorphic streaks, in `PostProcess`, when the camera's `anamorphicStreaks.intensity` is over 0 (ADR-0059: one `StreakDownsample` per level, from bloom's level 0, run after bloom's downsamples and before its upsamples, each level half the width of the one before and level 0's height, one per halving of level 0's width up to eight, with a horizontal-only filter; a view whose bloom is off first runs one `BloomDownsample` of its own into a level 0; then one `StreakUpsample` per level from the second narrowest up, each level below filtered with a horizontal tent and blended over its own by `anamorphicStreaks.length`, after `BloomComposite`; then `StreakComposite`, the first streak level over SceneColor, times the tint at unit luminance, by `anamorphicStreaks.intensity`) → the lens flare, in `PostProcess`, when the camera's `lensFlare.intensity` is over 0 (ADR-0059: `FlareGhosts`, `builtin:lens-flare` from bloom's level 1, run after the streaks' downsamples and before bloom's upsamples blend over it, into an RGBA16F level of its size; a view whose bloom is off first runs `BloomDownsample`s of its own down to level 1; then `FlareBlur`, bloom's 13-tap filter without the Karis average at the same size; then `FlareComposite`, that over SceneColor by `lensFlare.intensity`, after `StreakComposite`; with lens dirt, `BloomComposite` and `FlareComposite` are `builtin:bloom-upsample`'s `DIRT` variant, which also reads the dirt image) → `Output` (the linear RGBA16F `SceneColor` resolved, each channel at its own point under the camera's `chromaticAberration`, scaled by its `exposure`, darkened by its `vignette`, graded by its `colourGrading`, mapped into [0, 1] by its `tonemapper`, grained by its `filmGrain` and encoded into the view's viewport of its sRGB target; with the camera's `debugView` at `AmbientOcclusion`, `ShadowAtlas`, `SpotShadowAtlas` or `ReflectionConfidence`, its occlusion texture, its shadow atlas, the spot shadow atlas or its reflection hit target's confidence drawn as grey instead, black without one, and the passes only SceneColor needs culled; at `Reflections`, last frame's history at each reflection hit times its confidence, exposed, vignetted, graded, tonemapped and grained, read before `SceneHistory` replaces it, so that `Output` runs before it); then, once for the window, `Overlay 2D` (the overlay's 2D draw lists, when there are any) and `Overlay` (debug screen text and messages). A view whose draws sample an image another view draws runs after it. A window no view draws into is cleared to black, logged once.
5. Record each pass and submit it; then present.

## Components and resources

- `MeshRenderer { mesh, material, visible = true, castShadows = true }`: one mesh, one material, one draw, or one instance of a draw merged with matching items (ADR-0051). `visible` hides only its own entity. `castShadows` draws it into the sun's, the spot lights' and the point lights' shadows (see "Shadows"): only an `Opaque` or `Masked` material casts. An empty or stale mesh is skipped (a stale one logged once per handle); an empty or stale material draws with the fallback material, flat magenta and unlit, logged once per handle as a warning. A missing `Transform` is the identity.
- `InstancedMeshRenderer { mesh, material, instances, castShadows = true, visible = true }` (ADR-0051): one draw a pass of every copy in `instances`, a FenrirAssets `InstanceList` (`InstanceListData`: transforms relative to the entity, and one colour per transform or none), each at the entity's world matrix times its transform, its colour multiplying the base colour of `builtin:lit` and `builtin:unlit`. The list is uploaded when it is new or its revision moves on (`AssetStore::Replace`), never because the entity moved, into one buffer every list shares (set 3 binding 1, `Fenrir/Draw.glsl`'s `FenrirInstance`), which `CurrentDraw()` reads. It is never merged with other items; its world bounds are the box around every copy's mesh box, computed when the list is uploaded (ADR-0057), and a transparent material sorts the whole list by the entity's position and leaves it out of a camera whose frustum its bounds are outside. An empty or stale mesh or list is skipped (a stale list logged once per handle), as is a mesh with skin data (logged once per entity); materials fall back as a `MeshRenderer`'s do. `castShadows` draws every copy into the sun's, the spot lights' and the point lights' shadows, one draw a cascade, tile or cube (six where the cube's faces are drawn one at a time), as a `MeshRenderer`'s does.
- `SkinnedMesh { skeleton }`, beside a `MeshRenderer` whose mesh has skin data: skins it on the GPU from the pose of `skeleton`, the entity carrying FenrirSkeleton's `SkeletonPose` (see "Skinning"). **A skinned item is drawn with the skeleton entity's world matrix: the mesh entity's own `Transform` and its ancestors are never applied.** `visible` and the material stay on the mesh entity.
- `Camera`: a view from its entity along local -Z, +Y up, with reversed-Z depth (ADR-0026). Every enabled camera in the active scene draws one view a frame; there is no active camera.
  - `projection`: `Perspective { verticalFov = 60 degrees in radians, near = 0.1 }`, with an infinite far plane, or `Orthographic { height (full, world units) = 10, near = 0.1, far = 1000 }`. The aspect comes from the viewport's pixel size. A tagged union, as FenrirPhysics' `CollisionShape` is: assign a kind (`camera.projection = Fenrir::Orthographic{20.0f}`) and read it with `Is<T>()` and `As<T>()`.
  - `enabled` (true) and `order` (0): views into one target draw lowest order first, ties by entity id, logged once.
  - `viewport`: `{ x, y, width, height }` as fractions of the target from its top-left corner, the whole target by default. Each view has its own scene targets at its viewport's pixel size, and `Output` writes only its viewport; the first view into a target clears it to black.
  - `target`: `WindowTarget { window }` (the main window, the default) or `ImageTarget { image }`, a render target: an `ImageData` with a size, RGBA8, sRGB, flat, and no pixels, made with the store's `Add` and resized with `Replace`. A material texture parameter naming it samples it, and the view drawing it runs first. A view whose own draws sample its target gets the parameter's default texture there, logged once, as does one whose sampling would make views wait on each other in a cycle (broken in the views' order).
  - `background`: `SceneBackground` (the default: the scene's `Sky`) or `ColourBackground { colour }`, which overrides the `Sky` for this camera's view only.
  - `drawDebug` (true): whether the view draws the scene's debug shapes and world text (see "Debug drawing").
  - `exposure` (0): EV stops; `Output` multiplies the view's linear colour by 2^`exposure`, so each +1 doubles it. There is no auto-exposure.
  - `bloom` (`{ intensity = 0.04, radius = 0.7 }`): bright pixels bleed into their surroundings before the tonemap, as CoD: Advanced Warfare's bloom (ADR-0049). SceneColor is blurred over ever wider areas, down to a sixty-fourth of the view, and mixed back in: `intensity` (clamped to [0, 1]) is the share of the blur in the result, `radius` (clamped to [0, 1]) how much each wider blur adds against the one before it, so 0 keeps the narrowest only and 1 the widest only. There is no threshold: everything blooms by the same share and only what is several times brighter than its surroundings shows a glow. For exact colours set `intensity` to 0 as well as `tonemapper` to `None`; 0 also skips the passes. The blur keeps the scene's energy (its filters' weights sum to 1 and its levels are mirrored at their edges), less a little from very bright single pixels, which the Karis average holds down so they do not flicker.
  - `ambientOcclusion` (`{ enabled = false, radius = 0.5, intensity = 1 }`): ground-truth ambient occlusion (GTAO, ADR-0049), Intel's XeGTAO (MIT, `Resources/XeGTAO`) from the depth prepass: how much of the sky nearby geometry hides from each pixel's surface, within `radius` world units (times XeGTAO's 1.457), raised to XeGTAO's 2.2 times `intensity`. `Fenrir/Lighting.glsl` darkens the sky's diffuse light by the lesser of it and the material's own occlusion, and its specular light by a specular occlusion made from that; the directional, point, spot and rect lights never. Transparent items take none, as they are not in the prepass. Off, or a `radius` or `intensity` of 0, skips the passes.
  - `reflections` (`{ enabled = false, intensity = 1, maxDistance = 50, thickness = 0.5, roughnessCutoff = 0.6 }`): screen-space reflections (ADR-0056; see "Screen-space reflections"). On (enabled, with an intensity and a max distance above 0), the camera keeps across frames what they read, its view's history colour and two Hi-Z pyramids (about 44 MB at 1920 x 1080), drawn by its `HiZ` and `SceneHistory` passes, and its `ReflectionTrace` pass traces each pixel's mirror ray, up to `maxDistance` world units, a hit being a surface the ray passes behind by less than `thickness`; the kept textures are remade at a new viewport size, and freed after a frame the camera draws no view with them on. Every material lighting through `Fenrir/Lighting.glsl` takes the reflection over the sky's by its confidence times `intensity`, fading out over the 0.1 of roughness below `roughnessCutoff`. Off skips the passes and keeps nothing.
  - `anamorphicStreaks` (`{ intensity = 0, length = 0.75, tint = white }`): bright pixels drawn out into long, thin horizontal lines before the tonemap, after the bloom, as an anamorphic lens draws them (ADR-0059). A chain beside the bloom's, from its first level, halves only the width at each level with a horizontal-only filter and blends each level back over the next: `intensity` (clamped to [0, 1]) is the share of the streaks in the result, as bloom's is, and `length` (clamped to [0, 1]) how much each longer level adds against the one before it, so 0 keeps the shortest only and 1 the longest only, reaching most of the way across the view. `tint` is a linear colour scaled to unit luminance, so its hue and saturation count and its brightness does not (grey or black is white). As with bloom there is no threshold and the streaks keep the scene's energy, so they move light, never add it; a few hundredths draw lines from lights and leave dim surfaces alone. 0, the default, skips the passes; a view with bloom off still streaks.
  - `lensFlare` (`{ intensity = 0, ghostCount = 4, ghostSpacing = 0.4, haloRadius = 0.6, haloWidth = 0.1, chromaticOffset = 0.01, dirt = none, dirtIntensity = 1 }`): John Chapman's pseudo lens flare and lens dirt before the tonemap, after the streaks (ADR-0059). From bloom's second level, each pixel reads `ghostCount` ghosts (at most 8) along the line from it through the view's centre, ghost i at i x `ghostSpacing` of the way to the centre, so ghosts read past it land on the far side, and a halo: what is near the centre, drawn on a ring at `haloRadius` (0 at the centre, 1 at the corners) reaching `haloWidth` either side. Each read takes red and blue `chromaticOffset` apart along the line through the centre, so the ghosts fringe. A ghost fades with its read point's distance from the centre and with how far it is magnified; the pixel keeps the rest of its own light, so a flat view is left as it is. The result is blurred and mixed into SceneColor by `intensity` (clamped to [0, 1]), as bloom is, so the flare moves light, never adds it, and with no threshold a bright sky ghosts as a faint glare. 0, the default, skips the passes. `dirt` is a greyscale image of the lens's dirt (`GenerateLensDirt` in `FenrirRenderer/LensDirt.hpp` makes one), stretched over the view: where it is bright, the bloom's and the flare's share of each pixel is multiplied by 1 + `dirtIntensity` x its luminance, held at or below 1. It needs no flare: with the flare off it scales the bloom alone. A dirt image that is not a flat image with pixels (a cubemap, a render target) is none, logged once; the streaks take none of it.
  - `colourGrading` (identity): the view's look, set on the exposed scene colour in linear Rec. 709 before the tonemapper (ADR-0059), so contrast and saturation act on scene values, mid grey stays put and the tonemapper still rolls off whatever the grade brightens. Its steps run in this order. White balance: `temperature` (6500 K, held to 2500 to 25000) names the daylight the view takes as white and `tint` (0, from -1 to 1, positive greener, a Duv of 0.02 at 1) moves it off the daylight locus; a von Kries adaptation in CAT02's LMS takes that white to D65, so a lower temperature cools the picture, a higher one warms it, and a positive tint moves it to magenta. `contrast` (1): the slope in log2 around mid grey (0.18), which it keeps. Split toning: `shadowTint` and `highlightTint` (white; any grey is none), linear colours scaled to unit luminance, so each shifts hue and not brightness and its saturation is its strength, crossing from one to the other by luminance over four stops either side of the split, which `balance` (0, from -1 to 1) moves down by up to four stops from mid grey (positive gives the highlights more). `saturation` (1) around Rec. 709 luminance, after the tints, so lowering it fades them too. The ASC CDL's `slope`, `offset` and `power` per channel last, negatives clamped before the power (held at or above 0.001). An identity grade is skipped. The grade is mirrored on the CPU (`src/Core/ColourGrading.cpp`), which the GL tests hold the shader to; 3D LUTs, lift, gamma and gain, and shadows, midtones and highlights wheels are ADR-0059's "Not yet".
  - `chromaticAberration` (`{ intensity = 0 }`): each channel of SceneColor read at its own point as `Output` reads it, first in ADR-0059's order: green where it is, red `intensity` of the way towards the view's centre and blue as far away from it, so red fringes outwards and blue inwards by `intensity` of the half-diagonal at the corners, and the centre is as it is. Over 0 it draws through `builtin:output`'s `ABERRATION` variant, which under MSAA resolves green's texel and the four texels round red's and blue's points, blended bilinearly as the single-sampled read is, so MSAA and single-sampled views fringe alike; 0, the default, keeps the plain variant. A few thousandths fringe the edges.
  - `vignette` (`{ intensity = 0, radius = 0.5, smoothness = 0.5, roundness = 1 }`): the exposed linear colour multiplied by 1 - `intensity` x smoothstep(`radius`, `radius` + `smoothness`, d) before the grade and the tonemapper (ADR-0059), so it darkens as a lens does and the tonemapper still sees it. d is the distance from the view's centre, 0 there and 1 at the corners, measured in pixels for a `roundness` of 1, a circle whatever the view's aspect, and in each axis' own half-length for 0, an ellipse in the view's proportions. 0, the default, skips it.
  - `filmGrain` (`{ intensity = 0, response = 0.8, size = 1 }`): noise added after the tonemapper, display-referred (ADR-0059): the tonemapped colour is encoded with a 2.2 gamma, moved by up to `intensity` in every channel alike, weighted by mix(1, 4 L (1 - L), `response`) of its encoded luminance L so it shows most in the mid-tones and none at black and white for a `response` of 1, and decoded for the target's sRGB encoding. The noise is a hash (PCG3D) of the pixel's cell, `size` pixels a side, and the frame's index, so it moves each frame and a test's frame is reproducible. 0, the default, skips it.
  - All three are mirrored on the CPU (`src/Core/CameraEffects.cpp`), which the GL tests hold the shader to, and none applies under a grey debug view.
  - `debugView` (`CameraDebugView::None`): `AmbientOcclusion` shows the view's raw ambient occlusion as grey (white unoccluded) with no exposure or tonemap, black when `ambientOcclusion` is off; `ShadowCascades` tints the lit view by the sun's cascade each pixel reads (red, green, blue and yellow from the nearest, untinted past the last); `ShadowAtlas` shows the view's shadow atlas as grey depths, its cascades side by side stretched over the viewport, white nearest the sun, black when nothing casts; `SpotShadowAtlas` shows the frame's spot shadow atlas as grey depths in the same way, its tiles along the rows from the top left, nearest the cameras first, black when no spot light casts; `LightClusters` shows each lit pixel as the heat of how many lights it loops over, its cluster's or, unclustered, every light (black for none, then blue at 1, cyan at 4, green at 16, yellow at 64 and red at 256, the most a cluster lists, on a log scale), exposed and tonemapped; `Reflections` shows the view's screen-space reflections, the colour each pixel's mirror ray hit, from last frame's history at its sharpest level, times the hit's confidence, exposed, vignetted, graded, tonemapped and grained, black where nothing is reflected (what a mirror would blend: a material's roughness blurs and fades it in `Opaque`); `ReflectionConfidence` shows the confidence as grey with no exposure or tonemap. Both are black when `reflections` is off.
  - `tonemapper` (`Tonemapper::AgX`): how `Output` maps the exposed HDR colour into [0, 1] (ADR-0049). `AgX` desaturates bright colours towards white and keeps detail several stops over 1; `PbrNeutral` (Khronos PBR Neutral) shows colours up to about 0.76 as they are and compresses only the highlights, so base colours read true; `Aces` is Stephen Hill's fit of ACES, contrasty and saturated; `None` clamps each channel, the old `Output`, for exact colours (an unlit colour shows as its own value only under `None`). Under the others even a colour of 1 is darker than white: AgX maps 1 to 0.59 and mid grey 0.18 to 0.21.

  Not drawn, logged once: a camera targeting a window other than the main window, a viewport under one pixel, or a target image that is empty, stale or not a render target. A minimised window draws nothing.
- `DirectionalLight { colour, intensity, castShadows = true, shadowDistance = 100, shadowNormalBias = 1, shadowSlopeBias = 2 }` shines along its entity's world -Z, and casts the sun's cascaded shadows unless `castShadows` is off (see "Shadows"). Intensities are plain multipliers.
- `PointLight { colour, intensity, range = 10, castShadows = false, shadowNormalBias = 1, shadowSlopeBias = 2 }` shines from its entity's world position in every direction, and `SpotLight { colour, intensity, range = 10, innerAngle = 0, outerAngle = 45 degrees in radians, castShadows = false, shadowNormalBias = 1, shadowSlopeBias = 2 }` from its position along its world -Z, any number of each (ADR-0048). Their light falls with the square of the distance, windowed smoothly to zero at `range` (glTF's `KHR_lights_punctual`: 1 / d^2 x (1 - (d / range)^4)^2, with d^2 held at least 1e-4), so a white point light of intensity 1 one unit in front of a white rough face lights it about as a `DirectionalLight` of intensity 1 does. A spot's light is full inside `innerAngle` off its axis, none outside `outerAngle`, and smoothstep between their cosines. Each frame every one whose range, intensity and colour are not zero is written into the frame's light buffer (set 0 binding 4: the shadowed spot lights first, then the shadowed point lights, then points, then the other spots), and `Fenrir/Lighting.glsl` loops over those its pixel's cluster lists, skipping each whose range does not reach the pixel (see "Light clusters"). A point or spot light's `castShadows` casts within its kind's budget (see "Shadows").
- `RectLight { colour, intensity, width = 1, height = 1, twoSided = false, range = 10, visibleSurface = true }` is a glowing rectangle centred on its entity, `width` along its world +X and `height` along its world +Y (world units: the entity's scale does not stretch it), shining from its face towards its world -Z, and from its back too when `twoSided`, any number per scene (ADR-0048). It is shaded with linearly transformed cosines (Heitz, Dupuy, Hill and Neubelt 2016) for both the diffuse and the GGX specular, so its highlights take its shape and blur with the surface's roughness; the horizon is clipped with Hill's sphere approximation (the "clipless" form), which errs by about a tenth of the light of a rect straddling a surface's horizon. Its intensity is its radiance: a white rect light of intensity 1 filling a white rough face's view lights it about 1, as a white sky all round it does. Its light is windowed to zero at `range` from the rectangle's nearest point, as (1 - (d / range)^4)^2. It casts no shadows and is not drawn itself: give it an emissive mesh to see it. `visibleSurface` says the scene does: in a camera with reflections its specular is then scaled by 1 minus the reflection's share, so the mesh, reflected through the screen, is not reflected twice; set it false for a light with nothing drawn, which keeps its specular everywhere. Each frame every one whose range, intensity, colour, width and height are not zero is written into the light buffer after the point and spot lights. The two 64 x 64 RGBA16F lookup tables are the reference fit's own, committed as the generated header `src/Core/LtcTables.hpp` with their licence (`Resources/Ltc/`), and bound at set 0 bindings 5 and 6.
- `Sky` is a scene resource, the scene's ambient light as well as its backdrop, a tagged union like `projection` (ADR-0047): `ColourSky { colour }` (the default, a dark grey, which a scene without a `Sky` gets), `CubemapSky { cubemap, intensity, rotation }`, an `ImageData` of shape `Cubemap` with pixels, such as one loaded from a `.cubemap` file, or `PanoramaSky { image, intensity, rotation }`, a panorama: a flat image with pixels twice as wide as high, usually a linear HDR `.hdr` (RGBA32F). The cubemap is sampled by world direction with its faces laid out as GL and D3D lay out a cubemap's (+X, -X, +Y, -Y, +Z, -Z, each face's top row up), seamlessly across its edges. A panorama's centre looks along -Z, its right half turns towards +X and its top row looks up; the renderer draws it on the GPU into an RGBA16F cube texture with faces half as wide as the image is high and every mip level, once per image revision (values past the half float's 65504 are clamped), and then draws that like a cubemap. `intensity` (1 by default) multiplies what the sky draws; `rotation` (radians, 0 by default) turns it about world +Y, counter-clockwise seen from above. A cubemap that is empty, stale or not a cubemap with pixels, or a panorama that is empty, stale, or not a flat image with pixels twice as wide as high, draws the default dark grey, logged once per handle. Every view is lit by the scene's `Sky`, whatever its camera's background: a `ColourSky` lights with its colour from every side, and a cubemap or panorama sky through image-based lighting (diffuse from its spherical harmonics, specular from its prefiltered cube), scaled by its `intensity` and turned by its `rotation`.
- `SkyLight { sky }` is an optional scene resource that lights the scene in its `Sky`'s place, leaving the `Sky` drawn (ADR-0047): a sky of any kind, read as the `Sky` is, used only for its light. A skybox chosen for how it looks can light the scene with a neutral `ColourSky` or a softer panorama instead of its own colours. As a camera's `ColourBackground` changes what is drawn and not the light, a `SkyLight` changes the light and not what is drawn; either way one sky lights the scene.

## Materials and built-in shaders

Materials are FenrirAssets' `MaterialData`, edited through the asset store (ADR-0024). The renderer lays a material's set 2 out from its shader container's reflection: the `MaterialParams` block is the shader's default block image with the material's overrides written over it, and each texture parameter binds its image (uploaded with its mips, sRGB or linear as the image is; a render target image binds its texture) with the parameter's sampler. One sampler is made per distinct `SamplerDescription`. A texture left unset, or naming an image that cannot be sampled as a 2D texture (a cubemap, logged once), binds the renderer's default 1x1 `white`, `black` or `normal` texture, as its parameter default says, instead of adding a variant key. Sets 0 (frame), 1 (view) and 3 (draw) are declared in C++ as `Fenrir/Frame.glsl`, `View.glsl` and `Draw.glsl` declare them, and in debug builds a shader whose reflection disagrees fails its pipeline with a diagnostic and draws as the fallback material. A vertex stream a shader reads but the mesh lacks binds a constant (normal +Y, UV 0, colour white), logged once per mesh. Tangents are optional and not logged: a mesh without them binds the zero tangent, whose handedness 0 tells a shader it has none.

- **Blend modes:** `Opaque` and `Masked` draw in `DepthPrepass`, writing depth, then in `Opaque`, testing it for equality; `AlphaBlend` (straight alpha) and `Additive` (colour added, alpha kept) in `Transparent`, without writing it. Depth is otherwise tested greater-or-equal for reversed-Z, and `doubleSided` turns culling off. The prepass cuts a `Masked` item out as `builtin:lit` and `builtin:unlit` do, by its `baseColour` alpha times its `baseColourTexture`'s and the vertex colour's against its alpha cutoff; a `Masked` material whose shader has neither `baseColour` nor `baseColourTexture` is left out of the prepass and draws in `Opaque` writing its depth, as does an item whose vertex stage the prepass cannot run (logged once as a warning), and neither is in `SceneNormals`. Transparent items are sorted by their origins, not per triangle, and there is no order-independent transparency, so intersecting or nested transparent items can sort wrongly.
- **Variants:** the renderer picks the keys. A `Masked` material draws with its shader's `ALPHA_MASK` variant if the shader has the key, and its `alphaCutoff` (`SetAlphaCutoff`) is written into that variant's `alphaCutoff` block member, over any parameter override. A skinned draw uses the `SKINNED` variant when compute skinning is off, and the variant without it when on (see "Skinning"). A user shader's own keys stay off.
- `builtin:unlit`: `baseColour` (white) x `baseColourTexture` (white) x the vertex colour.
- `builtin:lit`: metallic-roughness GGX through `Fenrir/Lighting.glsl` (the directional light, the point, spot and rect lights, and the `Sky`'s image-based lighting), written as linear HDR, with `baseColour` (white) x `baseColourTexture` (white), `metallic` (0) and `roughness` (0.5) x the blue and green of `metallicRoughnessTexture` (white), `normalTexture` (the flat normal; a tangent-space map whose green points up the image, in the mesh's tangent stream's frame when it has one (glTF's MikkTSpace tangents, FBX's tangents and binormals; ADR-0048), and otherwise in a frame from screen-space derivatives of the position and UV0), `emissive` (opaque black) x `emissiveStrength` (1; glTF's `KHR_materials_emissive_strength`, so emission can pass 1) x `emissiveTexture` (white, so an emissive colour shows with no texture), and `occlusionTexture` (white; its red channel, glTF's, darkens the sky's light only, never the directional light's). Its BRDF is scaled by pi, so a white light of intensity 1 on a white rough face gives about 1, and so does a white sky of intensity 1 all round it, for a rough metal too: the specular lobe is GGX with height-correlated Smith visibility, with multi-scatter energy compensation from the BRDF lookup table (Fdez-Agüera 2019), and specular anti-aliasing widens the roughness where the normal turns quickly across a pixel (Tokuyoshi and Kaplanyan 2019). A double-sided face's back is lit as its own side.
- **User shaders:** a full vertex and fragment program on the engine includes, with its own `MaterialParams` block and textures in set 2, built by `fenrir_add_shaders` (embedded, or a container file read into `ShaderData`) and added to the store as a `Shader`. Its vertex stage reads its item through `Fenrir/Draw.glsl`'s `CurrentDraw()` and nothing else of set 3: the draw's record, with an instance list copy composed in, whether the pass drew it directly or through the cull pass's indirection (ADR-0057), so a shader that relies on `CurrentDraw()` alone needs no change for culling; set 3 is the renderer's, all four of its bindings, so a user shader declares no block of its own there. Its vertex stage also runs in the depth prepass and the shadow passes, behind `builtin:depth-prepass`'s fragment stage, which reads what `mesh.vert` writes: the world normal at location 1 and, for a `Masked` material, the vertex colour at 2 and UV0 at 3. `Fenrir/Vertex.glsl` declares `gl_Position` invariant, so both programs place a vertex alike and `Opaque`'s equal test holds; a vertex stage without it should declare `invariant gl_Position;` itself. Lighting is the shader's choice: it may fill a `FenrirSurface` (base colour, alpha, world normal and position, metallic, roughness, occlusion, emissive) and call `FenrirLitColour` from `Fenrir/Lighting.glsl` (ADR-0048) outside any branch neighbouring pixels may take differently (its specular anti-aliasing takes the normal's screen-space derivatives), which reads the lights, the sky's spherical harmonics, prefiltered cube and BRDF lookup table, and the rect lights' LTC tables from set 0 (`Fenrir/Frame.glsl`).

The built-ins are built by `fenrir_add_shaders` from `Shaders/Builtin/` and embedded as byte arrays, so the renderer needs no files beside it.

## Shadows

The `DirectionalLight` casts cascaded shadows (ADR-0050) unless its `castShadows` is off, or it lights nothing (black, intensity 0, or a `shadowDistance` of 0). `SpotLight`s with `castShadows` on cast within a budget, from one shared atlas, and `PointLight`s within theirs, from one shared cube array.

- **Cascades, per camera.** Each view's range from its near plane out to `shadowDistance` (or its far plane, if nearer) is split into `RendererConfig::shadowCascades` cascades by the practical scheme: split i of n is lambda x near (far / near)^(i / n) + (1 - lambda) x the even split, lambda `shadowSplitLambda`. Each cascade is the smallest sphere round its slice of the view, its radius rounded up to a sixteenth of a unit, seen by an orthographic view along the light, reversed-Z, its map holding the sphere with a texel to spare. The sphere's centre is moved in the light's view onto whole texels: as the camera moves its texels stay on the world's grid, and as it turns the sphere keeps its size, so shadow edges neither swim nor shimmer. Casters up to `shadowDistance` past the sphere towards the light are caught.
- **The pass.** `ShadowCascades`, one per view in the `Shadow` stage, draws every casting item into each cascade's square of a transient `Depth32Float` atlas, the cascades side by side, cleared to 0: the `Opaque` and `Masked` items of `MeshRenderer`s and `InstancedMeshRenderer`s with `castShadows` on, through the item's own vertex stage with the cascade's light matrix as its view block (`view.viewProjection`), behind `builtin:shadow`'s depth-only fragment stage. A `Masked` item is cut out by its base colour's alpha, texture and cutoff as in the prepass (one whose shader has no `baseColour` or `baseColourTexture` casts whole); blended items never cast. Both faces cast, and matching items merge into instanced draws as in `Opaque` (ADR-0051). Skinned items cast from the compute-skinned vertices (see "Skinning"), a user shader's through its own `SKINNED` vertex stage. `RendererStats::shadowDraws` counts its draws, one per run per cascade.
- **Reading it.** `Opaque` and `Transparent` bind the atlas at set 1 binding 2 (`Fenrir/View.glsl`'s `fenrirShadowAtlas`, a `sampler2DShadow`) and the cascades in the view block; every other pass, and a view without shadows, binds a 1 x 1 map that lights everything. `Fenrir/Shadows.glsl`'s `FenrirSunShadow`, which `Fenrir/Lighting.glsl` multiplies the directional light by, reads the first cascade whose range holds the pixel's view depth, and over the last tenth of that range blends into the next (the last into no shadow), so no boundary shows. Each read is 16 taps of a Vogel disk 1.5 texels across, each a bilinear hardware comparison, turned per pixel by interleaved gradient noise. Before reading, the pixel moves out along its normal by `shadowNormalBias` texels and towards the sun by `shadowSlopeBias` texels per unit of slope (the tangent of the angle between its normal and the sun, held between 0.1 and 8), in the cascade's own texels, so the biases fit every cascade. Raise them for acne (speckled self-shadowing on lit faces), lower them for shadows coming loose from their casters.
- **Cost.** One atlas per camera: at the defaults 8192 x 2048 at 4 bytes a texel, 64 MiB, transient and pooled across frames.
- **Spot lights, within a budget.** Each frame the `SpotLight`s with `castShadows` on that light anything are ranked by the distance from their position to the nearest camera, and the nearest `RendererConfig::spotShadowBudget` of them (8 by default; `Renderer::SetSpotShadowBudget` changes it) keep their shadows; the rest light unshadowed, warned about once. Every one is drawn into a tile of one spot shadow atlas the renderer keeps across frames: a `Depth32Float` grid of the budget's tiles, ceil(sqrt(budget)) across and as many rows as that needs, each `spotShadowMapSize` square (3 x 3 tiles of 1024, 36 MiB, at the defaults), made again when the budget changes. A light's tile is a square reversed-Z perspective from its position along its axis, wide enough for its outer cone (held to 80 degrees) with the filter's reach to spare, its near plane a two-hundredth of its range, at most 0.1. One `SpotShadows` pass in the `Shadow` stage draws every casting item into every tile, as `ShadowCascades` does, the tile's perspective as the view block; materials sampling render target images sample their defaults there, so it waits on no view. A mesh round a light's position (a glowing bulb) shadows all of its cone: turn its `castShadows` off.
- **Reading spot shadows.** The light buffer holds the shadowed spot lights first, in tile order, the frame block's `lights.y` counting them; set 0 binds a record of each (`Fenrir/Frame.glsl`'s `FenrirSpotShadow`: world to the atlas, the biases, a texel's size one unit along the light, and the tile's bounds) at binding 7 and the atlas at binding 8, with the comparison sampler (in the `SpotShadows` pass itself, and with no shadowed spot light, the map that lights everything). `Fenrir/Shadows.glsl`'s `FenrirSpotLightShadow`, which `Fenrir/Lighting.glsl` multiplies each shadowed spot light by, filters it as the sun's cascades are, its biases in its own texels at the pixel's distance along the light. Shadowed lights that change as the camera or the lights move swap in and out of the budget from one frame to the next: keep the budget above the casting spot lights near the camera, or the swaps show.
- **Point lights, within a budget.** Chosen as spot lights are, the nearest `RendererConfig::pointShadowBudget` (4 by default; `Renderer::SetPointShadowBudget`) keeping their shadows and the rest warned about once. Each is a cube of one cube array the renderer keeps (`Depth32Float`, the budget's cubes, `pointShadowMapSize` square faces: 4 x 6 x 512 x 512, 24 MiB, at the defaults), made again when the budget changes. A face holds the distance from the light to the nearest caster over the light's `range`, reversed (1 at the light, 0 at its range and past it), drawn through a 90-degree perspective from the light by `builtin:shadow`'s `POINT_SHADOW` variant. With no geometry shader: where the GPU lets a vertex stage write `gl_Layer` (on OpenGL a driver taking `SPV_EXT_shader_viewport_index_layer` in SPIR-V, or NVIDIA's `SPV_NV_viewport_array2`, the same capability, which the backend renames the stage's extension to; it logs which at start), one `PointShadows` pass draws each light's casters once, six instances each, through the item's shader's `POINT_SHADOW` variant, whose `Fenrir/Draw.glsl` turns each instance into its face and layer. Casters whose shader has no `POINT_SHADOW` key (list it in `fenrir_add_shaders`' `KEYS` to get it; the built-in mesh programs have it), and every caster on a GPU without the extension, are drawn a face at a time instead, by `PointShadowFaces` passes, one a face. `RendererStats::shadowDraws` counts a draw per run per light, and per face for those. A mesh round a light's position shadows everything it lights: turn its `castShadows` off.
- **Reading point shadows.** The light buffer holds the shadowed point lights after the shadowed spot lights, in cube order, the frame block's `lights.z` counting them; set 0 binds a record of each (`FenrirPointShadow`: the biases and a texel's size one unit along a face's axis) at binding 9 and the cube array at binding 10 (`samplerCubeArrayShadow`), with the comparison sampler (in the passes drawing it, and with no shadowed point light, a cube that lights everything). `Fenrir/Shadows.glsl`'s `FenrirPointLightShadow` reads it along the way from the light against the pixel's own distance, the same 16-tap Vogel disk laid across that way, the same biases in the cube's texels where the pixel is; the cube's faces filter into each other, so its edges show no seam.

## Debug drawing

The renderer draws the active scene's `DebugDraw` (FenrirDebugDraw, ADR-0025) when FenrirDebugDraw is installed; without it, nothing. Each frame it takes the `DebugDraw`'s tessellated batches and uploads them into per-frame ring buffers.

- **Shapes and world text** draw in each view's `Debug` pass, into its `SceneColor` after `Transparent`, unless the camera's `drawDebug` is off. Depth-tested shapes test the view's `SceneDepth` without writing it; on-top shapes skip the test and draw after them. Lines are expanded in the vertex shader into quads their thickness in pixels across, square-capped, so a zero-length line (a point) is a square dot. Solid triangles alpha-blend, unsorted. World text is centred on its point, at its size in pixels (logical pixels, scaled by the content scale, in a view of the window), facing the screen, never hidden, and not drawn behind the camera.
- **Screen text and on-screen messages** draw once, in the window's `Overlay` pass after every view's `Output`, as the overlay's top layer, when a view of the scene draws into the window; and last, in the `Overlay` stage before those, one `CullReadback` compute pass copying every view's command buffer into the readback ring (see "GPU culling"); views into images get none. Positions and sizes are logical units, scaled by the window's content scale. Messages stack from 8 units in from the window's top-left, newest first.
- **The font** is JetBrains Mono Regular (`Resources/Fonts/`, SIL Open Font License 1.1, `OFL.txt`), embedded at build time and rasterised at start-up with stb_truetype into one single-channel signed-distance-field atlas that serves every size. It covers printable ASCII and Latin-1; any other character, or a byte that is not UTF-8, draws `?`. Text has a thin dark outline so it reads over light and dark alike.

## The window overlay

Any UI draws over the game through the `Overlay` app resource (`FenrirRenderer/Overlay.hpp`, ADR-0027), filling FenrirDraw2D's plain-data `DrawList2D`s with its own shaders, vertex layouts, textures and scissors:

```cpp
Fenrir::DrawList2D list;
Fenrir::PipelineDescription2D pipeline;
pipeline.shader = store.Load<Fenrir::Shader>("builtin:2d", Fenrir::AssetOwner::App()).handle;
pipeline.vertexLayout = Fenrir::Vertex2DLayout(); // the ImGui layout: position, UV, RGBA8 colour
const std::uint32_t index = list.AddPipeline(pipeline);
// ... AppendVertices, AppendIndices, then a Command2D per draw naming `index`, its indices, textures and scissor
app.GetResource<Fenrir::Overlay>().Submit(Fenrir::Window::MainWindow(), 0, std::move(list));
```

- **When:** `Submit(window, layer, list)` any time before `Render`, from any system; the renderer draws the submissions that frame and clears them after it. A window with no submissions draws no UI, and one no camera draws into still gets its overlay over the black.
- **Order:** layers lowest first, then submission order, then each list's command order, in the window's `Overlay 2D` pass after every view's `Output`. Debug screen text and messages draw above every layer.
- **The target:** local coordinates are logical units from the window's top-left, Y down (the mouse's units), mapped to clip space over the window's logical size, its pixel size over its content scale. No depth and no culling. A scissor is scaled by the content scale, rounded outwards to whole pixels and clamped to the window.
- **Pipelines:** each 2D pipeline description becomes a device pipeline the first time it is drawn, cached by value while its shader lives, so equal descriptions share one. Blend modes take ADR-0027's colour and alpha factors: `AlphaBlend` (straight), `PremultipliedAlpha`, `Additive` (colour added, the window's alpha kept) and `Opaque`. Blending is linear and the sRGB backbuffer encodes on write; the `Gamma` blend space turns encoding off so values pass through and blend in sRGB, as stock ImGui assumes, and is allowed only on an 8-bit sRGB target (elsewhere it is logged as an error and draws as `Linear`).
- **Shaders:** 2D shaders take set 0 from the target (`Fenrir/2D.glsl`: `localToClip`, pixel size, content scale) and set 1 per command, laid out from the shader's reflection: a `MaterialParams` block at binding 0 (its parameter defaults with the command's up to 128 parameter bytes written over its start), then up to 4 textures, slot by slot in binding order. A texture slot's image is prepared as a material's is (a render target image binds its texture); a missing or stale one binds the texture's parameter default. The renderer picks the variant from the description: a shader with the keys gets `INPUT_SRGB` for sRGB vertex colours, `PREMULTIPLY` for `PremultipliedAlpha` and `GAMMA` for the gamma path.
- **`builtin:2d`:** the vertex colour times the slot-0 texture (white with none), on the ImGui layout. It decodes sRGB vertex colours, treats colours and texels as straight alpha, and premultiplies in linear for `PremultipliedAlpha`. On the gamma path it works in sRGB-encoded values: sRGB colours as given, linear ones encoded, texels (decoded on sampling) encoded again.
- **Skipped, each reason logged once:** a command with more than 4 texture slots or 128 parameter bytes, or a pipeline index or index range outside its list; a list whose pipeline names a stale shader or one that is not a 2D shader; and a submission to a window the renderer does not draw (only the main window, for now), logged once per window.

## Skinning

Skinned meshes (ADR-0035) are drawn on the GPU from their skeleton's palette. The renderer never links FenrirSkeleton (ADR-0041): it reaches skeleton poses through FenrirAssets' `SkinningSource`, which `Skeletons::Install` registers as the app resource `SkinningSourceRegistration`, and looks it up each `Render`, so install order does not matter. With no source, rigid meshes draw as usual and skinned ones are skipped.

- **What is drawn:** a `MeshRenderer` whose mesh has skin data and which has a `SkinnedMesh` naming a `Ready` skeleton entity whose skeleton the mesh was baked for: the mesh's `boneCount` is at most the skeleton's bone count, and its `expectedSignature` is the skeleton's bind signature unless it is 0. The verdict is cached per mesh entity, by the mesh's and the skeleton's handles and revisions.
- **Skipped, each logged once as a warning:** skin data but no `SkinnedMesh`; a `SkinnedMesh` whose skeleton entity is dead, has no `SkeletonPose` or is not `Ready`; no skinning source (once for the app); a failed compatibility check. A user shader without the `SKINNED` key draws a skinned mesh with the fallback material's `SKINNED` variant, magenta, never unskinned (once per shader). A `SkinnedMesh` on a mesh with no skin data is ignored, and the mesh draws rigidly (once).
- **The palette:** each frame the skinned draws' palettes are written into a storage buffer at set 3, binding 2, as `struct FenrirBone { vec4 r0, r1, r2; }` (rows 0-2 of each bone's skinning matrix, 48 bytes), ring-buffered per frame in flight and grown by doubling; nothing is kept across frames. One range is written per skeleton entity and pose generation in a frame, shared by every mesh and camera drawing it. Each draw record (set 3, binding 0) carries its `paletteOffset`, in bones, and the sign of its world matrix's determinant. A range past what was written is an internal error, and the draw is skipped. Debug builds check both records' layouts against the shader's reflection.
- **Screen-space reflections** (ADR-0056, a camera's `reflections`): each pixel of a reflecting view is traced before `Opaque` from what its depth prepass knows, its depth and its vertex normal, and each material decides in `Opaque` how much of the hit to use from what only it knows, its roughness and Fresnel. `ReflectionTrace` reflects the camera's view of the pixel about the normal and marches the ray through the Hi-Z pyramid (Uludag's Hi-Z tracing, GPU Pro 5), stepping down a level where the ray reaches the nearest depth of the texel it is over and up where it leaves the texel in front of it; it writes the hit's UV in last frame's view, its confidence and the ray's length. The confidence is the product of the hit (none past `maxDistance`, off the screen, after 64 steps, or for a ray turning towards the camera), fades over the last tenth of the screen at each edge, over the last fifth of `maxDistance` and as the ray turns towards the camera, facing (none where the hit's normal faces along the ray), the history (none on a camera's first reflecting frame, after a resize, or where the hit was off last frame's screen) and disocclusion (falling as the surface last frame's pyramid holds there was in front of the hit, by up to `thickness`). `Opaque` binds the hit target at set 1 binding 4 (`fenrirReflectionHits`) and the history at binding 5 (`fenrirSceneHistory`, trilinear), and the view block's `reflectionInfo` holds whether the view has them, the intensity, the roughness cutoff and the history's last mip; every other pass, and a view without reflections, binds 1 x 1 black stand-ins, zero confidence, so transparent items reflect nothing behind them. `Fenrir/Lighting.glsl` samples the history at the hit at the mip whose texels span the GGX lobe's cone at the ray's length, and mixes it over the sky's prefiltered specular by the confidence times the roughness fade times `intensity`, through the same single-scattering share and specular occlusion. They catch only what is on screen: what is off it or hidden falls back to the sky's specular and the lights' own, and a sign behind the camera still lights the street through its rect light's specular. They show last frame's colour, as the camera saw it then: the camera's own motion is undone by reprojecting the hit into last frame's view, but a moving object's is not (there are no motion vectors), so its reflection trails it by a frame, the disocclusion test hiding most of the ghost. The trace starts from the vertex normal, so a normal map's ripples do not bend the reflection.
- **Light clusters** (ADR-0049, on unless `RendererConfig::clusteredLights` or `Renderer::SetClusteredLights` turns it off): each view's frustum is cut into 16 x 9 tiles across its viewport and 24 slices in depth, spaced exponentially from its near plane to the farthest view depth any light reaches, 3456 clusters. Each view with point, spot or rect lights gets a `LightClusters` compute pass (stage `DepthPrepass`) running `builtin:light-clusters`, one invocation a cluster: each light's sphere (its `range` about its position; past its corners for a rect light) is listed in every cluster whose view-space box it touches, in light buffer order, up to 256 a cluster (fewer lights than that, room for all of them), into the view's own cluster buffer, each cluster's count then its list. Set 1 binds it at binding 3 (`Fenrir/View.glsl`'s `fenrirClusterLights`), the view block's `clusterSlices` and `clusterInfo` saying how to find a pixel's cluster, and `Fenrir/Lighting.glsl` loops over the lights its pixel's cluster lists; every other view block, and every view with clustering off or no lights, binds a buffer of one 0 and loops over the whole light buffer, so the light buffer is unchanged and materials never change. A cluster's 257th light and on light nothing in it. `Core/LightClusters` mirrors the grid, the boxes and the assignment on the CPU.
- **Compute skinning** (ADR-0050, on unless `RendererConfig::computeSkinning` or `Renderer::SetComputeSkinning` turns it off): one `Skinning` compute pass, before any view's passes, runs `builtin:skinning` once for each skinned mesh and palette range drawn this frame, however many items, cameras and passes draw it, one invocation a vertex, for the skinned draws of the built-in mesh programs (`builtin:lit`, `builtin:unlit` and the fallback). It reads the mesh's vertex buffer and the palette, and writes the model-space positions, unit normals and tangents a `SKINNED` vertex stage would compute (a mesh without normals skinned from +Y, one without tangents from the zero tangent, so its handedness stays 0) into the frame's skinned vertex buffer, three streams a mesh back to back, ring-buffered per frame in flight and grown by doubling. Every pass then draws the skinned item with its shader's variant without `SKINNED`, those three streams read from that buffer and the rest from the mesh, under the skeleton entity's world matrix as a rigid item is. Items merge into instanced draws only when they draw the same skinned vertices (one mesh on one skeleton), so a crowd of characters is a draw per member. A user shader's skinned draws keep its own `SKINNED` variant, which may do more than skin; a shader without `SKINNED` still draws skinned meshes as the fallback material, compute-skinned. The skip cases, the palette and bounds are unchanged. Off, or if the compute pipeline cannot be made (logged), skinned draws skin in their vertex stages as below. `Fenrir/SkinMaths.glsl` holds the blend, normal and tangent maths both share.
- **Shaders:** `Fenrir/Skinning.glsl` declares the palette and the joints and weights at vertex locations 6 and 7 (four `u16` indices and four `unorm16` weights, as `MeshData` stores them), and gives `FenrirSkinPosition`, `FenrirSkinNormal` and `FenrirSkinTangent`, each taking the draw record and returning world space: normals by the cofactor of the blended 3x3 (the inverse transpose's direction) with fallbacks for near-singular blends, tangents Gram-Schmidt'd against the normal with handedness `t.w x sign(det A) x sign(det W)`. The built-in programs are built with `SKINNED`; a user shader that should skin does the same (`KEYS SKINNED`) and calls them under `#ifdef SKINNED`.

## GPU culling

Every camera's opaque and masked draws go through a cull pass on the GPU before they are drawn (ADR-0057), so a frame's draws are indirect draws of what the pass kept: the copies inside the camera's frustum. Culling is in two levels: the CPU leaves whole entities outside a view out of its candidates, and the pass drops the copies outside it from the rest. The same pass chooses each kept copy's level of detail, when its mesh has levels (`MeshData::lods`, FenrirAssets's `GenerateLods`). The frame looks as it did drawing everything directly at full detail, apart from what was never visible and what is too far to tell.

- **The coarse cull.** Before the runs form, each view drops every draw whose world bounds (`Renderer::GetWorldBounds`: an item's mesh box under its world matrix, a list's the box around every copy's) are outside its `Math::Frustum`, as transparent items are dropped, so an entity behind the camera is no candidate for that view and costs the pass nothing. It stays on with `gpuCulling` off.
- **Candidates.** Each view's opaque and masked runs (ADR-0051's runs of merged items, each `InstancedMeshRenderer`'s list, and lone items as runs of one) are its cull pass's candidates: a merged run's items, a list's copies. Per view and run the renderer writes, into this frame's rings, one command template per level of detail of the run's mesh, contiguous (`DrawIndexedIndirectCommand`: the level's index count and first index in the mesh's index buffer, base vertex 0, no instances, and the base instance where the level's region of the view's indirection starts, each region the whole run's candidates long, as any copy may land in any level), one entry per template in the frame's level table (the level's error, which level of the run's it is, and how many the run has), and the run's entries in the frame's group table, one per 64 candidates naming the run's first command, first record, candidate count and the group's first candidate, so no work group straddles two runs. A mesh's index buffer holds level 0's indices then each coarser level's, so one buffer serves every level; a mesh without levels has one.
- **The pass.** `Cull`, one per view, first in the frame (the `Cull` stage opens the stage list, before `Prepare`, and is open to user passes like every other stage: a compute pass that must run before the frame belongs there), a compute pass that copies the view's templates over its command buffer (`CmdCopyBuffer`) and dispatches `builtin:cull` once, one work group per group table entry: each invocation tests its candidate (below), chooses its level of detail (below) and counts it into that level's command's instance count with an atomic and writes its entry, `uvec2(record, copy)` (`0xFFFFFFFF` for an item's copy), at the slot the count gave it in the command's region of the view's indirection, so the order within a run varies frame to frame, which an opaque pass behind a depth prepass does not show. The pass declares `StorageWrite` on the commands and the indirection, `CopyDestination` on the commands, and `StorageRead` on the records, the group table, the level table and the instance lists.
- **The test.** The job block (set 0) carries the view's planes, `Math::Frustum::Planes` as the camera's view-projection gives them each frame (five: no far plane), and the shader repeats `Math::Frustum`'s tests exactly, so FenrirMath's unit tests are its oracle: the sphere around the candidate's box (`SphereOf`: its centre moved, its half-diagonal scaled by the largest axis scale), dropped when it is wholly outside one plane, then the box's eight corners, moved, dropped only when every one is outside one plane. An item's record box already has its world matrix applied, so it is tested under the identity (the CPU's coarse cull already kept it); a list's record holds the mesh's local box, moved by the entity's world matrix times the copy's transform, read from the instance lists at set 1 binding 4. `RendererConfig::gpuCulling` off (`Renderer::SetGpuCulling`) sends no planes and allows no error, so the pass keeps every candidate at level 0 and the indirect draws keep their shape, for comparison.
- **The level.** The job block also carries the camera's position (where it was when frozen, frozen) and its projection as pixels per unit at distance 1 (half the viewport's height over tan(fov / 2); the height over the orthographic height for an orthographic view, which projects the same at any distance), the near plane's distance, and `RendererConfig::lodErrorPixels` and `minProjectedPixels`. For a kept candidate the shader takes its distance from the camera to the nearest point of its sphere (0 inside it, never under the near plane), drops it when its radius projects under `minProjectedPixels` (0: never), and draws it at the coarsest level whose error, scaled by the candidate's largest axis scale (as the sphere's radius is) and projected at that distance, is under `lodErrorPixels`: level 0, whose error is 0, when none is. `Core/LevelOfDetail.hpp`'s `SelectLod` is the same arithmetic on the CPU, the oracle of the GL tests, which read the levels' counts back and compare them with it exactly. A shadow view's casters still draw at level 0, directly (ticket 10).
- **The draws.** `DepthPrepass` and `Opaque` draw each run with one `DrawIndexedIndirect` from the view's command buffer, a multi-draw of its commands, one per level of detail of its mesh, declaring `IndirectRead` on the buffer and `StorageRead` on the indirection, so both draw exactly what the pass kept at the levels it chose; a run the prepass has no pipeline for (a `Masked` item it cannot cut out) leaves its commands to `Opaque`. Set 3 binding 3 is the view's indirection (`Fenrir/Draw.glsl`'s `fenrirVisible`), so each view has its own draw set per frame in flight; the shadow and transparent passes, which still draw directly, bind a one-entry buffer that says there is no indirection, and `CurrentDraw()` finds each instance's record as before. The palette stays binding 2, the third storage block GL numbers, since `Draw.glsl` declares all four of set 3's buffers whichever a program reads.
- **Buffers.** Per view, a command buffer (20 bytes a run and level; `Indirect | Storage | CopyDestination`) and an indirection (8 bytes a candidate and level), each a copy per frame in flight, kept between frames and grown by doubling when a frame needs more; per frame, the template, level table and group table rings and the job blocks. `RendererStats::draws` and `instances` are unchanged: what the CPU submitted, not what the GPU drew.
- **What the GPU drew.** A `CullReadback` pass, last in the frame (the `Overlay` stage, before the overlays), copies every view's command buffer into the frame's slot of a readback ring (`CopyDestination | Readback`, a slot per frame in flight, each view's commands at its templates' offset, grown by doubling). Each frame starts by reading the slot the frame `FramesInFlight` ago filled, through `GraphicsDevice::ReadBuffer`, which a backend allows only once the frame that last wrote the buffer has left flight, so it never waits on the GPU (GL reads with `glGetNamedBufferSubData`; the null backend returns what `WriteBuffer` or a copy last put there, zeros for what only a dispatch wrote). The sum of the commands' instance counts is `RendererStats::instancesDrawn`, and summed by each command's level of detail (kept beside the slot) `RendererStats::drawnByLod`, eight entries, the last holding level 7 and any coarser, usually two frames behind `instances`, the candidates submitted; a frame with no opaque run counts 0, and a frame whose slot was not filled `FramesInFlight` frames ago (the first frames, or a frame that was not drawn then) leaves the last count.
- **Frozen culling.** `Renderer::SetCullingFrozen(true)` freezes culling from the next frame: each camera keeps the frustum and position it has in that frame and culls against them, on the CPU and in its cull pass, however it moves after, while its view block follows it, so flying out of the frozen volume shows what was kept. The Debug stage draws each frozen frustum's twelve edges, amber, two pixels wide and on top, in every view (a perspective camera's far end a hundred units out along its rays). `SetCullingFrozen(false)` forgets them.

## Spawning models

`SpawnModel(app, scene, model, parent = {})` (`FenrirRenderer/SpawnModel.hpp`) spawns an imported `Model` as drawn entities and returns its root: the app's store's `SpawnNodes` (an entity per ordinary node, under a root named after the file), then `SpawnSkeletons` through the skinning source (a `SkeletonPose` on each skeleton's owner, and bone attachments), then a `MeshRenderer` per mesh of each node. A rigid mesh's first `MeshRenderer` goes on the node's entity and each further one on a child entity named after the node (`Body mesh 2`); a skinned mesh gets an entity of its own, named after its node, a child of its skeleton's owner at the identity, with a `SkinnedMesh` naming the owner. With no skinning source it skips `SpawnSkeletons`, logged once per call. It needs no `Renderer` installed.

## Read-back

- `GetWorldBounds(entity)`: the box around the entity's mesh in world space, from the mesh's local bounds and the world matrix now; empty without a `MeshRenderer` or an `InstancedMeshRenderer`, or with a mesh that does not resolve. A skinned mesh's comes from its skeleton's pose now: each bone's box moved by its palette matrix, with the unweighted vertices' box, under the skeleton entity's world matrix; conservative, and empty without a `SkinnedMesh`, a skinning source or a `Ready` skeleton. A transparent skinned item is sorted by its bounds' centre. An `InstancedMeshRenderer`'s is the box around every copy of its list's mesh box under the entity's world matrix (ADR-0057), as computed when the list was uploaded, or from the list itself before its first frame; empty for a list that does not resolve or has no copies.
- `GetFrustum(camera)`: the volume the camera sees now, as a `Math::Frustum` (`FenrirMath/Frustum.hpp`, ADR-0057) in world space from its world matrix and its target's size: the planes the renderer culls by, on the CPU and in the cull pass, for a game that culls or streams its own entities. Five planes for a perspective camera, whose far plane is at infinity, six for an orthographic one. Empty as `ScreenPointToRay`'s is.
- `Stats()`: the last drawn frame's `draws` (in each camera's `Opaque` and `Transparent` passes: one per merged run, one per transparent item drawn, one per instance list) and `instances` (one per item per camera, merged or not, `skinnedDraws` of them skinned, and one per copy of each instance list; a transparent item or list outside a camera's frustum is not drawn in it and not counted), `instancesDrawn` (the items and copies the cull passes kept, summed over cameras, read back from the most recent frame that has left flight, usually two behind; see "GPU culling") and `drawnByLod` (those by the level of detail they drew at, eight entries, the last for level 7 and coarser), `passes` run, and `uploads` (meshes, images, material blocks and instance lists).

## Picking

Computed on call from the camera's world matrix and its target's size now, so usable in `Update` (ADR-0026). Points are logical window coordinates from the top-left for a window (with no window, the null backend's 1280 x 720) and pixels for an image.

- `ScreenPointToRay(camera, point)`: the ray through the point, from a perspective camera's position, or from the point in an orthographic camera's plane along its -Z.
- `WorldToScreenPoint(camera, point)`: where a world point appears in the camera's target.
- `CameraAt(window, point)`: the highest-order enabled camera whose viewport holds the point (of equal orders, the highest entity id: the one drawn last); a null `Entity` if none.

A stale entity, one with no `Camera`, a camera that draws nothing, a point outside the viewport, or a point behind the camera gives empty. There is no mesh picking.

## The app's renderer

Code that does not hold the owner reaches the renderer installed in an `App` through statics of the same names that take the `App` first: `Renderer::IsInstalled(app)`, `GetWorldBounds(app, entity)`, `GetFrustum(app, camera)`, `Stats(app)`, `ScreenPointToRay(app, camera, point)`, `WorldToScreenPoint(app, camera, point)` and `CameraAt(app, window, point)`. Each answers as the owner's function while the owner `Install` made lives and is valid, and as an invalid owner otherwise. The scripting extension uses them.

## From C#

With `FENRIR_ENABLE_SCRIPTING` on, `FenrirRendererScripting` (`Scripting/`) gives C# the `Fenrir.Renderer` contract (`Managed/Fenrir.Renderer/`, ADR-0029): add `Renderer::ScriptingExtension()` (`FenrirRendererScripting/RendererScripting.hpp`) to `ScriptingConfig::extensions` after Input's and Assets's, whose contracts it builds on, and call `fenrir_deploy_renderer_scripting(<target>)` beside their deploy functions. It needs no `Renderer` installed.

- **Components:** `MeshRenderer`, `InstancedMeshRenderer`, `Camera`, `DirectionalLight`, `PointLight`, `SpotLight`, `RectLight` and `SkinnedMesh`, writable mirrors of the C++ ones: the same fields in PascalCase (the lights' `CastShadows` and shadow biases, `Camera`'s `Exposure`, `Tonemapper`, `Bloom`, `AnamorphicStreaks`, `LensFlare`, `ColourGrading`, `ChromaticAberration`, `Vignette`, `FilmGrain`, `AmbientOcclusion`, `Reflections` and `DebugView` among them), and `new` is C++'s `{}`. `Camera`'s unions are `[TaggedUnion]` structs: `CameraProjection` (`Perspective` or `Orthographic`), `RenderTarget` (`WindowTarget` or `ImageTarget`) and `CameraBackground` (`SceneBackground` or `ColourBackground`); `WindowTarget.Window` is a `Fenrir.Input.WindowId`. An `InstancedMeshRenderer` draws an instance list C# makes and edits through `Fenrir.Assets`' `Assets.AddInstanceList` and `ReplaceInstanceList`.
- **Resources:** `Sky` (`ColourSky`, `CubemapSky` or `PanoramaSky`, a union too, the last two with `Intensity` and `Rotation`) and `SkyLight`, writable scene-resource mirrors: `Resources.Get<Sky>()`. The `Sky` is the scene's ambient light (ADR-0047); C# has no `AmbientLight`.
- **`Renderer`** (write `Fenrir.Renderer.Renderer` inside a `Fenrir.*` namespace): `ScreenPointToRay(camera, point, out ray)`, `WorldToScreenPoint(camera, point, out screenPoint)` and `CameraAt(window, point)`; `GetWorldBounds(entity, out bounds)` and `Stats(out stats)`, every `RendererStats` count; `SetSpotShadowBudget(budget)` and `SetPointShadowBudget(budget)`, as C++'s; and `SpawnModel(model)` or `SpawnModel(model, parent)`, which records the tree C++'s `SpawnModel` makes through the change buffer and returns its root, alive at once so the same system can give it components.
- **No-op rules:** with no renderer (or, for `SpawnModel`, no asset store), an entity that is not alive or has no `Camera`, or an empty or stale model, a function does nothing and returns `false`, zero or `Entity.None`; nothing throws, and a debug build warns once per native call site and reason.

## Layers

Three targets, three layers (ADR-0019): `FenrirRenderer`, the ECS facade (`include/`, `src/Facade/`), the only one with public headers and the only one that links FenrirWindow, `PRIVATE`; `FenrirRendererCore`, the renderer core (`src/Core/`), with no FenrirApp, FenrirECS, FenrirScene or FenrirWindow dependency; and the graphics device with its backends (`src/Device/`, `src/Backend/`), where only `src/Backend/OpenGL/` includes GL. The core and the facade are tested on the null backend through `RendererProbe` (`FenrirRendererTests`), and the OpenGL backend and the scene through GL pixel probes and golden images (`FenrirRendererGlTests`, CTest label `gl`, skipped without a display or an OpenGL 4.6 context).

**Indirect draws** (ADR-0057): the graphics device draws indexed geometry from a buffer of commands the GPU may have written, `CmdDrawIndexedIndirect { buffer, offset, drawCount, stride }`, each command a `DrawIndexedIndirectCommand` of five words (index count, instance count, first index, base vertex, base instance), the layout GL's `DrawElementsIndirectCommand` and Vulkan's `VkDrawIndexedIndirectCommand` share. The buffer is made with `BufferUsage::Indirect`, the pass declares `ResourceUsage::IndirectRead` on it, and the index buffer is bound at its start (GL has no element-buffer offset for the GPU's commands to count from). The OpenGL backend replays it as one `glMultiDrawElementsIndirect`, and before any pass it issues the memory barrier the pass's declared reads of buffers an earlier pass wrote as `StorageWrite` need: `GL_COMMAND_BARRIER_BIT` for `IndirectRead`, the storage, vertex and element bits for `StorageRead` and `VertexInput`, the buffer-update bit for copies and `WriteBuffer`. The null backend records the draw and reports, as a `RendererProbe::StaleUses` line, a command buffer without `Indirect` usage, a pass that did not declare `IndirectRead` on it, commands past its end, an offset or stride that is not whole words or a stride under a command's size, or an index buffer bound past its start. `Fenrir/Draw.glsl`'s `FenrirDrawIndex()` holds for indirect draws unchanged: each command's base instance reaches the shader as a direct draw's does, and indexes the view's indirection (see "GPU culling").

## Golden images

Where a frame cannot be pinned by a few exact pixels, a GL test compares the whole of it with a small committed PNG in `Tests/OpenGL/goldens/` (ADR-0049): `RendererTest::RequireGolden` (`Tests/GoldenImages.hpp`) converts both into CIELAB and counts the pixels whose CIEDE2000 difference is over 2, about what a viewer can just see; up to 16 may differ, so another driver's rounding or an edge rasterised a pixel over passes and a changed colour fails. A failing test writes the frame and a difference image (the golden dimmed, each differing pixel magenta) into `golden-failures/` in the tests' build directory and says where. Goldens are written only on request: run the GL tests with `FENRIR_UPDATE_GOLDENS=1`, look at each image that changed, and commit them with the change that meant to alter them:

```sh
FENRIR_UPDATE_GOLDENS=1 out/build/msvc-x64-debug/packages/FenrirRenderer/Tests/FenrirRendererGlTests.exe "[golden]"
```

The goldens were made on an NVIDIA GeForce RTX 5080 (driver 617.14). A GPU that fails them by a few pixels along edges wants a looser `GoldenTolerance` for that test, not new goldens, which would fail on the first GPU instead. The tonemapping goldens draw one lit scene (three spheres under a sun bright enough to clip, and an orange ramp from a quarter to eight times its colour) through each tonemapper, through AgX at -2 and +2 EV, through AgX under a grade with every control off its default, and through AgX with each of chromatic aberration, a vignette and film grain alone (the grain in a fresh scene's first frame, so its frame index is fixed).
