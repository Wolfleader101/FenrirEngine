# 03: Character tracer bullet: a capsule that falls, lands and walks

**What to build:** FenrirPhysics has character bodies end to end, thinly: a capsule beside its `Collider` falls, lands, walks across flat ground, stops at a wall and is stopped by a ceiling, in tests and in a DemoApp "Character (C++)" scene on F5 (spec: "the `CharacterBody` component and `CharacterState`", "the move in `PostTick`", "ground state", "the Jolt backend"; ADR-0014, ADR-0010, ADR-0011). The spike on `prototype/fenrir-physics-character-spike` built this slice crudely; build it properly against the spec's API. The spike branch is reference only.

- **Components:** `GroundState`, `CharacterState` and `CharacterBody` declared with every field and default from the spec, documented (velocity is input and output; `state` is overwritten each write-back). Fields not wired up here (`pushForce`, `mass`, `interpolate`, `enabled`, the walking rules) are declared with their defaults and wired in later tickets. A `Collider` on a character's entity is not a static body.
- **`PostTick`:** the `CharacterBody` watch drained with the body and joint watches by net effect (characters destroyed before their bodies' batch, created after, inner bodies in batch order); characters diffed after bodies and before joints, in stable entity order; step 3b moves each character one at a time in ascending entity id with one temp allocator, by `velocity` over the tick's `dt`; step 5 writes back position (through `SetWorldTransform`, the `Transform` at the collider's centre), `velocity` and `state`.
- **The trim rule:** `velocity` is trimmed against the end-of-move contacts, never measured from displacement. An up-facing contact takes only the falling part (all of it on walkable ground); a wall or ceiling takes the part going into it along its normal. Gravity is game code's; physics adds none.
- **Ground state, first cut:** `OnGround` and `InAir`, with `groundBody`, `groundCollider`, `groundPoint` and `groundNormal` set only on ground; the private ground rule a supporting-volume plane from the shape along world +Y; `movedVelocity`; `onWall` and `onCeiling` from the same contacts. `OnSteepGround` and `Touching` come in ticket 04.
- **Inner body:** a kinematic body of the character's shape placed after each move with zero velocity, user data the entity, so raycasts, shape casts and overlaps hit the character and name its entity as body and collider.
- **Backend:** character operations on the backend class, built on `CharacterVirtual::ExtendedUpdate` with the trim in the contact-solve hook; `CharacterID` from the entity; inner `BodyID` pinned in batch order; `mMaxNumHits` high enough for sorted contacts; moves filtered through the inner body's object layer with the trigger tree excluded. Destroying a world destroys every character before any body.
- **ADR-0014 amended** (spec "Further Notes" 3): a teleport is a change of world position only, and there is no base-of-shape conversion.
- **DemoApp:** "Character (C++)" registers on F5 (Default ⇄ Character (C++)) with flat ground, a wall and the low ceiling. A demo component `DemoCamera { Vec3 Position; float Yaw; float Pitch; int Active; }` (`Demo.DemoCamera`, registered in the demo's scripting extension when scripting is on); one C++ system `DemoCameras` copying the active scene's `DemoCamera` into `Fenrir::Camera` while `Active` is set, after `CameraController` and after the C# Update systems; a C++ `CharacterCamera` controller following the character. Keys: WASD/arrows walk relative to the camera's yaw, Shift run, Space jump, Q/E orbit, C free camera and back, L log `state`, P autopilot. Game code steers the written-back horizontal `velocity` toward `input × speed` by at most `acceleration × dt`. The character's `Name` shows its readouts every frame; each ground change is logged with its tick.
- **Scene layout for later tickets:** one function per level piece and one autopilot leg per piece, so tickets 04–10 each add their own pieces, keys and legs without editing each other's. Each ticket that adds a piece extends the autopilot route and the smoke keys.

**Blocked by:** None (can start immediately).

**Status:** resolved

Built test-first on branch `claude/character-tracer-bullet-51480a`; the user did the F5 hand check after it merged. Where the build settled something the ticket left open:

- The inner body's `BodyID` comes from Jolt's body allocator in batch order (inner bodies made in entity order, after the bodies' batch), not `mInnerBodyIDOverride`: an override needs an ID known to be free, and allocation in batch order gives the same reproducibility. The bit-identical test covers it on one thread and many.
- The trim runs after `ExtendedUpdate`, over its end-of-move contacts (`GetActiveContacts`), as the trim bullet asks; Jolt's contact-solve hook sees mid-move contacts instead, so it is not used yet.
- Jolt's character position is the collider's centre less its 0.02 m padding (Jolt places the shape and inner body that far above the position); written back, it is the centre again.
- Ground state already maps all four of Jolt's states (`NotSupported` as `Touching`, which a jump into the ceiling or beside the wall shows for a tick); ticket 04 pins `OnSteepGround` and `Touching` and the face-normal rule. The walking rules are passed to the move from the component every tick, untested until 04.
- Not built here: teleports and rotation writes (05), `enabled` and inactive warnings (06; a character beside a `RigidBody`, with no `Collider` or with a mesh simply has no backend character), pushing settings and the inner body's `PhysicsMaterial` (08, 09). A `Collider` on an entity with a `CharacterBody` and no `RigidBody` is never a static body.
