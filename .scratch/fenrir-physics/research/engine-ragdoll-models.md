# How other engines build and drive ragdolls

Research for [50-how-other-engines-build-ragdolls](../issues/50-how-other-engines-build-ragdolls.md). This file reports how Unity (the Ragdoll Wizard, `CharacterJoint`, `ConfigurableJoint` drives, and the Unity Physics DOTS ragdoll sample), Unreal (the Physics Asset, `SetAllBodiesBelow*`, `PhysicalAnimationComponent`, the RigidBody anim node), Godot (`PhysicalBoneSimulator3D` and `PhysicalBone3D`), Jolt's own samples (API shape only) and Bevy (Rapier's ragdoll stress test and the `bevy_ragdoll` crate; bevy_rapier and Avian ship no ragdoll) put a ragdoll in front of game code, and what users complain about. It does not choose anything for FenrirPhysics. What Jolt itself offers is ticket 49's subject and is only sketched here. Vocabulary follows `GLOSSARY.md`: a **joint** is a physics constraint, a **bone** is a skeleton node.

Sources are engine source pinned to the commit or tag read, plus official docs and the engines' own trackers and forums. Line numbers refer to those revisions:

- Unity C# reference source, `master` @ [`bf60283`](https://github.com/Unity-Technologies/UnityCsReference/tree/bf6028387a4fc2ea6d41aa7d8998e774655aedf6), for `RagdollBuilder`, `CharacterJoint`, `ConfigurableJoint` and `Joint`. These are the managed bindings and editor only; the PhysX code behind them is closed. Unity docs are the 6000.2 Manual and Scripting Reference.
- Unity Physics samples, `EntityComponentSystemSamples` `master` @ [`6786a74`](https://github.com/Unity-Technologies/EntityComponentSystemSamples/tree/6786a741ee1f118ed14cecfa02beae8e926937b0) (Unity Physics 1.4.3), and the `com.unity.physics@1.4` API reference.
- Unreal Engine: the source needs an Epic account, so this file cites the 5.8 manual on dev.epicgames.com and the API reference at `application_version=5.4` (the only version whose API pages rendered; the unversioned API pages redirect to the documentation home). Pages are client-rendered and were read through a browser.
- Godot `master` @ [`95c0fa5`](https://github.com/godotengine/godot/tree/95c0fa5fe8a019adc29d074c16b64469b04571f7) and the `latest` docs.
- Jolt v5.6.0 @ [`e77f175`](https://github.com/jrouwe/JoltPhysics/tree/v5.6.0) (the engine FenrirPhysics pins).
- Rapier `master` @ [`475caa3`](https://github.com/dimforge/rapier/tree/475caa3ff4646fd9a796b67d14116256f4962bc7); bevy_rapier `master` @ [`8e330d9`](https://github.com/dimforge/bevy_rapier/tree/8e330d9df6c7d85fad1c42c90c13effc7cbb8415); Avian `main` @ [`a693f2b`](https://github.com/avianphysics/avian/tree/a693f2b7cec0955770fabfa45a8e0fae355c449f); `bevy_ragdoll` `main` @ [`f5d8995`](https://github.com/sagan-software/bevy-ragdoll/tree/f5d8995806364eaa82f4ade77c3905e0cd08926e), a third-party crate whose README says it "is in development and not yet published".

Every link is a full URL.

Sources that needed a login or did not render:

- Unreal's engine source (GitHub, Epic account) was not read; every Unreal claim is from the manual or the API reference. The "Physics Bodies reference" manual page named by the Physics Asset Editor overview could not be found under any slug; the `Physics Type` values are cited from the Python API's `PhysicsType` enum instead.
- Unity's `com.unity.physics@1.4` manual has no joints page (its `manual/joints.html` is a 404); joint facts are from the API reference and the samples repository.
- Unity's PhysX ragdoll solver, the engine-side half of `CharacterJoint`, is closed; only the bindings' doc comments are cited.
- The Godot `master` docs for `PhysicalBone3D`'s `joint_constraints/*` properties are empty ([godot#112892](https://github.com/godotengine/godot/issues/112892)); their defaults are read from `physical_bone_3d.h`.

Every engine surveyed builds a ragdoll the same way underneath: **one rigid body per chosen bone, a capsule (or box, sphere, hull) per body placed along the bone towards its child, and a joint from each body to its parent's body**, with collisions between a body and its parent switched off. The usual humanoid has 11 to 16 bodies. The engines then differ along four lines, and those decide most of the answers below:

- **Where the description lives:** on the bones themselves as components or child nodes (Unity's GameObjects, Godot's `PhysicalBone3D` nodes), in a separate asset keyed by bone name (Unreal's Physics Asset, Jolt's `RagdollSettings`, `bevy_ragdoll`'s profile), or in code (the Unity Physics sample, Rapier's stress test).
- **How a body meets its bone:** the body *is* the bone's transform (Unity, Godot's node with a `body_offset`), or the body is a separate object mapped by name with an offset (Unreal, Jolt, `bevy_ragdoll`).
- **Who blends:** the engine writes simulated poses into the skeleton with a per-body weight (Unreal) or a per-ragdoll weight (Godot), or game code copies transforms (Unity, Jolt, the ECS designs).
- **Powering:** per-body drive profiles in world or local space (Unreal), per-joint drives on `ConfigurableJoint` (Unity), joint motors driven to a pose (Jolt, `bevy_ragdoll`), or none (Godot, Unity Physics).

## Unity (built-in physics)

### The description

- **A wizard writes components onto the bone GameObjects.** `RagdollBuilder` asks for 13 transforms: pelvis, left and right hips, knee and foot, left and right arm and elbow, middle spine and head ([RagdollBuilder.cs L20–L25](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L20-L25)), plus `totalMass` (20), `strength` (0, unused by the builder) and `flipForward` ([L27–L29](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L27-L29)). An **Auto-Fill** button maps them from a humanoid `Avatar` through `HumanBodyBones` ([L44–L99](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L44-L99)). The character must be in a T-stand and the help text asks the user to check the blue axis faces forward ([L275–L281](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L275-L281)).
- **Per instance, not per asset.** Create adds `Collider`, `Rigidbody` and `CharacterJoint` components to the bone GameObjects ([L318–L328](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L318-L328)); the Manual says to save the result as a prefab for reuse ([Create a ragdoll](https://docs.unity3d.com/6000.2/Documentation/Manual/wizard-RagdollWizard.html)). Bodies match bones by *being* the bone's transform; there is no name table at runtime.
- **The wizard does not look at the mesh**: capsule lengths come from bone-to-child distances and radii from fixed fractions, so the result needs hand tuning for anything but a standard proportion (below).

### Bodies

- **13 bodies**: pelvis (box), spine (box), head (sphere), two upper arms, two forearms, two thighs, two shins (capsules); hands and feet are assigned as anchors but get no body of their own (feet end the shin capsule, hands are not asked for) ([L300–L316](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L300-L316)).
- **Capsules run from the bone origin to its child**: direction is the longest axis of the child's local position, `center` is half that distance, `height` the distance, `radius = |distance| × radiusScale` with scales 0.3 (thigh), 0.25 (shin, upper arm) and 0.2 (forearm) ([L372–L416](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L372-L416)). Torso boxes span the hip and shoulder anchors, clipped at the middle spine ([L553–L621](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L553-L621)); the head sphere's radius is a quarter of the shoulder width, offset away from the pelvis ([L623–L643](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L623-L643)).
- **Mass is a density weight per body, rescaled to `totalMass`**: pelvis and spine 2.5, thighs and shins 1.5, arms and head 1.0, summed and scaled so the whole character weighs the total ([L304–L315, L494–L506](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L494-L506)).

### Joints

- **`CharacterJoint` on the child, `connectedBody` the parent, `anchor` zero**, twist axis and swing axis computed from the T-pose ([L448–L481](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L448-L481)). `enablePreprocessing = false` "to handle degenerated scenarios, like spawning inside geometry" ([L463](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L463)).
- The joint is "an extended ball-socket joint which allows you to limit the joint on each axis": asymmetric `lowTwistLimit`/`highTwistLimit`, symmetric `swing1Limit` and `swing2Limit`, each a `SoftJointLimit`, with limit springs and projection ([CharacterJoint.bindings.cs L9–L58](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/CharacterJoint.bindings.cs#L9-L58)). Limits are "relative to the angle the two rigidbodies started the simulation out with" ([L27](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/CharacterJoint.bindings.cs#L27)).
- **Wizard limits (twist min, twist max, swing1; swing2 is always 0):** hips −20/70/30, knees −80/0/0, spine −20/20/10, arms −70/10/50, elbows −90/0/0, head −40/25/25 ([L307–L315](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/PhysicsEditor/RagdollBuilder.cs#L307-L315)). **Elbows and knees are the same swing-twist joint with both swings zeroed**, so they are hinges by limits, not by kind.

### Collision inside and around the ragdoll

- **Parent–child only, by the joint.** `Joint.enableCollision` ("Enable collision between bodies connected with the joint") defaults off ([Joint.bindings.cs L98–L99](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/Joint.bindings.cs#L98-L99)). Non-adjacent parts (hand against thigh) collide unless the user does something.
- **Against the character's own capsule and other parts: layers or per-pair ignores.** The Layer Collision Matrix "defines which GameObjects can collide with which Layers" ([Layer-based collision](https://docs.unity3d.com/6000.2/Documentation/Manual/LayerBasedCollision.html)); per-collider `excludeLayers`/`includeLayers` override it, and "If a layer is set to be included and excluded, it is excluded" ([Collider.excludeLayers](https://docs.unity3d.com/6000.2/Documentation/ScriptReference/Collider-excludeLayers.html)). `Physics.IgnoreCollision(collider1, collider2)` ignores one pair and "is not persistent" ([Physics.IgnoreCollision](https://docs.unity3d.com/6000.2/Documentation/ScriptReference/Physics.IgnoreCollision.html)). Two ragdolls hitting each other is the default; keeping one from its own capsule is a layer pair or an `IgnoreCollision` loop over every part.

### Switching

- **Kinematic bodies that follow animation, flipped to dynamic.** `Rigidbody.isKinematic` is documented for exactly this: a kinematic body "will be under full control of animation or script control by changing transform.position", "useful for characters which are normally driven by animation, but on certain events can be quickly turned into a ragdoll by setting isKinematic to false" ([Rigidbody.bindings.cs L341–L378](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/Rigidbody.bindings.cs#L341-L378)). The switch is per body; game code loops.
- **Velocity is not carried.** Nothing in the bindings transfers animation velocity to the bodies; the docs on `isKinematic` say nothing about velocity on the switch. The Animator's `Animate Physics` update mode runs it "in lock-step with the physics system" so kinematic bodies land on each fixed step ([Animator component](https://docs.unity3d.com/6000.2/Documentation/Manual/class-Animator.html)).
- The stability page says not to set the `Transform` of kinematic bodies connected by joints directly ([Joint and ragdoll stability](https://docs.unity3d.com/6000.2/Documentation/Manual/RagdollStability.html)).

### Blending

- **None built in.** The simulated pose reaches the skeleton because the bodies *are* the bone transforms; the Animator is disabled while the ragdoll is live. Blending back is game code lerping bone transforms towards a target pose, or a get-up clip started from a snapshot; Unity documents neither.

### Powered ragdolls

- **Drives live on `ConfigurableJoint`, not `CharacterJoint`.** `targetRotation` ("the desired rotation that the joint should rotate into"), `targetAngularVelocity`, `rotationDriveMode` (X & YZ or Slerp), `angularXDrive`/`angularYZDrive`/`slerpDrive` ([ConfigurableJoint.bindings.cs L99–L110](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/ConfigurableJoint.bindings.cs#L99-L110)). A `JointDrive` is `positionSpring`, `positionDamper`, `maximumForce` and `useAcceleration` ("whether the drive is an acceleration drive or a force drive") ([JointConstraints.cs L56–L143](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/Managed/JointConstraints.cs#L56-L143)): strength is a spring and damper with a force cap.
- **Local joint space by default**: `configuredInWorldSpace` makes "all Target values... calculated in world space instead of the object's local space" ([L131–L132](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/ConfigurableJoint.bindings.cs#L131-L132)). Active-ragdoll projects copy each animated bone's local rotation into `targetRotation` every step; Unity ships no helper for it.

### Hit boxes

- The same colliders. A raycast returns `RaycastHit.collider`, "The Collider that was hit" ([RaycastHit.collider](https://docs.unity3d.com/6000.2/Documentation/ScriptReference/RaycastHit-collider.html)), whose GameObject is the bone; the "bone name" is the GameObject's name. Kinematic bodies still receive hits.

### The character's root

- Nothing built in. The character root (controller, `CharacterController` capsule, camera target) stays where it was; the pelvis body wanders off under it. Game code moves the root to the pelvis on get-up.

### Scripting access

All C#: components with properties, `isKinematic` per body, `Physics.IgnoreCollision`, `ConfigurableJoint` drives.

### Complaints and the Manual's own answers

The stability page is a list of them ([Joint and ragdoll stability](https://docs.unity3d.com/6000.2/Documentation/Manual/RagdollStability.html)): **stretching** under "extreme conditions (such as spawning inside a wall)", answered by projection; **jitter**, answered by 10–20 solver iterations; small angular limits (keep 5–15 degrees or lock the axis); mass ratios above 2:1 ("a 10:1 ratio can make the simulation jittery"); non-unit scale on bodies or joints; overlapping bodies at spawn (lower `maxDepenetrationVelocity`); `enablePreprocessing` on. The bindings add `massScale`/`connectedMassScale` to get "less stretch of the limbs of a typical ragdoll" ([Joint.bindings.cs L110–L155](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/Joint.bindings.cs#L110-L155)). Forum threads report characters that fly off when `isKinematic` is cleared, traced to overlapping ragdoll and controller colliders, an Animator left running, or activation inside the physics step ([Rigidbody causes ragdoll character to fly](https://discussions.unity.com/t/rigidbody-causes-ragdoll-character-to-fly/94317), [Colliders flying off after activation](https://discussions.unity.com/t/colliders-flying-off-after-activation/601414)). `connectedOrientation` was added so a joint's rest pose survives disable and enable cycles, because "By default Unity recalculates the orientation" every time ([Joint.bindings.cs L50–L79](https://github.com/Unity-Technologies/UnityCsReference/blob/bf6028387a4fc2ea6d41aa7d8998e774655aedf6/Modules/Physics/ScriptBindings/Joint.bindings.cs#L50-L79)).

## Unity Physics (DOTS) ragdoll sample

Unity Physics has no skeleton, no animation integration and no ragdoll type. The sample shows a ragdoll as plain ECS data, and a `RagdollJoint` authoring component for GameObject conversion.

- **Code builds it.** `RagdollDemo.CreateRagdoll` creates 16 dynamic body entities: head (capsule, 5 kg), torso (convex hull of a mesh, 20), pelvis (capsule, 15), per side upper arm (10), forearm (5), hand (2), thigh (10), calf (5) and foot (2) ([RagdollDemo.cs L106–L415](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Common/Scripts/RagdollDemo.cs#L106-L415)). Capsules run along the limb between its ends; positions are hand-placed from the torso mesh bounds.
- **Joints are entities; a ragdoll joint is two of them.** `PhysicsJoint.CreateRagdoll(bodyAFromJoint, bodyBFromJoint, maxConeAngle, angularPlaneRange, angularTwistRange, out primaryConeAndTwist, out perpendicularCone)` returns two `PhysicsJoint`s, because "complex setups like ragdoll joints require more than one instance to stabilize", associated through `PhysicsJointCompanion` ([PhysicsJoint API](https://docs.unity3d.com/Packages/com.unity.physics@1.4/api/Unity.Physics.PhysicsJoint.html)). The sample calls `CreateJoint` twice per neck, shoulder, waist and hip ([L172–L174, L243–L246, L309–L312, L381–L384](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Common/Scripts/RagdollDemo.cs#L172-L174)); **elbows, wrists, knees and ankles are `CreateLimitedHinge`** (elbow 0–100°, wrist 0–135°, knee −90–0°, ankle ±5°) ([L248–L275, L386–L413](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Common/Scripts/RagdollDemo.cs#L248-L275)). Every joint names its pair in `PhysicsConstrainedBodyPair { EntityA, EntityB, EnableCollision }` ([API](https://docs.unity3d.com/Packages/com.unity.physics@1.4/api/Unity.Physics.PhysicsConstrainedBodyPair.html)). The `RagdollJoint` baker emits the same two joint entities from authoring fields (twist and perpendicular axes, max cone, perpendicular and twist ranges) ([RagdollJoint.cs L79–L107](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Samples/Unity%20Physics/1.4.3/Custom%20Physics%20Authoring/Unity.Physics.Custom/Joints/RagdollJoint.cs#L79-L107)).
- **Self-collision by a negative group index.** Each ragdoll's colliders get `CollisionFilter { BelongsTo = all, CollidesWith = all, GroupIndex = -ragdollIndex }` so no two parts of one ragdoll collide, while different ragdolls (different indices) do ([L75–L83, L118](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Common/Scripts/RagdollDemo.cs#L75-L83)); the filter rule is "If the value in both objects is equal and negative, the objects never collide" ([CollisionFilter API](https://docs.unity3d.com/Packages/com.unity.physics@1.4/api/Unity.Physics.CollisionFilter.html)). An `internalCollisions` flag instead uses ten layers, one per part kind, each excluding only its neighbours ([L51–L73, L139, L181–L182](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Common/Scripts/RagdollDemo.cs#L51-L73)).
- **Spawn velocity is set on every body** by writing `PhysicsVelocity.Linear` after repositioning the whole set about the pelvis ([L417–L453](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/Assets/Common/Scripts/RagdollDemo.cs#L417-L453)).
- **ECS fit:** bodies are ordinary entities with `PhysicsCollider`, `PhysicsVelocity`, `PhysicsMass` and `LocalTransform`; joints are entities with `PhysicsJoint` + `PhysicsConstrainedBodyPair`; nothing ties a body to a bone, a skeleton or a ragdoll beyond the group index. No switching, blending, motors or hit reporting beyond the generic body entity. The README's "Joints - Single Ragdoll" scene shows "GameObject ragdoll for Unity Physics (left) and built-in physics (right), created using the Ragdoll Wizard", i.e. the wizard's `CharacterJoint`s are converted to the two-joint pair ([README](https://github.com/Unity-Technologies/EntityComponentSystemSamples/blob/6786a741ee1f118ed14cecfa02beae8e926937b0/PhysicsSamples/README.md)).

## Unreal Engine

### The description

- **A hand-authored asset per skeletal mesh.** "A Physics Asset is used to define the physics and collision used by a Skeletal Mesh" and "only a single Physics Asset is allowed for a Skeletal Mesh" ([Physics Asset Editor](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-asset-editor-in-unreal-engine)). It is per asset, shared by every component using the mesh.
- **Generated from the mesh, then edited.** The Tools tab generates bodies for "the entire skeleton or selected bodies" with `Min Bone Size` ("Bones that are shorter than this value will be ignored for body creation"), `Primitive Type` (Box, Capsule, Sphere, Tapered Capsule, Single or Multi Convex Hull), `Vertex Weighting Type` (Any Weight, Dominant Weight: "How vertices are mapped to bones when approximating them with bodies"), `Auto Orient to Bone`, `Walk Past Small Bones`, `Create Body for All Bones`, `Disable Collisions by Default`, `Min Weld Size`, and for joints `Create Joints` and `Angular Constraint Mode` (Free, Limited, Locked) ([Tools and Profiles](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-asset-editor-in-unreal-engine---tools-and-profiles)). Bodies are keyed by bone name (`FPhysicalAnimationData::BodyName`, "The body we will be driving"; constraints by `Joint Name`, `Constraint Bone 1/2`). Generation fits shapes to skinned vertices, so it is better than a length heuristic, but the RigidBody node guide still expects jitter and asks for mass and damping tuning (below).
- **Per-body `Physics Type`**: `Default` ("Follow owner"), `Kinematic` ("Do not follow owner, but make kinematic"), `Simulated` ("Do not follow owner, but simulate") ([EPhysicsType](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/PhysicsType?application_version=5.7)).

### Bodies

Whatever the generator makes per bone above `Min Bone Size`, one shape kind for all; the user deletes, welds (`Min Weld Size`) and reshapes. The RigidBody guide's tuning advice for a chain: "setting the closest body to the parent structure, as the heaviest physics body, and halving the mass for each subsequent body", damping around 5.0, and moving each body's centre of mass towards its bone ([RigidBody](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-rigid-body-in-unreal-engine)).

### Joints

- **One six-DOF constraint per body pair.** Angular limits are `Swing 1Motion`, `Swing 2Motion`, `Twist Motion`, each Free, Limited or Locked, with `Swing 1Limit Angle`, `Swing 2Limit Angle` and `Twist Limit Angle`; soft limits have stiffness, damping and restitution ([Physics Constraint Reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-constraint-reference-in-unreal-engine)). The generator sets every axis to the one `Angular Constraint Mode`; **elbows and knees are the same cone-and-twist with one swing locked**, by hand.
- Per constraint: `Disable Collision` ("disables collision between the constrained components"), linear and angular projection ("a post-solve fixup where the child body is translated to resolve remaining errors"), `Enable Shock Propagation` ("Use this for world constraints and ragdoll physics"), `Parent Dominates`, breakable thresholds ([same page](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-constraint-reference-in-unreal-engine)). Constraint profiles store alternative limit and drive sets, applied at runtime by `SetConstraintProfile(JointName, ProfileName, bDefaultIfNotFound)` or `SetConstraintProfileForAll` ([USkeletalMeshComponent](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/USkeletalMeshComponent?application_version=5.4)).

### Collision inside and around the ragdoll

- **Per-body toggles in the asset.** "With default settings, collision will be disabled on all physics bodies"; the Skeleton Tree's right-click `Collision > Enable Collision All` turns pairs on ([RigidBody](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-rigid-body-in-unreal-engine)); the generator's `Disable Collisions by Default` and each constraint's `Disable Collision` set the same thing ([Tools and Profiles](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-asset-editor-in-unreal-engine---tools-and-profiles)). The RigidBody node adds `Force Disable Collision Between Constrained Bodies`.
- **Against the capsule and others:** collision profiles and channels per component, plus `UPrimitiveComponent::IgnoreActorWhenMoving(Actor, bShouldIgnore)`, which "Tells this component whether to ignore collision with all components of a specific Actor when this component is moved" but "Does not affect movement of this component when simulating physics" ([API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/UPrimitiveComponent/IgnoreActorWhenMoving?application_version=5.4)), so a simulating ragdoll still needs a profile that ignores Pawn. Forum answers for "can't get ragdoll" are "set the mesh to the Ragdoll collision preset" ([Can't get ragdoll](https://forums.unrealengine.com/t/cant-get-ragdoll/219218)).

### Switching

- **Per body, per subtree, or all**: `SetAllBodiesBelowSimulatePhysics(InBoneName, bNewSimulate, bIncludeSelf)` "Set all of the bones below passed in bone to be simulated" ([API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/USkeletalMeshComponent/SetAllBodiesBelo-_2?application_version=5.4)); `SetAllBodiesSimulatePhysics(bNewSimulate)` "Set bSimulatePhysics to true for all bone bodies"; `SetAllBodiesBelowPhysicsDisabled` removes bodies from the solver entirely, "different from SetAllBodiesBelowSimulatePhysics that changes bodies to Kinematic/simulated" ([API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/USkeletalMeshComponent/SetAllBodiesBelo-?application_version=5.4)). Bodies exist from spawn as kinematic (`Default` follows the animation); switching flips them.
- **Velocity:** kinematic bodies moved by animation carry velocity into the switch; `SetAllBodiesBelowLinearVelocity(InBoneName, LinearVelocity, bIncludeSelf)` sets it explicitly, and the RigidBody node's `Transfer Bone Velocities` will "transfer previous bone velocities from the input pose to make transition into simulation seamless" ([RigidBody](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-rigid-body-in-unreal-engine)). `AddImpulseToAllBodiesBelow(Impulse, BoneName, bVelChange, bIncludeSelf)` is the usual death kick.

### Blending

- **A weight per body, written into the pose by the component.** `SetAllBodiesBelowPhysicsBlendWeight(InBoneName, PhysicsBlendWeight, bSkipCustomPhysicsType, bIncludeSelf)`, `SetAllBodiesPhysicsBlendWeight`, `AccumulateAllBodiesBelowPhysicsBlendWeight`, and the global `SetPhysicsBlendWeight`, which "If PhysicsBlendWeight == 1.f, it will enable Simulation, and if PhysicsBlendWeight == 0.f, it will disable Simulation" ([USkeletalMeshComponent](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/USkeletalMeshComponent?application_version=5.4)). `bBlendPhysics` "Forces use of the physics bodies irrespective of whether they are simulated or using the physics blend weight"; `bUpdateMeshWhenKinematic` drives the mesh from kinematic bodies; `KinematicBonesUpdateType` decides whether non-simulated bones follow animation; `PhysicsTransformUpdateMode` is "Whether physics simulation updates component transform" ([same page](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/USkeletalMeshComponent?application_version=5.4)).
- **Getting up: a pose snapshot.** `Save Pose Snapshot` stores "all the Bone Transform data" of the ragdolled mesh, and the AnimGraph blends from the `Pose Snapshot` node into a get-up montage: "take whatever pose the character ends up in as a result of physics and generate a smooth blend from that pose" ([Animation Pose Snapshot](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-pose-snapshot-in-unreal-engine)).

### Powered ragdolls

- **`UPhysicalAnimationComponent` (Experimental)** drives bodies towards the animated pose: `SetSkeletalMeshComponent`, `ApplyPhysicalAnimationSettings(BodyName, FPhysicalAnimationData)`, `ApplyPhysicalAnimationSettingsBelow`, `ApplyPhysicalAnimationProfileBelow(BodyName, ProfileName, bIncludeSelf, bClearNotFound)`, `GetBodyTargetTransform(BodyName)`, and `StrengthMultiplyer` which "Multiplies the strength of any active motors. (can blend from 0-1 for example)" ([UPhysicalAnimationComponent](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/PhysicsEngine/UPhysicalAnimationComponent?application_version=5.4)).
- **A strength is a set of gains and force caps**: `FPhysicalAnimationData { BodyName, bIsLocalSimulation ("Whether the drive targets are in world space or local"), OrientationStrength, AngularVelocityStrength, PositionStrength, VelocityStrength ("Only used for non-local simulation"), MaxLinearForce, MaxAngularForce }` ([FPhysicalAnimationData](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/PhysicsEngine/FPhysicalAnimationData?application_version=5.4)). Profiles are authored in the asset; the how-to's "good set of starting values is 1000, 100, 1000, 100, 0, 0" ([Creating a Physical Animation Profile](https://dev.epicgames.com/documentation/en-us/unreal-engine/creating-a-physical-animation-profile-in-unreal-engine)).
- **World or local space is a per-body choice** (`bIsLocalSimulation`). Joint motors are the other route: `bUpdateJointsFromAnimation` "pass[es] joint position to joints each frame, so that they can be used by motorized joints to drive the ragdoll based on the animation", with `SetAllMotorsAngularPositionDrive(bEnableSwingDrive, bEnableTwistDrive)` and `SetAllMotorsAngularDriveParams(InSpring, InDamping, InForceLimit)` ([USkeletalMeshComponent](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Components/USkeletalMeshComponent?application_version=5.4)); the constraint's angular motor is SLERP or Twist-and-Swing with a `Target Orientation relative to the body reference frame`, `Strength` and `Max Force` ([Physics Constraint Reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-constraint-reference-in-unreal-engine)).
- **`FAnimNode_RigidBody`** runs the physics asset inside the AnimGraph in Component, World or Base Bone space, meant for "ponytails, chains" but with `Freeze Incoming Pose on Start` "useful for ragdolls, when we want the simulation to take over", `Reset Dynamics` after teleports, and clamps on how much component motion reaches the bodies ([RigidBody](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-rigid-body-in-unreal-engine)).

### Hit boxes

The same bodies, kinematic while animated. `FHitResult::BoneName` is "Name of bone we hit (for skeletal meshes)" and `MyBoneName` the "Name of the my bone which took part in hit event (in case of two skeletal meshes colliding)" ([FHitResult](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Engine/FHitResult?application_version=5.4)).

### The character's root

Not solved by the engine. The capsule stays; the mesh ragdolls under it. The forum pattern is to move the capsule to the pelvis each tick, which "push[es] the mesh forever while trying to catch up" when the capsule still collides with the mesh ([How do I properly relocate my capsule](https://forums.unrealengine.com/t/how-do-i-properly-relocate-my-capsule-to-my-skeletal-mesh-during-ragdoll/450839)), or to simulate the capsule too and right it on get-up ([How would my pawn go Ragdoll](https://forums.unrealengine.com/t/how-would-my-pawn-go-ragdoll-and-then-back-to-animations/281042)).

### Scripting access

Everything above is `BlueprintCallable` on the skeletal mesh and physical animation components; the asset and profiles are editor data.

### Complaints

**Get-up pops**: "when the character starts to get up instead of doing a transition he pops in the animation pose" despite a ramped blend weight ([Smooth transition](https://forums.unrealengine.com/t/smooth-transition-between-ragdoll-and-animation/372228)); **spinning and flying on blend-back** with `SetAllBodiesBelowPhysicsBlendWeight` ("it can even end into 100m into the sky") and the mesh "upside down or partially sideways" under the capsule without blending ([answers 499623](https://answers.unrealengine.com/questions/499623/view.html)); blending from `root` or `pelvis` fails where `spine_01` works ([answers 271627](https://answers.unrealengine.com/questions/271627/view.html)); proxies jerking in multiplayer ([forum 400862](https://forums.unrealengine.com/t/skeletalmeshcomponent-doesnt-update-correctly-on-proxy-instances-when-blending-physics/400862)); jitter in generated assets, answered by mass tapering and damping ([RigidBody](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-rigid-body-in-unreal-engine)).

## Godot

### The description

- **Nodes under a `PhysicalBoneSimulator3D`, one per bone, keyed by bone name.** `PhysicalBoneSimulator3D` is a `SkeletonModifier3D`, "Node that can be the parent of PhysicalBone3D and can apply the simulation results to Skeleton3D" ([PhysicalBoneSimulator3D.xml L3–L8](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/doc/classes/PhysicalBoneSimulator3D.xml#L3-L8)). Each `PhysicalBone3D` has a `bone_name` and resolves `bone_id` from the skeleton ([physical_bone_3d.cpp L1184–L1194, L1298–L1319](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L1298-L1319)). Per instance (scene nodes), copied with the scene.
- **The editor's "Create Physical Skeleton"** adds the simulator and, for every bone that has a child, a `PhysicalBone3D` with one `CollisionShape3D`, named "Physical Bone <bone name>", with `JOINT_TYPE_PIN` when the bone's parent also has a parent ([skeleton_3d_editor_plugin.cpp L586–L647](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/editor/scene/3d/skeleton_3d_editor_plugin.cpp#L586-L647)). The tutorial expects cleanup: remove utility and tiny bones, "A hand can be one bone instead of one per finger", then set joint types and limits by hand ([Ragdoll system](https://docs.godotengine.org/en/latest/tutorials/physics/ragdoll_system.html)).

### Bodies

- **A capsule along the bone from origin to first child**, `height = child_rest.origin.length()`, `radius = 0.1 × height` (half-height × 0.2); the body's `body_offset` looks along the child and sits half-way, `joint_offset` at the bone origin ([L649–L689](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/editor/scene/3d/skeleton_3d_editor_plugin.cpp#L649-L689)). Leaf bones get no body. Mass defaults to 1.0 per body; nothing distributes it ([PhysicalBone3D.xml L115](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/doc/classes/PhysicalBone3D.xml#L115)).
- The body's transform is `skeleton × bone_global_pose × body_offset` ([physical_bone_3d.cpp L100–L108](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L100-L108)); scale is orthonormalised away, which produces the "Non uniform scale warning on generated PhysicalBone3D" ([godot#77575](https://github.com/godotengine/godot/issues/77575)).

### Joints

- **One joint per body, by `joint_type`**: None, Pin, Cone (cone-twist), Hinge, Slider, 6DOF, created in `_reload_joint` between this body and the nearest ancestor bone that has a body, at `joint_offset` ([L950–L1043](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L950-L1043)). Defaults: cone `swing_span` 45°, `twist_span` 180°, softness 0.8; hinge limits off, ±90° when on ([physical_bone_3d.h L79–L106](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.h#L79-L106)).
- **Elbows and knees are hinges, by the tutorial's hand**: "ConeJoint... for shoulders, hips, and neck", "HingeJoint... for elbows and knees", the default Pin "causes bone crumpling", suggested cone spans 20–90° swing and 20–45° twist ([Ragdoll system](https://docs.godotengine.org/en/latest/tutorials/physics/ragdoll_system.html)).

### Collision inside and around the ragdoll

- **Jointed pairs do not collide** by the physics server's joint flag (ticket 21); nothing else is excluded inside the ragdoll. The tutorial's self-collision advice is layers and masks, and a forum report says bones set to collide with themselves gave "a ton of jitter" and never slept ([godotforums 33081](https://godotforums.org/d/33081-ragdoll-collision-masks)).
- **Against the character:** the tutorial says to set layers and masks so the `CharacterBody3D` capsule and the ragdoll ignore each other, or "the player will collide with its own (inactive) ragdoll" ([Ragdoll system](https://docs.godotengine.org/en/latest/tutorials/physics/ragdoll_system.html)); `physical_bones_add_collision_exception(RID)` walks every `CollisionObject3D` under the simulator and adds the exception ([physical_bone_simulator_3d.cpp L335–L356](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_simulator_3d.cpp#L335-L356)). While not simulating, a bone is static with layer and mask 0 when the simulator is inactive, or kinematic with its own layer and mask when active ([physical_bone_3d.cpp L1355–L1375](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L1355-L1375)).

### Switching

- **`physical_bones_start_simulation(bones = [])`** sets `simulating`, resets every bone's state, and marks a `PhysicalBone3D` simulating if the list is empty, or if its bone is in the list or a descendant of one ([L279–L333](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_simulator_3d.cpp#L279-L333)); the names are bone names, not node names, and "nonexistent bone names will not print any error or warning" ([Ragdoll system](https://docs.godotengine.org/en/latest/tutorials/physics/ragdoll_system.html)). Starting a body snaps it to the current animated pose (`reset_to_rest_position`), makes it `BODY_MODE_RIGID`, restores its layers and registers the state-sync callback ([physical_bone_3d.cpp L1341–L1353](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L1341-L1353)). **No velocity is carried**; game code sets `linear_velocity` or `apply_impulse` after the start.
- `physical_bones_stop_simulation()` returns every bone to kinematic or static ([L237–L252](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_simulator_3d.cpp#L237-L252)). The `Skeleton3D` versions of these calls are deprecated in favour of the simulator ([Skeleton3D docs](https://docs.godotengine.org/en/latest/classes/class_skeleton3d.html)).

### Blending

- **One `influence` per simulator, applied by the skeleton.** Each simulating body writes `skeleton⁻¹ × body × body_offset⁻¹` into the simulator's cached global pose on every physics sync ([physical_bone_3d.cpp L805–L836](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L805-L836)); `_process_modification` then calls `skeleton->set_bone_global_pose` for simulating bones and resets non-simulating ones to the animated pose ([physical_bone_simulator_3d.cpp L370–L387](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_simulator_3d.cpp#L370-L387)). The `SkeletonModifier3D.influence` "is used by Skeleton3D to blend" and the modifier must not apply it itself ([SkeletonModifier3D docs](https://docs.godotengine.org/en/latest/classes/class_skeletonmodifier3d.html)); default 1.0 means the ragdoll "fully overrides the rest of the animation" ([Ragdoll system](https://docs.godotengine.org/en/latest/tutorials/physics/ragdoll_system.html)). There is no per-bone weight, no ramp and no get-up helper; a modifier runs "after playback process of the AnimationMixer" and in tree order.

### Powered ragdolls

None. `PhysicalBone3D` exposes `_integrate_forces`, impulses and velocities ([PhysicalBone3D docs](https://docs.godotengine.org/en/latest/classes/class_physicalbone3d.html)); the 6DOF joint has angular springs per axis (`angular_spring_stiffness`, `damping`, `equilibrium_point`) that game code could aim ([physical_bone_3d.cpp L1013–L1041](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L1013-L1041)), but no API drives towards the animated pose.

### Hit boxes

The same bodies: a non-simulating bone is a kinematic body following the pose when the simulator is active, so raycasts hit it, "the SkeletonModifier3D.active property of the parent PhysicalBoneSimulator3D must be true" ([PhysicalBone3D.xml L8](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/doc/classes/PhysicalBone3D.xml#L8)). The hit is the node; `get_bone_id()` and `bone_name` give the bone.

### The character's root

Nothing built in. Simulating bones are made `top_level` (world space, detached from the parent's motion) ([physical_bone_3d.cpp L1351](https://github.com/godotengine/godot/blob/95c0fa5fe8a019adc29d074c16b64469b04571f7/scene/3d/physics/physical_bone_3d.cpp#L1341-L1353)); the `CharacterBody3D` stays put.

### Scripting access

GDScript and C# over the node API above; `physical_bones_start_simulation` is the only ragdoll-specific verb.

### Complaints

The tracker's longest-lived issues are authoring rot and ordering: "PhysicalBones break after saving and reloading the scene" (open since 3.2, "the physicalbone3d will be at the paused location it was saved at relative to the rest pose", editor code recomputing `body_offset` from a non-rest pose) ([godot#40549](https://github.com/godotengine/godot/issues/40549)); "PhysicalBone3D and PhysicalBoneSimulator3D is not following animations" after the modifier refactor, because "SkeletonModifier updates depending on the order of the tree" ([godot#96202](https://github.com/godotengine/godot/issues/96202)); setting `joint_type` to None at runtime "is simply ignored" ([godot#58638](https://github.com/godotengine/godot/issues/58638)); the non-uniform scale warning on generated bones ([godot#77575](https://github.com/godotengine/godot/issues/77575)); empty joint-constraint property docs ([godot#112892](https://github.com/godotengine/godot/issues/112892)); the generated pin joints "crumpling"; self-collision jitter (forum, above).

## Jolt's own samples (API shape only)

The facts belong to ticket 49; this is the shape FenrirPhysics would wrap.

- **A description object keyed by a Jolt `Skeleton`.** `RagdollSettings { Ref<Skeleton> mSkeleton; Array<Part> mParts; Array<AdditionalConstraint> mAdditionalConstraints }`, where a `Part` *is* a `BodyCreationSettings` plus `Ref<TwoBodyConstraintSettings> mToParent`, one-to-one with the skeleton's joints ([Ragdoll.h L89–L125](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Physics/Ragdoll/Ragdoll.h#L89-L125)). Bodies map to skeleton joints by index; the sample's hand-built human has 12 parts, all capsules, named LowerBody, MidBody, UpperBody, Head, UpperArm/LowerArm L/R, UpperLeg/LowerLeg L/R, joined by `SwingTwistConstraintSettings` with per-part twist, normal and plane half-angles (elbows: normal 0°, plane 90°, so hinge-like cones; knees "cheating here, a knee is not symmetric") ([RagdollLoader.cpp L127–L312](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Utils/RagdollLoader.cpp#L127-L312)). The loader can swap every joint kind for fixed, point, hinge, slider or cone ([L24–L123](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Utils/RagdollLoader.cpp#L24-L123)).
- **Setup helpers:** `Stabilize()`, `CalculateConstraintPriorities()` (root first), `DisableParentChildCollisions(jointMatrices, minSeparation)`, which builds one `GroupFilterTable` per ragdoll, sub-group = joint index, and with a pose also disables pairs that overlap at rest ([Ragdoll.h L26–L47](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Physics/Ragdoll/Ragdoll.h#L26-L47)). `CreateRagdoll(groupID, userData, system)` needs a unique group id per ragdoll instance ([L45–L62](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Physics/Ragdoll/Ragdoll.h#L45-L62)).
- **The instance:** `Ragdoll` holds `mBodyIDs` and `mConstraints`; `AddToPhysicsSystem`, `SetPose(SkeletonPose)`, `GetPose`, `DriveToPoseUsingKinematics(pose, dt)` (sets velocities so the bodies reach the pose), `DriveToPoseUsingMotors(pose)` and `(prevPose, pose, dt)`, `SetLinearAndAngularVelocity`, `AddLinearVelocity`, `AddImpulse`, `GetRootTransform`, `ResetWarmStart` after a `SetPose` ([L136–L249](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Physics/Ragdoll/Ragdoll.h#L136-L249)). The motor drive handles only `SwingTwist` and `Hinge` constraints, setting `SetTargetOrientationBS` from the pose's joint rotation ([Ragdoll.cpp L647–L720](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Physics/Ragdoll/Ragdoll.cpp#L647-L720)); targets are in local joint space.
- **The samples' three modes:** `KinematicRigTest` creates the parts `Kinematic` and calls `DriveToPoseUsingKinematics` each step ([KinematicRigTest.cpp L44–L82](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Tests/Rig/KinematicRigTest.cpp#L44-L82)); `SoftKeyframedRigTest` does the same on `Dynamic` parts with `mMaxLinearVelocity = 10` and cancels gravity each step, so the rig follows the animation but yields to hits ([SoftKeyframedRigTest.cpp L43–L93](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Tests/Rig/SoftKeyframedRigTest.cpp#L43-L93)); `PoweredRigTest` samples the animation, puts the root joint on the first body's transform and drives motors, with a position or position-and-velocity option ([PoweredRigTest.cpp L66–L115](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Tests/Rig/PoweredRigTest.cpp#L66-L115)).
- **Animation skeleton to ragdoll skeleton:** `SkeletonMapper::Initialize(ragdollSkeleton, neutralPose1, animSkeleton, neutralPose2, canMap)` matches joints by name by default; the animation skeleton "can contain extra joints between those in skeleton 1 and... at the root and leaves"; `Map` fills unmapped joints from the animated local pose and reorients chains; `MapReverse` goes the other way; `LockAllTranslations` removes visual stretch because "constraints are never 100% rigid" ([SkeletonMapper.h L64–L112](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Skeleton/SkeletonMapper.h#L64-L112); [SkeletonMapperTest.cpp L79–L136](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Tests/Rig/SkeletonMapperTest.cpp#L79-L136)).
- **Collision around the ragdoll:** the samples put every part on `Layers::MOVING` ([RagdollLoader.cpp L38, L281](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Utils/RagdollLoader.cpp#L281)); the group filter only separates parts of one ragdoll from each other, and `SetGroupID` re-keys an instance ([Ragdoll.h L162–L163](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Jolt/Physics/Ragdoll/Ragdoll.h#L162-L163)). Characters are not in the Rig samples.
- **Switching** is the part's `mMotionType` at creation (the loader overrides it for every part, [L32–L35](https://github.com/jrouwe/JoltPhysics/blob/v5.6.0/Samples/Utils/RagdollLoader.cpp#L32-L35)); the samples never flip a live ragdoll. `SetPose` teleports (`BodyInterface::SetPositionAndRotation`), so `ResetWarmStart` follows it.
- No blending, hit reporting, root handling or scripting: the samples copy poses in and out themselves, in C++.

## Bevy: Rapier, bevy_rapier, Avian and `bevy_ragdoll`

- **bevy_rapier and Avian ship no ragdoll example, type or doc.** Their example directories hold joints, chains and motors only ([bevy_rapier3d/examples](https://github.com/dimforge/bevy_rapier/tree/8e330d9df6c7d85fad1c42c90c13effc7cbb8415/bevy_rapier3d/examples), [avian3d/examples](https://github.com/avianphysics/avian/tree/a693f2b7cec0955770fabfa45a8e0fae355c449f/crates/avian3d/examples)); a tree search for "ragdoll" or "skeleton" finds nothing in either.
- **Rapier's stress test is the reference shape**: a 10-body ragdoll (torso capsule, head ball, two-link arms and legs), 9 joints, "spherical neck, shoulders and hips; revolute elbows and knees", every joint with limits and `.contacts_enabled(false)`, built in code from offsets about the torso ([ragdolls3.rs L4–L81](https://github.com/dimforge/rapier/blob/475caa3ff4646fd9a796b67d14116256f4962bc7/examples3d/stress_tests/ragdolls3.rs#L4-L81)). Spherical limits are per axis (AngX, AngY, AngZ), not a cone.
- **`bevy_ragdoll`** (third party, unpublished, Bevy 0.20, `bevy_rapier3d` 0.37 and an Avian git pin) is the only Bevy design that answers the ticket's bullets, so it is summarised as a design, not an engine:
  - **Description:** a `Ragdoll` component on the character entity with an optional `RagdollProfile` asset; `Ragdoll::default()` "generates bodies, shapes, masses, and joints from the bones it finds", humanoids by an alias table covering "UE4 and UE5 mannequins, Mixamo, Unity, Godot and VRM humanoid names, Rigify deform bones, and 3ds Max Biped" and other rigs by topology ([README](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/README.md); [humanoid.rs L1–L6](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/auto/humanoid.rs#L1-L6)). A profile `Body` is `{ index, bone: String, shape, mass, rest, role }` and a `Joint` is `{ child, parent, frame (child rest in parent frame), limits (X bend, twist, Z bend), max_torque, basis }` ([body.rs L13–L26](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/profile/body.rs#L13-L26); [joint.rs L12–L25](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/profile/joint.rs#L12-L25)). Bodies are capsules at a density of 985 kg/m³, humanoids rescaled by a segment-mass table to a reference 80 kg ([generate.rs](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/auto/generate.rs)); 16 bodies and 15 joints in its human ([rapier-powered spike](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/docs/spikes/rapier-powered.md)).
  - **ECS fit:** body entities are top-level, with `RagdollBodyOf(character)` and a reciprocal `RagdollBodies` relationship, `BodyIndex`, `BodyKind { Kinematic, Dynamic, Fixed }`, `JointToParent { parent, frame, limits, max_torque }`, `JointDriveTarget { rotation, angular_velocity, stiffness, damping, max_torque }` and `NoContactWith(u64)`, a bit mask of excluded profile bodies the backend applies through contact hooks ([components.rs L677–L697](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/components.rs#L677-L697); [body.rs L240–L338](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/body.rs#L240-L338); [rapier3d contact.rs](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/crates/bevy_ragdoll_rapier3d/src/contact.rs)). Variable-rate systems bind, capture the animated pose and write back around transform propagation; fixed-rate sets order behaviour, drive, backend apply, backend read and bookkeeping ([sets.rs L1–L9](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/sets.rs#L1-L9)).
  - **Switching:** a `RagdollMode { Animated, Kinematic, Dynamic, Frozen }` component on the character: "The runtime creates and removes body entities at these transitions, so systems should change the mode rather than editing body kinds directly" ([components.rs L85–L112](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/components.rs#L85-L112)). `Frozen` keeps the last pose for blending back after settle.
  - **Blending:** `RagdollBlend` per character, "zero preserves the animated local transform, one uses the physics pose"; writeback "reads fixed-step history, composes each bone from parent-first local transforms, applies the animation-to-physics blend", and "non-body bones keep their animated locals" ([components.rs L435–L447](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/components.rs#L435-L447); [writeback.rs L1–L9](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/writeback.rs#L1-L9)).
  - **Powered:** `RagdollDrive { muscle, pin }` strengths in 0..1 plus per-body `RagdollBodyWeights`; muscles are joint motors towards the captured `RagdollTargetPose`, pins are world-space forces on chosen bodies; backends without motors get "equal and opposite stable-PD torques" ([components.rs L114–L134, L215–L308, L513–L529](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/components.rs#L114-L134); [drive.rs L1–L7](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/drive.rs#L1-L7)). Its Rapier notes record that "Coupled angular motors are not implemented" in Rapier, so a cone-limited joint cannot be motor-driven there ([physics-api.md L126](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/docs/plan/reference/physics-api.md)). The spike's best single-ragdoll powered run had 3.3° mean joint error and 0.19 m pelvis drift at a 6 Hz motor ([rapier-powered spike](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/docs/spikes/rapier-powered.md)).
  - **Hits** are messages naming the body entity and an impulse; the runtime weakens muscles locally by `BodyRole` floors and spreads the impulse up the body tree ([hit.rs L1–L8](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/runtime/hit.rs#L1-L8); [role.rs](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/src/profile/role.rs)).
  - **Root and get-up** are listed under its planned balance crate ("centre of mass, support polygon... get-up"), not built ([decisions.md](https://github.com/sagan-software/bevy-ragdoll/blob/f5d8995806364eaa82f4ade77c3905e0cd08926e/docs/plan/decisions.md)).
  - **Scripting:** Rust only; everything is a reflected component, so an editor or a RON overrides file can set it.
- **Complaints** for Bevy are design notes rather than tracker threads: Rapier's missing coupled angular motors, the pelvis drift the spike could not close (0.19 m at best), and `bevy_rapier`'s joint-on-child model that its own issue calls un-ECS-like (ticket 21).

## What this means for FenrirPhysics

FenrirPhysics keeps plain-data components physics diffs each tick, one component of each type per entity (ADR-0011); joints are joint entities with explicit local frames and `collideConnected` (ADR-0013, ticket 25); the animation side already fixed how simulated poses enter (`PoseOverride` world targets with gameplay-owned per-bone override weights, ADR-0038), how bone-following kinematic bodies are moved (`Transform` written in `Tick` from `PoseKind::Simulation`, ADR-0040) and that `RigidBody::motionType` is the switch. Against those, the survey leaves these options for tickets 51 to 57. What Jolt can back is ticket 49's answer.

**Where the description lives**

- **A. A ragdoll asset keyed by bone name** (Unreal's Physics Asset, Jolt's `RagdollSettings`, `bevy_ragdoll`'s profile): one description per skeleton asset, instanced per character. Matches FenrirSkeleton's arrays-not-entities bones and ADR-0038's "glue owns the mapping". Needs an asset type and a bone-name match (Jolt's `SkeletonMapper` and `bevy_ragdoll`'s alias table both match by name).
- **B. Components on body entities naming a bone** (Godot's node per bone with `bone_name` and `body_offset`; Unity's components on bone transforms): a `RagdollBody { skeleton, boneName/boneIndex, offset }` beside `RigidBody`, `Collider` and the `Joint` entities FenrirPhysics already has. No new asset; the ragdoll is the set of body entities pointing at one skeleton entity, as wheels point at a vehicle (ADR-0015). Per instance, so sharing is prefab or code.
- **C. Code builds it** (Unity Physics sample, Rapier): a builder API that spawns B's entities from a few parameters. Every engine's wizard is this with a UI.

**Generating bodies and joints.** Every wizard uses bone-to-child length for a capsule (Unity, Godot, `bevy_ragdoll`); Unreal fits skinned vertices. Masses: Unity's density weights scaled to a total, `bevy_ragdoll`'s segment table to 80 kg, Godot's none. Jolt's `Stabilize` and `CalculateConstraintPriorities` are post-passes. Hands and feet are optional everywhere (Unity drops them, Godot prunes by hand, Unity Physics keeps them).

**Joint kinds.** The swing-twist joint FenrirPhysics already has (ticket 23) is what Unity, Jolt and Unreal use for every ragdoll joint, with elbows and knees as swing-twists with the swing zeroed (Unity, Jolt) or a hinge kind (Unity Physics, Godot, Rapier). Jolt's motor drive handles both. Unity Physics's two-joint cone pair is a solver workaround FenrirPhysics does not need.

**Collision inside the ragdoll.** Three levels: jointed pairs only (`collideConnected`, already there; Unity, Godot); a group per ragdoll so no part hits another (Unity Physics's negative `GroupIndex`, Jolt's `GroupFilterTable` with sub-groups, `bevy_ragdoll`'s mask), optionally with overlapping-at-rest pairs disabled (Jolt); per-pair toggles in the asset (Unreal). Jolt's table is the obvious backing for ticket 51's general collision groups, and its unique-group-id-per-ragdoll requirement is a constraint on the design. Against the character's own body every engine uses layers or an ignore list; FenrirPhysics's `CollisionFilter` layers suffice if the ragdoll and the `CharacterBody` are on layers that ignore each other, or a group that excludes the character's inner body.

**Switching.** ADR-0040 already fixed it as `motionType` per body; the survey adds the granularity choices:

- **Per body** (Unity's `isKinematic`, Godot's `set_simulate_physics`): the primitive every other level is built from; game code loops.
- **Per bone subtree** (Unreal's `SetAllBodiesBelow*(BoneName, ..., bIncludeSelf)`, Godot's bone-name list with descendants): the common gameplay unit (a limp arm, legs only); needs the skeleton's parent table, which `SkeletonData` and ADR-0038's subtree query already give.
- **Whole ragdoll** (`bevy_ragdoll`'s `RagdollMode`, Jolt's per-part motion type set once): one field on the character; partial ragdolls then need per-body weights anyway.

Velocity carry-over is a kinematic body's own velocity (Unreal), an explicit set (Jolt's `SetLinearAndAngularVelocity`, Unity Physics's `PhysicsVelocity`) or a captured animation velocity (`bevy_ragdoll`, Unreal's `Transfer Bone Velocities`); Godot and Unity carry none and their forums show the resulting jumps. A kinematic body moved by ADR-0040's glue each tick already has the right velocity in Jolt when it turns dynamic.

**Blending.** ADR-0038's per-bone override weights are Unreal's per-body `PhysicsBlendWeight` plus subtree assignment, finer than Godot's one `influence` and `bevy_ragdoll`'s one `RagdollBlend`. Getting up is game code everywhere; Unreal's Pose Snapshot (hold the final simulated pose, blend into a clip) is ADR-0038's "entries glue stops refreshing hold the last simulated pose" plus a crossfade, which FenrirAnimation has.

**Powered ragdolls.** Two drive spaces: local joint-space motor targets (Unity default, Jolt, `bevy_ragdoll` muscles) or world-space body targets (Unreal's non-local profiles, `bevy_ragdoll` pins). Strength is a spring and damper with a force cap (Unity `JointDrive`, Unreal's six gains and two max forces, `bevy_ragdoll`'s stiffness, damping, max torque) with a global multiplier (Unreal `StrengthMultiplyer`, `bevy_ragdoll`'s 0..1 drive). FenrirPhysics's `JointMotor` (position mode, `JointSpring` as Hz and damping ratio, `maxForce`) is the local form; a world-space pin would be new. Targets from the base pose (ADR-0038) at tick time (ADR-0040) are what Jolt's `PoweredRigTest` does with its own animation.

**Hit boxes.** Every engine with a skeleton uses the ragdoll bodies themselves, kinematic while animated, and reports the bone by name (Unreal) or by the hit object (Unity, Godot). ADR-0040 already makes a `RagdollBody` entity the hit box; ticket 52 decides how the bone name reaches the hit payload (an entity to look up, or a name in the event).

**The character's root.** No engine moves the controller for you; the recurring bugs are the controller colliding with its own ragdoll (Unreal, Godot, Unity) and the capsule chasing the pelvis. ADR-0038 already asks glue or game code to move the skeleton entity under the root body; the `CharacterBody` is the open piece (disable it, or teleport it to the pelvis on get-up).

**ECS fit.** Unity Physics and `bevy_ragdoll` agree: bodies and joints are ordinary entities; a per-body back-reference to the character (`RagdollBodyOf`) and a per-character mode or weight component carry the ragdoll-level state; the skeleton is not entities. `bevy_ragdoll` creates and destroys body entities on mode changes, which ADR-0009 forbids from C# native functions; FenrirPhysics would keep bodies alive and switch `motionType`, as ADR-0040 says.

**Scripting.** Everything above is data on components (B/C) or verbs on a component (Unreal, Godot); the C# side mirrors whichever is chosen. The gap to avoid is Unity's: a wizard with no runtime description, leaving every game to write its own switch, blend and ignore loops.

**Complaints to design against.** Stretching under load (Unity's projection and mass scale, Jolt's `LockAllTranslations`); jitter from self-collision (Godot, Unity) and from mass ratios (Unity's 2:1 advice, Unreal's halving); flying off on the switch from overlapping the controller or activation mid-step (Unity, Unreal); get-up pops and spins from blending back by weight alone (Unreal); descriptions that rot when authored against a non-rest pose (Godot's offsets, Unity's captured joint frames; ADR-0013's explicit frames already answer the joint half).
