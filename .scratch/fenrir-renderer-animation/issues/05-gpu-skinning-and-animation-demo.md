# 05: the renderer skins meshes on the GPU through the skinning source, and AnimationDemo shows playback, the skeleton and skin diagnostics

**What to build:** a skinned glTF character animates on screen: `SkinnedMesh` beside `MeshRenderer` draws from its skeleton's palette under the `SKINNED` variant, reached through the skinning source with no link to FenrirSkeleton, and the new AnimationDemo app opens with scenes 1 (Playback), 2 (Skeleton) and 3 (Skin diagnostics), its README and smoke runs (spec: "FenrirRenderer: skinning", "Spawning", "AnimationDemo"; ADR-0035, ADR-0041). The palette stats and the crowd scene are ticket 07; the FBX character in scene 2 is ticket 06.

- **`SkinnedMesh { Entity skeleton; }`**, plain and blittable, documented prominently: a skinned item is drawn with the skeleton's world matrix and the mesh entity's own `Transform` and ancestors are never applied; `visible` and the material stay on the mesh entity.
- **The renderer's `SpawnModel`** runs `SpawnNodes`, then `SpawnSkeletons` through the skinning source, then adds `MeshRenderer`s; each skinned mesh entity becomes a child of its skeleton's owner with an identity `Transform` and a `SkinnedMesh` naming it; with no source it skips `SpawnSkeletons` and logs once. This replaces ticket 02's interim skip.
- **Skip cases, each a warning logged once:** skin data but no `SkinnedMesh`; a `SkinnedMesh` whose skeleton is dead, has no `SkeletonPose` or is not `Ready`; no skinning source; a failed compatibility check (`boneCount` ≤ the skeleton's bones, signatures equal unless `expectedSignature` is 0, cached per mesh entity by both revisions); a user shader without `SKINNED` drawing with the fallback material. A `SkinnedMesh` on a mesh with no skin data draws rigidly, logged once. The foundation's magenta missing-material fallback becomes a warning too, so smoke runs pass.
- **Variants and palette:** the reserved `SKINNED` key set for skinned items and the built-in programs built with it; joints and weights in the two free vertex locations; a std430 storage buffer at set 3, binding 1, ring-buffered per frame in flight, doubling, no cross-frame cache; `paletteOffset` (in bones) and the world determinant sign on each draw record; uploads deduplicated within a frame by (scene, skeleton entity, `PoseGeneration`); capacity checked before recording with a failure skipping the draw as an internal error. `FenrirBone { vec4 r0, r1, r2; }` packed by one `GpuBone` with static layout asserts and a debug reflection check.
- **`Fenrir/Skinning.glsl`** with `FenrirSkinPosition`, `FenrirSkinNormal` and `FenrirSkinTangent` as the spec writes them: zero weight is identity in bind space; cofactor normals with the determinant and length fallbacks; tangents through the world 3×3, Gram–Schmidt'd with a perpendicular fallback; handedness `t.w × sign(det A) × sign(det W)`; the world normal matrix and sign shared with rigid draws.
- **Bounds:** `GetWorldBounds` of a skinned mesh unioning the per-bone boxes and the zero-weight box under the owner, `nullopt` when not `Ready` or with no source; a transparent skinned item sorted by its bounds' centre.
- **AnimationDemo** at `examples/AnimationDemo/` through `fenrir_add_demo_app`, added to the examples list, installing FenrirSkeleton and FenrirAnimation, with assets in `examples/AnimationDemo/assets/` and an `ATTRIBUTION.md`: a Quaternius CC0 glTF humanoid with idle, walk, run and wave clips on its own rig, and the Khronos `Fox` (model CC0, rig and animation CC-BY 4.0), each file and licence checked before it is added. Scenes, leaving the others for their tickets:
  1. *Playback:* `Animator` speed, reverse, `Loop`/`Once`, pause and seek on keys; clip events shown as world text; a short fast clip hitting the 64-event budget with `AnimationEventsDropped` on screen.
  2. *Skeleton:* the humanoid's bones through FenrirDebugDraw (parent-to-child lines, axes, names as world text), keys toggling mesh, bones and names; the Fox beside it.
  3. *Skin diagnostics:* one labelled entity per skip case (no `SkinnedMesh`, an `Unavailable` skeleton, a failed bind signature, a shader without `SKINNED` drawn magenta), each label placed even when its draw is skipped.

  The README gives each scene's purpose, keys, expected behaviour, the tickets it depends on and the hand checks. Smoke runs on null everywhere and llvmpipe on Linux CI, with no exceptions.

## Comments

Built 2026-10-29 on `claude/animation-04-playback-4ee621` at 189bd9a1 (ticket 04, PR #240, not merged yet), as a stacked PR. Decisions to review:

- **Assets are procedural stand-ins.** No download was approved in this session, and the Quaternius humanoid's licence could not be confirmed (Poly Pizza lists its "Animated Base Character" as CC-BY 3.0, not CC0; the CC0 packs on itch.io are downloaded by hand). `examples/AnimationDemo/assets/make_assets.py` writes `mannequin.gltf` (17 bones; Idle, Walk, Run, Wave and a quarter-second Flutter clip) and `critter.gltf` (a four-legged rig with a tail; Wag), MIT as the repository. The Khronos Fox's licence is confirmed (model CC0, rig and animation CC-BY 4.0) and recorded in `ATTRIBUTION.md`; adding its three files waits on the download being approved. Scene 2 labels both models as stand-ins.
- **`SpawnModel` takes the App:** `SpawnModel(app, scene, model, parent = {})`, replacing `(store, scene, ...)`, because only the App reaches both the store and the skinning source. ADR-0023 is amended; RendererDemo, PhysicsDemo, ScriptingDemo and the scripting native move to it. A skinned mesh gets an entity of its own named after its node, under its skeleton's owner at the identity (the node's own entity stays, without the mesh). With no source the warning is once per call. The scripting native still records only Name, Transform and MeshRenderer, so a model spawned from C# gets no `SkinnedMesh` or `SkeletonPose` and its skinned meshes are skipped with the "no SkinnedMesh" warning: ticket 13's.
- **Who logs what:** the facade logs the per-entity skip cases (no `SkinnedMesh`, dead skeleton entity, no `SkeletonPose`, `Unavailable`, incompatible, `SkinnedMesh` on a rigid mesh), each once per entity and reason, and "no skinning source" once per renderer; an incompatible verdict is logged again when a new pairing fails. The core logs a shader without `SKINNED` once per shader. A palette range past what was written this frame is the internal error, checked against the frame's palette (which never exceeds the ring's capacity). The foundation's missing-material fallback already logged a warning, so nothing changed there.
- **Draw set:** the draw record grows to 144 bytes (`paletteOffset` and `worldSign` after the two matrices, padded). Set 3's binding group is made by the scene renderer from the draw ring's and the palette ring's buffers, one per copy, remade when either ring regrows; `BlockRing` gained `Buffer`, `Capacity` and a no-groups mode for this.
- **The reflection check needed a reflection change:** SPIRV-Reflect reports a storage block made of a runtime array as 0 bytes, so `ShaderBinding::size` could not be checked. The shader compiler now gives such a block the size of one record (the array's offset plus its stride), documented on `ShaderBinding::size` and tested in `Flattening.cpp`; the renderer's debug check then compares 144 for `DrawData` and 48 for the palette. No container format change.
- **The CPU mirror of `Fenrir/Skinning.glsl`** is `src/Core/Skinning.{hpp,cpp}` (`BlendBones`, `SkinModelNormal`, `SkinPosition`, `SkinNormal`, `SkinTangent`, `RigidNormal`), kept step for step with the shader; the CPU unit tests check its maths and the GL probes hold the GPU to it. The three GLSL functions take the draw record and return world space. The built-in vertex stage uses position and normal only (builtin:lit derives its tangent frame from derivatives), so `FenrirSkinTangent` is there for user shaders.
- **New vertex formats** `Uint16x4` (read with `glVertexArrayAttribIFormat`) and `Unorm16x4`, for the joints and weights at locations 6 and 7; their constant defaults are zero bits (no weight, the identity).
- **`GetWorldBounds`** finds the skeleton entity's scene by asking each scene's entity list for its id, since an entity does not name its scene. A skinned mesh without a `SkinnedMesh` has no bounds (it is not drawn).
- **The scaffold deploys scripting for every demo app:** `fenrir_add_demo_app` now runs `fenrir_deploy_scripting` for an app with no `SCRIPTS` too, since the scaffold links the scripting host whenever scripting is built; AnimationDemo would otherwise not start (0xc0000135, `nethost.dll` missing). Outside the Touches line.
- **`.github/workflows` unchanged:** the smoke runs are found by label, so CI's null job runs `AnimationDemo-Smoke-null` with no edit, and the llvmpipe job (still commented out) would run the GL one.
- **Not done here (later tickets):** `Stats`' palette counters and the crowd (07), the FBX character (06), C# `SkinnedMesh` (13).
- **Test-first, with a caveat:** each slice's tests were written before its code and seen failing (to compile, or on the bounds, `SpawnModel` and reflection cases), but the facade's skip cases were implemented in the same step as the first slice, so their tests went green on first run; the transparent-sorting test was added last and was checked to fail by reasoning about the origin order, not by running it red.
- **A pre-existing failure:** `FenrirPhysicsScripting` fails on this machine (its fixture assembly does not load) on ticket 04's build too, so it is not this ticket's.
