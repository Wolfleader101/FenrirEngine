# 03: FenrirSkeleton poses skeletons headlessly, with the pose pipeline, generations, the palette and spawning

**What to build:** the new FenrirSkeleton package: a skeleton entity with a `SkeletonPose` can be posed by hand, read in local, model and world space, driven through the pose pipeline's stages, and spawned from a model, all with no animation, renderer or physics (spec: "Packages, build and install", "FenrirSkeleton: instances and reads", "The pose pipeline and modifiers", "Spawning"; ADR-0028, ADR-0031, ADR-0033, ADR-0035, ADR-0041). The pose override, attachments and tick-posed timing are later tickets (09, 10, 11), but the types they fill in are declared here where the spec puts them on the component (`PoseTiming`, `PoseKind`).

- **Package:** `packages/FenrirSkeleton/`, built under `FENRIR_ENABLE_ASSETS` with no option of its own, depending on FenrirAssets, FenrirECS, FenrirScene, FenrirApp, FenrirMath and FenrirTime, with its tests and a `PublicHeaders.cpp`. The owner and facade is `Skeletons`. `Skeletons::Install(App&)` registers the skinning source as an app resource and the pipeline's systems, and returns the move-only owner; it fails with one diagnostic and `IsValid() == false` without FenrirAssets; a second registration is logged and ignored; teardown removes the source.
- **Instances:** `SkeletonPose { AssetHandle<Skeleton> skeleton; PoseTiming timing = Frame; }` on the skeleton entity; the private `SkeletonPoses` scene resource holding base locals, final locals, model matrices and the cached palette; Reconcile creating, rebuilding on a handle or revision change, and sweeping; `Ensure(entity)`; `PoseState` (`Ready`, `Unavailable` with empty reads and one log, `Missing`) with recovery rebuilding the instance.
- **Reads and writes:** the spans with their validity rule; `FindBone`, `GetLocal`, `GetModel`, `GetBaseLocal`, `GetBaseModel` (lazy, cached) and `GetBoneWorldMatrix` (`GetWorldMatrix(entity) × M_model[bone]`, `std::optional`); `PoseKind` accepted and, on a frame-posed skeleton, both kinds returning the render pose; `EditBasePose` marking pose-dirty; the three kinds of change kept apart. `PoseGeneration` from one `SkeletonPoses`-wide counter, advanced on finalised-pose change and rebuild, never on a move. `GetPalette` built lazily on the main thread for the current generation and cached with it.
- **Pipeline:** one sequential `PostUpdate` system on the active scene running Reconcile, `Animate`, Prepare, `Modify`, Finalise, Attach (empty until ticket 10) and `Late`; `AddModifier`, `AddAnimate` and `AddLate` with `int` order, ties by registration, handles that remove outside the pipeline, `ModifierOrder::Override = 1000`; inactive scenes paused without catch-up. The `Animate` item context gives the pass's timing, step and instances (frame pass only until ticket 11), and `EditBasePose` on the other timing during `Animate` is refused with one log per call site.
- **Modifiers:** `PoseEdit` with `Base()`, `Local(bone)`, `Model(bone)` and `Write(bone, Target)`; `Target { space, trs, channels, weight }`; each write resolving at once (world through the inverse skeleton world matrix read at `Modify` start, model through the parent's current model matrix), blended in local space for the masked channels, writes composing sequentially, model matrices invalidated and recomputed lazily; a missing inverse skipped with a rate-limited warning; shear dropped; clean instances skipping Prepare and Finalise.
- **Skinning source:** FenrirSkeleton's implementation of the FenrirAssets interface answering `PoseState`, the handle, generation, palette and model matrices per scene and entity.
- **Spawning:** `SpawnSkeletons(scene, model, spawned)` adding `SkeletonPose` to owners whose skeleton loaded and calling `Ensure` (the attachment step of ordinary nodes below bones is ticket 10), and `Skeletons::SpawnModel(scene, model, parent)` for headless apps.
- **Docs:** the package README, GLOSSARY entries for the pose vocabulary, and the root `CMakeLists.txt` adding the package after FenrirAssets.

No demo scene: Seam 8 is the proof. The renderer does not link the package and still draws nothing skinned. Spawning tests use procedural models until ticket 02 lands, then its fixtures.

## Comments

Built 2026-10-29, stacked on 01's branch beside ticket 02. Decisions to review:

- **How the renderer finds the source (for ticket 05):** FenrirAssets' `SkinningSource.hpp` gains `struct SkinningSourceRegistration { SkinningSource* source; }`, the app resource `Skeletons::Install` adds and the owner's teardown removes (only if it still points at its own source). The renderer calls `app.TryGetResource<SkinningSourceRegistration>()` in each `Render` and each call that needs it; null means no skinning source.
- **Reads take the scene:** every read and `EditBasePose` is a static `Skeletons::F(scene, entity, ...)`, because an `Entity` cannot name its scene and the instances are a scene resource. Static reads need no owner, so stage work, the skinning source and later packages call them without capturing the move-only owner. `Ensure`, `SpawnSkeletons`, `SpawnModel`, stage registration and `Remove` are owner members.
- **A second install fails whole:** it logs one error and returns an owner whose `IsValid()` is false, adding no second pipeline system, so the spec's "a second registration is logged and ignored" never runs two pipelines.
- **Owners come from `Model::skeletonOwners`:** ticket 02 adds that field to `Model`; this ticket declares the same field with 02's text in the same place, so the stacks merge cleanly. `Add<Model>` is new in FenrirAssets (a `PrepareAsset(Model&)` checking parents first, bone nodes naming a skeleton of the model, and one non-bone owner per skeleton), so the spawning tests build procedural models; once 02 lands they can use its fixtures as well.
- **Stage work:** `AddAnimate`, `AddModifier` and `AddLate` take `std::function`s of `AnimateContext&`, `ModifierContext&` and `LateContext&`. `PoseStageHandle` is a plain id that `Skeletons::Remove` takes; `Remove` inside the pipeline is refused with an error. Each stage runs a snapshot of its work taken when it starts, so work added during the pipeline waits for the next frame.
- **Skipping, precisely:** prepare and finalise run for an instance whose base pose is dirty or that a modifier edited last frame (so its final pose returns to the base pose); a modifier's first `Edit` of the frame prepares any other instance on demand. Only finalised instances get a new generation, so a clean instance keeps its own.
- **World targets** read the inverse skeleton world matrix at the instance's first edit of the frame's `Modify`, which equals "when `Modify` starts" since no modifier may move entities.
- **Refusals:** `EditBasePose` is refused (empty span, one warning per call site, by `std::source_location`) during `Modify` and `Late`, and during `Animate` on the other timing. A degenerate inverse is warned at most once every 300 frames per entity and bone. Unavailability is warned once each time an instance becomes unavailable.
- **`PoseKind`** is accepted everywhere the spec puts it and ignored for now: tick-posed skeletons (ticket 11) are what tell the kinds apart. A tick-posed skeleton keeps its base pose until then; frame `Animate` work may not write it.
- **Checks:** `PublicHeaders.cpp` fails the build if a header reaches the renderer, physics, a window or GL; the package's CMake fails configuring if FenrirRenderer or FenrirPhysics links it (a deferred check run once every target exists).
