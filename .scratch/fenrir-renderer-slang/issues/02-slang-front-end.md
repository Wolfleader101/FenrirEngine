# 02: The Slang front end: `.slang` stages compile through Slang beside the GLSL ones

**What to build:** `FenrirShaderCompiler` compiles a stage whose file ends in `.slang` (one file per stage, named `<name>.<stage>.slang`: `mesh.vert.slang`, `lit.frag.slang`, `cull.comp.slang`) through Slang's compilation API and everything else through glslang, both into the same `CompiledStage`, so a program may be all Slang, all GLSL, or one stage of each (ADR-0073, "The move is gradual, program by program, with two front ends"). Reflection for Slang stages is ticket 03; this ticket gets SPIR-V out with the right options and the right diagnostics, and a Slang program through the container tests.

- **A `SlangStageCompiler`** beside `StageCompiler` (`src/SlangStageCompiler.cpp`, `.hpp`), with a process-wide global session (as `GlslangProcess` is) and one session per stage: search paths from `--include` (the stage's own directory first, then `INCLUDE_DIRECTORIES`, then the engine's), preprocessor macros from `--key` (`NAME=1`, as the GLSL preamble gives them), target `spirv`, profile `spirv_1_0`, `-matrix-layout-row-major` (ADR-0073: it gives glslang's `ColMajor`), `-emit-spirv-directly`, no debug info, Slang's optimizer at its default. The entry point is the one function with `[shader("vertex")]`, `[shader("fragment")]` or `[shader("compute")]`, and it must match the stage the file name's `.vert`, `.frag` or `.comp` says and the stage `fenrir_add_shaders` asked for; a file with none, more than one, or one of another stage is an error naming the file (ADR-0073, "One file per stage"). A `#include` directive anywhere in a `.slang` file is an error naming the file and line and saying `import Fenrir.<Name>;` instead (ADR-0073, "A Slang file imports and never includes"): the tool checks Slang's dependency list for the stage, which must hold only module files.
- **Dispatch:** `CompileStage` picks the front end by extension; `Program.cpp` and `Arguments.cpp` change only where they assume GLSL (the preamble, the `.vert`/`.frag`/`.comp` names in messages). `fenrir_add_shaders` accepts `.slang` for `VERTEX`, `FRAGMENT` and `COMPUTE` with no new argument, and its header comment says so.
- **Diagnostics** come from Slang's diagnostic blob, re-emitted through `Diagnostics` in the tool's `file:line: error: message` shape, so IDEs and the must-fail fixtures match them as they match glslang's. Slang's warnings are errors for the tool's own build (`FenrirRendererCore`'s programs) and warnings for users', as the GLSL path treats them.
- **The depfile** lists every file Slang loaded (the session's dependency file list), so editing a module rebuilds the programs that import it, as `Includer` records includes today.
- **Fixtures:** `Tests/fixtures/plain.vert.slang` and `plain.frag.slang`, and `twod.vert.slang` and `twod.frag.slang`, each the Slang twin of its GLSL fixture; must-fail twins `two_entry_points.frag.slang` (a vertex and a fragment entry point in one file), `wrong_stage.frag.slang` (a `[shader("vertex")]` entry point in a `.frag.slang`) and `includes.frag.slang` (a `#include`); `Containers.cpp` builds a Slang program and a mixed program (GLSL vertex, Slang fragment) and reads the containers back.
- **Rules deferred to 03:** every rule `RuleChecker` enforces on glslang's AST is left unchecked for Slang stages in this ticket, and the ticket's fixtures obey them by construction.
