# 06: Modules for the sets, the draw and the vertex: `Fenrir.Frame`, `Fenrir.View`, `Fenrir.Draw`, `Fenrir.DrawRecord`, `Fenrir.Vertex`, `Fenrir.Normals`, `Fenrir.CubeFaces`, `Fenrir.Constants` and `Fenrir.2D`

**What to build:** the includes that declare binding sets 0, 1 and 3, the standard vertex locations and the small shared maths become Slang modules in the same directory, each the twin of its `.glsl` (ADR-0073, "Includes become modules under `Fenrir.`"). The GLSL includes stay and are kept in step until ticket 12; a change to a layout changes both. No built-in is ported here: the modules are proven by fixtures and by the renderer's debug-build layout check.

- **`Fenrir.Frame`** (`Frame.slang`): `FrameData` as a `ConstantBuffer` at `[vk::binding(0, 0)]`, and the sky, BRDF LUT, light buffer, LTC tables, spot and point shadow records and atlases at their bindings, each `public`, with the GLSL's comments carried over. **`Fenrir.View`**: `ViewData` at `(0, 1)`, the occlusion texture, shadow atlas, cluster lights, reflection hits and scene history (ADR-0056). **`Fenrir.DrawRecord`**: `DrawItem` (192 bytes), `FenrirInstance` (128), `FenrirNoCopy`, `FenrirNoIndirection`, shared by compute and vertex stages (ADR-0057). **`Fenrir.Draw`**: the four storage blocks of set 3 (draws, instances, palette, indirection), the spec constant `fenrirInstanceIndexExcludesBase` as `[vk::constant_id(61440)]`, `FenrirDrawIndex()`, `FenrirCubeInstance()`, `FenrirCubeFaceOf()` and `CurrentDraw()`, reading `SV_VulkanInstanceID` and `SV_StartInstanceLocation` (ADR-0073: never `SV_InstanceID`), with `POINT_SHADOW` as a macro and the layer written through an `out` parameter the entry point returns as `SV_RenderTargetArrayIndex`, since a module cannot write a system-value output itself. **`Fenrir.Vertex`**: the standard inputs as a `FenrirVertexInput` struct with `[vk::location]`s 0 to 5, plus 6 and 7 under `SKINNED`. **`Fenrir.Normals`**, **`Fenrir.CubeFaces`**, **`Fenrir.Constants`**, **`Fenrir.2D`**: straight ports.
- **Layout parity:** a tool test compiles a Slang stage importing each set module and the GLSL stage including each set include, and asserts equal `bindings` (set, binding, kind, name, size) and, for `ViewData`, `FrameData` and `DrawItem`, equal member offsets. The renderer's `CheckFixedSets` (debug builds) is the second check: a fixture program built from the modules makes a pipeline on the null backend with no diagnostic.
- **The palette rule (ADR-0057):** `Fenrir.Draw` declares all four storage blocks, and ticket 03's reflection keeps unused ones, so the palette stays the third storage block GL numbers; a test asserts the non-`SKINNED` variant's `fenrirVisible` is at GL point 27.
- **Where the modules live:** `packages/FenrirRenderer/Shaders/include/Fenrir/*.slang`, found through `FENRIR_SHADER_INCLUDE_DIR` as the search path, so `import Fenrir.View;` resolves for users as the include did. Each module's header comment names its `.glsl` twin and the ADRs it serves.
- **Docs:** ADR-0051 and ADR-0057 get amendment lines naming `Fenrir.Draw` and `Fenrir.DrawRecord`; `GLOSSARY.md` gains *shader module* ("one `Fenrir.<Name>` file under the engine's shader include directory, imported by `import`; the Slang form of a shader include") and marks *shader include* as its GLSL predecessor.
