# 05: generate-type-registry: the tool, the CMake module and target, and table-driven visitors for fixed-layout types, against the fixture

**What to build:** a second .NET tool beside describe-api, `tools/generate-type-registry`, that reads a package's `.api.json` and the `[registration]` table of its `.api.toml` and writes a committed C++ header and source: one `TypeDescription` per described type as static data, a table-driven visitor for every fixed-layout type, `Construct` and `Destroy`, doc text compiled in, a `Describe<T>` specialisation per type, and one registration function that adds them all to a `TypeRegistry` (ADR-0074). Run against describe-api's fixture description, it produces a header and source the FenrirTypes tests compile and exercise. Owning types, base chains and attachments are ticket 06.

- **The tool:** `tools/generate-type-registry/` with `src/` and `tests/` as describe-api has, the same `Directory.Build.props`, xunit tests; `fenrir_generate_type_registry(<target> api/<Package>.api.toml)` in `cmake/FenrirGenerateTypeRegistry.cmake` beside `FenrirDescribeApi.cmake` joins one `fenrir-generate-type-registry` target the ordinary build never runs, the shape of `fenrir-describe-api` and `fenrir-generate-bindings`.
- **`[registration]`:** `header` (a public header beside the package's headers, `include/<Package>/Generated/<Package>Types.hpp`, declaring the registration function and each `Describe<T>` specialisation), `source` (`src/Generated/<Package>Types.cpp`), `function` (`Fenrir::Generated::Register<Package>Types(TypeRegistry&)`) and `includes` (the package headers the source needs). A missing table means the package has no registration and the tool writes nothing for it.
- **What it writes:** `// Generated by tools/generate-type-registry from <Package>.api.json. Do not edit.` first; per type the description, fields and metadata as `constexpr` or static data; a table-driven visitor from the fields' offsets for every `component`, `event`, `scene-resource`, `app-resource`, `shared-struct`, `bound-type` (its components) and `nested` type; an `enum`'s enumerators; `Construct` as placement default construction and `Destroy` as the destructor; the registration function. Written only when the content changes, the same bytes on every platform, LF endings. A kind or role the tool does not know fails naming the type; `data-asset` and `settings` types fail here with "ticket 06" in the message, so the fixture's registration in this ticket is generated from a selection without them, or the tool takes a flag that skips them for this ticket alone and ticket 06 removes it.
- **FenrirTypes tests:** the fixture description's generated header and source are committed under `packages/FenrirTypes/Tests/Generated/` beside the fixture header, compiled into the test executable, and tested: register everything, find each type by name, visit a fixed-layout type and see the values the header holds, a bound type's components, an enum's enumerators, `Describe<T>` equal to the registered description.
- **Docs:** `tools/generate-type-registry/README.md` (what it reads, what it writes, how a package opts in), and a paragraph in `tools/describe-api/README.md` pointing at it.
