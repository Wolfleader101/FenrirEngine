# 01: ExtensionSet behind the NativeRegistrar seam, with its rules as Rules tests

**What to build:** the extensions' native rules leave `Scripting::InstallImpl` for an `ExtensionSet` module behind a `NativeRegistrar` seam with an Iris adapter and a fake, and the six rules become Rules tests with no fixture and no HeadlessApp (spec: "Solution").

- **`packages/FenrirScripting/src/NativeRegistrar.hpp`** (new): `Detail::NativeRegistrar` with one pure virtual, `Register(const NativeFunction& function, void* state)` returning `Iris::CallResult<void>`. Includes `FenrirScripting/ScriptingExtension.hpp`. Names nothing of Iris but `CallResult`.
- **`packages/FenrirScripting/src/ExtensionSet.{hpp,cpp}`** (new): `Detail::ExtensionSet` as the spec's listing. `static Iris::CallResult<ExtensionSet> Install(std::vector<ScriptingExtension>, NativeRegistrar&)`: first every rule over every extension with no side effect, in today's order per function (binding name non-empty, then the state check, then the duplicate check against a `name -> extension` map), with today's messages verbatim as the diagnostic and status `InvalidArgument`; then, all passed, every native of every extension in order through `registrar.Register(function, extension.m_state.get())`, a refusal returning the registrar's status with "the native function 'X' of extension 'Y' could not be registered: " + its diagnostic. The set keeps each extension's `m_state` (non-null ones) and the shared assemblies in extension order; `SharedAssemblies()` is its one accessor. `ReadableName` (the `cxxabi` demangler) and the `checkState` text move here from `Scripting.cpp`.
- **`packages/FenrirScripting/include/FenrirScripting/ScriptingExtension.hpp`**: `NativeFunction` gains `friend class Detail::IrisNativeRegistrar` (for `Register`) and `friend class Detail::ExtensionSet` (for `StateType`); `ScriptingExtension` gains `friend class Detail::ExtensionSet` (for `m_state`, `m_stateType`). Forward-declare both in `Fenrir::Detail`. No other change.
- **`packages/FenrirScripting/src/Scripting.cpp`**: `IrisNativeRegistrar` in the anonymous namespace beside the two loaders, its `Register` being `return function.Register(state);`. `State` loses `extensionStates` and gains `std::optional<Detail::ExtensionSet> extensions` (declared where `extensionStates` was; never reset by Shutdown). Stages three and four collapse into one: after `ActivateEngineContext` succeeds and `contextActive` is set, `IrisNativeRegistrar registrar; auto installed = Detail::ExtensionSet::Install(std::move(config.extensions), registrar);`, a failure becoming `StartupFailure{installed.diagnostic, {}}`, success moving the set into `state->extensions`. Stage five reads `state->extensions->SharedAssemblies()` and prefixes `bridgeDirectory` as today. `checkState`, `ReadableName`, the `<cxxabi.h>` include, `<typeindex>` and `<unordered_map>` go if nothing else uses them. The stage comments say what each stage is, as today.
- **`packages/FenrirScripting/Tests/Rules/FakeNativeRegistrar.hpp`** (new): `RulesTest::FakeNativeRegistrar`: `std::string refuse` (a binding name to refuse with `InvalidArgument` and "the fake registrar refused " + name), and `std::vector<Registered> registered` where `Registered` is `{std::string bindingName; std::string nativeName; void* state;}`, appended on every call, refused ones included.
- **`packages/FenrirScripting/Tests/Rules/ExtensionSetTests.cpp`** (new): the eleven cases in the spec's "Done looks like", tag `[extension-set]`. Natives are small functions in the test's anonymous namespace made with `NativeFunction::Make` (as `ZeroingOutputsTests.cpp` does): one stateless (`int F(const CallContext&)`), one taking a `RulesTest` state struct, one taking another. Case 10 holds a `std::weak_ptr` to a state, moves the extensions into `Install`, and checks it is alive while the set is and expired after the set is destroyed. Case 8 registers a sound extension, then one whose second native the fake refuses, and checks the recorded list still holds the first's natives.
- **`packages/FenrirScripting/Tests/CMakeLists.txt`**: `Rules/ExtensionSetTests.cpp` and `Rules/FakeNativeRegistrar.hpp` added to `FenrirScriptingRulesTests`.
- **`packages/FenrirScripting/Tests/AdmissionTests.cpp`**: the three cases "two extensions declaring one native function fail Install and name both", "a native function taking a state its extension lacks fails Install and names it" and "a native function taking a state of another type fails Install and names both types" go, with their functions. The two broken-extension cases stay. The file's header comment drops "names an extension cannot take" only if nothing left covers it (the shadowing case does; keep it).
- **`GLOSSARY.md`**: *Extension set* after *Extension state*: "Every scripting extension an Install was given, the built-in first, once its native functions have passed the naming, state and duplicate rules and been registered through the `NativeRegistrar` seam (`ExtensionSet`): it keeps the extension states alive for as long as the natives can be called and gives the contracts in extension order, so the contracts are shared only after the natives they bind are registered. *Avoid:* registry (that is the components', events', shared structs' and resources'), plugin list."
