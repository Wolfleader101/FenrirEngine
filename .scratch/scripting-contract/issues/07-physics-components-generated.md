**What to build:** candidate E for FenrirPhysics (spec: "Stage 2", "What does not change"): the hand-written C# mirrors, the twenty stand-ins, the hand mappings, the registration lists and the defaults tests are replaced by what ticket 06's tool generates from ticket 05's description. `Fenrir.Physics`'s public surface does not change.

- **Binding configuration** `packages/FenrirPhysics/Scripting/api/FenrirPhysics.binding.toml`: namespace `Fenrir.Physics`; bound types `Math::Vec3` → `System.Numerics.Vector3`, `Math::Quat` → `System.Numerics.Quaternion`, `Fenrir::Transform` → `Fenrir.Scripting.Transform`, `Fenrir::Entity` → `Fenrir.Scripting.EntityLink`; rename exceptions as needed so every public C# name stays as it is today (`hull` → `ConvexHull` in `CollisionShape`'s storage, and any others the diff below finds); `Generated/` output into `Managed/Fenrir.Physics/Generated/`, `Scripting/src/Generated/` and `Scripting/Tests/Generated/`.
- **`iris_generate_binding(FenrirPhysics ...)`** in `Scripting/CMakeLists.txt`; the generated sources join the contract's glob, the extension's library and its tests.
- **The C# contract**: `Components.cs`, `CollisionShape.cs`, `Joints.cs`, `Characters.cs`, `Vehicles.cs`, `Events.cs`, `Queries.cs` keep only behaviour as second `partial` parts: constructors (`Collider(CollisionShape)`), `IEquatable<CollisionMesh>` and its operators, the tagged unions' `Noun`, helper properties, and type-level remarks that are not the C++ doc. Every field, field initialiser, `public T() {}`, `[FieldOffset]`, `[StructLayout]`, `[NativeComponent]` and event attribute moves to the generated part. `FixedJoint`, `BallJoint` and `TrailerVehicle` lose `_unused`.
- **The extension**: every `Detail::*Layout` stand-in, every hand-written `Iris::StructMapping` and the `extension.components`/`events` lists go from `PhysicsScripting.cpp`; the generated mapping and registration sources replace them; `extension.sharedStructs` is the generated list (new: today nothing validates these). `EngineMappings.hpp`'s `EntityLinkView` is no longer referenced by physics (ticket 09 removes it).
- **Tests**: the generated defaults test replaces the hand-written defaults cases (Joint at `PhysicsScriptingTests.cpp:936`, CharacterBody `:1681`, Vehicle `:2039`, wheel/differential/anti-roll bar `:2074`, RigidBody `:176`) and the tests' twelve `Same()` copies (the engine's `Same()` overloads in `src/Same.hpp` and `VehicleSettings.hpp` stay; the duplicate `Same(JointSpring)` goes). The existing `ValidateStruct` cases for query mirrors go: the load-time shared-struct check covers them.
- **Public API diff**: build the pre-ticket `Fenrir.Physics.dll` and the new one and diff their public surfaces (e.g. with `Microsoft.DotNet.ApiCompat` or a reflection dump committed to the PR); the only differences allowed are the three removed private fields. Record the diff in the PR.
- `Scripting/CMakeLists.txt`'s and `README.md`'s comments describe the generated layout and how to regenerate.

Points for review:
- **The query types are bound from a description of their own.** C++'s `QueryFilter`, hits and `Contact` hold a 16-byte `Entity` and C#'s a 32-bit `Entity` (ticket 05's open point), so binding them from FenrirPhysics's description would have changed the public API. `Scripting/src/ScriptQueries.hpp` declares them as C# holds them (`EntityValue` for each entity, C#'s docs as comments), `Scripting/api/FenrirPhysicsScripting.api.toml` selects them, `fenrir_describe_api(FenrirPhysicsScripting ...)` describes them, and the binding `exclude`s FenrirPhysics's seven. The natives convert as before, now between `Fenrir::X` and `ScriptQueries::X`; `Bounds` writes `Math::AABB` directly. They are shared structs, so the load checks them and the defaults test covers them. Ticket 08 can map native pointer parameters to these types by name.
- **Iris.Bindings gained what the contract needed to stay as it was** (outside the Touches line, with eight tests and its README; Iris's "Changes" lists it): `exclude`; `[csharp] readonly-structs` (`CharacterState`, `VehicleState`, `VehicleWheelState` as `readonly struct`s, and the fields holding them `readonly`, which the CompileFail cases need); a bound type's `default` (`EntityLink.None`, since C#'s `new EntityLink()` is entity 0, not C++'s empty `Entity`); integral bound-type components written as integers (`new(4294967295)` for the ignored body); and a constructor and initialisers only where some default is not all zero bytes, or the mirror is read-only. Without the last, `CollisionMesh`, the shapes' handles, `VehicleTyre`, `Aabb`, the hits and the empty kinds would each have gained a `public T()`; with it alone, `VehicleState` would have lost one. The fixture's `Marker` lost its constructor, `Limits` became read-only, and `Handle` names its own default.
- **The API diff is not only `_unused`.** A reflection dump (every type, attribute, layout, field with offset and modifiers, public member, and `new T()`'s value) of the pre-ticket and new `Fenrir.Physics.dll` differs in the three removed `_unused` fields and in a `public T()` on `ContactBegin`, `ContactEnd`, `TriggerEnter`, `TriggerExit` and `JointBroken`. Their C++ defaults are empty entities, so the generated defaults test needs C#'s `new()` to hold `EntityLink.None`, which field initialisers and so a constructor give; `new ContactBegin()` used to hold entity-0 links. Additions only, so scripts compiled against the old contract still bind. No name, order, offset, `readonly` or other default changed.
- **The ticket's bound types were adjusted to the code:** `Math::Vec3` and `Math::Quat` bind to `Fenrir.Scripting.Vector3` and `Quaternion` (what the contract has used all along, not `System.Numerics`); `Quaternion`'s constructor is `[x, y, z, w]`. No `[names]` exception but `Math::AABB` = `Aabb` was needed: `_convexHull` comes from the tag (ticket 06).
- **The generated docs are the C++ ones,** with C++ spelling (`collider.shape.As<BoxShape>()`, `RigidBody::interpolate`); C#-only guidance (views throw, `new` against `default`, `Ref<T>`) is in the hand-written parts' `<remarks>`. The registration lists are in description order (alphabetical), not the old hand order.
- **Left as they were:** the drifted stand-ins of the load-failure tests now hold `Entity` (mapped through `BoundMappings.hpp`); the fixture's `AddNewJoint`, `AddNewCharacter`, `AddNewVehicle`, `AddNewWheel`, `AddNewDifferential` and `AddNewAntiRollBar` are no longer called, since the fixture scripts are not to be edited. There is no `packages/FenrirPhysics/README.md`; the root README and `Scripting/CMakeLists.txt` describe the generated layout and how to regenerate, and FenrirScripting's README no longer says physics maps through stand-ins.
