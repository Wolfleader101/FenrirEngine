# 08: Physics natives spelled once

**What to build:** the native-function half of candidates E and H (spec: "Native functions spelled once"): a native is written once, as its C++ function; its C# declaration and its registration are generated.

- **`tools/describe-api --natives`**: a second mode reading an extension's C++ sources (configured in a `natives` section of the binding configuration, since natives are binding glue, not the neutral description) and writing `packages/<Package>/Scripting/api/<Package>.natives.json`: every free function whose first parameter is `const CallContext&`, with its name, whether its second parameter is the extension's state, and each remaining parameter's C++ type and name, plus the return type and the function's doc comment. Functions are written in source order of one configured list of files, so the registration order is deterministic.
- **The Iris tool** reads it and emits: the C# `static partial class <Native>` (`PhysicsNative`) declarations, `[NativeFunction] public static partial R Name(...)` with the leading context and state dropped and the C++ parameter types mapped as the hand-written declarations are today (`std::uint32_t entity` → `Entity`, `const T*` → `in T`, `T*` output → `out T` when the C++ doc marks it an output and `T*` plus a count otherwise, `std::int32_t`/`float`/`bool`/`std::uint64_t` as themselves, `const char*` + length → `string`); and the C++ `extension.functions = { NativeFunction::Make<&F>("Namespace.Native.F"), ... }` list in the registration source. A C++ type it cannot map fails naming the function and parameter.
- **FenrirPhysicsScripting**: `CreateMesh` → `CreateCollisionMesh`, `ReleaseMesh` → `ReleaseCollisionMesh`, `FrameFromWorldNative` → `FrameFromWorld` (in a namespace that does not clash with FenrirPhysics's free function), so every native is named as C# calls it; the hand-written `extension.functions` list goes; `PhysicsNative`'s 23 hand-written declarations go from `PhysicsWorld.cs`, which keeps the friendly wrappers, now without the nine `filter ?? new QueryFilter()` lines (a `QueryFilter` default parameter of `default` and a `QueryFilter` whose `default` means "everything").
- **Test**: the natives test from ticket 03 (every output zeroed with no world) is generated from the natives file, one case per native with an output.
- **Build and CI**: the natives mode runs under `fenrir-describe-api`; the clean-tree check covers the natives file.

Points for review:
- **Entity parameters are told apart by type, not name.** The natives take `ScriptQueries::EntityId` (an alias of `std::uint32_t` in `ScriptQueries.hpp`), which `[natives] types` maps to C#'s `Entity`; a plain `std::uint32_t` (`SetDebugDraw`'s categories) stays `uint`. The description keeps an alias outside `std` and the global namespace and spells every other number by its kind, so it is the same on Windows and Linux.
- **A pointer followed by a `std::int32_t` count is a span, const or not.** The ticket's `const T*` → `in T` would have made `CreateCollisionMesh`'s `const Vec3* vertices` an `in Vector3`; `const T*` is `in T` only when no count follows. `const char*` with a count is a `string`.
- **The generated registration declares the natives**, so they leave the anonymous namespace for `Fenrir::PhysicsNatives` (where `FrameFromWorld` calls FenrirPhysics's as `Fenrir::FrameFromWorld`), and the state moves to `src/PhysicsScriptingState.hpp` (`NativeFunction::Make` needs it complete). A native with internal linkage fails describe-api; `ToFilter` takes the `EntityList` now, so it is not a native by shape. A declaration that drifted from its definition would fail to link.
- **Warnings derive the native's name** from `std::source_location::function_name()` (`PhysicsScripting::NativeName`), so `WorldOf` and `HasBody` no longer take it and no name is spelled in a warning string. The messages are as before.
- **`default(QueryFilter)` means "everything" at the native**: `ToFilter` treats an all-zero filter (mask 0, which as written finds nothing) as the new filter, as `ScriptQueries.hpp` and so the generated `QueryFilter` docs say. The nine wrappers take `QueryFilter filter = default`. Public API diff: only those nine parameters, from `QueryFilter? filter = null`; `PhysicsNative`'s internal signatures are unchanged. A script that passed `null` explicitly no longer compiles (none in the repository does).
- **The natives test calls each native with every input zero or null**, not ticket 03's dead entity `0x00ABCDEF`: every native with an output returns on a null pointer or no world before it reads an entity.
- **Iris's fixture** binds the describe-api fixture's natives (`Fixture.natives.json` copied, like `Fixture.api.json`). Its natives class has no bodies without the SDK's generator, so only the SDK check compiles it; its natives test, like its registration, is never compiled. The tests cover every parameter form, a native added with an output, and four unmappable cases (a struct by value, an undescribed pointee, a non-const pointer that is neither output nor span, a pointer result).
