# 09: The built-in extension on the same tooling

**What to build:** the engine's own scripting API described and generated like physics (spec: "Scope"; ADR-0009: the core and a package's extension are two users of one seam), so no hand mapping or hand-registered native remains anywhere.

- **API descriptions** for the packages that own the engine's shared types: `packages/FenrirECS/api/FenrirECS.api.toml` (`Name`, `Relationship` as components, `Relationship` read-only; `Entity` as a struct with a pointer member) and `packages/FenrirMath/api/FenrirMath.api.toml` (`Transform` as a component, `Vec3` and `Quat` as bound types), each with `fenrir_describe_api` in its package. If `Transform` lives elsewhere, the description goes with the package that defines it.
- **Binding configuration** `packages/FenrirScripting/api/FenrirScripting.binding.toml`: namespace `Fenrir.Scripting`, the renames `pos` → `Position`, `rot` → `Rotation`, `scale` → `Scale`, `Entity` → `EntityLink` with its fields `value`/`Value`, `reserved`, `owner`/`Owner`; `Vec3`/`Quat` bound to `System.Numerics`; natives from `src/Bindings.cpp`.
- **Generated**: `Fenrir.Scripting`'s `Transform`, `Name`, `Relationship` and `EntityLink` mirrors as partials (hand-written parts keep their behaviour: `EntityLink`'s helpers, `Name`'s text accessors); the Iris mappings replacing `EngineMappings.hpp` (`EntityLinkView` goes: `Entity` maps directly through the pointer kind of ticket 01); `EngineComponents()` replaced by the generated registration source; the 24 natives' C# declarations in the contract's `Native` class and their registration list generated from `Bindings.cpp` by the natives mode, so `BuiltInExtension`'s hand-written list goes.
- **Tests**: the generated defaults test for the engine components and the zeroing test for its natives join FenrirScripting's tests; hand-written cases they duplicate go.
- `packages/FenrirScripting/README.md` describes the built-in extension as generated and points at ADR-0016; `Fenrir.Scripting`'s public surface is diffed as physics's was, with no difference allowed.

**Blocked by:** 02 (state), 06 (generator), 08 (natives mode).

**Touches:** `packages/FenrirECS/api/`, `packages/FenrirECS/CMakeLists.txt`, `packages/FenrirMath/api/`, `packages/FenrirMath/CMakeLists.txt`, `packages/FenrirScripting/api/`, `packages/FenrirScripting/CMakeLists.txt`, `packages/FenrirScripting/include/FenrirScripting/EngineMappings.hpp`, `packages/FenrirScripting/src/Bindings.cpp`, `packages/FenrirScripting/src/`, `packages/FenrirScripting/Managed/Fenrir.Scripting/`, `packages/FenrirScripting/Tests/`, `packages/FenrirScripting/README.md`.

Points for review:
- **The public API diff is not empty.** `Transform`, `Relationship` and `EntityLink` each gain a `public T()`, and `new T()` now holds C++'s defaults: an identity rotation and unit scale, and empty links (`EntityLink.None`). The ticket asks both for no difference and for the generated defaults test to cover these types, and the test needs `new T()` to equal C++'s `T{}`, so both cannot hold. `default(T)` is unchanged, and these are additions, so compiled scripts still bind; ticket 07 took the same change for physics's events. `EntityLink` also loses its private `reserved` field: C++'s `Entity` has padding there, not a member, so nothing describes it, and the layout (16 bytes, owner at 8) is unchanged. `Name`'s `Capacity` constant is unchanged but now follows `Text` in metadata order.
- **The two tools gained what the built-in types needed** (outside the Touches line, with tests and docs): describe-api's `private-members` (Name's buffer and Entity's members are private), an enum with no enumerators recorded as its integer with any constant default (`entt::entity` and `entt::null`), a plain `char` as `u8` on every target, a second parse that instantiates a selected but uninstantiated template (glm's `qua`, which nothing in FenrirMath's header instantiates), and in natives mode `@param[in,out]` and `@notrunning <expression>`. Iris.Bindings' `registered-namespace` (the components stay `Fenrir.Transform` while their C# types are `Fenrir.Scripting.*`), `[csharp] private-fields` and `fixed-buffers` (EntityLink's private fields, Name's `fixed byte Text[256]`), `void*` parameters and results, `[in,out]` pointers as `T*`, and the `@notrunning` value as `Make`'s second argument. Both fixtures cover each.
- **`Vec3` and `Quat` bind to the contract's `Vector3` and `Quaternion`, not `System.Numerics`**, as in ticket 07; they are mapped by hand in `include/FenrirScripting/BoundMappings.hpp` (by `offsetof`, so no `IRIS_FIELD`), as physics maps its bound types. No `scale` rename is configured: PascalCase gives `Scale`. The ticket's `reserved` is not a C++ member, so it has no rename (above).
- **`Native`'s internal signatures follow the natives mode**: the seven text parameters are `string`s (the SDK's generator does the UTF-8 that `Log`, `ComponentIds`, `EventIds`, `ScriptComponents` and `ScriptEvents` did by hand), `uint value` replaces `uint entity` where C++ names it so, and the methods are in source order. The `uintptr_t` addresses go through an alias, `Detail::NativeAddress`, mapped to `nuint`. `EntityWorldTransform` now writes the default `Transform` before it returns false, which C# never saw (it throws then).
- **The registration is in description order** (Name, Relationship, Transform, as physics's is alphabetical), so the engine components' registry ids change order. Nothing depended on it.
- **Outside the Touches line:** `tools/describe-api/`, `packages/Iris/` (Iris.Bindings, its README and "Changes", `docs/`), FenrirECS's `DefaultComponents.hpp` and `Entity.hpp` (doc comments only, which the C# mirrors now carry; FenrirPhysics's description picks up `Transform`'s), physics's `Scripting/src/BoundMappings.hpp`, the DemoApp's `ScriptingDemo.hpp` (one include) and the root README.
