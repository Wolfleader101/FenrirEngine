# How do engines serialise scenes and prefabs?

Type: research
Status: resolved
Blocked by: none

## Question

How do engines write a scene (a tree of entities or nodes with their components, and the scene's own settings) to a file, and how do they make part of a scene reusable, in the areas that constrain Fenrir's scene file: Godot's `.tscn`/`PackedScene` (inherited scenes, instanced scenes, editable children), Unity's YAML scenes and prefabs (nested prefabs, prefab variants, overrides, `fileID`/`guid` references), Unreal's levels (actors, Blueprints as prefabs, Level Instances and Packed Level Actors, World Partition's one-file-per-actor), Source's `.vmf` and Source 2's `.vmap` (entities, instances, prefabs, visgroups), Bevy's `DynamicScene` and the BSN scene format work, and an ECS-first format such as Flecs's or EnTT's snapshots.

- **Entity identity in the file:** how an entity is named so references to it survive editing and reload (sequential ids, GUIDs, paths), and how a component's reference to another entity (a joint's two bodies, a skinned mesh's skeleton) is written.
- **Component data:** how a component's fields are written, how a type the engine no longer knows is kept or dropped, and how script components sit beside native ones.
- **Hierarchy and ordering:** how parent-child is encoded and whether sibling order is meaningful.
- **Scene-level state:** environment, sky, physics settings, what Fenrir calls scene resources.
- **Prefabs:** how an instance names its source, what an override is (per-field, per-component, added or removed children), how nesting and variants work, how changes to the source propagate, and how a prefab is "unpacked".
- **Composition and additive loading:** scenes inside scenes, several scenes loaded at once, streaming cells.
- **Merge-friendliness:** what each format does for diffs and version-control merges (stable ordering, one-entity-per-file, smart merge tools).

Write findings to a Markdown file on the `research/engine-scene-files` branch (`.scratch/fenrir-serialisation/research/engine-scene-files.md`), citing each claim's source and pinning the versions read, and link it here.

## Answer

Findings: `.scratch/fenrir-serialisation/research/engine-scene-files.md` on branch `research/engine-scene-files` (commit `7a00ec14`), against Godot 4.7 docs and master (`packed_scene`, `resource_format_text`, `resource_uid`, PRs #50786, #50676, #60597, #106837), Unity 6000.0 manual and script reference (with 2022.x editions for diffing, Addressables 2.7.6, Entities 1.3.15), Unreal 5.9 docs and 5.4/5.5 release notes (engine source not read), the Valve Developer Community and `source-sdk-2013` master (`vbsp/map.cpp`, `map_shared.cpp`, fgdlib, `mapentities`), Bevy 0.16.1 source with the 0.19 and 0.20 release notes and migration guide, Flecs master (about v4.2.0) and EnTT 3.15 and 4.0. Bevy renamed `bevy_scene` to `bevy_world_serialization` in 0.19 (June 2026) and the new `bevy_scene` is BSN; Godot 4.6 (October 2025) added `unique_id` node ids.

- **Entity identity:** every authoring format uses a file-level id distinct from the runtime handle plus a remap on load. Godot: name paths (`parent="A/B"`), with 4.6 adding `unique_id=N` on node headers as a rename-proof fallback; node references are relative `NodePath`s; resource references are `ext_resource` string ids plus `uid://` with a path fallback. Unity: an arbitrary per-file `fileID` for in-file references and a `.meta` GUID plus type for cross-file ones; cross-scene references cannot be saved. Unreal: the object path plus an `ActorGuid` that keys World Partition's descriptors and one-file-per-actor files; renames leave redirectors. Source: an integer `id` per object plus non-unique `targetname` strings resolved at fire time. Flecs: dot paths. Bevy's `DynamicScene` and EnTT's snapshots write raw entity bits and remap on load (Bevy through `#[entities]` fields that derive `map_entities`, EnTT through a hand-written `loader.map()` per member) and are documented as same-process formats, not for serialisation between runs.
- **Component data:** Godot and Unreal write only non-default values (Godot by comparing against defaults; Unreal skips tagged properties unchanged from the post-constructor default, updating instances whose value equals an old default); Unity, Bevy and Flecs write every field. Unknown types: Godot 4 keeps them as `MissingNode` and `MissingResource` placeholders re-saved as the original class; Unity preserves `SerializeReference` payloads whose type is gone and documents nothing for missing MonoBehaviours; Unreal drops removed properties silently and relies on CoreRedirects for renames; Source keeps every keyvalue verbatim; Bevy and strict Flecs refuse to load. Scripts sit beside native data as a reference property (`script = ExtResource(...)`, `m_Script: {fileID, guid}`, a `vscripts` keyvalue) with exported variables as ordinary fields.
- **Hierarchy and ordering:** Godot writes `parent=` paths, parents first; sibling order is file order and meaningful (`_process` runs in tree order). Unity keeps `Transform.m_Father` plus an ordered `m_Children` list and a `SceneRoots` list at the file's end (which replaced `m_RootOrder` around 2022.2). Unreal keeps actors flat in the level and the component tree through `AttachParent`, with no documented actor order and editor-only folders. Source is flat; `parentname` is runtime attachment and visgroups are editor-only. Bevy 0.16 treats `ChildOf` as the source of truth but writes and restores the ordered `Children` list with hooks skipped. Flecs leaves order unspecified unless `OrderedChildren`; EnTT has none.
- **Scene-level state:** Godot has no scene-wide block (environment is a `WorldEnvironment` node, physics is project-level). Unity opens each scene with object-less `OcclusionCullingSettings`, `RenderSettings`, `LightmapSettings` and `NavMeshSettings` at fixed ids 1 to 4; the active scene wins when several are loaded; baked lighting is a separate asset. Unreal has a per-level `AWorldSettings` actor, a Level Blueprint and a `MapBuildDataRegistry`. Source uses `worldspawn` keyvalues plus the first `light_environment` and `sky_camera`. Bevy writes a `resources` map keyed by type path, applied after entities and mapped with `ReflectMapEntities`: the closest analogue to Fenrir's scene resources. Flecs includes singletons; EnTT's context is not covered by snapshots.
- **Prefabs:** three shapes. *Diff against source:* Godot's instance node stores only overridden properties (`instance=ExtResource(...)`, `[editable path=...]` for editable children; an inherited scene is a root with `instance=`; base nodes cannot be removed or reordered; "Make Local" unpacks). Unity's `PrefabInstance` names its source and lists `m_Modifications` per property path plus removed components and (2022.2+) removed and added objects, with stripped placeholder documents; a variant is a prefab whose root is a `PrefabInstance`; unpack one level or completely. Unreal's Blueprint class is the prefab and instances are archetype deltas; Level Instances edit in context with "Break" to unpack, Packed Level Actors bake to one actor, and their property overrides are editor-only and barely documented. *Copy and fix up:* Source 1's `func_instance` is a file reference collapsed by VBSP with name prefixes and literal `$variable` substitution; Hammer prefabs are plain copies with no link; Source 2's `.vmap` prefabs are live-linked with a single per-instance override kind and "Collapse" to unpack. *Live inheritance:* Flecs's `(IsA, prefab)`, where an override is an owned copy masking the shared component and removing it re-exposes the prefab's value, prefab-of-prefab for variants. Bevy shipped no prefab layer until BSN landed in 0.19 as code-only patches, with the `.bsn` loader still unshipped at 0.20 and a default-diffing writer in draft. EnTT has none.
- **Composition and additive loading:** universal and simple: Godot `instantiate()` plus `add_child()` with a threaded loader; Unity `LoadSceneMode.Additive`, `MergeScenes` and multi-scene editing; Unreal's persistent level plus sublevels; Bevy's many `SceneRoot`s, each with an `InstanceId` and entity map that hot reload rewrites through; Flecs merges by path; EnTT's `continuous_loader` merges snapshots. Only Unreal ships streaming cells (World Partition's grid, Data Layers, HLOD, Level Instances embedded into cells); Godot explicitly does not (four open proposals; only `InstancePlaceholder`); Unity leaves it to Addressables and DOTS subscenes; Source 1 is one BSP per level with a 512-entity carry-over.
- **Merge-friendliness:** text plus stable ids plus a fixed order plus a semantic merge driver is the state of the art. Godot moved to random string ids in 4.0 "to minimize conflicts when merging" and removed `load_steps` in 4.6 as a frequent source of conflicts; UID churn and duplicates are its live pain. Unity defaults to text, uses one-line inline mappings to cut noise, and ships `UnityYAMLMerge` with rules keying arrays on `fileID` and property path with float epsilons. Unreal gave up on text: binary assets, editor file locks, one-file-per-actor precisely so actors are separate files, and a Blueprint diff tool. Source rewrites the whole VMF on save with a `.vmx` backup; Source 2's `.vmap` is binary DMX with "Save Copy As Text". Bevy's RON keys are allocation-dependent entity bits so re-saves churn; Flecs's JSON by path is id-independent.
- **For Fenrir:** Bevy's `#[entities]` field attribute is the closest precedent for marking `Entity` fields in the API description for remapping, and writing only non-default fields is cheap because the description already carries defaults. Not confirmed: Unreal's one-file-per-actor path scheme and the release that added Level Instance overrides; Unity's handling of missing MonoBehaviours; the version and rationale of Unity's `SceneRoots` change.
