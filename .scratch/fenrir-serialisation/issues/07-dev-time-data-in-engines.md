# How do engines hold dev-time data: project settings, import sidecars and per-developer overrides?

Type: research
Status: resolved
Blocked by: none

## Question

How do engines store the data the development workflow needs that is not game content, in the areas that constrain Fenrir's dev-time data: Godot's `project.godot`, `override.cfg` and `.import` sidecars with `.godot/imported/`; Unity's `ProjectSettings/`, `.meta` files with importer settings and GUIDs, `UserSettings/` and `Library/`; Unreal's `Config/*.ini` hierarchy (Base, Default, platform, Saved, per-user) and import options stored on the asset; Bevy's and Flax's equivalents.

- **Project settings:** what is a project setting versus a scene's or an asset's (window, rendering options, physics defaults, input bindings, package configuration such as what Fenrir's `Install(App&, Config)` takes), how settings are layered (defaults, project, platform, user), and how the shipped game reads them.
- **Import sidecars:** what sits beside a source asset (scale and axes for a model, which sub-assets to keep, texture compression, sampler defaults), whether the sidecar is the asset's identity (Unity's `.meta` GUID) or only its options (Godot), what happens when the sidecar is missing or the source moves, and where imported results are cached.
- **Per-developer overrides:** local window positions and last-opened scene aside (editor state, out of scope), what dev-only overrides exist (local asset roots, debug flags, device selection), where they live, and how they stay out of version control.
- **Shipping:** which of these files ship, which are baked into the executable or a pack, and which exist only in development.

Write findings to a Markdown file on the `research/dev-time-data` branch (`.scratch/fenrir-serialisation/research/dev-time-data.md`), citing each claim's source and pinning the versions read, and link it here.

## Answer

Findings: `.scratch/fenrir-serialisation/research/dev-time-data.md` on branch `research/dev-time-data` (commit `2d1b62fe`), against Godot 4.7 docs and master `e6e2a874`, Unity 6000.6, Unreal 5.9 docs and the 5.8 Python API (several C++ API and packaging pages render empty to a fetch and are listed as unread), Bevy 0.20.1 with wgpu-types 30.0.1, and Flax docs `401d5cf` with engine master `24fdd2c6`. Its section 5 reads the findings against Fenrir's `Install` configs for [What dev-time data does the engine hold?](18-dev-time-data.md).

- **Two families:** Godot, Unity, Unreal and Flax have a project file plus an editor-edited, game-read settings store; Bevy has neither: settings are plugin structs overridden by environment variables (`BEVY_ASSET_ROOT`, `WGPU_BACKEND`, `RUST_LOG`) and Cargo features. Fenrir today is in Bevy's family.
- **Project versus scene draws the same line everywhere:** window, rendering backend and quality, physics defaults, input map, layer and tag names, first scene, product identity and packaging are project settings; scenes hold instances. Project settings legitimately reference data assets rather than inline them (Unity's render pipeline assets, Flax's `GameSettings.json` naming `Time`, `Physics` and `Input` JSON assets by GUID plus a custom-settings dictionary, Unreal's Interchange pipelines).
- **Layering:** Unreal has twelve ordered `.ini` layers (base, project default, platform, three user locations) plus command-line overrides; Godot goes C++ `GLOBAL_DEF` defaults, `project.godot`, feature-tag suffixes (`key.debug`), `override.cfg` (also loaded from an exported executable's directory), a settings-override path, then the command line; Unity has project settings, per-platform player tabs and committed build-profile overrides; Flax has one JSON asset per area plus per-platform assets and no user layer; Bevy is code, environment, features.
- **Shipped form:** Godot converts `project.godot` to a binary `project.binary` in the pack; Unreal stages the merged `.ini` files into the pak minus key and section denylists; Unity bakes into `globalgamemanagers`; Flax cooks its JSON settings assets to LZ4 chunks in `.flaxpac`; Bevy compiles everything in. Runtime-writable settings go to a user directory everywhere.
- **Sidecar identity splits three ways:** Unity's `.meta` is the asset's identity (GUID) and all its import settings, moved by the editor, and a lost `.meta` breaks every reference; Godot's `.import` holds `[remap]` (importer, type, `uid`, output paths), `[deps]` and `[params]`, with a `uid` deterministic from project name, lowercased path and file MD5, renamed with the file; Bevy's `.meta` is RON holding loader and settings with no identity field, identity being the asset path. Unreal and Flax have no sidecar: Unreal stores import data on the asset and relies on redirectors on move; Flax stores the import path, user and options in the `.flax` file's editor-only metadata, identity being the GUID in its header.
- **Missing sidecar:** Unity generates a new `.meta` as if the asset were new (new GUID); Godot reimports with the importer's defaults overlaid by the project's importer defaults (new uid); Bevy uses the default meta and, in processed mode, writes default `.meta` files back into the source folder; Flax logs and uses defaults.
- **Caches:** Godot `.godot/imported/<name>-<md5>.<ext>` plus a `.md5` sidecar, reimporting on source hash, importer version, moved source or missing outputs; Unity's `Library/` (a source database keyed by content hash and GUID, an artifact database with dependencies and platform), regenerable and shareable; Bevy's `imported_assets/Default` with hashes in the processed meta and a write-ahead log; Unreal's disposable DDC, local Zen store, shared through a path; Flax has no import cache (the import is the asset). All five name one ignored directory, and Godot writes its own `.gitignore`.
- **Sampler defaults** are the one import option engines disagree on: in the sidecar for Unity and Bevy, on the texture asset for Unreal, not at import for Godot (a material or shader hint with a project default) or Flax.
- **Per-developer overrides:** Unity's `UserSettings/` and `Library/EditorUserBuildSettings.asset`, excluded from version control; Unreal's `Saved/` and the user `.ini` layers (two outside the project, one inside the committed `Config/`); Godot's `override.cfg`, per-user editor settings holding tool paths, and uncommitted export credentials beside committed presets; Flax's editor options in the user's cache folder with a documented `.gitignore`; Bevy's environment and Cargo config. Device and backend selection is command line or environment in every engine, never a committed setting. An asset-root override exists only as Bevy's `BEVY_ASSET_ROOT` chain and Godot's whole-project `--path`; Unity, Unreal and Flax fix the root. Debug flags are build configurations everywhere.
- **What ships versus stays:** Godot ships `project.binary`, `.import` files cut to `[remap]`, the imported outputs and remap files, never `project.godot`, `[deps]`, `[params]`, `.godot/` or presets; Unity ships `globalgamemanagers`, level and shared asset files and `StreamingAssets` verbatim, never `.meta`, `ProjectSettings/`, `Library/` or `UserSettings/`; Unreal ships cooked assets in paks plus the merged denylisted `.ini` files; Flax ships `.flaxpac` chunks and drops import metadata and dependencies on cook; Bevy ships the executable plus `assets/` including the `.meta` files, read per load unless disabled.
- **For Fenrir:** `RendererConfig`, `PhysicsConfig` and `AssetsConfig` are the same shape as every settings store read (flat scalars, enums, strings and asset references), so they can come from a file without type changes; what engines keep out of such files is host-specific state and code-only wiring (`ScriptingConfig::extensions`). Flax is the model for settings as data assets in all but role (typed assets referenced by id from one root file, loaded and cooked by the normal pipeline); Godot is the model for plain config with its own reader and a binary twin for shipping. `ScriptingConfig`'s doc comment already names a `.feproj` file that nothing reads, so the name is pre-empted. Not verified: Unreal's device-profile override and denylist defaults, Godot's custom project-setting keys, Flax's `Settings<T>` template name.
