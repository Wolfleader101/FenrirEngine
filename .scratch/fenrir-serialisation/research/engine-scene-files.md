## Summary

- Every engine that has a text scene format names an entity by something more stable than its runtime handle: Godot by name-path (plus, since 4.6, a per-node integer id as fallback), Unity by a per-file `fileID` plus the `.meta` GUID for cross-file, Unreal by object path plus an `ActorGuid`, Source by an editor `id` plus a `targetname` string, Flecs by dot-path. Bevy's `DynamicScene` (now `DynamicWorld`) and EnTT snapshots are the exceptions: they write raw entity bits and remap on load, and both are documented as "same-process" formats, not authoring formats.
- Every engine with an authoring format stores either *only non-default values* (Godot, Unreal) or *every serialised field* (Unity, Bevy, Flecs); the first makes files short and prefab diffs natural, the second makes them robust to default changes. Unknown types are kept as placeholders (Godot 4 `MissingNode`/`MissingResource`), kept as inert data (Unity's SerializeReference, Source keyvalues) or dropped with a rename table (Unreal CoreRedirects); Bevy and Flecs-strict refuse the file.
- Prefabs come in two shapes. **Diff-against-source** (Godot instanced/inherited scenes, Unity `PrefabInstance` + `m_Modifications`, Unreal Blueprint instances vs class defaults): the file stores the source reference plus per-property overrides, added children/components, and (Unity 2022.2+, never Godot) removals; propagation happens at load because the file holds only the diff. **Copy-and-fix-up** (Source 1 `func_instance`, Hammer prefabs): the instance is a file reference collapsed at compile time with name prefixing and `$variable` substitution; no per-property overrides. Flecs is a third shape: live `IsA` inheritance where an override is an owned copy masking the shared component.
- Additive loading is universal and simple (add a loaded tree under a node / `LoadSceneMode.Additive` / sublevels); only Unreal ships streaming cells (World Partition), and Godot explicitly does not (open proposals).
- For merges: text + stable ids + fixed ordering (Unity "Force Text", Godot's string ids and the 4.6 removal of `load_steps`) plus a semantic merge driver (Unity's `UnityYAMLMerge` keyed on `fileID`) is the state of the art; Unreal gave up on text and went to one file per actor instead.

## 1. Entity identity in the file

### Godot
- A node is identified by **name plus path**: `[node name="X" type="T" parent="A/B"]`; `parent="."` is a child of the root, the root has no `parent=`; sibling names must be unique and `. : @ / " %` are replaced by `_`. [TSCN file format, 4.7 docs](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html); [Node, 4.7](https://docs.godotengine.org/en/stable/classes/class_node.html).
- **4.6 adds `unique_id=N`** (int32) to node headers. PR #106837 "Add unique Node IDs to support base and instantiated scene refactorings" (reduz, merged 2025-10-06, milestone 4.6): "These IDs act as a fallback to names when saving"; "If a scene renames or moves a node, inherited or instantiated scenes will no longer lose reference to it"; "USED AS A FALLBACK ... should not break any current existing scene". The writer (`ResourceFormatSaverTextInstance::_parse_nodes`, master) appends `name`, `type`, `parent` (+`parent_id_path`), `owner` (+`owner_uid_path`), `index`, `unique_id`, `node_paths`, `groups`, then `instance_placeholder`/`instance`. [PR #106837](https://github.com/godotengine/godot/pull/106837); [resource_format_text.cpp, master](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/resource_format_text.cpp); [Upgrading to 4.6](https://docs.godotengine.org/en/stable/tutorials/migrating/upgrading_to_godot_4.6.html). `SceneState::_instantiate` has an `_find_node_by_id` recovery path that warns "Please re-save this scene". [packed_scene.cpp, master](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.cpp).
- **`owner` decides membership**: `PackedScene.pack` saves "the node as well as all the nodes it owns"; nodes without an owner "won't be saved". [PackedScene, 4.7](https://docs.godotengine.org/en/stable/classes/class_packedscene.html).
- **Node-to-node references are relative `NodePath`s**: Joint3D `node_a`/`node_b`, MeshInstance3D `skeleton` are written `node_a = NodePath("../BodyA")`. Exported `Node` *object* references are also stored as paths, flagged `FLAG_PATH_PROPERTY_IS_NODE` and listed in `node_paths=`, then resolved after instantiation ("Replace properties stored as NodePaths with actual Nodes"). [Joint3D, 4.7](https://docs.godotengine.org/en/stable/classes/class_joint3d.html); [MeshInstance3D, 4.7](https://docs.godotengine.org/en/stable/classes/class_meshinstance3d.html); [packed_scene.h, master](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.h). `%Name` (scene-unique names) resolve only within the owning scene; `unique_name_in_owner = true` is a stored property. [Scene unique nodes, 4.7](https://docs.godotengine.org/en/stable/tutorials/scripting/scene_unique_nodes.html).
- **Resource references**: `[ext_resource type="Texture2D" uid="uid://dapwmgsmnl28u" path="res://x.tres" id="2_eorut"]` and `[sub_resource type="CapsuleShape3D" id="CapsuleShape3D_fdxgg"]`, used as `ExtResource("2_eorut")`/`SubResource("...")`. Ext ids are `<index>_<5 random chars>`, sub ids `<Class>_<5 chars>` (`Resource::generate_scene_unique_id`). On load the loader tries `ResourceUID::get_id_path(uid)` first and falls back to `path=` with a warning. [TSCN docs](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html); [resource.cpp, master](https://raw.githubusercontent.com/godotengine/godot/master/core/io/resource.cpp).
- **`uid://`** came in PR #50786 "Implement Resource UIDs" (reduz, merged 2021-07-24, 4.0): 64-bit ids in base-35 text, stored in headers, ext_resource lines and `.import` files; "UID always has priority"; purpose is to "keep references between resources intact ... even if files are renamed or moved"; cached in `.godot/uid_cache.bin`. [PR #50786](https://github.com/godotengine/godot/pull/50786); [ResourceUID, 4.7](https://docs.godotengine.org/en/stable/classes/class_resourceuid.html). **4.4** added `.uid` sidecars for scripts and shaders (headerless text files that cannot carry a uid); commit them, move them with the file. [UID changes coming to Godot 4.4, 2025-01-15](https://godotengine.org/article/uid-changes-coming-to-godot-4-4/).

### Unity
- Each Object (GameObject, Component, settings object) is its own YAML document `--- !u!<classID> &<fileID>`; "The number following the ampersand is an object ID number unique within the file, although the number is assigned to each object arbitrarily." In-file references are `{fileID: 6}`. [Format description, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/format-description).
- Cross-file references are `{fileID, guid, type}`: "When Unity serializes an asset reference it points to two things: the GUID and file ID"; local ids are signed 64-bit. [AssetDatabase.TryGetGUIDAndLocalFileIdentifier, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/assetdatabase/trygetguidandlocalfileidentifier). The guid lives in the `.meta` file; losing it means "any reference to that asset is broken". [Asset metadata, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/assets-and-media/import-assets/asset-metadata).
- `GlobalObjectId` identifier types: "0 = Null, 1 = Imported Asset, 2 = Scene Object, 3 = Source Asset"; for an object inside a prefab instance the id is the pair (source object's local fileID, the PrefabInstance's fileID). "Moving an object to a new scene changes its GlobalObjectId." The docs do **not** describe how instance fileIDs are hashed. [GlobalObjectId, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/globalobjectid).
- A component's reference to another object in the same file (Transform `m_Father`, `m_Children`, `m_GameObject`) is a plain `{fileID: N}`; the manual has no Joint- or SkinnedMeshRenderer-specific rule beyond this. [YAML scene example, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yamlscene-example).
- **Cross-scene references cannot be saved**: "cross-Scene references cannot be saved in Scene files ... If you need cross-Scene references at runtime, you need to create those references at runtime". [EditorSceneManager.preventCrossSceneReferences, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/scenemanagement/editorscenemanager/preventcrossscenereferences).

### Unreal
- Objects are addressed by **object path** `/package/path.assetname[:subpath]`; a placed actor is a subobject of the level, e.g. `/Game/Maps/Main.Main:PersistentLevel.Actor_0`. [SoftObjectPath, Python API 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/SoftObjectPath); [ULevel::GetActorPackageName, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/ULevel/GetActorPackageName). The Outliner label is editor-only ("Actor labels are only available in development builds"). [Actor, Python API 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/Actor).
- **`ActorGuid`**: "The GUID for this actor; this guid will be the same for actors from instanced streaming levels"; `ActorInstanceGuid` is unique per instance. World Partition's actor descriptors are keyed by ActorGuid; conversion warns that "Unstable actor GUIDs can produce different output". [Actor, Python API 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/Actor); [TActorDescList, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/TActorDescList); [World Partition, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine).
- **OFPA files**: "External Actor filenames are encoded, so they are hard to read in a source control client"; roots are `ULevel::GetExternalActorsPath` and `FExternalPackageHelper::GetExternalObjectsPath` (`__ExternalActors__`, `__ExternalObjects__`). The exact hashed directory scheme is *not confirmed* by Epic docs. "Actors are embedded in their Level files when cooked." [One File Per Actor, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/one-file-per-actor-in-unreal-engine).
- **References**: hard references load the target; soft references (`TSoftObjectPtr`, `FSoftObjectPath`) "store the path as a string". In the package, cross-package references go through the import table (`FObjectImport`, `FPackageIndex` distinguishing import/export/null). [Referencing assets, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/referencing-assets-in-unreal-engine); [FObjectImport, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/CoreUObject/FObjectImport). Since 5.4 soft paths from a parent level into Level Instance actors are supported despite cell embedding changing runtime paths. [UE 5.4 release notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5.4-release-notes?application_version=5.4).
- **Renames leave redirectors**: "When you move or rename an asset ... it leaves a Redirector in the asset's old location" so unloaded referencers still resolve; fixup resaves them. [Asset redirectors, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/asset-redirectors-in-unreal-engine).

### Source 1 / Source 2
- Every `world`, `solid`, `side`, `group`, `entity` block carries an integer `"id"`, "a unique value among other ... ids"; side ids must be unique across solids "for entities like cubemaps that reference one specific face". [VMF, VDC, last edited 2026-10-25](https://developer.valvesoftware.com/wiki/VMF_(Valve_Map_Format)). VBSP renames `id` to `hammerid` when loading ("rename this field since DME code uses this name") so the BSP entity lump carries the editor id; the game keeps it "so that entities can be tracked between save/restore and vmf". [map_shared.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/utils/common/map_shared.cpp); [baseentity.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/server/baseentity.cpp); [CBaseEntity, VDC 2026-11-07](https://developer.valvesoftware.com/wiki/CBaseEntity).
- Runtime references are **`targetname` strings**: "Targetnames do not need to be unique, they can be shared"; wildcards `*` trailing only; procedural `!activator`, `!caller`, `!self`, `!player`. [Targetname, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Targetname). I/O connections are stored only on the sender as `"OnTrigger" "bob,Color,255 255 0,1.23,1"` (target, input, parameter, delay, times-to-fire; separator `,` or ESC 0x1B); "Inputs are not stored as they are simply traced from the outputs." `FireOutput` resolves the target name at fire time, so a rename breaks the link. [VMF page](https://developer.valvesoftware.com/wiki/VMF_(Valve_Map_Format)); [entitydefs.h](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/fgdlib/entitydefs.h); [cbase.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/server/cbase.cpp); [Inputs and Outputs, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Inputs_and_Outputs).
- Source 2 `.vmap` is a DMX file; DMX elements carry 128-bit ids. [VMAP, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/VMAP); [DMX, VDC 2025-12-07](https://developer.valvesoftware.com/wiki/DMX). Entities inside prefabs get fixed-up names at compile time. [Prefabs and Instances, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Source_2_Docs/Level_Design/Prefabs_and_Instances).

### Bevy
- `SceneSerializer` writes `Scene(resources: {...}, entities: {<entity bits>: (components: {...})})`; the map key is the `Entity` itself, whose serde impl is `serialize_u64(self.to_bits())`, documented "Only useful for identifying entities within the same instance of an application. Do not use for serialization between runs." Hence keys like `4294967296`. [serde.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/serde.rs); [entity/mod.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/src/entity/mod.rs); [load_scene_example.scn.ron v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/assets/scenes/load_scene_example.scn.ron).
- On spawn `DynamicScene::write_to_world_with` allocates a fresh entity per scene entity, then applies components through `ReflectComponent::apply_or_insert_mapped`, which calls `C::map_entities` with a `SceneEntityMapper`; an unmapped source maps to a dead entity "guaranteed to never point to any living entity". Components with `Entity` fields opt in with `#[entities]` on the field (the `Component` derive emits `map_entities` for marked fields and for relationship fields). `ChildOf(#[entities] pub Entity)`; `Children(Vec<Entity>)` is mapped as the relationship target. [dynamic_scene.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/dynamic_scene.rs); [reflect/component.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/src/reflect/component.rs); [map_entities.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/src/entity/map_entities.rs); [macros/src/component.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/macros/src/component.rs); [hierarchy.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/src/hierarchy.rs).
- In **0.19** this crate was renamed `bevy_world_serialization` (`DynamicScene`→`DynamicWorld`, `SceneRoot`→`WorldAssetRoot`, `SceneSpawner`→`WorldInstanceSpawner`) because "it still handles round-trip World serialization and GLTF scene spawning, which the new BSN system doesn't cover yet"; the new `bevy_scene` is BSN, whose `#Name` syntax names an entity and lets other parts of the scene refer to it. [0.18→0.19 migration guide](https://bevy.org/learn/migration-guides/0-18-to-0-19/); [Bevy 0.19, 2026-06-19](https://bevy.org/news/bevy-0-19/).

### Flecs
- JSON entities carry `"parent"`, `"name"`, optional `"id"` (only with `serialize_entity_id`), `"tags"`, `"pairs"`, `"components"`; paths are dot-separated (`Sun.Earth`). Entity-typed members are written as paths by `flecs_json_path`; nameless entities as `"#<id>"`. On load `flecs_json_ensure_entity` looks the path up and creates the entity if missing; a `"#N"` is bound consistently across the document and may get a new id. [FlecsRemoteApi.md, master](https://raw.githubusercontent.com/SanderMertens/flecs/master/docs/FlecsRemoteApi.md); [json.h](https://raw.githubusercontent.com/SanderMertens/flecs/master/include/flecs/addons/json.h); [meta/serialize.c](https://raw.githubusercontent.com/SanderMertens/flecs/master/src/addons/meta/serialize.c); [json/deserialize.c](https://raw.githubusercontent.com/SanderMertens/flecs/master/src/addons/json/deserialize.c). Flecs Script references entities by path too. [FlecsScript.md](https://raw.githubusercontent.com/SanderMertens/flecs/master/docs/FlecsScript.md).

### EnTT
- `entt::snapshot{registry}.get<entt::entity>(archive).get<T>(archive)` "serializes all entities along with their versions" as raw ids; `snapshot_loader` keeps the ids and "requires that the destination registry be empty"; `continuous_loader` remaps ("Identifiers that entities originally had are not transferred to the target") and the user wraps the archive to call `value.parent = loader.map(value.parent)` per `Entity`-typed member. No generic member remapping. [entity.md v3.15.0](https://raw.githubusercontent.com/skypjack/entt/v3.15.0/docs/md/entity.md); [entity.md v4.0.0](https://raw.githubusercontent.com/skypjack/entt/v4.0.0/docs/md/entity.md).

## 2. Component data

### Godot
- Only properties with `PROPERTY_USAGE_STORAGE` are considered and **only non-default values are written** (`SceneState::_parse_node` drops a value when `PropertyUtils::get_property_default_value` is valid and `!is_property_value_different`); `PROPERTY_USAGE_NO_INSTANCE_STATE` is skipped on instanced nodes; pinned properties bypass the default check. Written as `key = value` lines (`transform = Transform3D(...)`). [@GlobalScope, 4.7](https://docs.godotengine.org/en/stable/classes/class_@globalscope.html); [packed_scene.cpp, master](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.cpp); [TSCN docs](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html).
- **Scripts** are an ordinary property: `script = ExtResource("1_x")`; exported script variables (`PROPERTY_USAGE_SCRIPT_VARIABLE`) are written beside built-in ones; `.tres` headers may carry `script_class="Name"`. [resource_format_text.cpp, master](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/resource_format_text.cpp).
- **Unknown types**: PR #60597 "Implement missing Node & Resource placeholders" (reduz, merged 2022-05-05, 4.0): when a class is unavailable the loader creates `MissingNode`/`MissingResource` holding `original_class` and the data, re-saved as the original class, so "missing types no longer cause data loss"; gated by `ResourceLoader::is_creating_missing_resources_if_class_unavailable_enabled()` (editor); without it nodes fall back to `Node`/`Node2D`/`Node3D`/`Control` with a warning and sub_resources fail. Unassignable values are kept under `META_MISSING_RESOURCES` metadata. [PR #60597](https://github.com/godotengine/godot/pull/60597); [MissingNode, 4.7](https://docs.godotengine.org/en/stable/classes/class_missingnode.html); [MissingResource, 4.7](https://docs.godotengine.org/en/stable/classes/class_missingresource.html).

### Unity
- Serialised fields: public or `[SerializeField]`, non-static/const/readonly, of a serialisable type; custom classes "inline by value" unless `[SerializeReference]`; "Inline serialization can't represent null"; `UnityEngine.Object` fields are references. [Serialization rules, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/programming-environment/code-reload-serialization/script-serialization/rules). The examples write **every** property including defaults (`m_Enabled: 1`, full `m_LocalScale`); "When reading a scene file, Unity tries to assign default values to any properties for which a value hasn't been set." [YAML scene example, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yamlscene-example).
- MonoBehaviours carry `m_Script: {fileID: 11500000, guid: ..., type: 3}` beside their fields. [MonoBehaviour, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/monobehaviour). The Manual has no page stating that a MonoBehaviour's data is kept while its script is missing (only `RemoveMonoBehavioursWithMissingScript` exists); retention **is** documented for `[SerializeReference]`: "When types referred to by SerializeReference are no longer available when deserializing, Unity replaces the instance with null, but the serialized information is preserved." `SerializeReference` writes a `references` list after the regular fields with id, fully qualified class name and values (the YAML key is `rid`). [SerializeReference, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/serializereference); [RemoveMonoBehavioursWithMissingScript, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/gameobjectutility/removemonobehaviourswithmissingscript).
- Renames: `[FormerlySerializedAs("hitpoints")]` "rename a field without losing its serialized value". [FormerlySerializedAs, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/serialization/formerlyserializedasattribute). Hooks: `ISerializationCallbackReceiver` ("the Unity serializer runs on a different thread from most of the Unity API"). [ISerializationCallbackReceiver, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/iserializationcallbackreceiver). `m_ObjectHideFlags` heads every document; `DontSaveInEditor` etc. [HideFlags, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/hideflags).

### Unreal
- **Tagged properties, delta against defaults**: "all UProperty values are automatically written or read unless explicitly marked as 'transient'", skipped "when unchanged from the post-constructor default"; "New properties get default values copied from the new CDO" and "Removed properties are silently ignored"; on a CDO change, an instance value equal to the *old* default is updated, otherwise "the assumption is that the value was set intentionally". [Unreal Object Handling, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-object-handling-in-unreal-engine); [Objects, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/objects-in-unreal-engine). Cooked builds may switch to unversioned property serialisation, which "assumes writer and reader share the same property definitions". [FArchive::SetUseUnversionedPropertySerialization, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Core/FArchive/SetUseUnversionedPropertySeriali-).
- Specifiers: `Transient`, `SaveGame`, `Instanced` (per-instance subobject copy), `Export`, `SkipSerialization` ("can still be exported to a text format"), `DuplicateTransient`, `TextExportTransient`. [UProperties, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-uproperties).
- **Versioning**: assets store engine version, `EUnrealEngineObjectUE5Version` and per-object custom versions (`FGuid` + number); older engines refuse newer packages; unreadable references "load as null". [Versioning of assets, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/versioning-of-assets-and-packages-in-unreal-engine). **Core Redirects** (`[CoreRedirects]` in `DefaultEngine.ini`) remap classes, structs, enums, functions, packages and properties on load; a renamed property with no redirect "does not receive its old data". [Core Redirects, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/core-redirects-in-unreal-engine).
- Blueprint vs native components: `EComponentCreationMethod` = Native, SimpleConstructionScript, UserConstructionScript, Instance ("a component added to a single Actor instance via the Component section of the Actor's details panel"). [EComponentCreationMethod, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/EComponentCreationMethod); [Components window, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/components-window-in-unreal-engine); [Construction Script, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/construction-script-in-unreal-engine).

### Source
- No components: an entity is a `classname` plus string keyvalues; the FGD "is nothing more than a reference for the map editor". [FGD, VDC 2026-11-06](https://developer.valvesoftware.com/wiki/FGD). **Unknown keys are kept**: properties "can be anything, but only valid properties will mean anything when compiled"; SmartEdit off "lets you add or edit keys and values directly". VBSP copies every key verbatim and the chunk parser skips unhandled blocks ("No handler for this chunk. Skip to the matching close curly brace."). [VMF page](https://developer.valvesoftware.com/wiki/VMF_(Valve_Map_Format)); [Hammer Object Properties Dialog, VDC 2025-05-13](https://developer.valvesoftware.com/wiki/Hammer_Object_Properties_Dialog); [chunkfile.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/chunkfile.cpp).
- Scripts attach as keyvalues: `vscripts` ("Space delimited list of VScript files ... executed after all entities have spawned") and `thinkfunction`; Source 2 entities carry the same keys. [Worldspawn, VDC 2026-10-16](https://developer.valvesoftware.com/wiki/Worldspawn); [Env_sky, VDC 2026-05-15](https://developer.valvesoftware.com/wiki/Env_sky).

### Bevy
- `DynamicSceneBuilder` silently skips a component that is filtered out, unregistered, or lacks `ReflectComponent`; default is "all types registered with ReflectComponent or ReflectResource". Keys are full `type_path()`s (`"bevy_transform::components::transform::Transform"`), "sorted by type path before they're serialized". [dynamic_scene_builder.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/dynamic_scene_builder.rs); [serde.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/serde.rs).
- Load is strict: `SceneSpawnError::UnregisteredComponent{type_path}` ("consider adding `#[reflect(Component)]`"), `UnregisteredResource`, `UnregisteredType`, `UnregisteredButReflectedType`, `NoRepresentedType`. Values go through `TypedReflectDeserializer` and `ReflectFromReflect`; components with `ComponentCloneBehavior::Ignore` are skipped on write. [scene_spawner.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/scene_spawner.rs); [dynamic_scene.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/dynamic_scene.rs). 0.19 added `HandleSerializeProcessor`/`HandleDeserializeProcessor` for asset handles. [Bevy 0.19](https://bevy.org/news/bevy-0-19/).

### Flecs
- Components appear under `"components"` keyed by name; with reflection data a value, otherwise `null`. `ecs_from_json_desc_t.strict`: "Require components to be registered with reflection data. When not in strict mode, values for components without reflection are ignored" (an id with no type info is added as a tag). [FlecsRemoteApi.md](https://raw.githubusercontent.com/SanderMertens/flecs/master/docs/FlecsRemoteApi.md); [json.h](https://raw.githubusercontent.com/SanderMertens/flecs/master/include/flecs/addons/json.h); [deserialize.c](https://raw.githubusercontent.com/SanderMertens/flecs/master/src/addons/json/deserialize.c).

### EnTT
- "This module comes with bare minimum support for serialization": the archive is "an opaque object with a suitable interface"; the component list is the chain of `.get<T>()` calls and must be replayed "in the same order it was serialized"; no type names unless the archive writes them. [entity.md v4.0.0](https://raw.githubusercontent.com/skypjack/entt/v4.0.0/docs/md/entity.md).

## 3. Hierarchy and ordering

- **Godot**: hierarchy is the `parent=` path; parents precede children in the file (loader calls `parent->_add_child_nocheck`). **Sibling order is meaningful** (file order; `_process` runs "in tree order, or top to bottom as seen in the editor"); `index=` "sets the order of appearance in the tree" and is only written when the node belongs to an inherited scene or its parent is an instanced scene, otherwise "inherited nodes will take precedence over plain ones". [TSCN docs](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html); [SceneState, 4.7](https://docs.godotengine.org/en/stable/classes/class_scenestate.html); [Node, 4.7](https://docs.godotengine.org/en/stable/classes/class_node.html); [packed_scene.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.cpp).
- **Unity**: `GameObject.m_Component` is an ordered list; `Transform.m_Children` is the ordered child list and `m_Father: {fileID: 0}` marks a root; documents are ordered by fileID, not hierarchy; "At the end of the file, Unity stores the scene root transforms" in a `SceneRoots` object (class 1660057539, fileID `9223372036854775807`). [YAML scene example, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yamlscene-example); [Class ID reference, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/class-idreference). `SceneRoots` is in the 2022.3 class-id reference but not 2022.2's, consistent with the `m_RootOrder`→`SceneRoots` switch in the 2022.2/2022.3 window; no Manual page states the version or rationale. [ClassIDReference 2022.3](https://docs.unity3d.com/2022.3/Documentation/Manual/ClassIDReference.html); [ClassIDReference 2022.2](https://docs.unity3d.com/2022.2/Documentation/Manual/ClassIDReference.html). `rootOrder` is still listed as a default override. [PrefabUtility.IsDefaultOverride, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/isdefaultoverride).
- **Unreal**: actors are a flat set in a level ("A Level is a collection of Actors"); "actors do not directly store Transform"; the component tree hangs off `RootComponent`; actor-to-actor attachment is "by attaching its root Component to a Component of the other Actor" via `AttachParent` + `AttachSocketName`. Outliner folders (`FolderPath`) "are only available in development builds". No Epic page assigns meaning to actor order, and under OFPA each actor is its own package so the level carries no order list. [Actors, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/actors-in-unreal-engine); [Components, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/components-in-unreal-engine); [USceneComponent, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/USceneComponent); [SetFolderPath, 5.9](https://dev.epicgames.com/documentation/unreal-engine/BlueprintAPI/EditorScripting/ActorEditing/SetFolderPath).
- **Source**: VMF is flat (`versioninfo`, `visgroups`, `viewsettings`, `world`, `entity`…, `hidden`, `cameras`, `cordon`); "the order doesn't matter to Hammer"; brush entities own `solid{}` children; visgroups are editor-only (`editor{ visgroupid ... }`, nested). `parentname` is runtime attachment: at spawn entities are sorted by hierarchy depth and `SetParent` applied; an ambiguous name warns. [VMF page](https://developer.valvesoftware.com/wiki/VMF_(Valve_Map_Format)); [mapentities.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/server/mapentities.cpp). Source 2 Hammer has an Outliner of map nodes and per-entity embedded `parentname`/`parentAttachmentName`/`local.origin`. [Hammer Overview, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Source_2_Docs/Level_Design/Hammer_Overview); [Env_sky](https://developer.valvesoftware.com/wiki/Env_sky).
- **Bevy 0.16**: "The Relationship component is the 'source of truth', and the RelationshipTarget component is updated to reflect that source of truth". `ChildOf` reflects `Serialize`/`Deserialize`; `Children` has `ReflectComponent` but no serde derive; both are extracted, so the scene writes `Children`'s ordered `Vec<Entity>` and applies with `RelationshipHookMode::Skip`, i.e. the serialised child order (not the hook) rebuilds the list. No test covers child order. [Bevy 0.16](https://bevy.org/news/bevy-0-16/); [hierarchy.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/src/hierarchy.rs); [relationship/mod.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_ecs/src/relationship/mod.rs); [dynamic_scene.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/dynamic_scene.rs).
- **Flecs**: hierarchies are `(ChildOf, parent)` pairs or a `Parent` component ("A single entity cannot both have a ChildOf pair and a Parent component"); "Order is not guaranteed by default", the `OrderedChildren` trait preserves creation or custom order (`ecs_set_child_order`), and `Parent` hierarchies are built on it; `ecs_world_to_json` writes parents before children; Flecs Script creates prefab/template children with `Parent`. [HierarchiesManual.md](https://raw.githubusercontent.com/SanderMertens/flecs/master/docs/HierarchiesManual.md); [serialize_world.c](https://raw.githubusercontent.com/SanderMertens/flecs/master/src/addons/json/serialize_world.c); [FlecsScript.md](https://raw.githubusercontent.com/SanderMertens/flecs/master/docs/FlecsScript.md).
- **EnTT**: no hierarchy concept; parent fields are plain members you remap yourself. [entity.md v4.0.0](https://raw.githubusercontent.com/skypjack/entt/v4.0.0/docs/md/entity.md).

## 4. Scene-level state

- **Godot has no scene-wide block.** A `.tscn` is descriptor + ext_resources + sub_resources + nodes + connections (+ `[editable]`). Environment is the `WorldEnvironment` node ("only one WorldEnvironment may be instantiated in a given scene at a time"), overridable per Camera3D; physics and everything else is `project.godot`. The header is `[gd_scene format=3 uid="uid://..."]`; `load_steps=N` was only a progress hint and is no longer written since 4.6; `FORMAT_VERSION = 4`, `FORMAT_VERSION_COMPAT = 3`. [WorldEnvironment, 4.7](https://docs.godotengine.org/en/stable/classes/class_worldenvironment.html); [TSCN docs](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html); [Upgrading to 4.6](https://docs.godotengine.org/en/stable/tutorials/migrating/upgrading_to_godot_4.6.html); [resource_format_text.h, master](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/resource_format_text.h).
- **Unity**: the scene file opens with GameObject-less settings objects at fixed small fileIDs: `!u!29 &1 OcclusionCullingSettings`, `!u!104 &2 RenderSettings`, `!u!157 &3 LightmapSettings`, `!u!196 &4 NavMeshSettings`, and ends with `SceneRoots`. "Each scene manages its own settings, so only settings associated with that scene save to the scene file"; with several scenes open "Unity uses the rendering settings from the active scene". Physics is project-level (Edit > Project Settings > Physics). Baked lighting is a separate Lighting Data Asset "so changes to the precomputed lighting data do not result in changes to the Scene file". [YAML scene example](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yamlscene-example); [Setting up multiple scenes, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/multi-scene-editing/setupmultiplescenes); [Physics settings, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-settings-reference/comp-manager-group/class-physics-manager); [Lighting Data Asset, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/lighting-overview/direct-and-indirect-lighting/lightmap-data/lightmap-snapshot).
- **Unreal**: per-level `AWorldSettings`, an "Actor containing all script accessible world properties": GameMode override, physics (`global_gravity_z`, `kill_z`, default physics volume), world bounds, navigation, Lightmass, World Partition setup, HLOD, rendering, audio. Post-process volumes are actors. The Level Blueprint is "a level-wide global event graph". Built lighting lives in `UMapBuildDataRegistry` / `AMapBuildDataActor` (World Partition, experimental 5.5). The WorldSettings of an embedded Level Instance "does not exist at runtime". [World Settings, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-settings-in-unreal-engine); [WorldSettings, Python API 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/WorldSettings); [Post Process Effects, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/post-process-effects-in-unreal-engine); [Level Blueprint, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/level-blueprint-in-unreal-engine); [AMapBuildDataActor, API 5.9](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/AMapBuildDataActor); [Level Instancing, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/level-instancing-in-unreal-engine).
- **Source**: `worldspawn` "is the single entity that stores the noninteractive parts of a map, alongside some global configuration options" (`skyname`, `detailvbsp`, `maxpropscreenwidth`, `_minlight`, `mapversion`, `vscripts`…); global lighting is the first `light_environment` ("only the first light_environment is used"); `sky_camera` marks the 3D skybox origin. Source 2: `env_sky`, `light_environment` with `skytexture`, `env_combined_light_probe_volume`, Map Properties "Map Type" (Standard / 3D Skybox). [Worldspawn](https://developer.valvesoftware.com/wiki/Worldspawn); [Light_environment, VDC 2026-10-11](https://developer.valvesoftware.com/wiki/Light_environment); [Sky_camera, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Sky_camera); [Env_sky](https://developer.valvesoftware.com/wiki/Env_sky); [Light_environment (Source 2), VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Light_environment_(Source_2)); [Env_combined_light_probe_volume, VDC 2026-03-05](https://developer.valvesoftware.com/wiki/Env_combined_light_probe_volume); [3D Skybox Creation, VDC 2026-11-01](https://developer.valvesoftware.com/wiki/Source_2_Docs/Level_Design/3D_Skybox_Creation).
- **Bevy**: `DynamicScene { resources: Vec<Box<dyn PartialReflect>>, entities }`; resources need `ReflectResource`, are written as a `resources: { "type::path": value }` map, mapped with `ReflectMapEntities` if registered, and applied after all entities exist. This is the closest analogue to Fenrir's scene resources: typed, one per type, keyed by type path, in the same file as the entities. [dynamic_scene.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/dynamic_scene.rs); [serde.rs v0.16.1](https://raw.githubusercontent.com/bevyengine/bevy/v0.16.1/crates/bevy_scene/src/serde.rs).
- **Flecs**: singletons are components on their own component entity, so `ecs_world_to_json` includes root-level ones (its query excludes `ChildOf(flecs)` unless `serialize_builtin` and modules unless `serialize_modules`); Flecs Script sets them with `$ { TimeOfDay: { t: 0.5 } }`. [serialize_world.c](https://raw.githubusercontent.com/SanderMertens/flecs/master/src/addons/json/serialize_world.c); [FlecsScript.md](https://raw.githubusercontent.com/SanderMertens/flecs/master/docs/FlecsScript.md).
- **EnTT**: `registry.ctx()` ("an `any` object map accessible by both type and name") is not covered by snapshots, which only chain storages. [entity.md v4.0.0](https://raw.githubusercontent.com/skypjack/entt/v4.0.0/docs/md/entity.md).

## 5. Prefabs

### Godot: instanced, inherited, editable children
- **Instance**: `[node name="Ball" parent="." instance=ExtResource("1_abcd")]` (`TYPE_INSTANTIATED`). The entry stores only properties whose value differs from the source ("Changing a property on an instance always overrides values from the corresponding packed scene"); nodes inside the instance are written only if they have overrides or groups and are discarded unless the instance is editable; inherited groups are not re-saved. [Instancing, 4.7](https://docs.godotengine.org/en/stable/getting_started/step_by_step/instancing.html); [packed_scene.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.cpp).
- **Editable children**: `Node.set_editable_instance(node, true)` makes "all nodes owned by node ... available, and editable, in the Scene dock"; stored as `[editable path="Sub/Path"]` lines. Disabling it reverts descendant overrides and reparents added nodes. [Node, 4.7](https://docs.godotengine.org/en/stable/classes/class_node.html); [scene_tree_dock.cpp, master](https://raw.githubusercontent.com/godotengine/godot/master/editor/docks/scene_tree_dock.cpp).
- **Inherited scene**: the root node itself carries `instance=ExtResource(...)`; `SceneState::base_scene_idx` points at the base; instantiation builds the base first, then applies the derived file's nodes and overrides, so **propagation happens at load** because the file holds only the diff. Added children get `parent=` and `index=`. [packed_scene.cpp](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.cpp); [Scenes versus scripts, 4.7](https://docs.godotengine.org/en/stable/tutorials/best_practices/scenes_versus_scripts.html).
- **Limits**: "nodes from the base scene can't be removed, but additional nodes can be added anywhere"; "Subresources can't be edited"; editor errors "Can't reparent nodes in inherited scenes, order of nodes can't change." [Import configuration, 4.7](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/import_configuration.html); [scene_tree_dock.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/docks/scene_tree_dock.cpp).
- **Unpack**: "Make Local" clears `scene_file_path`, re-owns descendants to the edited root and strips inherited connections so the subtree is written verbatim; "Clear Inheritance? (No Undo!)" drops `scene_inherited_state`. [scene_tree_dock.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/docks/scene_tree_dock.cpp). **Placeholder**: `instance_placeholder="res://x.tscn"` defers the load to an `InstancePlaceholder` until `create_instance()`. [InstancePlaceholder, 4.7](https://docs.godotengine.org/en/stable/classes/class_instanceplaceholder.html).
- **`SceneState` internals**: `names`, `variants`, `node_paths`, `editable_instances`, `base_scene_idx`, `nodes` (`NodeData{parent, owner, type, name, instance, index, properties[], groups}`), `connections` (`{from,to,signal,method,flags,unbinds,binds}`), 4.6 `id_paths`/`ids`; connections saved only if `CONNECT_PERSIST` and only when they originate or end in the saved scene. [packed_scene.h](https://raw.githubusercontent.com/godotengine/godot/master/scene/resources/packed_scene.h); [SceneState, 4.7](https://docs.godotengine.org/en/stable/classes/class_scenestate.html).

### Unity: PrefabInstance, nested, variants
- A `PrefabInstance` (class 1001) names its source `m_SourcePrefab: {fileID: 100100000, guid, type: 3}` ("The fileID is always 100100000"). Its `m_Modification` block holds `m_TransformParent`, `m_Modifications` (entries `target: {fileID, guid, type: 3}`, `propertyPath`, `value`, `objectReference`), `m_RemovedComponents`, `m_RemovedGameObjects`, `m_AddedGameObjects`, `m_AddedComponents`; empty lists are still written. So an override is **per property path**, plus per-component and per-GameObject add/remove lists. [YAML prefab serialization, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yaml-prefab-serialization).
- **Stripped objects**: "The `stripped` keyword on the document header indicates that the object is a placeholder" (`--- !u!4 &N stripped`) with `m_CorrespondingSourceObject` (cross-file to the source), `m_PrefabInstance` (owning instance) and `m_PrefabAsset`; a parent's `m_Children` references the stripped Transform. [YAML prefab example, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yaml-prefab-example).
- **Variants**: "Unity represents a prefab variant's root as a PrefabInstance element ... rather than as a separately serialized GameObject" with `m_TransformParent: {fileID: 0}`; "A variant can use any prefab as its base, including other variants." **Nested**: "Nested prefabs keep their links to their own prefab assets, while also forming part of another prefab asset" (both 2018.3). [Prefab variants, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-gameobjects/prefabs/prefab-variants); [Nested prefabs, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-gameobjects/prefabs/nested); [Nested Prefabs, 2018.3](https://docs.unity3d.com/2018.3/Documentation/Manual/NestedPrefabs.html).
- **Propagation and precedence**: "If the Prefab Asset is changed, all the Prefab instances are automatically updated accordingly"; "An overridden property value on a prefab instance always takes precedence". [Introducing new prefab workflows, Unity blog 2018-06-20](https://unity.com/blog/technology/introducing-new-prefab-workflows); [Prefab instance overrides, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-gameobjects/prefabs/override/prefab-instance-overrides).
- **Removed GameObjects as overrides** arrived in 2022.2 ("Deleting GameObjects as Overrides ... recorded as an Override stored in the scene file"); `PrefabUtility.GetRemovedGameObjects` is in the 2022.2 SR, not 2022.1. [Prefabs: what's new in 2022.2, Unity blog 2022-11-22](https://unity.com/blog/engine-platform/prefabs-whats-new-2022-2); [PrefabUtility 2022.2](https://docs.unity3d.com/2022.2/Documentation/ScriptReference/PrefabUtility.html); [PrefabUtility 2022.1](https://docs.unity3d.com/2022.1/Documentation/ScriptReference/PrefabUtility.html).
- **Default overrides** (never applied or reverted): root `name`, root Transform `localPosition`/`localRotation`/`localEulerAnglesHint`/`rootOrder`, RectTransform anchors. [IsDefaultOverride, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/isdefaultoverride).
- **Unpack**: `OutermostRoot` "replaces the prefab instance with that content"; `Completely` "also unpacks any prefab instances that are part of the unpacked content"; unpacking a variant one level "leaves an instance of the base prefab". `GetCorrespondingObjectFromSource` maps one level up. [UnpackPrefabInstance, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/unpackprefabinstance); [GetCorrespondingObjectFromSource, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/getcorrespondingobjectfromsource).

### Unreal: Blueprint classes, Child Actors, Level Instances
- The **Blueprint Class** is the prefab: "defines a new Actor type that can be placed in maps"; an instance stores only values that differ from the class defaults and class changes propagate unless the instance value was changed (section 2's archetype-delta rule). Instance-to-class push-back exists (`SSCSEditor::OnApplyChangesToBlueprint`, "Propagates instance changes to the blueprint"). Data-Only Blueprints expose only values. [Anatomy of a Blueprint, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/anatomy-of-a-blueprint-in-unreal-engine); [Unreal Object Handling, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-object-handling-in-unreal-engine); [OnApplyChangesToBlueprint, UE 4.26 API](https://docs.unrealengine.com/4.26/en-US/API/Editor/Kismet/SSCSEditor/OnApplyChangesToBlueprint/index.html); [Types of Blueprints, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/types-of-blueprints-in-unreal-engine).
- **Child Actor Component**: "A component that spawns an Actor when registered, and destroys it when unregistered", with a `child_actor_template` for the details panel. [ChildActorComponent, Python API 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/ChildActorComponent).
- **Level Instances**: "collections of Actors combined into a sublevel"; edit in context (Level > Edit, Commit Changes); "Changes made to one instance are repeated across all instances when saved"; Break restores the actors and "cannot be undone"; **Packed Level Actors** are "Static Mesh assets that are combined to create a single Blueprint Actor that is optimized for rendering" (`APackedLevelActor`, non-mesh components yield "an incomplete APackedLevelActor"). ### Flecs: live `IsA` inheritance

## 7. Merge-friendliness

- **Godot**: TSCN is "mostly human-readable and easy for version control systems to manage"; "Godot aims to be VCS-friendly and generate mostly readable and mergeable files". Proposal #471 reported sequential integer ids colliding when two developers add resources; PR #50676 "Implement textual ext/subresource IDs" (reduz, 2021-07-22, 4.0) introduced `"1_ylvbm"`/`"Type_xxxxx"` ids "to minimize conflicts when merging" and to stop renumbering (text format 3). `load_steps` was "a frequent source of Git conflicts" (proposal #11802) and was removed in 4.6 (PR #103352); re-saving produces one large expected diff. Known pain: UIDs randomly resetting (#62258) and duplicate UIDs from files copied outside the editor (#102490, open; 4.4 warns "UID duplicate detected"). [TSCN docs](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html); [Version control systems, 4.7](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html); [proposal #471](https://github.com/godotengine/godot-proposals/issues/471); [PR #50676](https://github.com/godotengine/godot/pull/50676); [proposal #11802](https://github.com/godotengine/godot-proposals/issues/11802); [Upgrading to 4.6](https://docs.godotengine.org/en/stable/tutorials/migrating/upgrading_to_godot_4.6.html); [#62258](https://github.com/godotengine/godot/issues/62258); [#102490](https://github.com/godotengine/godot/issues/102490).
- **Unity**: "Force Text" is the default Asset Serialization Mode ("To help with version control merges"); "Reduce version control noise" (`serializeInlineMappingsOnOneLine`) stops 80-column wrapping; text "can be merged more easily than binary files" and "can be generated and parsed by tools", but UnityYAML "does not implement the full YAML specification" (no comments, tags). **UnityYAMLMerge** merges `.unity`, `.prefab`, `.meta` "in a semantically correct way", driven by `mergerules.txt`: `[arrays]` declares keyed sets (`set *.GameObject.m_Component *.fileID`, `set *.Prefab.m_Modification.m_Modifications target.fileID target.guid propertyPath`), `[exclusions]` force conflicts, `[comparisons]` give float epsilons; `--nomappinginoneline` must match the editor setting. [Editor settings, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-settings-reference/comp-manager-group/class-editor-manager); [serializeInlineMappingsOnOneLine, SR 6000.0](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/editorsettings/serializeinlinemappingsononeline); [Text scene format, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format); [UnityYAML, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/unity-yaml); [Smart merge, M 6000.0](https://docs.unity.com/en-us/engine/6000.0/manual/get-started/project-configuration/version-control/smart-merge).
- **Unreal**: `.uasset`/`.umap` are binary: "Binary files can't be opened as text or merged with a text-based merge tool", so the editor checks files out (locks). **OFPA's rationale**: editing actors previously "locked other team members out of that file until your work was complete"; with external actor files the level "no longer needs saving for Actor changes"; changelist validation guards dangling references. The UE Diff Tool exists because text diffs "don't represent Blueprints or assets well". T3D is the copy/paste text path (`SkipSerialization` properties "can still be exported to a text format"). [Using Perforce, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-perforce-as-source-control-for-unreal-engine); [One File Per Actor, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/one-file-per-actor-in-unreal-engine); [UE Diff Tool, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/ue-diff-tool-in-unreal-engine); [UProperties, 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-uproperties); [ActorExporterT3D, Python API 5.9](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/ActorExporterT3D).
- **Source**: VMF is text KeyValues with per-object ids and `versioninfo` (`mapversion` increments per save); Hammer rewrites the whole file and normalises block order; `.vmx` is the previous version's backup. Manifests exist so that "multiple people [can] work on a map at the same time ... make a map's source files easier to track in version control software like Git". Source 2 `.vmap` "is just a DMX file under binary encoding version 4", with "Save Copy As Text" for an ASCII copy and `dmxconvert` between encodings. [VMF page](https://developer.valvesoftware.com/wiki/VMF_(Valve_Map_Format)); [VMX, VDC 2024-07-12](https://developer.valvesoftware.com/wiki/VMX); [Instance](https://developer.valvesoftware.com/wiki/Instance); [VMAP](https://developer.valvesoftware.com/wiki/VMAP); [DMX](https://developer.valvesoftware.com/wiki/DMX).

## What this means for Fenrir (observations, not decisions)

- The map's Notes say Fenrir entities are plain handles and several components hold `Entity` fields. Every engine with an authoring format solves that with a **file-level identity distinct from the runtime handle** plus a remap on load; the ECS-first formats that write raw handles (Bevy `DynamicScene`, EnTT snapshots) are documented by their authors as same-process snapshot formats, not authoring formats, and Bevy is now replacing its own with BSN. Bevy's `#[entities]` field attribute (derive-generated `map_entities`) is the closest precedent to what `describe-api` could emit for `Entity`-typed fields.
- Fenrir's **scene resources** (one per C++ type) map directly onto Bevy's `resources: { "type::path": value }` block and Flecs singletons; Unity's unnamed settings objects at fixed fileIDs and Unreal's `AWorldSettings` are the same idea with a fixed set of types. Godot has no such block at all, which is why its environment is a node.
- **Prefab override granularity** is per property path everywhere that has overrides (Godot, Unity, Unreal, Flecs own-copy). Removals are the hard case: Godot forbids them, Unity added them in 2022.2 as a list on the instance, Flecs has none (an instance can only add). Fenrir's "component" is the natural unit between Godot's node and Unity's property path, and its plain-data structs make "store only non-default fields" (Godot, Unreal) cheap to compute from `.api.json` defaults.
- Only Unreal ships streaming cells, and it did so by changing the storage unit to one-actor-per-file; Godot and Unity leave cells to the game or a package, which matches the map's "streaming is the game's" line.
- Sibling order is meaningful in Godot, Unity and Bevy (an ordered child list), unspecified in Flecs unless `OrderedChildren`, and absent in Unreal and Source; if Fenrir's `Children` or draw order depends on it, the file must carry it explicitly.
