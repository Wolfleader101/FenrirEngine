# How engines hold dev-time data: project settings, import sidecars, per-developer overrides and what ships

Answers [How do engines hold dev-time data?](../issues/07-dev-time-data-in-engines.md) for the grilling ticket [What dev-time data does the engine hold, and in what files?](../issues/18-dev-time-data.md). Fenrir's packages are configured in code (`X::Install(App&, XConfig)`: `AssetsConfig::root` is "the directory relative asset paths resolve against. Empty means `assets/` beside the executable" (`packages/FenrirAssets/include/FenrirAssets/AssetStore.hpp`); `ScriptingConfig::scriptAssembly` is already described as "the `scriptAssembly` field of the .feproj" (`packages/FenrirScripting/include/FenrirScripting/Scripting.hpp`), though no `.feproj` reader exists in the tree). This file reports what five engines do in the four areas the ticket names and ends with what that implies for Fenrir. It decides nothing.

Each claim carries the URL it was read at.

## The short answer

- **Two families.** Godot, Unity, Unreal and Flax have a project file plus a settings store the editor edits and the game reads; Bevy has neither: its "project settings" are plugin structs built in code and overridden by environment variables and Cargo features. Fenrir today is in Bevy's family.
- **Project vs scene is the same line everywhere:** window, rendering backend and quality, physics defaults, input map, layer and tag names, first scene, product identity and packaging live in project settings; a scene holds instances. Settings that are themselves assets (Unity's URP/HDRP settings objects, Flax's `TimeSettings`/`PhysicsSettings` JSON assets, Unreal's Interchange pipeline assets) are referenced from the project settings, not embedded.
- **Layering** runs from Unreal's twelve `.ini` layers plus platform folders, per-user files and command-line `-ini:` overrides, through Godot's C++ defaults + `project.godot` + feature-tag suffixes + `override.cfg` + command line, Unity's project settings + per-platform tabs + build-profile overrides, down to Flax's one JSON asset per area with per-platform assets and no user layer, and Bevy's code + env vars + features.
- **Sidecars split three ways.** Unity's `.meta` is the asset's identity (GUID) *and* its import settings; Godot's `.import` holds the options, the imported output paths and the `uid`, and the editor moves it with the file; Bevy's `.meta` is loader or processor settings only, identity is the path. Unreal and Flax have no sidecar: the import options and the source path are stored inside the imported asset, which is also where identity lives (Unreal: package path plus redirectors on move; Flax: a `Guid` in the `.flax` header).
- **A missing sidecar** means a fresh identity in Unity (references break), a reimport with defaults in Godot (new `uid`), and defaults in Bevy (`AssetMetaCheck::Always`: "If the meta does not exist, the default meta will be used").
- **Caches** are always outside version control and keyed by content: Godot's `.godot/imported/<name>-<md5 of path>` with a `.md5` sidecar of source and destination hashes; Unity's `Library/` with `SourceAssetDB` and `ArtifactDB`, platform in the hash; Bevy's `imported_assets/Default` with `hash` and `full_hash` in the processed `.meta` and a write-ahead log; Unreal's DDC, "disposable" and regenerable from `.uasset`; Flax has no import cache because the import *is* the asset, only a registry `Cache/AssetsCache.dat`.
- **Per-developer data** has a dedicated home in each engine: Unity `UserSettings/` and `Library/EditorUserBuildSettings.asset`; Unreal `Saved/` and the `User<Category>.ini` layers; Godot `override.cfg`, the per-user editor settings file and `.godot/`; Flax `Cache/` and editor options in the user's cache folder; Bevy environment variables and `.cargo/config.toml`. Device and backend selection is mostly command line or environment (`--gpu-index`, `-vulkan`, `WGPU_BACKEND`); an asset-root override exists only in Bevy (`BEVY_ASSET_ROOT`) and, as a whole-project switch, Godot (`--path`, `--main-pack`).
- **What ships:** Godot converts `project.godot` to `project.binary` and rewrites each `.import` to its `[remap]` section inside the PCK; Unity bakes settings into `globalgamemanagers` and ships artifacts, never `.meta`, `ProjectSettings/`, `Library/` or `UserSettings/`; Unreal stages the `.ini` files into the pak with key and section denylists; Flax cooks the JSON settings assets into LZ4 binary chunks in `Content/Data_N.flaxpac` and strips import metadata; Bevy ships the executable, `assets/` (or `imported_assets/Default`) and, by default, the `.meta` files it reads at runtime.

## 1. Project settings

### Godot

**The file.** A project is "any folder containing a `project.godot` file" ([Data paths](https://docs.godotengine.org/en/stable/tutorials/io/data_paths.html)). `save_custom` writes the text form with the header `; Engine configuration file.`, then `config_version=` + `CONFIG_VERSION` (which is `5`, `core/config/project_settings.h`), an optional `custom_features="..."` line, then `[section]` blocks; paths ending in `.godot` or `override.cfg` are written as text and paths ending in `.binary` as binary with the four-byte `ECFG` header, a 32-bit count and key/variant pairs ([project_settings.cpp](https://raw.githubusercontent.com/godotengine/godot/master/core/config/project_settings.cpp), [project_settings.h](https://raw.githubusercontent.com/godotengine/godot/master/core/config/project_settings.h)). Names are full paths with the category, `"application/config/name"` ([ProjectSettings](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html)).

**What is a project setting.** Defaults are registered from C++: `_GLOBAL_DEF` sets the default if the key is missing, reads it back, then calls `set_initial_value`, `set_builtin_order`, `set_as_basic`, `set_restart_if_changed`, `set_ignore_value_in_docs` and `set_as_internal` (project_settings.cpp). The constructor registers, among others, `application/config/name`, `application/run/main_scene`, `application/config/use_custom_user_dir`, `application/config/custom_user_dir_name`, `application/config/project_settings_override`, `display/window/size/viewport_width`, `rendering/occlusion_culling/bvh_build_quality`, `rendering/textures/canvas_textures/default_texture_filter` and `rendering/textures/canvas_textures/default_texture_repeat`; the built-in input map is added under the hidden `input/` prefix, each action a dictionary with `"deadzone"` and `"events"` (project_settings.cpp). Per-importer defaults are project settings too: `importer_defaults/<importer name>` (see §2). Editor-related project keys exist (`editor/export/convert_text_resources_to_binary`, default `true`; `editor/import/atlas_max_width`; `editor/run/main_run_args`) ([ProjectSettings](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html)), and a project can override editor settings for everyone who opens it through `set_editor_setting_override`, stored under the `editor_overrides/` prefix (project_settings.cpp, project_settings.h). What is *not* a project setting is anything per user: `EditorSettings` is "the project-independent editor settings", saved automatically, with keys such as `filesystem/import/blender/blender_path` and `filesystem/import/fbx/fbx2gltf_path` ([EditorSettings](https://docs.godotengine.org/en/stable/classes/class_editorsettings.html)), in a file named `editor_settings-%d.%d.tres` (major.minor; before 4.3 `editor_settings-%d.tres`) in the editor config dir ([editor_settings.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/settings/editor_settings.cpp)), which is `%APPDATA%\Godot\` on Windows, `~/Library/Application Support/Godot/` on macOS and `~/.config/godot/` on Linux ([Data paths](https://docs.godotengine.org/en/stable/tutorials/io/data_paths.html)). Per-project editor metadata (`project_metadata.cfg`) goes in `EditorPaths::get_project_settings_dir()`, "paths like `res://.godot/editor`" ([editor_paths.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/file_system/editor_paths.cpp), editor_settings.cpp).

**Layering.** (1) C++ defaults; (2) `project.godot`; (3) feature-tag suffixes: a key `name.feature` is split on `"."` in `_set` and each tag stored in `feature_overrides[name]`; `get_setting_with_override` checks each tag with `OS::has_feature` (project_settings.cpp). The docs' example is `subsection/example = "Release"` / `subsection/example.debug = "Debug"`, and they warn that `ProjectSettings.get_setting()` ignores tags while `get_setting_with_override()` respects them ([Feature tags](https://docs.godotengine.org/en/stable/tutorials/export/feature_tags.html)). Default tags cover platform (`windows`, `linux`, `macos`, `android`, `ios`, `web`, ...), build (`debug`, `release`, `editor`, `editor_hint`, `editor_runtime`, `template`), precision, bitness, host type (`mobile`, `pc`, `web`), threading and texture compression (`etc`, `etc2`, `s3tc`); custom tags are set in the export preset and "apply only to exported builds" (same page). (4) `override.cfg`, compiled under `OVERRIDE_ENABLED`, loaded from `res://override.cfg`, the executable's directory, the main pack's directory and the macOS bundle, unless `p_ignore_override` or `application/config/disable_project_settings_override` is set; (5) a further text file named by `application/config/project_settings_override`, loaded in `setup()` (project_settings.cpp). The docs: "Any project setting can be overridden by creating a file named `override.cfg` in the project's root directory", it "can be exported alongside the project binary", and base feature tags still apply, so an override must carry the tag to apply everywhere ([ProjectSettings](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html)). (6) Command line: `--rendering-driver`, `--rendering-method` (`forward_plus`, `mobile`, `gl_compatibility`), `--gpu-index`, `--display-driver`, `--audio-driver`, `--headless`, `--position`, `--resolution`, `--fullscreen`, `--path`, `--main-pack`, `--upwards` ([Command line tutorial](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html)). In non-editor tool builds the `GODOT_EDITOR_CUSTOM_FEATURES` environment variable also feeds `custom_features` (project_settings.cpp).

**How the game reads them.** `_setup` probes, in order: the user-supplied main pack; the executable itself (embedded PCK); on Apple bundles `<exe basename>.pck` then `<exe filename>.pck` in the bundle; the same two names in the executable's directory; then in the working directory; on Android `res://assets.sparsepck`; then `OS::get_resource_dir()`; then a directory search from `p_path` (walking up with `..` when `p_upwards`); at each stage it looks for `project.godot` or `project.binary` (`_load_settings_text_or_binary` tries the binary first) and `override.cfg` (project_settings.cpp). So the shipped game reads the same settings, in binary form, from inside its pack.

### Unity

**The folder.** `ProjectSettings` "contains project-specific settings files, such as settings for building, graphics, and memory, and managers for input, tags, and presets"; `Packages` "contains a manifest.json file which defines the packages to use in your project" ([Default directories](https://docs.unity.com/en-us/engine/6000.6/manual/get-started/project-configuration/default-directories)). The Project Settings window (Edit > Project Settings) covers Adaptive Performance, Audio, Build Pipeline, Diagnostics, Editor, Graphics, Memory, Package Manager, Physics, Physics 2D, PhysicsCore 2D, Player, Preset Manager, Quality, Scene Template, Script Execution Order, Services, Shader Graph, Sprite Editor, Tags and Layers, Time, UI Toolkit, Version Control and XR Plug-in Management ([Project Settings](https://docs.unity.com/en-us/engine/current/manual/unity-editor/editor-settings-reference/comp-manager-group)). Editor settings include Asset Serialization Mode, "set to **Force Text** by default" (Mixed / Force Binary / Force Text), Enter Play Mode Settings ("Reload Scene only" is the default), Prefab Mode environments and the Accelerator cache-server mode ([Editor settings](https://docs.unity.com/en-us/engine/current/manual/unity-editor/editor-settings-reference/comp-manager-group/class-editor-manager)); Version Control Mode is "Hidden meta files", "Visible meta files" ("This is the default setting") or "Perforce" ([Version Control settings](https://docs.unity.com/en-us/engine/6000.6/manual/unity-editor/editor-settings-reference/comp-manager-group/class-version-control-settings)).

**Project vs user.** Preferences are "personal Editor preferences that apply to your computer across all projects" (Edit > Preferences; macOS Unity > Settings) ([Preferences](https://docs.unity.com/en-us/engine/current/manual/unity-editor/editor-settings-reference/preferences)); `EditorPrefs` are stored "in the registry under the HKCU\Software\Unity Technologies\Unity Editor 5.x key" on Windows, `~/Library/Preferences/com.unity3d.UnityEditor5.x.plist` on macOS and `~/.local/share/unity3d/prefs` on Linux ([EditorPrefs](https://docs.unity.com/en-us/engine/current/script-reference/unityeditor/editorprefs)). A custom setting is a `SettingsProvider` whose scope "determines whether the SettingsProvider appears in the Preferences window (SettingsScope.User) or the Settings window (SettingsScope.Project)"; the documented pattern stores project settings as a `ScriptableObject` created with `AssetDatabase.CreateAsset` at `Assets/Editor/MyCustomSettings.asset` ([SettingsProvider](https://docs.unity.com/en-us/engine/current/script-reference/unityeditor/settingsprovider)).

**Player settings and platforms.** Player settings "determine how Unity builds and displays your final application"; "Each platform has its own Player settings which you'll need to set for each version of your application you want to build", with shared general settings (Company Name and Product Name, which Unity "uses to locate the preferences file", Version, Default Icon, Default Cursor) ([Player settings](https://docs.unity.com/en-us/engine/6000.6/manual/unity-editor/editor-settings-reference/comp-manager-group/class-player-settings)). Build Profiles layer on top: "A build profile is a set of configuration settings you can use to build your application on a particular platform"; "Unity saves the build profile as an asset file that is ready for use with version control"; platform profiles share settings ("if you enable the Development Build setting for one platform profile, Unity will enable the setting across all the available platform profiles"), build profiles do not ([Build profiles](https://docs.unity.com/en-us/engine/6000.6/manual/building-and-publishing/build-settings/build-profiles)). A profile adds optional sections through **Add Settings**: "Player Settings" ("inherit their initial values from the global Player settings for the build profile's target platform"), "Scripting Defines" ("additive and don't override other scripting defines in your project"), "Scene List" ("scenes are automatically inherited from the global scene list"), Quality Settings (levels inherited from Edit > Project Settings > Quality) ([Build Profiles reference](https://docs.unity.com/en-us/engine/6000.6/manual/building-and-publishing/build-settings/build-profiles-reference)); "Build profile overrides are used in Play mode and within the Unity Player", and a section can be Reset "to the global values for the target platform" ([Customize settings with build profiles](https://docs.unity.com/en-us/engine/6000.6/manual/building-and-publishing/build-settings/build-profiles-override-settings)).

**How the game reads them.** The build's Data folder has `globalgamemanagers`, which "Contains core engine data, global project settings (like Quality Settings, Graphics Settings Physics settings, Tags, and Layers)", and `globalgamemanagers.assets`, which "Contains assets referenced from the globalgamemanager file. This can include ScriptableObjects, such as HDRP or URP settings"; with LZ4 compression "The compressed file for Player builds is always called data.unity3d"; "The exact layout and file formats that Unity uses might change between versions" ([Build content output](https://docs.unity.com/en-us/engine/current/manual/building-and-publishing/build-content-output)). Runtime-written settings go to `PlayerPrefs`, stored "into the user's platform registry" (Windows `HKEY_CURRENT_USER\Software\ExampleCompanyName\ExampleProductName`, macOS `~/Library/Preferences/ExampleBundleIdentifier.plist`, Linux `~/.config/unity3d/ExampleCompanyName/ExampleProductName`) ([PlayerPrefs](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/playerprefs)) or under `Application.persistentDataPath` (`%userprofile%\AppData\LocalLow\<companyname>\<productname>` on Windows) ([persistentDataPath](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/application/persistentdatapath)).

### Unreal

**The hierarchy.** "Category configuration files are loaded in the following order", later files overriding earlier: `Engine/Config/Base.ini`; `Engine/Config/Base<CATEGORY>.ini`; `Engine/Config/<PLATFORM>/Base<PLATFORM><CATEGORY>.ini`; `Engine/Platforms/<PLATFORM>/Config/Base<PLATFORM><CATEGORY>.ini`; `<PROJECT_DIRECTORY>/Config/Default<CATEGORY>.ini`; `Engine/Config/<PLATFORM>/<PLATFORM><CATEGORY>.ini`; `Engine/Platforms/<PLATFORM>/Config/<PLATFORM><CATEGORY>.ini`; `<PROJECT_DIRECTORY>/Config/<PLATFORM>/<PLATFORM><CATEGORY>.ini`; `<PROJECT_DIRECTORY>/Platforms/<PLATFORM>/Config/<PLATFORM><CATEGORY>.ini`; `<LOCAL_APP_DATA>/Unreal Engine/Engine/Config/User<CATEGORY>.ini`; `<MY_DOCUMENTS>/Unreal Engine/Engine/Config/User<CATEGORY>.ini`; `<PROJECT_DIRECTORY>/Config/User<CATEGORY>.ini`. Categories: Engine, Game, Input, DeviceProfiles, GameUserSettings, Scalability, RuntimeOptions, InstallBundle, Hardware, GameplayTags; editor-only Editor, EditorPerProjectUserSettings, EditorSettings, EditorKeyBindings, EditorLayout; desktop-only Compat, Lightmass. Sections are `[/Script/ModuleName.ClassName]` (plugins `[/Script/PluginName.ClassName]`, Blueprints `[/PathToUAsset/UAssetName.UAssetName_C]`); array keys take `!` (empty), `+` (append if absent), `-` (remove), `.` (append even if duplicate). In C++ `UCLASS(config=Game)` picks the category and `UPROPERTY(Config) int32 MyConfigVariable;` makes a member configurable; `GConfig->GetInt(...)` with `GGameIni` reads manually; `SaveConfig(CPF_Config, *PathToConfigFile)` writes. Command-line overrides (not for arrays): `-ini:<CATEGORY>:[SECTION]:<KEY>=<VALUE>`, `-Def<CATEGORY>Ini=<FILE>`, `-<CATEGORY>Ini=<FILE>`, `-iniFile=<PATH>`, `-IniBootstrap=<FILE>`; the `GetIni` console command shows a loaded value ([Configuration Files](https://dev.epicgames.com/documentation/en-us/unreal-engine/configuration-files-in-unreal-engine)).

**Project Settings window.** It "provides access to configuration options that affect" the project, how the engine behaves running it and how it runs on platforms; settings are stored in `<ProjectDirectory>\Config\DefaultEngine.ini`, platform files such as `<ProjectDirectory>\Config\Windows\WindowsEngine.ini` "must be edited manually", and Export/Import buttons back settings up to a file ([Project Settings](https://dev.epicgames.com/documentation/en-us/unreal-engine/project-settings-in-unreal-engine)). `UDeveloperSettings` is "The base class of any auto discovered settings object" (module `DeveloperSettings`, `DeveloperSettings.h`) ([DeveloperSettings](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/DeveloperSettings)). The Project section holds Description (Project Name, Project Version, Company Name), Maps & Modes (Game Default Map, Editor Startup Map, Default GameMode, Game Instance Class), Packaging and Encryption ([Project section](https://dev.epicgames.com/documentation/en-us/unreal-engine/project-section-of-the-unreal-engine-project-settings)). Editor Preferences are a separate window covering viewports, look and feel, source control, Content Browser (where "source files for textures are monitored and textures are automatically re-imported"), privacy and auto save ([Editor Preferences](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-editor-preferences)).

**Platform and device layers.** Device profiles live in a project `Config/DefaultDeviceProfiles.ini` as `[<Name> DeviceProfile]` sections with `DeviceType=IOS`, `BaseProfileName=IOS`, `+CVars=r.BloomQuality=1` and `+TextureLODGroups=(Group=TEXTUREGROUP_World, ...)`, selected at runtime by `iOSDeviceProfileSelector` / `AndroidDeviceProfileSelector` plugins; memory buckets come from `[PlatformMemoryBuckets]` in `Android/AndroidEngine.ini` ([Device profiles](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-device-profiles-in-unreal-engine)). Scalability groups come from `BaseScalability.ini` in `[UE_InstallPath]/Engine/Config`, customised by "a new `.ini` file called `DefaultScalability.ini`" in the project's Config with sections `[FoliageQuality@0]`..`@3`, driving `sg.` and `r.` CVars ([Scalability](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-reference-for-unreal-engine)). The player's own choices are `UGameUserSettings`, which "Stores user settings for a game (for example graphics and sound settings)" with `apply_settings` ("Applies all current user settings to the game and saves to permanent storage (e.g. file)"), `save_settings`, `load_settings`, `set_screen_resolution`, `set_fullscreen_mode`, `set_v_sync_enabled`, `set_overall_scalability_level` and `run_hardware_benchmark` ([GameUserSettings](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/GameUserSettings)). `[CoreRedirects]` in `DefaultEngine.ini` remaps renamed classes, enums, functions, packages, properties and structs at load time (`+ClassRedirects=(OldName="Pawn",NewName="MyPawn",InstanceOnly=true)`) ([Core Redirects](https://dev.epicgames.com/documentation/en-us/unreal-engine/core-redirects-in-unreal-engine)).

**Directories.** `Config` holds "Settings that control engine behavior. Project Config values override `Engine\Config`"; `Saved` holds autosaves, `.ini` configuration files and logs and "can be deleted and rebuilt"; `Intermediate` holds temporary build files; `DerivedDataCache` "Contains derived data files generated on-load for referenced content" ([Directory structure](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-directory-structure)).

### Bevy

**No project file.** Settings are plugin values: `AssetPlugin { file_path, processed_file_path, watch_for_changes_override, use_asset_processor_override, mode, meta_check, unapproved_path_mode }`, whose `Default` is `mode: AssetMode::Unprocessed`, `file_path: "assets"`, `processed_file_path: "imported_assets/Default"`, `meta_check: AssetMetaCheck::default()` (`#[default] Always`), `unapproved_path_mode: UnapprovedPathMode::default()` (`#[default] Forbid`, "Fails to load any asset that is unapproved"; approved folders are `file_path` and each `AssetSource`'s folder) ([lib.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/crates/bevy_asset/src/lib.rs), [AssetPlugin](https://docs.rs/bevy/latest/bevy/asset/struct.AssetPlugin.html)). `WgpuSettings` "Provides configuration for renderer initialization" (`backends`, `power_preference`, `priority`, `features`, `limits`, `adapter_name`, `force_fallback_adapter`, `instance_flags`, ...) ([WgpuSettings](https://docs.rs/bevy/latest/bevy/render/settings/struct.WgpuSettings.html)); `ImagePlugin::default_sampler` is "The default image sampler to use when ImageSampler is set to Default", with `default_nearest()` and `default_linear()` constructors ([ImagePlugin](https://docs.rs/bevy/latest/bevy/image/struct.ImagePlugin.html)).

**Layering is environment and features.** `WgpuSettings::default()` reads `WGPU_SETTINGS_PRIO`, `Backends::from_env()`, `PowerPreference::from_env()`, `Dx12Compiler::from_env()`, `Gles3MinorVersion::from_env()` and `InstanceFlags::with_env()` ([settings.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/crates/bevy_render/src/settings.rs)); the variables are wgpu's `WGPU_BACKEND` (comma-separated `vulkan`/`vk`, `dx12`/`d3d12`, `metal`/`mtl`, `gl`, `webgpu`) and `WGPU_POWER_PREF` ([Backends](https://docs.rs/wgpu-types/latest/wgpu_types/struct.Backends.html), [PowerPreference](https://docs.rs/wgpu-types/latest/wgpu_types/enum.PowerPreference.html)). The asset root resolves as `BEVY_ASSET_ROOT`, else `CARGO_MANIFEST_DIR`, else the executable's parent directory ([file/mod.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/crates/bevy_asset/src/io/file/mod.rs)). "If you define the `RUST_LOG` environment variable, the `LogPlugin` settings will be ignored" ([LogPlugin](https://docs.rs/bevy/latest/bevy/log/struct.LogPlugin.html)). Cargo features: `file_watcher` ("Enables watching the filesystem for Bevy Asset hot-reloading"), `asset_processor`, `embedded_watcher`, `dynamic_linking` ("improves iterative compile times"), `trace`, `bevy_dev_tools`, `bevy_remote`, `bevy_ci_testing`, `debug`, and the `dev` collection: "This should not be enabled for published apps!" ([cargo_features.md](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/docs/cargo_features.md)).

### Flax

**Two files.** `<project_name>.flaxproj` is the "project description and metadata file (used by editor and launcher)" ([Project structure](https://docs.flaxengine.com/manual/get-started/project-structure.html)); `ProjectInfo` holds `Name`, `ProjectPath`, `Version`, `Company`, `Copyright`, `GameTarget` ("the build target to use for the game building (final, cooked game code)"), `EditorTarget`, `References` (each `{Name, Project}`), `DefaultScene` ("The default scene asset identifier to open on project startup"), `DefaultSceneSpawn`, `MinEngineVersion`, `EngineNickname` ([ProjectInfo.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Editor/ProjectInfo.h)); the docs' example references the engine and a plugin under `$(ProjectPath)/Plugins/` (Project structure). `Content/GameSettings.json` is the "fixed location for the game settings asset" (same page); "Game Settings infrastructure is used to prepare the Flax options for the built game" and the asset is "always located" there ([Game Settings](https://docs.flaxengine.com/manual/editor/game-settings/index.html)). `GameSettings` holds `ProductName`, `CompanyName`, `CopyrightNotice`, `Version`, `Icon`, `FirstScene`, `NoSplashScreen`, `SplashScreen`, then `Guid` containers `Time, Audio, LayersAndTags, Physics, Input, Graphics, Network, Navigation, Localization, GameCooking, Streaming`, per-platform containers `WindowsPlatform, UWPPlatform, LinuxPlatform, PS4Platform, XboxOnePlatform, XboxScarlettPlatform, AndroidPlatform, SwitchPlatform, PS5Platform, MacPlatform, iOSPlatform, WebPlatform`, and `CustomSettings: Dictionary<String, Guid>` for game- and plugin-defined options ([GameSettings.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Core/Config/GameSettings.h)). Each referenced settings object is a JSON asset created from Content > New > Settings; "Settings assets are plain JSON" and "It's highly recommended to use a version control system for settings as they are text files" (Game Settings). A JSON asset on disk is `{"ID": "...", "TypeName": "MySettings", "EngineBuild": 6147, "Data": {...}}` ([Custom asset](https://docs.flaxengine.com/manual/scripting/tutorials/custom-asset.html)).

**Reading.** `GameSettings::Get()` loads `Globals::ProjectContentFolder / "GameSettings.json"` as a `JsonAsset`; `Load()` preloads each container; `GameSettingsService` (order -70) calls it at init; `CustomSettings` entries are kept only when the value is a 32-character `Guid` string; in cooked builds the per-platform getter is compiled under the platform macro ([GameSettings.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Core/Config/GameSettings.cpp)). Scripts call `GameSettings.Load()` / `GameSettings.Load<TimeSettings>()` in C# and `TimeSettings::Get()` in C++ (Game Settings). Build-time configuration is C# code: `GameTarget.Build.cs`, `GameEditorTarget.Build.cs` and `<GameModule>.Build.cs` (Project structure), and Game Cooker presets inject custom defines read in `.Build.cs` as `Configuration.CustomDefines` ([Game Cooker](https://docs.flaxengine.com/manual/editor/game-cooker/index.html)). There is no user layer in the settings model; the runtime layer is the command line (`-windowed`/`-fullscreen`, `-vsync`/`-novsync`, `-vulkan`/`-d3d12`/`-d3d11`/`-null`, `-nvidia`/`-amd`/`-intel`, `-headless`, `-mute`, `-lowdpi`, `-CoreLimit=X`) ([Command line](https://docs.flaxengine.com/manual/editor/advanced/command-line-access.html)).

## 2. Import sidecars

### Godot: options and outputs beside the source, identity in it too

"Importing will add an extra `<asset>.import` file next to the source file, containing the import configuration", and "Make sure to commit these files to your version control system" ([Import process](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/import_process.html)). `EditorFileSystem::_reimport_file` writes `[remap]` with `importer="<name>"`, `importer_version=N` (when > 0), `type="<resource type>"`, `uid="uid://..."`, then `path="..."` for one output or `path.<feature>="..."` per variant; `[deps]` with `source_file=` and `dest_files=`; and `[params]` with the options. Defaults come from the importer's option list, overlaid with `importer_defaults/<importer name>` from project settings when the importer was chosen by extension ([editor_file_system.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/file_system/editor_file_system.cpp)); the editor exposes those as the "Import Defaults" tab of Project Settings and per-asset presets (Import process). 3D scene options include Root Type/Name, Apply Root Scale, Ensure Tangents, Generate LODs, Create Shadow Meshes, Light Baking, Use Named Skins, animation Import/FPS/Trimming, an Import Script path and the Advanced Import Settings dialog; "Embedded Texture Handling" can "Extract Textures" to external images ([Import configuration](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/import_configuration.html)). Image options: Compress > Mode (Lossless, Lossy, VRAM Compressed "Stored as S3TC, BPTC or ETC2 depending on platform", VRAM Uncompressed, Basis Universal), Mipmaps > Generate, Compress > Normal Map, Process > Fix Alpha Border / Premult Alpha / Size Limit, Detect 3D > Compress To. There are no sampler options at import: "Since Godot 4.0, texture filter and repeat modes are set in the CanvasItem properties in 2D (with a project setting acting as a default)", per material in 3D, and by `sampler2D` hints in shaders ([Importing images](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)).

**Identity.** The `uid` in the `.import` is the resource UID. `ResourceUID::create_id_for_path` seeds its generator from `application/config/name`, the lowercased path and the file's MD5, so "UIDs generated for that path will be always the same within the current project"; the cache is `get_project_data_path().path_join("uid_cache.bin")` ([resource_uid.cpp](https://raw.githubusercontent.com/godotengine/godot/master/core/io/resource_uid.cpp), [ResourceUID](https://docs.godotengine.org/en/stable/classes/class_resourceuid.html)). Non-imported files that need one get a `.uid` sidecar (`ResourceLoader::should_create_uid_file`, written to `path + ".uid"`) (editor_file_system.cpp). When the editor moves a single file, `FileSystemDock::_try_move_item` also renames `old_path + ".import"` and `old_path + ".uid"`, then `_update_dependencies_after_move` calls `ResourceLoader::rename_dependencies` on every dependent file ([filesystem_dock.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/docks/filesystem_dock.cpp)).

**Missing or stale.** `ResourceFormatImporter::recognize_path` is `FileAccess::exists(p_path + ".import")`, and `_get_path_and_type` reads `path` / `path.<feature>` (matched with `OS::has_feature`), `type`, `importer`, `uid`, `group_file`, `metadata` and `valid`; an empty `type`, or an empty `path` with a missing importer, is `ERR_FILE_CORRUPT` ([resource_importer.cpp](https://raw.githubusercontent.com/godotengine/godot/master/core/io/resource_importer.cpp)). A file with no `.import` is queued as `ACTION_FILE_TEST_REIMPORT` and imported with default params; `_test_for_reimport` reimports when the `.md5` sidecar is missing ("No md5's stored for this resource"), the UID is missing ("UID not found, old format, reimport."), the destination files are gone, `importer->get_format_version() > version` ("Version changed, reimport."), the source MD5 differs, or the recorded `source_file` differs from the current path ("File was moved, reimport."); `valid=false` ("Invalid import (failed previous import)") and `keep`/`skip` importers are left alone (editor_file_system.cpp).

**Cache.** Outputs go to `get_project_data_path().path_join("imported")`, i.e. `res://.godot/imported/`, named `<basename>-<MD5 of the full path>.<ext>`, with a `.md5` sidecar holding `source_md5` and `dest_md5` (resource_importer.cpp `get_import_base_path`; editor_file_system.cpp; project_settings.cpp). The data dir is `"." + PROJECT_DATA_DIR_NAME_SUFFIX` (`"godot"`) unless `application/config/use_hidden_project_data_directory` is off; it also holds `global_script_class_cache.cfg`, `scene_groups_cache.cfg`, `uid_cache.bin` and the `editor/` subfolder (project_settings.cpp, project_settings.h, editor_paths.cpp). "committing the `.godot/` folder to the version control system is not recommended" (Import process); the editor's own `.gitignore` is `# Godot 4+ specific ignores`, `.godot/`, `/android/`, with a `.gitattributes` of `* text=auto eol=lf` ([editor_vcs_interface.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/version_control/editor_vcs_interface.cpp)); the docs list `.godot/` and `*.translation` as the files to ignore from 4.1 on ([Version control systems](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html)).

### Unity: the sidecar is the identity

"Unity creates `.meta` files for each folder and file in your project's `Assets` folder", and "The `.meta` files contain the unique ID assigned to the asset, and values for all the asset's import settings"; the ID "is an ID that Unity uses internally to reference the asset, so that it can move or rename the asset without breaking anything". "If you move or rename an asset within the Project window, Unity automatically moves or renames the corresponding `.meta` file"; outside Unity "you must move or rename the `.meta` file to match". "If an asset loses its `.meta` file, any reference to that asset is broken in your project", and "Unity generates a new `.meta` file for the moved or renamed asset as if it's a brand new asset"; a texture's materials and a script's GameObjects lose their references ([Asset metadata](https://docs.unity.com/en-us/engine/current/manual/assets-and-media/import-assets/asset-metadata)). Folder `.meta` files reconcile empty folders across VCS (same page).

**Options.** The texture importer exposes `filterMode`, `wrapMode` (`wrapModeU/V/W`), `anisoLevel`, `mipmapEnabled`, `sRGBTexture`, `textureType`, `textureCompression`, `maxTextureSize`, `isReadable` and `GetPlatformTextureSettings` / `SetPlatformTextureSettings` ([TextureImporter](https://docs.unity.com/en-us/engine/current/script-reference/unityeditor/textureimporter)); per-platform overrides are `TextureImporterPlatformSettings` with `overridden`, `maxTextureSize`, `format`, `textureCompression`, `compressionQuality`, `crunchedCompression`, `resizeAlgorithm`, `allowsAlphaSplitting`, `androidETC2FallbackOverride` ([TextureImporterPlatformSettings](https://docs.unity.com/en-us/engine/current/script-reference/unityeditor/textureimporterplatformsettings)). The Model tab has Scale Factor, Convert Units, Bake Axis Conversion, Import BlendShapes / Visibility / Cameras / Lights, Preserve Hierarchy, Sort Hierarchy By Name, Mesh Compression, Read/Write, Optimize Mesh, Generate Colliders, Keep Quads, Weld Vertices, Index Format, Normals, Tangents, Swap UVs, Generate Lightmap UVs ([Model Import Settings](https://docs.unity.com/en-us/engine/current/manual/assets-and-media/asset-types/models/importing/fbximporter-model)). "If you're developing a cross-platform project, you can override the default settings and assign different import settings on a per-platform basis" ([Importing assets](https://docs.unity.com/en-us/engine/6000.6/manual/assets-and-media/import-assets/importing-assets)). Defaults come from Presets: "assets that you can use to save and apply identical property settings", also used "to specify default settings for new components and default import settings", by type or by folder; "Presets have no effect at runtime" ([Presets](https://docs.unity.com/en-us/engine/current/manual/assets-and-media/presets)).

**Cache.** "When you modify a file in Unity, Unity doesn't modify your original source file"; "The source asset files remain unchanged, and Unity stores the internal data in the project's Library folder"; "If your project isn't open, you can safely delete the Library folder, because Unity can regenerate all its data from the Assets and ProjectSettings folders" (Importing assets). "The original file is referred to as the source asset and its imported counterpart is called an artifact"; "Each artifact file name is a GUID with no file extension" in two-character subfolders; `Library\SourceAssetDB` holds "last modified date, a hash of the file's contents, GUIDs", `Library\ArtifactDB` holds "the import dependency information, artifact meta-information and a list of artifact files"; "The platform is part of the hash the Asset Database uses to store the import results"; "Artifacts are treated as cached data because Unity can always regenerate them from the source assets, using the import settings and project settings"; "Make sure to exclude these database files from version control systems" ([Asset Database contents](https://docs.unity.com/en-us/engine/6000.6/manual/assets-and-media/asset-database/contents)). Teams share artifacts through Unity Accelerator, which "keeps copies of a team's imported assets" ([Caching assets](https://docs.unity.com/en-us/engine/6000.6/manual/assets-and-media/importing-caching-assets)).

### Unreal: no sidecar; options and source path inside the asset

Every imported asset carries an `AssetImportData` whose `source_data` is "Source file data describing the files that were used to import this asset" ([AssetImportData](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/AssetImportData)); `StaticMesh.asset_import_data` and `Texture.asset_import_data` are properties of the asset ([StaticMesh](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/StaticMesh), [Texture](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/Texture)). FBX import options: Import Translation / Rotation / Uniform Scale; Convert Scene, Force Front XAxis, Convert Scene Unit; Auto Generate Collision, Generate Lightmap UVs, Import Mesh LODs, Normal Import Method, Remove Degenerates; Material Import Method, Import Textures, Invert Normal Maps; Skeleton, Import Content Type, Import Morph Targets; Animation Length, Frame Import Range, Custom Sample Rate ([FBX Import Options](https://dev.epicgames.com/documentation/en-us/unreal-engine/fbx-import-options-reference-in-unreal-engine)). With Interchange, "An ordered list of pipelines that process an imported file" is a pipeline stack; "You can find the pipeline stack in the **Project Settings** under **Engine > Interchange**"; on reimport "Unreal Engine remembers the pipeline stack and options that were used, and displays those options"; the default pipelines are content under Engine > Plugins > Interchange Framework Content > Pipelines ([Importing with Interchange](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-assets-using-interchange-in-unreal-engine)); the project settings hold Pipeline Stacks, Default Pipeline Stack, Pipeline Configuration Dialog Class and "Show Pipeline Stacks Configuration Dialog" ([Interchange settings](https://dev.epicgames.com/documentation/unreal-engine/interchange-settings-in-the-unreal-engine-project-settings?lang=en-US)). Sampler and compression defaults are texture asset properties: `compression_settings`, `srgb`, `lod_group` ("Texture group this texture belongs to"), `filter`, `mip_gen_settings`, `lod_bias`, `max_texture_size`, `power_of_two_mode` (Texture) and `address_x` / `address_y` ([Texture2D](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/Texture2D)).

**Identity and moves.** Moving or renaming an asset "leaves a Redirector in the asset's old location" so unloaded packages can still find it; right-click **Fixup** resaves referencing packages and deletes the redirector; `ResavePackages` with `-FixupRedirectors` cleans a project; the Content Browser filters "Show Redirectors" / "Redirectors" ([Asset redirectors](https://dev.epicgames.com/documentation/en-us/unreal-engine/asset-redirectors-in-unreal-engine)). Reimport can be automatic: Editor Preferences > Loading & Saving > Auto Reimport watches "Directories to Monitor", with "Auto Create Assets", "Auto Delete Assets" (1-to-1 only) and "Detect Changes on Restart"; "it is recommended that you place all source content files alongside their relevant assets in the Content folder" ([Auto reimport](https://dev.epicgames.com/documentation/unreal-engine/reimporting-assets-automatically-in-unreal-engine?lang=en-US)).

**Cache.** "Many Unreal Engine (UE) Assets require additional derived data before you can use them"; "Content stored in the DDC is disposable, and UE can regenerate it anytime using the data stored in `.uasset` files", so it is kept "instead of checking it into source control". UE 5.4+ uses "an Unreal Zen Store DDC as a Local DDC, with a default storage location of `AppSettingsDir/Zen/Data`"; a Shared DDC "is either a network or mapped drive", set by `UE-SharedDataCachePath=[path to folder]` or Editor Preferences General > Global > Derived Data Cache > "Global Shared DDC Path"; `-ddc=noshared` disables it; `[DerivedDataBackendGraph]` in `DefaultEngine.ini` / `BaseEngine.ini` configures it; packaging "creates a `DDC.ddp` file in the `Project\DerivedDataCache` directory" ([Using the DDC](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-derived-data-cache-in-unreal-engine)).

### Bevy: the sidecar is loader or processor settings; identity is the path

`AssetMeta` is "Asset metadata that informs how an Asset should be handled by the asset system": `meta_format_version` (`META_FORMAT_VERSION = "1.0"`), `processed_info: Option<ProcessedInfo>` and `asset: AssetAction`, where `AssetAction` is `Load { loader, settings }` ("Load the asset with the given loader and settings"), `Process { processor, settings }` or `Ignore`; `ProcessedInfo` holds `hash` ("A hash of the asset bytes and the asset `.meta` data"), `full_hash` (adds "the `full_hash` of every `process_dependency`") and `process_dependencies`; it serialises with `ron::ser::to_string_pretty` ([meta.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/crates/bevy_asset/src/meta.rs)). Loader settings are the sidecar's payload: `ImageLoaderSettings { format, is_srgb, sampler, asset_usage, texture_format }`, where `sampler` is the "ImageSampler to use when rendering - this does not affect the loading of the image data" ([ImageLoaderSettings](https://docs.rs/bevy/latest/bevy/image/struct.ImageLoaderSettings.html)); `GltfLoaderSettings { load_meshes, load_materials, load_cameras, load_lights, load_animations, include_source, default_sampler, override_sampler, validate, convert_coordinates, skinned_mesh_bounds_policy, mesh_compression }`, "By default, all recognized contents of the gltf will be loaded" ([GltfLoaderSettings](https://docs.rs/bevy/latest/bevy/gltf/struct.GltfLoaderSettings.html)). Identity is the `AssetPath`, "a path to an asset in a 'virtual filesystem'": optional source, path, optional label, `"custom://some/path/scene.gltf#Mesh0"` ([AssetPath](https://docs.rs/bevy/latest/bevy/asset/struct.AssetPath.html)); the meta format has no identity field, so a moved file is a different asset.

**Missing meta.** `AssetMetaCheck::Always` (the default): "Always check if assets have meta files. If the meta does not exist, the default meta will be used"; `Paths` limits the lookup; `Never` "always use the default meta" (lib.rs, [AssetMetaCheck](https://docs.rs/bevy/latest/bevy/asset/enum.AssetMetaCheck.html)).

**Cache (processed mode).** `AssetMode::Processed`: "Assets will be 'pre-processed'. This enables assets to be imported / converted / optimized ahead of time"; "By default, this assumes the processor _has already been run_" (lib.rs). The `AssetProcessor` is "A 'background' asset processor that reads asset values from a source"; "Assets will only be re-processed if they have been changed"; a `ProcessorTransactionLog` "uses 'write-ahead logging' to make the AssetProcessor crash and failure resistant"; `initialize` "will validate transactions and recover failed transactions when necessary"; for a source with no meta it takes the default processor for the extension, else the loader's default meta, else `AssetAction::Ignore`; `write_default_meta_file_for_path` writes the default meta into the *source* reader ("we get the reader rather than the processed reader, since we want to write the meta") ([processor/mod.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/crates/bevy_asset/src/processor/mod.rs)); the example confirms "The AssetProcessor will create `.meta` files automatically for assets in the `assets` folder" ([asset_processing.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/examples/asset/processing/asset_processing.rs)). The log is `LOG_PATH = "imported_assets/log"` with `Begin <path>` / `End <path>` lines and `UnrecoverableError` ([processor/log.rs](https://raw.githubusercontent.com/bevyengine/bevy/v0.20.1/crates/bevy_asset/src/processor/log.rs)).

### Flax: no sidecar; import path, user and options inside the `.flax` file, identity too

Assets are `.flax` files (`ASSET_FILES_EXTENSION TEXT("flax")`; packages `TEXT("flaxpac")`) ([Config.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Content/Config.h)). `AssetHeader` is `ID` ("Unique asset ID", a `Guid`), `TypeName` and `Chunks`; `AssetInitData` adds `SerializedVersion`, `CustomData` and, under `USE_EDITOR`, `Metadata` ("The asset metadata information. Stored in a Json format.") and `Dependencies` ("Asset dependencies list used by the asset for tracking") ([AssetHeader.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Content/Storage/AssetHeader.h)). `CreateAssetContext::AddMeta` writes `"ImportPath"` (made relative to `Globals::ProjectFolder` when `UseImportPathRelative`, on Windows only if the drive matches) and `"ImportUsername"` (`Platform::GetUserName()`) into that JSON; a missing source logs `"Missing file '{0}'"` ([AssetsImportingManager.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/ContentImporters/AssetsImportingManager.cpp)). The model importer serialises its `Options` into the same metadata (`context.AddMeta(importOptionsMeta)`, `options.Serialize(...)`) and on reimport `TryGetImportOptions` parses the existing asset's `Metadata` to "Restore the previous settings or use default ones", else logs "Missing model import options. Using default values." ([ImportModel.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/ContentImporters/ImportModel.cpp)). `BinaryAsset::GetImportPath()` "Gets the imported file path from the asset metadata (can be empty if not available)" and `Reimport()` calls `AssetsImportingManager::Import(importPath, GetPath())`, all under `USE_EDITOR` ([BinaryAsset.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Content/BinaryAsset.h), [BinaryAsset.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Content/BinaryAsset.cpp)). The docs put it as "Every model can be re-imported (the relative path to the source file is cached)" with options Type (Model, Skinned Model, Animation, Prefab), Scale, Calculate Normals, Smoothing Normals Angle, Calculate Tangents, Optimize Meshes, Merge Meshes, Import LODs, Import Vertex Colors, Import Blend Shapes, Lightmap UVs Source, Center Geometry, Use Local Origin, Import Materials, Import Textures, Keep Material Slots on Reimport, Generate LODs, LOD Count, Triangle Reduction, Rotation, Translation, Split Objects, Object Index, Sub Asset Folder and animation options ([Importing models](https://docs.flaxengine.com/manual/graphics/models/import.html), [ModelTool.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Tools/ModelTool/ModelTool.h)); textures likewise, with `Type`, `IsAtlas`, `sRGB`, `Compress`, `GenerateMipMaps`, `FlipY`, `FlipX`, `Scale`, `Resize`, `MaxSize`, `SizeX/Y`, `PreserveAlphaCoverage`, `TextureGroup` ("The texture group for streaming (negative if unused)") and `Sprites` ([TextureTool.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Tools/TextureTool/TextureTool.h), [Textures](https://docs.flaxengine.com/manual/graphics/textures/index.html)); no sampler option exists at import.

**Registry, not cache.** The editor's registry is `Globals::ProjectCacheFolder / "AssetsCache.dat"` (cooked: `Globals::ProjectContentFolder / "AssetsCache.dat"`), entries of `AssetInfo` (ID, type name, path) plus `FileModified`; a missing file logs "Cannot find assets cache file" and marks the registry dirty; entries whose files are gone are rejected on load under `ENABLE_ASSETS_DISCOVERY` ("Enables searching workspace for missing assets", `= USE_EDITOR`); "In cooked game all assets are there and all access to registry is read-only" ([AssetsCache.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Content/Cache/AssetsCache.cpp), [AssetsCache.h](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Engine/Content/Cache/AssetsCache.h), Config.h). Because references are by `Guid`, moving a `.flax` file keeps them; the `Cache` folder is "editor local cache folder, build cache, used for thumbnails, game cooker cache and other temporary files" (Project structure) and `-clearCache` "Clears the project cache before the editor starts" (Command line).

Two observations. First, none of the four editor engines has a *settings-override* file for developers that is both project-local and ignored by default: Godot's `override.cfg` is the closest, and its docs describe it as a shipping-time mechanism as much as a developer one; Unreal's per-user layer lives outside the project (AppData, My Documents) except for the `Config/User*.ini` file; Unity's `UserSettings/` holds editor state and importer-worker tuning, not game-setting overrides. Second, debug flags are build-time everywhere: Unity's Development Build defines `DEBUG` through Script Debugging and is build-profile state; Unreal's are build configurations (Debug, DebugGame, Development, Test, Shipping); Flax's are Debug / Development / Release presets plus `-gpudebug`; Bevy's are Cargo features and profiles; Godot's are the debug/release templates and `-d`.

## 4. Shipping

### Godot

Export produces an executable plus a PCK or ZIP, or embeds the pack: `save_pack(..., p_embed)` opens the executable read-write, pads to 8 bytes and appends the pack with a trailer of the PCK size and `PACK_HEADER_MAGIC` ([editor_export_platform.cpp](https://raw.githubusercontent.com/godotengine/godot/master/editor/export/editor_export_platform.cpp)). Inside: `project.binary`, produced by `ProjectSettings::save_custom(engine_cfb, custom_map, custom_list)` with the preset's custom features and plugin features, stored as `res://project.binary` with `source_path = "res://project.godot"`; each `.import` rewritten to keep only `[remap]`, with `path.<feature>` entries kept only `if (remap_features.has(feature))` and `deps` and `params` erased, importers `"skip"` dropped and `"keep"` exporting the raw bytes; the imported files read from each remapped `path`; `.tres`/`.tscn` converted to `export-<md5>-<name>.res`/`.scn` under `editor/export/convert_text_resources_to_binary` with a `from + ".remap"` file of `[remap]\n\npath="..."`; `global_script_class_cache.cfg`, the UID cache (`ResourceUID::get_cache_file()`) and the GDExtension list forced in; directories beginning with `"."` skipped (same file). Export modes are all resources, selected scenes or resources with dependencies, all except checked, and dedicated server (visual resources replaced by placeholders); two filters add non-resource files (`.txt`, `.json`, `.csv`) or exclude a type; "Files and folders whose name begin with a period will never be included"; `--export-pack` exports only the pack ([Exporting projects](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html)). `override.cfg` is not exported unless it passes the filters or is placed beside the executable, where `_setup` looks for it (project_settings.cpp). Runtime writes go to `user://`, "guaranteed to be writable to, even in an exported project" (`%APPDATA%\Godot\app_userdata\[project_name]` or, with `use_custom_user_dir`, `%APPDATA%\[project_name]`) (Data paths). Extra PCKs load with `ProjectSettings.load_resource_pack()` and by default "the imported one will replace it" for same-named files; patch PCKs hold only changed resources ([Exporting packs](https://docs.godotengine.org/en/stable/tutorials/export/exporting_pcks.html)). Development only: `project.godot`, `.import` `[deps]`/`[params]`, `.godot/`, `export_presets.cfg`, `.godot/export_credentials.cfg`, editor settings.

### Unity

The player's Data folder holds `globalgamemanagers`, `globalgamemanagers.assets`, `resources.assets` ("all assets located within any folder named Resources ... always included in the build, regardless of whether they're directly referenced"), `level0..N` (one per Scene List entry), `sharedassets0..N`, `.resS` texture and mesh payloads, `.resource` audio and video payloads, `Resources/unity_builtin_extra` and `Resources/unity default resources` ([Build content output](https://docs.unity.com/en-us/engine/current/manual/building-and-publishing/build-content-output)). `StreamingAssets` files "are copied without modification into the Player output", reached through `Application.streamingAssetsPath` (a URL needing `UnityWebRequest` on Android and Web), and "At runtime the StreamingAssets location is read-only" ([Streaming assets](https://docs.unity.com/en-us/engine/current/manual/building-and-publishing/streaming-assets)). An `Editor` folder is "Reserved for Editor scripts ... but aren't available in Player builds at runtime"; files and folders starting with `.`, ending with `~`, named `cvs` or ending `.tmp` are never imported ([Reserved folder names](https://docs.unity.com/en-us/engine/current/manual/get-started/project-configuration/special-folders)). Build options: "Development Build" ("includes the Profiler and assertions"), "Script Debugging" ("defines the `DEBUG` scripting symbol"), "Compression Method" Default / LZ4 / LZ4HC (Build Profiles reference). Development only: `.meta`, `ProjectSettings/`, `Library/`, `UserSettings/`, `Temp/`, Presets ("no effect at runtime"), source assets (the artifact ships).

### Unreal

BuildCookRun stages: Build "compiles the executeables"; Cook "converts Assets used by the UE into ones that can be read on the platforms being deployed to"; Stage "copies the executables and content to a staging area"; Package "packages the project into a platform's native distribution format"; `RunUAT.bat BuildCookRun -project=MyProject.uproject -clientconfig=Development` ([Build operations](https://dev.epicgames.com/documentation/en-us/unreal-engine/build-operations-cooking-packaging-deploying-and-running-projects-in-unreal-engine)). Configurations: Debug, DebugGame, Development (the editor default), Test ("some console commands, stats, and profiling tools enabled"), Shipping (removes console commands, stats and profiling tools; still produces symbols with Include Debug Files) ([Build configurations](https://dev.epicgames.com/documentation/en-us/unreal-engine/build-configurations-reference-for-unreal-engine)). Packaging settings: Use Pak File (default on), Use Io Store (`.utoc` / `.ucas`), Use Zen Store, Generate Chunks, Share Material Shader Code, "Ini Key Denylist" and "Ini Section Denylist" (`.ini` keys and sections stripped when packaging), "Cook Everything in the Project Content Directory", "List of Maps to Include in a Packaged Build", "Additional Asset Directories to Cook", "Directories to Never Cook", "Additional Non-Asset Directories to Package / Copy" (relative to `Content`), "Exclude Editor Content When Cooking"; Encryption has "Encrypt Pak Ini Files" ("Encrypts all `.ini` files in the `.pak`") ([Project section](https://dev.epicgames.com/documentation/en-us/unreal-engine/project-section-of-the-unreal-engine-project-settings)). So the `Config/*.ini` files ship, merged into the pak, minus denylisted keys and sections. Chunked `.pak` files land in `Saved/StagedBuilds/[PlatformName]/[ProjectName]/Content/Paks` and "are not interchangeable between platforms" ([Cooking and chunking](https://dev.epicgames.com/documentation/en-us/unreal-engine/cooking-content-and-creating-chunks-in-unreal-engine)); the older cook page gives `<Game>/Saved/Sandboxes/Cooked-<Platform>` and `-cookonthefly` server mode ([Cooking content](https://dev.epicgames.com/documentation/en-us/unreal-engine/cooking-content-in-unreal-engine)). `GameUserSettings` saves to "persistent storage" at runtime (GameUserSettings). Development only: `Saved/`, `Intermediate/`, the DDC (unless a `DDC.ddp` is packaged), editor-only config categories.

### Bevy

An executable plus whatever the configured `AssetSource`s read: by default the `assets` folder found by `get_base_path`, which at runtime is the executable's parent directory (file/mod.rs), or `imported_assets/Default` in `AssetMode::Processed`, which "assumes the processor _has already been run_" (lib.rs). `.meta` files ship with the assets because `AssetMetaCheck::Always` reads them per load; `Never` avoids that (lib.rs). `embedded_asset!` "uses the `include_bytes` macro internally" and registers the file under the `embedded://` source, with hot reload via `embedded_watcher` ([embedded_asset](https://docs.rs/bevy/latest/bevy/asset/macro.embedded_asset.html)). Nothing else ships: settings are compiled in; the `dev` features "should not be enabled for published apps" (cargo_features.md) and "Shipping your game with dynamic linking enabled is not recommended" (Setup). Development only: the processor's `imported_assets/log`, `BEVY_ASSET_ROOT`, `CARGO_MANIFEST_DIR`, `.cargo/config.toml`.

### Flax

`GameCookerImpl::Build()` runs `ValidateStep`, `CompileScriptsStep`, `DeployDataStep`, `PrecompileAssembliesStep`, `CollectAssetsStep`, `CookAssetsStep`, `PostProcessStep`, with the configuration from `BUILD_DEBUG` / `BUILD_DEVELOPMENT` / `BUILD_RELEASE` and the cooker cache at `Globals::ProjectCacheFolder / "Cooker" / <tools>` ([GameCooker.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Editor/Cooker/GameCooker.cpp)). `ValidateStep` seeds the root set with `data.AddRootAsset(Globals::ProjectContentFolder / TEXT("GameSettings.json"))` and fails on "Missing game settings.", "Missing product name.", "Missing company name." or "Missing first scene. Set it in the game settings." ([ValidateStep.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Editor/Cooker/Steps/ValidateStep.cpp)). `DeployDataStep` registers engine shaders, default materials, models and textures as root engine assets (editor shaders such as `Shaders/Editor/VertexColors` only when the configuration is not Release; `Editor/Fonts/Roboto-Regular` unless `SkipDefaultFonts`; `Engine/Textures/Logo` only when a splash is shown), adds `AdditionalAssets`, `AdditionalScenes` and every file under `AdditionalAssetFolders`, and copies the .NET runtime into `Dotnet/` (or strips it under `SkipDotnetPackaging` / AOT); it does not copy the `.flaxproj`, `Source/` or `Cache/` ([DeployDataStep.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Editor/Cooker/Steps/DeployDataStep.cpp)). `CollectAssetsStep` walks `Asset::GetReferences` from the roots, treating textures, cube textures and shaders as leaves ([CollectAssetsStep.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Editor/Cooker/Steps/CollectAssetsStep.cpp)). `CookAssetsStep` rewrites JSON assets as LZ4-compressed binary chunk 0 ("game settings are loaded from `Content/GameSettings.json` file which is packages in one of the packages"), drops `Metadata` and `Dependencies` (`initData.Metadata.Release(); initData.Dependencies.Resize(0);`), compiles shaders per platform profile (`DirectX_SM6`, `Vulkan_SM5`, `WebGPU`, ...) honouring `ShadersNoOptimize` and `ShadersGenerateDebugData`, packs assets into `Content/Data_{N}.flaxpac` by `MaxAssetsPerPackage` and `MaxPackageSizeMB`, writes `Content/head` (version, product, company, flags, content key) and `Content/AssetsCache.dat`, and keeps an incremental `CookedHeader_{0}.bin` cache ([CookAssetsStep.cpp](https://raw.githubusercontent.com/FlaxEngine/FlaxEngine/master/Source/Editor/Cooker/Steps/CookAssetsStep.cpp)). The docs add Output Name tokens, Content Key ("Setting 0 randomizes it during building"), For Distribution, Skip Packaging, Skip .NET Runtime Packaging and the presets with named targets ([Build settings](https://docs.flaxengine.com/manual/editor/game-settings/build-settings.html)); custom JSON assets "are compressed and encrypted during game cooking" (Custom asset). Development only: `.flaxproj`, `Source/`, `Cache/` (including `AssetsCache.dat`), the import metadata (source path, user, options), the editor shaders in Release.

## 5. What this says for Fenrir

Grouped by the questions in [18-dev-time-data](../issues/18-dev-time-data.md).

- **Config structs from a project file.** Every settings store read above is a flat or shallow key tree of scalars, enums, strings and references to assets: Godot's `[section] key=value`, Unreal's `[/Script/Module.Class] Key=Value`, Flax's `{"Data": {...}}` per settings type, Unity's serialized managers. Fenrir's `RendererConfig` (`backend`, `vsync`, `msaa`, `debugValidation`, `framesInFlight`, `automaticInstancing`, `computeSkinning`, `clusteredLights`, `shadowCascades`, `shadowMapSize`), `PhysicsConfig` (`maxBodies`, `maxBodyPairs`, `maxContacts`, `collisionLayers`, `useWorkerThreads`, `interpolate`) and `AssetsConfig::root` are the same shape, so they can come from a file without changing their types; the two things the engines keep *out* of such files are host-specific state (per-developer) and code-only wiring (Bevy's plugin graph, Unreal's module list in `.uproject`, Fenrir's `ScriptingConfig::extensions`). Flax is the model to study if the answer to "same format, same registry" is yes: each settings area is a typed JSON asset with the common `ID`/`TypeName`/`Data` envelope, referenced by `Guid` from one root asset at a fixed path, read through the ordinary content pipeline, and cooked by the ordinary cooker; the cost is that the root must exist before anything else loads (`GameSettingsService` at order -70; `ValidateStep` refuses to cook without it). Godot is the model for "plain configuration with its own reader": `ConfigFile` syntax, defaults in C++ via `GLOBAL_DEF`, a binary twin for shipping.
- **Project vs scene resources.** All four editor engines put the window, the rendering backend and quality tiers, physics defaults, the input map, layer and tag names and the first scene in project settings; Fenrir's scene resources (`GLOSSARY.md`) would hold what Unreal puts in a map's World Settings and Godot in a scene's `WorldEnvironment`: per-scene environment, not device or package state. Unity's `globalgamemanagers.assets` and Flax's containers show that project settings legitimately *reference* data assets (render pipeline settings, physics settings objects) rather than inline them.
- **Layering.** The minimum every engine offers is defaults in code, a committed project file, a per-platform or per-feature override, and a command line; the richer ones add a per-user layer (Unreal `User*.ini`, Godot `override.cfg`) and an environment variable (`GODOT_EDITOR_CUSTOM_FEATURES`, `BEVY_ASSET_ROOT`, `WGPU_*`, `UE-SharedDataCachePath`). Godot's `name.feature` suffix is the cheapest platform mechanism found: one file, one lookup rule, feature tags decided at export. Unreal's twelve files are the most capable and the hardest to reason about (its docs ship a `GetIni` console command to find out where a value came from).
- **Same file or cooked.** Godot and Unreal ship the same data in another container (binary `ECFG`; `.ini` inside the pak with denylists); Flax ships the same assets cooked; Unity bakes into `globalgamemanagers`; Bevy compiles it in. No engine makes the shipped game parse the editor's text file as-is, but three of them keep the shipped form a mechanical conversion of it, which is what the map's "designed so a cooked form can follow" asks for.
- **Sidecar and identity.** The ticket's "whether it also carries the asset's stable identity" has three answers in the field: yes and it is the only identity (Unity), yes alongside the options (Godot `uid`, deterministic per path), no (Bevy: path; Unreal and Flax: inside the asset). What all sidecar engines agree on: the sidecar is committed, the editor moves it with the file, a missing sidecar yields defaults, and the imported output is cached under a content hash in an ignored folder (Godot `.godot/imported`, Unity `Library`, Bevy `imported_assets/Default`). What the engines whose imports run at load do (Bevy unprocessed mode, and Fenrir today) is read the sidecar at load, which means the sidecar ships. Sampler defaults are the one option the engines disagree on: in the sidecar in Unity and Bevy, on the asset in Unreal, in the material or scene node in Godot and Flax.
- **Per-developer file.** The named-and-ignored per-developer file the ticket asks for exists as `UserSettings/` (Unity, editor state) and `override.cfg` (Godot, any setting) and as the `User*.ini` layer (Unreal); none of the five has a per-developer asset-root file, only Bevy's environment variable and Godot's `--path`/`--main-pack`. Device selection is a command-line or environment concern everywhere, never a committed setting. Precedence, where documented, is: user file above project file (Godot, Unreal), command line and environment above both (Godot, Unreal, Bevy).
- **Caches.** Each engine names one ignored directory for everything regenerable (`.godot/`, `Library/`, `Saved/`+`Intermediate/`+`DerivedDataCache/`, `imported_assets/`, `Cache/`) and writes the ignore file itself (Godot) or documents it (Unity, Flax). Keys are content hashes of source plus settings plus platform (Unity states platform explicitly; Godot keys the *name* by path hash and checks the content hash in a `.md5` sidecar; Bevy stores `hash` and `full_hash` with dependency hashes).
