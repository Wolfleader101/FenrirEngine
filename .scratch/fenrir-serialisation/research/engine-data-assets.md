# How engines type, inherit and reference data assets

Research for [01 — How do engines type, inherit and reference data assets?](../issues/01-how-engines-type-data-assets.md).
Read 2026-11-10 against primary sources only (official docs, source at pinned tags, engine authors' writing); every claim links its source and the "Versions read" section pins what was read. Items the sources did not settle are marked **unverified**.

Engines: Godot `Resource`, Unity `ScriptableObject`, Unreal `UDataAsset` / `UPrimaryDataAsset` / `UDataTable`, Bevy typed assets, Flax JSON assets, Stride assets, O3DE `SerializeContext` assets. Structured by the ticket's six bullets; each bullet ends with the cross-engine pattern that bears on Fenrir's data asset (the map's Notes: defined from C++ and C#, files name types language-neutrally, reflection is a build-time description of plain data, Godot-style inheritance liked).

## 1. Typing

### Godot (4.7)

- A data asset is a `Resource` subclass instance saved as `.tres` (text) or `.res` (binary). Resources are "data containers" that "don't do anything on their own"; anything saved or loaded from disk is one ([Resources tutorial](https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html)). A custom type is a script `class_name BotStats extends Resource` with `@export` members, or in C# `[GlobalClass] public partial class BotStats : Resource` with `[Export]` properties and a parameterless constructor (same page; [C# global classes](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_global_classes.html)).
- **How the file names its type.** The `.tres` header is `[gd_resource type="ArrayMesh" format=3 uid="uid://dww8o7hsqrhx5"]`; `type` is "the resource's class" ([TSCN format, 4.7](https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html)). In the saver `type` is `_resource_get_class(p_resource)` (= `get_class()`, i.e. the **native** class such as `Resource`; a `MissingResource` writes its original class), and `script_class="BotStats"` is appended only `if (script.is_valid() && script->get_global_name())` ([resource_format_text.cpp @ 4.7-stable](https://github.com/godotengine/godot/blob/4.7-stable/scene/resources/resource_format_text.cpp)). The script itself is an ordinary external reference, `[ext_resource type="Script" uid="uid://…" path="res://bot_stats.gd" id="1_abc"]`, assigned in the `[resource]` body as `script = ExtResource("1_abc")` (the `type="Script"` spelling is what the editor writes; `get_save_class()` for scripts was not read in source — **unverified** beyond observation).
- **On load the script class name is not used.** `ResourceLoaderText::load()` does `Object *obj = ClassDB::instantiate(res_type);` then applies every body line through the generic `resource->set(assign, value)` path, so `script = ExtResource(...)` reaches `Object::set_script`, which "instantiates it, which calls the script's `_init()`" ([Object](https://docs.godotengine.org/en/stable/classes/class_object.html)). `script_class` is only read into a member in `open()` and consumed by `get_resource_script_class()`; `rename_dependencies()`/`set_uid()` rewrite it. So Godot's "type" on disk is *native base class + script reference*, with the global class name as an editor-facing hint used to index files by class ([resource_format_text.cpp](https://github.com/godotengine/godot/blob/4.7-stable/scene/resources/resource_format_text.cpp); [editor_file_system.cpp](https://github.com/godotengine/godot/blob/4.7-stable/editor/file_system/editor_file_system.cpp) uses `get_resource_script_class` during scanning and registers global classes via `ScriptServer::add_global_class` into the cache at `ProjectSettings::get_global_class_list_path()`).
- **One property mechanism for native, GDExtension, GDScript and C#.** Everything goes through `Object.get_property_list()` dictionaries (`name`, `class_name`, `type`, `hint`, `hint_string`, `usage`) ([Object](https://docs.godotengine.org/en/stable/classes/class_object.html)); script variables carry `PROPERTY_USAGE_SCRIPT_VARIABLE` ("distinguishes exported script variables from built-in variables"), storage is `PROPERTY_USAGE_STORAGE` "serialized and saved in the scene file (default for exported properties)" ([@GlobalScope](https://docs.godotengine.org/en/stable/classes/class_@globalscope.html)). A GDExtension C++ class registers with `GDCLASS`, `_bind_methods` (`ClassDB::bind_method`, `ADD_PROPERTY(PropertyInfo(Variant::FLOAT, "speed", PROPERTY_HINT_RANGE, "0,20,0.01"), "set_speed", "get_speed")`) and `GDREGISTER_CLASS` ([GDExtension C++ example, 4.7](https://docs.godotengine.org/en/stable/tutorials/scripting/cpp/gdextension_cpp_example.html)), so it lands in ClassDB and a file names it directly in `type=` with no script line. C# `[GlobalClass]` requires the file name to match the class name, case-sensitively (C# global classes page); `CSharpScript::get_global_name()` returns the name only when `is_global_class` ([csharp_script.cpp](https://github.com/godotengine/godot/blob/4.7-stable/modules/mono/csharp_script.cpp)).
- Type shape: a class with fields; nested resources and typed arrays (`Array[Texture]`) are first-class ([GDScript exports](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_exports.html)); the docs say Unreal DataTables "can be recreated with Resource scripts" using dictionaries of resources (Resources tutorial). Inner classes (`class` keyword) cannot be a resource's script: "its custom properties are not serialized" (same page).
- Text format versions: `FORMAT_VERSION = 4` ("PackedByteArray can be base64 encoded, and PackedVector4Array was added"), `FORMAT_VERSION_COMPAT = 3` ("New string ID for ext/subresources, breaks forward compat"), saved as 3 unless the new features are used ([resource_format_text.h](https://github.com/godotengine/godot/blob/4.7-stable/scene/resources/resource_format_text.h)); the docs still describe `format=3` for 4.x and `format=2` for 3.x (TSCN page).

### Unity (6000.3)

- `ScriptableObject` "is a serializable Unity type derived from UnityEngine.Object", lives "in the project as assets", and "The script file must have the same name as the class" ([ScriptableObject manual](https://docs.unity.com/en-us/engine/6000.3/manual/scripting/get-started/fundamental-unity-types/class-scriptable-object)). `[CreateAssetMenu]` lists it under Assets > Create ([CreateAssetMenuAttribute](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/createassetmenuattribute)).
- **How the file names its type: by script-asset GUID, not by name.** Every object is a YAML document `--- !u!<classID> &<fileID>`; "Classes defined from scripts will always have class ID 114 (MonoBehaviour)" and ScriptableObject has no class ID of its own ([class ID reference](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-scenes/text-scene-format/class-idreference); [format description](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-scenes/text-scene-format/format-description)). The type is the `m_Script: {fileID: 11500000, guid: <script .meta GUID>, type: 3}` reference to the MonoScript asset ([direct references](https://docs.unity.com/en-us/engine/6000.3/manual/assets-and-media/assets-managing-runtime/assets-direct-reference)); a real file: [Markers.asset](https://github.com/Unity-Technologies/arfoundation-samples/blob/16489599d11baf15548b1d8b632bc455c65e07ca/Assets/Scenes/Markers/Markers.asset). A MonoScript stores one type ("if the file contains multiple types, we will return null for the other types", [MonoScript.bindings.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Editor/Mono/MonoScript.bindings.cs)). Moving a class into a DLL requires rewriting `guid`/`fileID` by hand ([TryGetGUIDAndLocalFileIdentifier](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/assetdatabase/trygetguidandlocalfileidentifier)); the MD4 hash used for DLL-hosted classes is community knowledge only (**unverified**). Losing a script's `.meta` leaves "an unassigned script component" ([asset metadata](https://docs.unity.com/en-us/engine/6000.3/manual/assets-and-media/import-assets/asset-metadata)).
- **Serialisation rules**: fields only (`public` or `[SerializeField]`, not static/const/readonly); primitives, enums, Unity structs, `[Serializable]` classes/structs **inline by value**, `UnityEngine.Object` references, arrays and `List<T>`; no dictionaries, jagged/multidimensional arrays or nested containers; `[Serializable]` "isn't inherited"; inline classes cannot be null, cannot be shared, and lose polymorphism ("only parent-class fields are serialized") ([serialization rules](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/rules)). The Inspector "accesses the serialized backing field directly", never property getters ([how Unity uses serialization](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/how-unity-uses)).
- Native vs script: one language, but engine-native types have numeric class IDs and `serializedVersion:` while script-defined blocks have neither ([YAML scene example](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-scenes/text-scene-format/yamlscene-example)).

### Unreal (5.6 API / 5.9 docs)

- A DataAsset is a **class instance with `UPROPERTY` fields**: `UDataAsset` is `UCLASS(Abstract, …, Meta=(LoadBehavior="LazyOnDemand"))`, "Create a simple asset that stores data related to a particular system in an instance of this class" ([UDataAsset 5.6](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UDataAsset?application_version=5.6); [Data Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-assets-in-unreal-engine)).
- **How the file names its type.** A `.uasset` is a package: `FPackageFileSummary` ("table of contents") + name table + import table + export table ([FPackageFileSummary](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FPackageFileSummary?application_version=5.6)). Each `FObjectExport` has `ClassIndex` ("Location of the resource for this export's class"), `SuperIndex`, `TemplateIndex` ("template/archetypes") and `ScriptSerializationStartOffset` ([FObjectExport](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FObjectExport?application_version=5.6)); `ClassIndex` points at an `FObjectImport` whose `ClassPackage`/`ClassName`/`PackageName` are `FName`s — the class is named by path (`/Script/Module.Class`), never by GUID ([FObjectImport](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FObjectImport?application_version=5.6)). Object paths are `/Path/To/Package.AssetName` ([FTopLevelAssetPath](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FTopLevelAssetPath?application_version=5.6)), `FAssetData::AssetClassPath` e.g. `/Script/Engine.StaticMesh` ([FAssetData](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FAssetData?application_version=5.6)).
- **Three flavours.** `UPrimaryDataAsset` adds `GetPrimaryAssetId()` = `Type:Name` (type "usually the name of a base UClass": "the first native class going up the hierarchy or the highest-level Blueprint class") and asset bundles ([FPrimaryAssetId](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FPrimaryAssetId?application_version=5.6); Data Assets page). `UDataTable` is an "Imported spreadsheet table": `RowStruct` "must inherit from FTableRowBase", rows keyed by `FName`, CSV/JSON import with `bIgnoreExtraFields`/`bIgnoreMissingFields`/`bPreserveExistingValues`, rows addressed by `FDataTableRowHandle {DataTable, RowName}`, row pointers "should not be cached further than the local scope of a function" ([UDataTable](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UDataTable?application_version=5.6); [FDataTableRowHandle](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/FDataTableRowHandle?application_version=5.6); [Data Driven Gameplay](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-driven-gameplay-elements-in-unreal-engine)).
- **Blueprint and C++ share one reflection.** `UBlueprintGeneratedClass : public UClass` with `PropertyGuids` ("The property GUID map") ([UBlueprintGeneratedClass](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UBlueprintGeneratedClass?application_version=5.6)); a Data-Only Blueprint is "a Blueprint Class that contains only the … variables, and components inherited from its parent … essentially a replacement for archetypes" (C7 [Blueprint class assets](https://dev.epicgames.com/documentation/unreal-engine/blueprint-class-assets-in-unreal-engine)); `UUserDefinedStruct` members are identified by GUID ([UUserDefinedStruct](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/CoreUObject/UUserDefinedStruct), C7). Structs are "not part of the UObject ecosystem", not GC'd, `UPROPERTY` but no `UFUNCTION` ([Structs](https://dev.epicgames.com/documentation/en-us/unreal-engine/structs-in-unreal-engine)).

### Bevy (0.20.1)

- **Files do not name their type.** `#[derive(Asset)]` (`Asset: VisitAssetDependencies + TypePath + Send + Sync + 'static`) marks a type; the loader is chosen by extension, by requested handle type, or by loader type path, "last-registered loader wins" per extension and the requested type overrides the extension ([Asset](https://docs.rs/bevy_asset/0.20.1/bevy_asset/trait.Asset.html); [AssetLoader](https://docs.rs/bevy_asset/0.20.1/bevy_asset/trait.AssetLoader.html); [loaders.rs @ v0.20.1](https://github.com/bevyengine/bevy/blob/v0.20.1/crates/bevy_asset/src/server/loaders.rs)). The payload is plain serde (`CustomAsset ( value: 42 )`, RON's leading struct name optional) ([custom_asset example](https://github.com/bevyengine/bevy/blob/v0.20.1/examples/asset/custom_asset.rs)).
- The only engine-level type statement is the optional `.meta` sidecar: `AssetMeta { meta_format_version, processed_info, asset: AssetAction::{Load{loader: String, settings} | Process{processor, settings} | Ignore} }`, loader named by Rust type path, e.g. `processor: "LoadTransformAndSave<CoolTextLoader, CoolTextTransformer, CoolTextSaver>"` ([meta.rs](https://github.com/bevyengine/bevy/blob/v0.20.1/crates/bevy_asset/src/meta.rs); [a.cool.ron.meta](https://github.com/bevyengine/bevy/blob/v0.20.1/examples/asset/processing/assets/a.cool.ron.meta)).
- Reflection-driven files key on the **full Rust type path string**: `ReflectDeserializer` "expects a map with a single entry" like `"my_crate::MyStruct": ( value: 123 )` and returns a `Box<dyn PartialReflect>` that is a `DynamicStruct` unless the type registers `ReflectDeserialize`; `TypedReflectDeserializer` takes just the payload; `TypeRegistry::get_with_short_type_path` returns `None` if ambiguous ([ReflectDeserializer](https://docs.rs/bevy_reflect/0.20.1/bevy_reflect/serde/struct.ReflectDeserializer.html); [TypeRegistry](https://docs.rs/bevy_reflect/0.20.1/bevy_reflect/struct.TypeRegistry.html)). World files (`.scn.ron`, crate `bevy_world_serialization` in 0.20) use the same keys: `"bevy_transform::components::transform::Transform": ( translation: … )` ([load_scene_example.scn.ron](https://github.com/bevyengine/bevy/blob/v0.20.1/assets/serialized_worlds/load_scene_example.scn.ron); [serde.rs](https://github.com/bevyengine/bevy/blob/v0.20.1/crates/bevy_world_serialization/src/serde.rs)).
- Everything is Rust; game and engine crates use the same derives. No script layer.

### Flax (1.13.7014.1)

- Two asset kinds: binary `.flax` and "Json assets (files with extension .json/.scene/etc.)". Any class can be a JSON asset: C# `public class MySettings { … }`; C++ `class … : public ISerializable` with `API_AUTO_SERIALIZATION(); DECLARE_SCRIPTING_TYPE_NO_SPAWN(MySettings);` and `API_FIELD()` members ([Custom asset tutorial](https://docs.flaxengine.com/manual/scripting/tutorials/custom-asset.html)).
- **The file names its type by fully qualified name.** `JsonAssetBase::saveInternal` writes `"ID"` (Guid), `"TypeName"`, `"EngineBuild"`, `"Data"`; `DataTypeName` is "The data type name from the header. Allows to recognize the data type." ([JsonAsset.cpp](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/JsonAsset.cpp); [JsonAsset.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/JsonAsset.h)). Real file: `TypeName` = `FlaxEditor.Content.Settings.AudioSettings`, `EngineBuild` 6222 ([Audio Settings.json](https://github.com/FlaxEngine/FlaxSamples/blob/master/BasicTemplate/Content/Settings/Audio%20Settings.json), unpinned). Binary `.flax` entries also carry `Guid ID; String TypeName` ([FlaxStorage.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/Storage/FlaxStorage.h)).
- **One registry for C++ and C#.** `JsonAsset::CreateInstance` → `Scripting::FindScriptingType(DataTypeName)`; `ScriptingType { Fullname, Type: {Script, Structure, Enum, Class, Interface}, BaseTypeHandle, ManagedClass, Module (ManagedBinaryModule / NativeBinaryModule) … }`, `ScriptingTypeHandle { BinaryModule* Module; int32 TypeIndex; IsSubclassOf; IsAssignableFrom }` ([ScriptingType.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Scripting/ScriptingType.h)). C++ types get there via `API_CLASS/API_FIELD/…` parsed by Flax.Build, which "will generate the glue code" ([API tags](https://docs.flaxengine.com/manual/editor/flax-build/api-tags.html)). A missing type leaves `Instance` null and the load still succeeds; a type without `ISerializable` logs "Cannot deserialize {0} from Json Asset because it doesn't implement ISerializable interface." (JsonAsset.cpp). C# side: `assembly.GetType(dataTypeName)`, `Activator.CreateInstance`, `JsonSerializer.Deserialize` ([JsonAsset.cs](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/JsonAsset.cs)).
- Member rules (C#): instance fields/properties; non-public only with `[Serialize]`; `[NoSerialize]` excluded; properties need get+set; `[Obsolete]` properties read but not written ([ExtendedDefaultContractResolver.cs](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Serialization/JsonCustomSerializers/ExtendedDefaultContractResolver.cs)). The manual's claim that protected members serialise by default is contradicted by this resolver.

### Stride (4.4.1)

- Design-time assets are YAML `.sd*` files. The asset class carries `[AssetDescription(".ext")]`, `[AssetContentType(typeof(RuntimeType))]` and inherits `[DataContract(Inherited = true)] public abstract class Asset` with `[DataMember(-10000)] AssetId Id`, `[DataMember(-8000)] Dictionary<string, PackageVersion> SerializedVersion`, `Tags`, `Archetype` ([Asset.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/Asset.cs); [Custom assets](https://doc.stride3d.net/latest/en/manual/scripts/custom-assets.html)).
- **The file names its type with a YAML tag.** A real `.sdmat`: `!MaterialAsset` / `Id: 1bed9f3b-…` / `SerializedVersion: {Stride: 2.0.0.0}` / `Tags: []` / `Attributes:` / `  Diffuse: !MaterialDiffuseMapFeature` / `    DiffuseMap: !ComputeColor` … ([Material.sdmat @ 4.4.1](https://github.com/stride3d/stride/blob/releases/4.4.1/samples/UI/UIElementLink/Assets/Shared/Material.sdmat)). Tags come from `DataContractAliases` (a `[DataContract("Alias")]` or the class name), `TagFromType` falls back to `!{typeName}`, assemblies not processed by the assembly processor log "has not been processed by assembly processor with --serialization flags" ([YamlAssemblyRegistry.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core.Yaml/Serialization/YamlAssemblyRegistry.cs)).
- Member rules: `[DataContract]`, `[DataMember]` (`Order` "Default is -1 (default to alphabetical)"), `DataMemberMode {Default, Assign, Content, Never}`, `[DataMemberIgnore]`; "Most public fields and properties are included without it"; `[DataAlias]` is YAML/editor only ([Serialization](https://doc.stride3d.net/latest/en/manual/scripts/serialization.html)). The asset is compiled into a separate runtime object whose binary serialisers are generated post-build by `Stride.Core.AssemblyProcessor` ([README](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core.AssemblyProcessor/README.md)). Whole engine is C#: engine and game types take the same path.

### O3DE (2605.0)

- Types are identified by **UUID**: `AZ_TYPE_INFO(Class, "{UUID}")`/`AZ_RTTI(Class, "{UUID}", Bases…)`; registration is runtime C++ in a `Reflect(AZ::ReflectContext*)` function: `serializeContext->Class<MyComponent, AZ::Component>()->Version(1)->Field("SomeFloat", &MyComponent::m_someFloatField)` ("Base classes with serialized data should be listed as additional template arguments"; field names "must be unique and are not user facing") ([Reflecting for serialization](https://docs.o3de.org/docs/user-guide/programming/components/reflection/reflecting-for-serialization/); [SerializeContext.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/SerializeContext.h)).
- **Files name types by UUID or name.** ObjectStream XML: `<Class name="ClassName" field="elementName" type="{UUID}" version="N" value="…">` ([ObjectStream.cpp](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/ObjectStream.cpp)). JSON (`AZ::JsonSerialization`): `"$type"` holds the bare class name, or `"{uuid} Name"` only "if there are multiple classes sharing the same name"; load tries UUID first, then `FindClassId(Crc32(name))` filtered by `CanDowncast` against the declared base, else `FailedDueToMultipleTypeIds` ([JsonSerializer.cpp](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/Json/JsonSerializer.cpp); [JsonDeserializer.cpp](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/Json/JsonDeserializer.cpp)). Real prefab: `"$type": "EditorInspectorComponent"` next to `"$type": "{27F1E1A1-…} TransformComponent"` where the name is ambiguous ([DefaultLevel.prefab](https://github.com/o3de/o3de/blob/2605.0/Templates/DefaultProject/Template/Levels/DefaultLevel/DefaultLevel.prefab)).
- Generic data asset: `AzFramework::GenericAssetHandler<AssetType>` — "Generic implementation of an asset handler for any arbitrary type that is reflected for serialization", keyed by extension, default ObjectStream XML ([GenericAssetHandler.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzFramework/AzFramework/Asset/GenericAssetHandler.h)). Scripts (Lua, Script Canvas) consume `BehaviorContext` bindings of C++; no documented way for a script to define a `SerializeContext` type (**unverified** as an explicit statement) ([Behavior Context](https://docs.o3de.org/docs/user-guide/programming/components/reflection/behavior-context/)).

### Pattern (typing)

- Six of seven put a type name in the file; Unity puts a script-asset GUID (class name lives in the MonoScript); Bevy puts nothing (loader by extension) except in reflect-serialised files, where the key is the Rust type path. The language-neutral spellings are Flax's `Namespace.Type` from one C++/C# registry, Unreal's `/Script/Module.Class` path, O3DE's UUID-with-name, and Stride's YAML tag (alias or short name). Godot's spelling is two-level: native class in `type=` plus a script *reference*, with the script's global class name as an advisory `script_class`.
- Every engine's data asset is a **class/struct with named fields**, serialised by name; the row table (Unreal `UDataTable`) is the one tabular variant and is a struct per row. None uses a "bag of parts" for data assets; Unity's `SerializeReference` and Unreal's instanced subobjects / `FInstancedStruct` add open polymorphic parts *inside* a class.
- Minimum field vocabulary every engine supports and Fenrir's api.json does not today: strings, variable-length lists, nested objects by value, and references to other assets (Unity rules page, Godot exports, Bevy serde, Flax/Stride/O3DE reflection, Unreal `UPROPERTY`).

## 2. Inheritance and polymorphism

### Godot

- Class inheritance all the way: scripts `extends Resource` or any Resource subclass ("extending resource types other than the base Resource", Resources tutorial); script-of-script inheritance via `get_base_script()` ([Script](https://docs.godotengine.org/en/stable/classes/class_script.html)).
- **A base-typed field accepts a derived file because the file carries its own type.** `@export var resource: AnimationNode` — "The drop-down menu will be limited to AnimationNode and all its derived classes"; "Custom classes declared with `class_name` can also be used" ([GDScript exports](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_exports.html)); C#: an export typed as a global class "limits assignment to instances of that class or its derived classes", while without `[GlobalClass]` the restriction falls back to the Godot base type ([C# global classes](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_global_classes.html)). The hint is `PROPERTY_HINT_RESOURCE_TYPE` with the class name as hint string; editing "shows a popup menu of valid resource types to instantiate" ([@GlobalScope](https://docs.godotengine.org/en/stable/classes/class_@globalscope.html)).
- **Editor cost.** `EditorResourcePicker::_add_allowed_type` recurses `ClassDB::get_inheriters_from_class(p_type, …)` for engine classes and `ScriptServer::get_inheriters_list(p_type, …)` for script classes; assignment is validated by `_is_type_valid` using `ClassDB::is_parent_class` and `EditorNode::get_editor_data().script_class_is_parent`; "New" instantiates with `script_class_instance(intype)` for global classes else `ClassDB::instantiate(intype)`; `base_type` is a comma list with `-` exclusions ([editor_resource_picker.cpp](https://github.com/godotengine/godot/blob/4.7-stable/editor/inspector/editor_resource_picker.cpp); [EditorResourcePicker](https://docs.godotengine.org/en/stable/classes/class_editorresourcepicker.html)). So the cost is a global class registry (`class_name` / `[GlobalClass]`, cached by the editor file system) plus `ScriptServer` inheritance queries; GDExtension classes come free through ClassDB.
- Nested polymorphism: every `[sub_resource type=… id=…]` names its own type and may carry its own `script = ExtResource(...)`, so an `Array[Effect]` of mixed subclasses round-trips; typed arrays use `PROPERTY_HINT_TYPE_STRING` ([@GlobalScope](https://docs.godotengine.org/en/stable/classes/class_@globalscope.html); TSCN page). No composition/parts system; composition is nested resources.

### Unity

- `ScriptableObject` subclassing is plain C#; a `UnityEngine.Object`-typed field is a `{fileID, guid, type}` reference and the target carries its own `m_Script`, so a base-typed SO field holds a derived asset without any attribute ("do not require the SerializeReference attribute", [SerializeReference](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/serializereference)); the object picker filters by `objType` ([ObjectField](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/editorguilayout/objectfield)). Lucas Meijer (Unity, 2014): polymorphism "works for UnityEngine.Object references" ([Serialization in Unity](https://unity.com/blog/engine-platform/serialization-in-unity)).
- **Plain classes need `[SerializeReference]`**: field type may be a class, abstract class, interface or `System.Object`; the value must be `[Serializable]`, "Must not derive from UnityEngine.Object", "Must not be a C# Value type"; supports null, shared references within one host, cycles; "To share referenced values between multiple host objects, use ScriptableObject instead"; by-value "is more efficient … so you should only use SerializeReference in situations which require it" (SerializeReference page). On disk: a `references: version: 2 / RefIds: - rid: … / type: {class, ns, asm} / data:` block after the regular fields ([Markers.asset](https://github.com/Unity-Technologies/arfoundation-samples/blob/16489599d11baf15548b1d8b632bc455c65e07ca/Assets/Scenes/Markers/Markers.asset)); IDs are Int64, stable since 2021 LTS ("generated from a hash of time and system information", Martin Barrette, Unity, [2022 blog](https://unity.com/blog/engine-platform/serializereference-improvements-in-unity-2021-lts)).
- **Tooling cost**: no built-in subclass picker for `[SerializeReference]` fields — the docs only expose `SerializedProperty.managedReferenceValue` ([managedReferenceValue](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/serializedproperty/managedreferencevalue)); the community fills it (e.g. `[SubclassSelector]`, secondary). Without it, Unity's documented workaround is `ISerializationCallbackReceiver` with a type-tag enum and one list per subtype ([custom serialization](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/custom-serialization)).
- Composition idiom: SO-per-behaviour / flyweight data ([Unity how-to](https://unity.com/how-to/separate-game-data-logic-scriptable-objects), unsigned Unity Technologies page). Ryan Hipple's talk is Schell Games, not Unity (secondary).

### Unreal

- Subclassing `UDataAsset` in C++ or Blueprint; `TObjectPtr<T>` "is meant as a drop-in replacement for a raw pointer … serialized in the same way as a raw pointer to a UObject" (C7 [object pointers](https://dev.epicgames.com/documentation/unreal-engine/object-pointers-in-unreal-engine)); a `TObjectPtr<UWeaponData>` property takes an asset of a derived Blueprint class because Blueprint classes are `UClass` subclasses (§1) and `Cast<T>`/`IsA` are the RTTI ([Object handling](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-object-handling-in-unreal-engine)).
- `TSubclassOf<T>`: "Template to allow UClass types to be passed around with type safety", `GetDefaultObject()` ([TSubclassOf](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/TSubclassOf?application_version=5.6)). `TSoftObjectPtr<T>` "restricts the editor picker to that class" ([Async loading](https://dev.epicgames.com/documentation/en-us/unreal-engine/asynchronous-asset-loading-in-unreal-engine)); `TSoftClassPtr<T>` "works like a TSubclassOf, it can be used in UProperties for blueprint subclasses" ([TSoftClassPtr](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/TSoftClassPtr?application_version=5.6)).
- **Instanced subobjects** (polymorphic parts by value): `UPROPERTY(Instanced)` "it will be given a unique copy of the Object assigned to this property in defaults … Implies EditInline and Export"; `Export`: "exported in its entirety as a subobject block" ([UPROPERTY specifiers 5.6](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-uproperties?application_version=5.6)); `UCLASS(EditInlineNew)` "Objects of this class can be created from the Unreal Editor Property window", `DefaultToInstanced`, `HideDropdown` ([Class specifiers](https://dev.epicgames.com/documentation/en-us/unreal-engine/class-specifiers)); the editor's `PropertyCustomizationHelpers::MakeEditInlineObjectClassPicker` builds the class picker (C7 [PropertyEditor](https://dev.epicgames.com/documentation/unreal-engine/API/Editor/PropertyEditor)).
- **`FInstancedStruct`** "works similarly as instanced UObject* property but is USTRUCTs", with `InitializeAs<T>`, `Get<T>`, `GetScriptStruct()`, serialisation and `FStructReinstancer` support; header lives in CoreUObject in 5.6 ([FInstancedStruct](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FInstancedStruct?application_version=5.6)); the "moved to core in 5.5" release note is **unverified**.
- **Gameplay Tags** as composition: `FGameplayTag` "hierarchical name of the form x.y", filtered in the editor with `meta = (Categories = "Tag1.Tag2")` (C7 [GameplayTags](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/GameplayTags); [Using Gameplay Tags](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-gameplay-tags-in-unreal-engine)).
- Tooling cost is metadata: `AllowedClasses`, `ExactClass`, `AllowAbstract`, `BlueprintBaseOnly` ([Metadata specifiers](https://dev.epicgames.com/documentation/en-us/unreal-engine/metadata-specifiers-in-unreal-engine)); `MetaClass`/`MustImplement` as UPROPERTY meta keys **unverified** (documented only as `SClassPropertyEntryBox` arguments, C7).
- Epic's own guidance on inheritance for data: "With blueprint subclasses, use Data Only Blueprints (and not Data Asset instances) to properly handle data inheritance and updating the parent class" (C7 [UPrimaryDataAsset](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UPrimaryDataAsset)); Blueprint primary assets are *classes*, non-Blueprint ones are *instances* and "cannot be inherited from" ([Asset Management](https://dev.epicgames.com/documentation/en-us/unreal-engine/asset-management-in-unreal-engine)).

### Bevy

- No inheritance. `#[derive(Reflect)]` "works on all structs and enums (unions are not supported)" ([derive Reflect](https://docs.rs/bevy_reflect/0.20.1/bevy_reflect/derive.Reflect.html)); enums for closed polymorphism, `Box<dyn Reflect>` keyed by type path for open polymorphism. `Handle<A>` is typed; loading a file as the wrong `A` "will fail and an error will be printed to the logs" ([AssetServer](https://docs.rs/bevy_asset/0.20.1/bevy_asset/struct.AssetServer.html)). Tooling cost: derives only.

### Flax

- Ordinary C++/C# inheritance; `JsonAsset::GetInstance<T>()` returns the instance only if `T::TypeInitializer.IsAssignableFrom(InstanceType)` ("Returns null if asset is not loaded or loaded object has different type"), so a `JsonAssetReference<Base>` field accepts a file whose `TypeName` is a derived class ([JsonAsset.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/JsonAsset.h)); C# `struct JsonAssetReference<T> { JsonAsset Asset; T Instance => (T)Asset?.Instance; }` ([JsonAssetReference.cs](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/JsonAssetReference.cs)). Nested polymorphic C# members rely on Json.NET `TypeNameHandling.Auto` ([JsonSerializer.cs](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Serialization/JsonSerializer.cs)); the `$type` key spelling is Json.NET's (**unverified** in Flax docs). C++ needs `API_CLASS` + `API_AUTO_SERIALIZATION()` or hand-written `Serialize/Deserialize`.

### Stride

- `[DataContract(Inherited = true)]` is "implicitly inherited by all its descendant classes" ([DataContractAttribute.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core/DataContractAttribute.cs)); any base-/interface-typed member is written with the concrete type's `!Tag` (see the `!MaterialDiffuseMapFeature` value above), so derived values in base-typed slots are the normal case; alias tags resolve on read but are never emitted (YamlAssemblyRegistry.cs). Cost: `[DataContract]` and the automatic assembly-processor pass.

### O3DE

- `AZ_RTTI(Class, Uuid, Base1…)` "Up to 5 direct base classes … for rtti casting", virtual `RTTI_IsTypeOf` etc., requires a virtual destructor ([RTTIMacros.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/RTTI/RTTIMacros.h)); fields may be "Pointers, including AZStd::smart_ptr, AZStd::intrusive_ptr, and raw native pointers" to "Any class that has also been reflected" (Reflecting for serialization). JSON writes `$type` only when the runtime type differs from the declared type and from the default object's ([JsonSerializer.cpp](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/Json/JsonSerializer.cpp)); load disambiguates by `CanDowncast` to the declared base. Cost: `AZ_RTTI` + a `Class<Derived, Base>()` registration per type; no codegen.

### Pattern (inheritance and polymorphism)

- Every engine with reference-typed fields gets **"base-typed field accepts derived file" for free from the referenced file naming its own type** (Godot, Unity SO, Unreal, Flax, Stride, O3DE). The type system only has to answer *is-a* at assignment time: Godot `ClassDB::is_parent_class` + `script_class_is_parent`, Flax `IsAssignableFrom`, Unreal `IsA`, O3DE `CanDowncast`. None requires the *reflection layout* to describe inheritance; Flax and O3DE register `BaseTypeHandle`/base UUIDs as data, which is what a non-standard-layout-free description (the map's concern) needs.
- Polymorphism *by value inside* a file is where engines diverge and pay: Unity `[SerializeReference]` (no picker, no structs), Unreal `Instanced`/`EditInlineNew`/`FInstancedStruct` (metadata + class picker), Godot/Stride/O3DE/Flax (every nested value tags its own type — cheapest, because the file format is self-describing).
- Editor cost of inheritance is one query: "enumerate concrete descendants of T" (Godot `get_inheriters_from_class` + `ScriptServer::get_inheriters_list`, Unreal class picker, Flax/Stride by registry). Interfaces/traits appear only as filters (Unreal `MustImplement`/`RequiredInterface`, Unity interface-typed `SerializeReference`), never as the file's type.

## 3. References

### Godot

- **Both stable id and path, id preferred.** `[ext_resource type="Material" uid="uid://c4cp0al3ljsjv" path="res://material.tres" id="1_7bt6s"]` (TSCN page). On load the loader tries the uid first (`if has_id(uid) → path = get_id_path(uid)`), else the stored path with `WARN_PRINT(… " - ext_resource, invalid UID: " + uidt + " …")`, suppressed in the editor when `ResourceLoader::get_resource_uid(path) == uid` (resource_format_text.cpp). "Resource UIDs … allow the engine to keep references between resources intact … even if files are renamed or moved"; `ResourceUID.INVALID_ID = -1`, `uid://<invalid>` ([ResourceUID](https://docs.godotengine.org/en/stable/classes/class_resourceuid.html)). `ResourceLoader.get_dependencies()` returns `uid::path` triples with the "fallback path" third ([ResourceLoader](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html)); `ResourceLoader::_validate_local_path` turns a `uid://` string into a path before loading ([resource_loader.cpp](https://github.com/godotengine/godot/blob/4.7-stable/core/io/resource_loader.cpp)).
- **Where the uid lives.** In the `.tres`/`.tscn` header, in the `.import` file for imported assets, and since 4.4 in a `.uid` sidecar (`some_file.gd.uid`) for scripts and shaders, which "are plain text with no place to store a UID"; "make sure `.uid` files are committed" (Hugo Locurcio, [UID changes coming to Godot 4.4](https://godotengine.org/article/uid-changes-coming-to-godot-4-4/), 2025-01-15). IDs are random 63-bit (`CryptoCore::RandomGenerator`, masked `0x7FFFFFFFFFFFFFFF`), text form base-34 (`a`–`y`, `0`–`8`; the source comments its own off-by-one: "'z' and '9' characters never to be used"), and the project-wide map is persisted in `<project data path>/uid_cache.bin` ([resource_uid.cpp](https://github.com/godotengine/godot/blob/4.7-stable/core/io/resource_uid.cpp)); the editor scan registers each file's uid with `add_id`/`set_id` and writes `.uid` sidecars when `should_create_uid_file(path)` ([editor_file_system.cpp](https://github.com/godotengine/godot/blob/4.7-stable/editor/file_system/editor_file_system.cpp)). `create_id_for_path` seeds a PCG from `project_name.hash64() * path.to_lower().hash64() * md5(path).hash64()` (resource_uid.cpp).
- **What happens on move.** Inside the editor: `_find_file_owners` collects dependents from the cached `EditorFileSystem` deps, `_try_move_item` renames the file plus its `.import`/`.uid` sidecars, `_update_dependencies_after_move` calls `ResourceLoader::rename_dependencies(file, renames)` on each dependent (rewriting their stored paths), `_update_resource_paths_after_move` re-paths in-memory resources (splitting `::` sub-resource paths), `_update_project_settings_after_move` fixes `PROPERTY_HINT_FILE` settings and autoloads ([filesystem_dock.cpp](https://github.com/godotengine/godot/blob/4.7-stable/editor/docks/filesystem_dock.cpp)). Outside the editor: uids resolve after the rescan (the `.uid` sidecar must move too), and a stale path falls back with a warning until re-saved (Locurcio article).
- **Sub-resources.** `[sub_resource type="CapsuleShape3D" id="CapsuleShape3D_fdxgg"]` — no `path`, no `uid`; must precede its users; `SubResource("id")` vs `ExtResource("id")` may share an id (TSCN page). Their runtime path is `local_path + "::" + id` with `set_scene_unique_id(id)` (resource_format_text.cpp); ids are `<Class>_<5 chars>` from `generate_scene_unique_id()`, `resource_scene_unique_id` is `PROPERTY_USAGE_NONE` ([Resource](https://docs.godotengine.org/en/stable/classes/class_resource.html); [resource.cpp](https://github.com/godotengine/godot/blob/4.7-stable/core/io/resource.cpp)). "Built-in" resources are those with no path, saved inside the owner; clearing the path makes one built-in (Resources tutorial); `ResourceSaver.FLAG_BUNDLE_RESOURCES` bundles externals, `FLAG_REPLACE_SUBRESOURCE_PATHS` takes over sub-resource paths ([ResourceSaver](https://docs.godotengine.org/en/stable/classes/class_resourcesaver.html)).

### Unity

- One reference kind: `{fileID, guid, type}`. GUID "A 128-bit … ID that uniquely identifies the asset file on disk", stored in the `.meta`; fileID "A 64-bit ID that is unique to the target object within that specific asset file"; resolved to an `InstanceID` at load ([direct references](https://docs.unity.com/en-us/engine/6000.3/manual/assets-and-media/assets-managing-runtime/assets-direct-reference)). `type`: 0 NonAsset (built-ins, constant GUID), 2 SourceAsset (`.mat`, `.asset`, `.controller`), 3 PrimaryArtifact (scripts, prefabs, textures, models — resolves "to the imported artifact in the Library folder"); type 1 is pre-3.5 and auto-upgraded ([6000.7 table](https://docs.unity.com/en-us/engine/6000.7/manual/assets-and-media/assets-managing-runtime/assets-direct-reference); [FileIdentifierType](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/fileidentifiertype)). Local refs are `{fileID: N}`, none is `{fileID: 0}` (format description).
- **Move:** the `.meta` carries the GUID "so that it can move or rename the asset without breaking anything"; move outside Unity and you must move the `.meta` yourself; "If an asset loses its .meta file, any reference to that asset is broken" and Unity treats it "as if it's a brand new asset" ([asset metadata](https://docs.unity.com/en-us/engine/6000.3/manual/assets-and-media/import-assets/asset-metadata)). No path is stored in references at all.
- **Sub-assets:** `AssetDatabase.AddObjectToAsset` (only into `.asset` files, no GameObjects, then `SaveAssets`) ([AddObjectToAsset](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/assetdatabase/addobjecttoasset)); `IsMainAsset`/`IsSubAsset`, `LoadAllAssetRepresentationsAtPath` "only returns sub-assets that are visible in the Project view"; an unsaved SO referenced from a scene "serializes it directly into the scene file", governed by `HideFlags` ([HideFlags](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/hideflags); [ScriptableObject](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/scriptableobject)).
- **Addressables (2.6.0)** as the runtime address layer: `AssetReference` "A serializable reference to an addressable asset" storing `m_AssetGUID`, `SubObjectName`, `SubObjectGUID`, typed `AssetReferenceT<T>`; the catalog maps keys (address, label, GUID) to physical locations ([AssetReference](https://docs.unity3d.com/Packages/com.unity.addressables@2.6/api/UnityEngine.AddressableAssets.AssetReference.html); [catalogs](https://docs.unity3d.com/Packages/com.unity.addressables@2.6/manual/build-content-catalogs.html)). Legacy `Resources.Load(path)` is by folder-relative path ([Resources.Load](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/resources/load)).

### Unreal

- **Path, not GUID.** Hard references (`UPROPERTY` object pointer) load the target with the owner; soft references (`FSoftObjectPath` = `FTopLevelAssetPath` + `SubPathString`, "a simple struct that contains a string with the full name of an asset … handles cooking and redirects") load on demand via `FStreamableManager`/`TryLoad` ([Referencing assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/referencing-assets-in-unreal-engine); [Async loading](https://dev.epicgames.com/documentation/en-us/unreal-engine/asynchronous-asset-loading-in-unreal-engine); [FSoftObjectPath](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FSoftObjectPath?application_version=5.6)). The import table names packages and objects by `FName`; `FObjectExport` has no GUID (the "deprecated PackageGuid member" was removed, `REMOVE_OBJECT_EXPORT_PACKAGE_GUID` in `EUnrealEngineObjectUE5Version`, C7); the only GUID is the package summary's `PersistentGuid` and the 5.3 docs say "UPackage::Guid has not been used by the engine for a long time" ([FPackageFileSummary 5.3](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/UObject/FPackageFileSummary?application_version=5.3)). `PrimaryAssetId` (`Type:Name`) is the stable logical id, with project-level "Primary Asset ID, Type, and Name Redirects" (Asset Management).
- **Move/rename leaves a `UObjectRedirector`** ("redirect an object load to another object, so if an object is renamed to a different package or group, external references to the object can be found", [UObjectRedirector](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/UObjectRedirector?application_version=5.6)); "Fixup" "resaves every package that points to the redirector. The redirector is deleted only if all referencing items were resaved successfully"; batch `-run=ResavePackages -fixupredirects` ([Asset Redirectors](https://dev.epicgames.com/documentation/unreal-engine/asset-redirectors-in-unreal-engine?lang=en-US)).
- **Subobjects** are rows in the same export table (`OuterIndex`, `TemplateIndex`, `bIsInheritedInstance`), `FObjectInitializer::CreateDefaultSubobject` "instanced inside all instances of this class" ([FObjectInitializer](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FObjectInitializer?application_version=5.6)); `Instanced`/`Export` properties are "exported in its entirety as a subobject block" (UPROPERTY specifiers); `FAssetData::OptionalOuterPath` for non-top-level objects.

### Bevy

- **By path only.** `AssetPath` = optional source + path + optional `#label` (`"some/path/scene.gltf#Mesh0"`) ([AssetPath](https://docs.rs/bevy_asset/0.20.1/bevy_asset/struct.AssetPath.html)); `Handle<A>` is `Strong(Arc<StrongHandle>)` or `Uuid(Uuid, …)` ("stable-across-runs … only when an asset is explicitly registered in Assets with a UUID"); no `Weak` variant in 0.20 (`weak_handle!` deprecated for `uuid_handle!`) ([Handle](https://docs.rs/bevy_asset/0.20.1/bevy_asset/enum.Handle.html); [AssetId](https://docs.rs/bevy_asset/0.20.1/bevy_asset/enum.AssetId.html)). Moving a file breaks references; there is no GUID in files.
- Sub-assets are loader-emitted **labelled assets** (`LoadContext::add_labeled_asset`, `labeled_asset_scope`); `LoadContext::load(path)` "adds that path as a dependency"; `#[dependency]` on `Handle<T>` fields drives `VisitAssetDependencies` and `AssetEvent::LoadedWithDependencies` ([LoadContext](https://docs.rs/bevy_asset/0.20.1/bevy_asset/struct.LoadContext.html); [derive Asset macro](https://github.com/bevyengine/bevy/blob/v0.20.1/crates/bevy_asset/macros/src/lib.rs)).

### Flax

- **By Guid only.** `AssetsCache::Registry = Dictionary<Guid, Entry{AssetInfo(id, typeName, path)}>` with reverse `PathsMapping`; "In cooked game all assets are there and all access to registry is read-only" ([AssetsCache.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/Cache/AssetsCache.h)). `AssetReference`, `WeakAssetReference`, `SoftAssetReference`, `SoftObjectReference` all serialise `stream.Guid(v.GetID())` ([Serialization.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Serialization/Serialization.h)); "References to the scene objects (actors, scripts) are serialized as Guid (hex format, inlined)" ([Serialization manual](https://docs.flaxengine.com/manual/scripting/serialization/index.html)). `Content::RenameAsset` moves the file and updates the cache: "The asset's ID is not changed" ([Content.cpp](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/Content.cpp)). Hard `AssetReference<T>` loads on assignment; `SoftAssetReference<T>` "gets referenced (loaded) on actual use" ([SoftAssetReference.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/SoftAssetReference.h)). One asset per `.json`; nested data is inline JSON; `.flax` storage can hold multiple entries.

### Stride

- **Both id and URL, written together.** `AssetReference { [DataMember(10)] AssetId Id; [DataMember(20)] string Location; ToString() => $"{Id}:{Location}" // "WARNING: This should not be modified as it is used for serializing" }` ([AssetReference.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/AssetReference.cs)); runtime `UrlReference<T>` and `AttachedReference { Url, Id, IsProxy, Data }` ([UrlReference.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core.Serialization/Serialization/UrlReference.cs); [AttachedReference.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core.Serialization/Serialization/AttachedReference.cs)). Which side wins on mismatch at load: **unverified**. Composite assets embed parts with per-part `Id` and `Base = new BasePart(new AssetReference(Id, baseLocation), partId, instanceId)` ([AssetCompositeHierarchy.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/AssetCompositeHierarchy.cs)); collections carry per-item ids (`CollectionWithIdsSerializer`, `ItemId`; the on-disk `~Id` spelling **unverified**).

### O3DE

- `AssetId { Uuid m_guid; u32 m_subId; }` ("To allow easier and more consistent asset guid, we can provide asset sub ID") ([AssetCommon.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Asset/AssetCommon.h)); in a prefab: `{"assetId": {"guid": "{0CD745C0-…}", "subId": 277889906}, "assetHint": "objects/groudplane/groundplane_512x512m.azmodel"}` (DefaultLevel.prefab) — id plus a path *hint*.
- **The default source UUID is a path hash, so moving breaks it.** "The source asset UUID is generated based on the file name and scan directory relative path" ([Asset dependencies and identifiers](https://docs.o3de.org/docs/user-guide/assets/pipeline/asset-dependencies-and-identifiers/)); `CreateSafeSourceUUIDFromName` → `AZ::Uuid::CreateName(lowerVersion.c_str())` ([assetUtils.cpp](https://github.com/o3de/o3de/blob/2605.0/Code/Tools/AssetProcessor/native/utilities/assetUtils.cpp)). Mitigation is the opt-in **metadata relocation** system: for enabled extensions `UuidManager` "will generate random UUIDs and store in a metadata file", keeps `legacyUuids`, "the metadata file must be moved or renamed as well", "By default, the metadata system is disabled" ([UuidManager.h](https://github.com/o3de/o3de/blob/2605.0/Code/Tools/AssetProcessor/native/utilities/UuidManager.h); [Asset metadata](https://docs.o3de.org/docs/user-guide/assets/pipeline/metadata/)). "If a sub ID changes, any reference to that product breaks" ([Product assets](https://docs.o3de.org/docs/user-guide/assets/pipeline/product-assets/)). Resolution through `AzFramework::AssetCatalog` ("registry of asset data information (file name, size, type, etc)") ([AssetCatalog.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzFramework/AzFramework/Asset/AssetCatalog.h)).

### Pattern (references)

- Stable id *and* path: Godot (uid first, path fallback + warning), Stride (`Guid:Url`), O3DE (id + `assetHint`). Id only: Unity (GUID in `.meta`), Flax (Guid in header, registry maps path↔id). Path only: Unreal (redirector files on move), Bevy (no mechanism). The engines that moved from path to id (Godot 4.4's `.uid`, O3DE's metadata relocation) both chose **sidecar files for formats that cannot carry an id** and **kept the path as a fallback/hint for humans and diagnostics**.
- Every engine distinguishes *hard* (load with owner) from *soft* (string/id resolved on demand) references at the field-type level: Unreal `TObjectPtr` vs `TSoftObjectPtr`, Flax `AssetReference` vs `SoftAssetReference`, Unity direct vs `AssetReference`, O3DE `AssetLoadBehavior::{PreLoad, QueueLoad, NoLoad}`, Godot direct vs `@export_file` path.
- Sub-assets embedded in a file get file-local ids (Godot `::id`, Unity `fileID`, Unreal export index, Stride part `Id`, Bevy `#label`); external references to them are *owner id + local id*.

## 4. Defaults and inheritance of values

### Godot

- **Only values that differ from the default are written.** "Properties equal to their default value are not stored, to keep files compact" (TSCN page). The saver: `if (pi.usage & PROPERTY_USAGE_STORAGE …)` then `default_value = PropertyUtils::get_property_default_value(...)`; `if (default_value.get_type() != Variant::NIL && bool(Variant::evaluate(Variant::OP_EQUAL, value, default_value))) continue;`; null objects are skipped unless `PROPERTY_USAGE_STORE_IF_NULL` (resource_format_text.cpp). `PropertyUtils::get_property_default_value` asks, in order, the scene inheritance/instance state stack (nodes), then "the topmost script having a default" (`Script::get_property_default_value`), then `ClassDB::class_get_default_property_value`; floats compare with `Math::is_equal_approx` because "there might be a tiny difference in floats due to numerical error" ([property_utils.cpp](https://github.com/godotengine/godot/blob/4.7-stable/scene/property_utils.cpp)). GDScript fills `member_default_values_cache` from `@export` initialisers ([gdscript.cpp](https://github.com/godotengine/godot/blob/4.7-stable/modules/gdscript/gdscript.cpp)); C# gets them from the source generator via `ScriptManagerBridge_GetPropertyDefaultValues` into `exported_members_defval_cache` (csharp_script.cpp), and "Godot doesn't run the property's `get` to find the default. It analyzes the source" ([C# exports](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_exports.html)). Consequence: changing a script default changes every file that did not override it (same semantics as Unreal's CDO below). Custom defaults: `_property_can_revert`/`_property_get_revert` (Object page).
- **`resource_local_to_scene`**: "If `true`, the resource is duplicated for each instance of all scenes using it" (Resource page). In `SceneState::instantiate` → `make_local_resource`: non-local resources pass through; for the main scene "use the resource as is" (`configure_for_local_scene`), "For instances, a copy must be made" (`duplicate_for_local_scene`), one copy per owning scene, then `setup_local_to_scene()` on each ("Setup may be required for the resource to work properly") ([packed_scene.cpp](https://github.com/godotengine/godot/blob/4.7-stable/scene/resources/packed_scene.cpp)); override `_setup_local_to_scene()` to customise the copy (Resource page).
- **No archetype/variant for resources.** Nothing on the Resource pages describes value inheritance between resource files (absence-based); scene inheritance exists for scenes (ticket 02). Copies are explicit: `duplicate(deep)` copies `PROPERTY_USAGE_STORAGE` properties ("sets the script first", skips `script`), `duplicate_deep(DeepDuplicateMode)`; `PROPERTY_USAGE_ALWAYS_DUPLICATE`/`NEVER_DUPLICATE` override the mode; scripts are never duplicated (resource.cpp; @GlobalScope).

### Unity

- Defaults are C# field initialisers; `Reset()` is editor-only "to give good default values in the Inspector" ([Reset](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/scriptableobject/reset)); don't call Unity APIs from initialisers because they "run on a separate loading thread" ([best practices](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/best-practices)). Everything serialisable is written (no stripping of defaults is documented; the YAML examples contain every field).
- **No archetype/variant for ScriptableObjects**: Prefab Variants are defined purely in prefab terms ("A prefab variant inherits properties from a base prefab", [Prefab variants](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-gameobjects/prefabs/prefab-variants)); no SO page describes value inheritance (absence-based). Editor-time defaults for new objects are **Presets**: "You can only apply Presets in the Editor. Presets have no effect at runtime"; default presets per type; scripting support for custom SO classes ([Presets](https://docs.unity.com/en-us/engine/6000.3/manual/assets-and-media/presets); [Preset](https://docs.unity.com/en-us/engine/current/script-reference/unityeditor/presets/preset)). Missing fields taking the C# default on load is implied by `FormerlySerializedAs` and hot reload but not stated on a 6000.3 page (**unverified** as a quote).

### Unreal

- **CDO + archetype delta serialisation.** Each `UCLASS` has a Class Default Object, "a default 'template' Object, generated by the class constructor and unmodified thereafter" ([Objects](https://dev.epicgames.com/documentation/en-us/unreal-engine/objects-in-unreal-engine)); `FObjectInitializer::GetArchetype()` "Return the archetype that this object will copy properties from later" ([FObjectInitializer](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FObjectInitializer?application_version=5.6)); `UObject::SerializeScriptProperties` "When saving, only saves those properties which differ from the corresponding value in the specified 'DiffObject' (usually the object's archetype)" (C7 [SerializeScriptProperties](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/CoreUObject/UObject/SerializeScriptProperties)); `UStruct::SerializeTaggedProperties(Ar, Data, DefaultsStruct, Defaults, …)` ([SerializeTaggedProperties](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/UStruct/SerializeTaggedProperties?application_version=5.6)).
- **Changing a C++ default:** "the engine applies new defaults to loaded instances whose values still match the old default. Instances with intentionally different values keep them" (Health 100→150, a 500 stays 500) (Object handling, UE4-era text on the 5.9 page) — the direct consequence of delta serialisation.
- **Blueprint parent→child propagation**: `GetCustomPropertyListForPostConstruction` "a linked list of properties with default values that differ from the parent default object" (C7 [UBlueprintGeneratedClass](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UBlueprintGeneratedClass/GetCustomPropert-)); Data-Only Blueprints "allow those inherited properties to be tweaked and modified, but no new elements can be added" (C7 Blueprint class assets); `EditDefaultsOnly` vs `EditInstanceOnly` (UPROPERTY specifiers). Config defaults: `UPROPERTY(Config)` "saved to the .ini file associated with the class and will be loaded when created", `UDeveloperSettings` "The base class of any auto discovered settings object" (UPROPERTY specifiers; C7 [UDeveloperSettings](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/DeveloperSettings/UDeveloperSettings)).

### Bevy

- `#[reflect(Default)]` registers `ReflectDefault` so `FromReflect` starts from `Default` and fills missing fields; `#[serde(default)]` for files (derive Reflect page). No archetype/variant/diff-against-default in `bevy_asset`/`bevy_reflect`; the new `bevy_scene` is patch-based ("patches from multiple sources merge into a single `ResolvedScene`") but only through the `bsn!` macro — "Bevy does not currently have support for `.bsn` files" ([bevy_scene lib.rs](https://github.com/bevyengine/bevy/blob/v0.20.1/crates/bevy_scene/src/lib.rs)). The `AssetProcessor` can change an asset's type at process time ([asset_processing example](https://github.com/bevyengine/bevy/blob/v0.20.1/examples/asset/processing/asset_processing.rs)).

### Flax

- **Diff-against-other is the core primitive**: `virtual void Serialize(SerializeStream& stream, const void* otherObj) = 0; // "Serializes object to the output stream compared to the values of the other object instance (eg. default class object). If other object is null then serialize all properties."` ([ISerializable.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Core/ISerializable.h)); `SERIALIZE(name)` writes only when the value differs from `other`, `SERIALIZE_EPSILON 1e-7f` ([SerializationFwd.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Serialization/SerializationFwd.h)); C# `JsonSerializer.SerializeDiff(obj, other)` "Used to serialize modified properties of the object during prefab instance serialization" (JsonSerializer.cs).
- But **standalone JSON assets save fully**: `JsonAsset::OnGetData` calls `Serialize(writer, nullptr)`; `other` is non-null only for prefab-linked scene objects, where `SceneObject::Serialize` writes `PrefabID`/`PrefabObjectID` instead of `TypeName` and diffs against `Prefab::GetDefaultInstance()` ("read-only and are used internally for objects serialization (prefab diff)") ([SceneObject.cpp](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Level/SceneObject.cpp); [Prefab.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Level/Prefabs/Prefab.h)). No archetype for JSON assets; defaults are field initialisers.

### Stride

- **Archetypes with per-member override markers.** "An archetype is a master asset that controls the properties of assets you derive from it"; "Overridden and unique properties are white, and inherited (identical) properties are gray"; "Reset to base value"; "Clear archetype"; derived-of-derived allowed ([Archetypes, 4.3 docs](https://doc.stride3d.net/4.3/en/manual/game-studio/archetypes.html)). Mechanism: `Asset.Archetype` (`AssetReference`), `CreateDerivedAsset` sets it (Asset.cs); `enum OverrideType { Base = 0 "taken from a base value or this instance if no base (default)", New = 1 "overridden locally. Base value is ignored.", Sealed = 2 "cannot be changed by inherited instances" }`, read/written per member on the YAML DOM by `DynamicYamlMapping.GetOverride/SetOverride`, rendered by `OverridePostfixes.ToText` ([OverrideType, 4.2 API](https://doc.stride3d.net/4.2/en/api/Stride.Core.Reflection.OverrideType.html)); the literal postfix characters are **unverified** at 4.4.1. Upgraders also process `~Base`/`~BaseParts` sub-documents ([AssetUpgraderBase.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/AssetUpgraderBase.cs)). Whether the YAML saver omits default-valued members: **unverified**.

### O3DE

- **JSON strips defaults**: the serializer starts from a default-constructed object "to avoid storing default values"; `Store(...)` takes a default object to compare against; `JsonSerializerSettings::m_keepDefaults` (default `false`); pointer default `"{}"` means "creating a new default instance"; containers "are always considered to be empty" ([JsonSerialization.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/Json/JsonSerialization.h); [JSON serialize/deserialize](https://docs.o3de.org/docs/user-guide/programming/serialization/json-serialize-deserialize/)). ObjectStream XML writes every field. `CreatePatch`/`ApplyPatch` exist (prefab overrides; mechanics **unverified**). No archetypes for data assets; defaults are member initialisers.

### Pattern (defaults)

- **Diff-against-default is the majority**: Godot (per-property default lookup through script then ClassDB), Unreal (archetype/CDO delta), O3DE JSON (default-constructed object), Flax (for prefab instances), Stride (archetype override markers). Unity and Bevy write everything. Diff-against-default makes a type's declared default part of the file's meaning: changing it silently changes every file that did not override (Unreal documents this explicitly; Godot's code implies it). Fenrir's api.json already carries per-field defaults, which is exactly the input this needs.
- Value inheritance *between files* exists in three forms: Unreal Data-Only Blueprint classes (a child class whose CDO delta-serialises against the parent CDO), Stride archetypes (derived asset + per-member `Base/New/Sealed`), Flax/Unity/Godot prefab-or-scene instances (scene-level only; nothing for plain data assets). Godot's `local_to_scene` is not inheritance but *per-instance copy-on-instantiate*.

## 5. Lifecycle

### Godot

- **Loading**: `load()`/`preload()` are synchronous; `preload` needs a constant path and is GDScript-only (Resources tutorial). Threaded: `load_threaded_request(path, type_hint, use_sub_threads, cache_mode)` → poll `load_threaded_get_status` (`THREAD_LOAD_IN_PROGRESS/FAILED/LOADED`, progress 0–1) → `load_threaded_get` blocks if unfinished ([ResourceLoader](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html)); implemented on `WorkerThreadPool` with `LOAD_THREAD_DISTRIBUTE` when sub-threads are requested and a cycle detector ("CYCLE: Stealing on thread…") (resource_loader.cpp). `UDataAsset`-style laziness is absent: exported resource fields "become dependencies of the instance, so referenced resources load with the scene"; for on-demand loading use `@export_file` paths (GDScript exports).
- **Sharing**: "The engine keeps a global cache of all loaded resources, referenced by paths"; a resource "only loads it once"; `ResourceCache::resources` is `HashMap<String, Resource*>`; `set_path` fails with "Another resource is loaded from path '%s' (possible cyclic resource inclusion)" unless `take_over_path` (Resource page; resource.cpp). `CACHE_MODE_IGNORE/REUSE/REPLACE/IGNORE_DEEP/REPLACE_DEEP`; REPLACE refreshes cached objects of matching type in place (ResourceLoader page; `old_res->copy_from(load_task.resource)` in resource_loader.cpp). Freed when unreferenced (`RefCounted`); "In C#, resources will not be freed instantly after they are no longer in use" (Resource page).
- **Hot reload (editor)**: `EditorFileSystem::_scan_fs_changes` queues `ACTION_FILE_RELOAD` on mtime change, `_update_scan_actions` reloads only `if (ResourceCache::has(path))`, then `emit_signal("resources_reload", reloads)` (editor_file_system.cpp) → `EditorNode::_resources_changed` → `res->reload_from_file()` for non-imported resources (imported ones go through `_resources_reimported`) ([editor_node.cpp @ 4.7-stable](https://github.com/godotengine/godot/blob/4.7-stable/editor/editor_node.cpp)) → `Resource::reload_from_file` loads with `CACHE_MODE_IGNORE` and `copy_from(s)`, which requires the same class, calls `reset_state()`, copies every storage property except `resource_path`, assigns sub-resources by reference, and emits `changed` once (resource.cpp). So the **shared instance keeps its identity**; holders see the `changed` signal ("Emitted when the resource changes, usually when one of its properties is modified", Resource page). No file watcher at runtime; games reload explicitly with `CACHE_MODE_REPLACE`.
- **Script shape change**: `GDScriptLanguage::reload_scripts` captures `instance->get_property_state(state)` per instance, detaches (`set_script(Variant())`), reloads, then "//restore state if saved" via `script_inst->set(name, value)` — `set()` returns false for names that no longer exist and the result is ignored, so removed/renamed members are **silently dropped**; if compilation fails, `placeholder_fallback_enabled` keeps values on a `PlaceHolderScriptInstance` via `property_set_fallback` ([gdscript.cpp](https://github.com/godotengine/godot/blob/4.7-stable/modules/gdscript/gdscript.cpp)); `Script.reload(keep_state)` "Reloads the script's class implementation" (Script page). C#: editor-only (collectible assemblies are disabled in the player); `CSharpInstanceBridge_SerializeState` → `StateBackup{properties, event_signals}` keyed by object id → unload → reload → `DeserializeState`; placeholders if the reload fails (csharp_script.cpp). GDExtension: `reloadable = true` "lets the editor reload the extension after recompiling … only for debug builds" (GDExtension C++ example).

### Unity

- "When a ScriptableObject is referenced from a field on a MonoBehaviour, it is loaded automatically" and "there is one copy of the data in memory"; Unity "loads the complete graph into memory so the root object functions correctly" ([ScriptableObject](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/scriptableobject); ScriptableObject manual; direct references). `OnEnable` "Called when the object is loaded" (also on every domain reload, scene load and first Project-window selection), `OnDisable`, `OnDestroy` ([OnEnable](https://docs.unity.com/en-us/engine/current/script-reference/unityengine/scriptableobject/onenable)). `Resources.Load` is synchronous; Addressables "uses asynchronous operations" with reference counting ("every time you load an asset, you must also release it") ([get started](https://docs.unity3d.com/Packages/com.unity.addressables@2.6/manual/get-started-use-addressable.html); [memory management](https://docs.unity3d.com/Packages/com.unity.addressables@2.6/manual/MemoryManagement.html)).
- Editor vs player: "In the Unity Editor, you can save data to ScriptableObjects in Edit mode and Play mode. In a standalone Player at runtime, you can only read saved data" (ScriptableObject manual); script edits need `EditorUtility.SetDirty`.
- **Hot reload = domain reload**: "Unity serializes and stores all variables in all loaded scripts" → reload → "restores them to their original, pre-serialization values"; private fields are serialized for this even without `[SerializeField]`; "Unity never restores static variables" ([how Unity uses serialization](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/how-unity-uses)); with domain reload disabled, statics and non-serialized fields leak between Play sessions "including … ScriptableObjects" ([domain reloading](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/code-reloading-editor/domain-reloading)). `ISerializationCallbackReceiver` runs "on a different thread from most of the Unity API" ([ISerializationCallbackReceiver](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/iserializationcallbackreceiver)); `Instantiate` = serialize → create → deserialize (how-unity-uses).

### Unreal

- `StaticLoadObject` "Find or load an object by string name" (sync) ([StaticLoadObject](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/StaticLoadObject?application_version=5.6)); `LoadPackageAsync` "Non-blocking" ([LoadPackageAsync](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/LoadPackageAsync?application_version=5.6)); `FStreamableManager::RequestAsyncLoad` "is the primary streamable operation", "keeps hard references to any assets it loads until the delegate is called" ([RequestAsyncLoad](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/FStreamableManager/RequestAsyncLoad?application_version=5.6); Async loading); `UAssetManager::LoadPrimaryAssets` with bundles (`meta=(AssetBundles="…")` on `TSoftObjectPtr` properties), loaded assets "stay in memory until explicitly unloaded"; "By default, only UWorld Assets (levels) are Primary" ([LoadPrimaryAssets](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UAssetManager/LoadPrimaryAssets?application_version=5.6); Asset Management). `UDataAsset` is `LoadBehavior="LazyOnDemand"` (§1).
- One instance per object path (`LoadObject` "performs the FindObject lookup internally", Referencing assets); GC "builds a reference graph from a root set … Keep a UPROPERTY reference to any object you need to survive" (Object handling). Hooks: `PostLoad` "not called for newly-created objects" ([PostLoad](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/UObject/PostLoad?application_version=5.6)), `PreSave` ([PreSave](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/UObject/PreSave?application_version=5.6)), `PostEditChangeProperty`, `UDataTable::OnDataTableChanged` + `FTableRowBase::OnDataTableChanged` "Called on every row when the owning data table is modified" (UDataTable; FTableRowBase).
- **Class shape change**: Live Coding patches binaries while running; **Object Reinstancing** "replaces existing object instances so that large-scale changes in their code can take effect"; "values set in the constructor implemented in the .cpp file will not update in existing instances" but header-initialised values do ([Live Coding](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime)); `IReload::Reinstance()`, `FBlueprintCompilationManager::ReinstanceStruct` "Safely updates all instances using the provided UUserDefinedStruct" (C7). "Added properties get CDO defaults on load, and removed ones are ignored" (Object handling).

### Bevy

- `AssetServer::load` "will not block", returns an existing handle if loaded; `wait_for_asset`; `add`/`add_async` for runtime assets (AssetServer page). One `Assets<A>` slot per path; strong handles ref-counted; `AssetEvent::{Added, Modified, Removed, Unused ("last Handle::Strong … dropped"), LoadedWithDependencies}` ([AssetEvent](https://docs.rs/bevy_asset/0.20.1/bevy_asset/enum.AssetEvent.html)). Hot reload: `AssetPlugin.watch_for_changes_override`, off "unless the `watch` cargo feature is set … or a specific watcher like `file_watcher` is enabled"; modified files re-run the loader and emit `Modified` ([AssetPlugin](https://docs.rs/bevy_asset/0.20.1/bevy_asset/struct.AssetPlugin.html)). Type shape change = Rust rebuild; serde errors on missing fields unless `#[serde(default)]`.

### Flax

- `Content::LoadAsync` returns immediately and loads on another thread; `Content::Load` = `LoadAsync` + `WaitForLoaded` (30 s default); `GetAsset` returns only already-loaded; `AssetsUnloadInterval` "The time after asset with no references will be unloaded"; `GetReferencesCount` "Asset will be automatically unloaded when this reaches zero"; `LoadAsync(Guid)` checks `Assets.TryGet(id)` so **one instance per Guid** ([Content.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/Content.h); [Asset.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/Asset.h); Content.cpp). Events `Asset::Loaded`, `Reloading` ("when asset start reloading (e.g. after reimport)"), `Unloaded`; `JsonAsset::OnScriptsReloadStart/OnScriptsReloaded` destroy and recreate `Instance` on C# hot reload (JsonAsset.cpp); "Might be null if asset was loaded before binary module with that asset was loaded" (JsonAsset.h).
- Script hot reload (maintainer blog, 2018): "Flax serializes all the scene objects (actors, scripts)" to a temp scene → GC → unload only `Game`/`Game.Editor` assemblies → load new → reload temp scene; "Editor state is untouched" ([Flax Facts #16](https://flaxengine.com/blog/flax-facts-16-scripts-hot-reload/)). Shape change therefore goes through a JSON round-trip of every object.

### Stride

- `ContentManager.Load<T>(url)`: "If the asset is already loaded, it just increases the reference count of the asset and return the same instance"; `Get<T>` doesn't count; `Unload`; `Reload(obj, newUrl)` "If possible, same recursively referenced objects are reused"; `PublicReferenceCount` vs `PrivateReferenceCount` ([ContentManager.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core.Serialization/Serialization/Contents/ContentManager.cs); [ReferenceCounting.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/core/Stride.Core.Serialization/Serialization/Contents/ContentManager.ReferenceCounting.cs)). `LoadAsync` **unverified**. No runtime hot reload documented beyond `Reload`; the editor rebuilds through the asset compiler; "If you change the runtime class, delete … obj/stride and bin/db" (Custom assets).

### O3DE

- `AssetManager::GetAsset(id, type, loadBehavior)` "this is an async operation, the asset will not be loaded after the call"; `AssetLoadBehavior { PreLoad (parent not ready until it loads), QueueLoad (auto load, parent doesn't wait), NoLoad (call Asset<T>::QueueLoad), Default = QueueLoad }`, meaningful "only when the Asset<T> is saved to disk"; one `Asset` per `AssetId`; `AssetBus::OnAssetReady` "loaded, patched and ready" ([AssetManager.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Asset/AssetManager.h); AssetCommon.h).
- Hot reload: the Asset Processor pushes change notifications; `AssetCatalog::AssetChanged` re-registers and calls `AssetManager::Instance().ReloadAsset(assetId, …)`; `OnAssetReloaded` "usually in tool mode … should not be called in final build"; `ReloadAssetFromData` ("Ownership … transferred"), `AssignAssetData` ("Listeners will be notified") — i.e. a **new `AssetData` object replaces the old**, holders are notified ([AssetCatalog.cpp](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzFramework/AzFramework/Asset/AssetCatalog.cpp); AssetManager.h). Type shape change = C++ rebuild + version converters (§6).

### Pattern (lifecycle)

- **One instance per file identity, shared, ref-counted** everywhere (Godot path cache, Unity InstanceID, Unreal object path, Bevy `Assets<A>`, Flax Guid, Stride URL, O3DE AssetId). Explicit duplication is the exception (Godot `duplicate`, `local_to_scene`; Unreal `Instanced`).
- Loading is sync-by-default with an async path in every engine; Unreal and O3DE encode hard/soft *per field* so the loader can decide; Godot and Unity load the whole dependency graph with the owner.
- Two hot-reload designs: **mutate in place and signal** (Godot `copy_from` + `changed`; Unreal editor edits + `PostEditChangeProperty`; Unity reimport) vs **replace the object and notify holders** (O3DE `AssignAssetData`, Bevy `Modified`, Flax `Reloading`/`Loaded`). In-place reload needs a same-class check and a `reset_state`; replacement needs every holder to hold a handle, not a pointer.
- Script/type shape change is uniformly **"serialise instances to a property bag by name → swap code → restore by name, drop what no longer fits"** (Godot GDScript/C#, Unity domain reload, Flax temp scene, Unreal reinstancing with tagged properties). A file-format-level property bag is what makes this possible.

## 6. Versioning

### Godot

- **File format**: `format=` in the header; `if (format_version > FORMAT_VERSION)` → "Saved with newer format version" (`ERR_FILE_UNRECOGNIZED`); older formats are read directly, with no per-version migration code in the text loader (resource_format_text.cpp; header version comments in resource_format_text.h).
- **Class renames**: `ClassDB::add_compatibility_class("Spatial", "Node3D")`, `("SpatialMaterial", "StandardMaterial3D")`, `("StreamTexture", "CompressedTexture2D")`, … under `#ifndef DISABLE_DEPRECATED` ("Renamed in 4.0.", "Keep alphabetical ordering…") ([register_scene_types.cpp](https://github.com/godotengine/godot/blob/4.7-stable/scene/register_scene_types.cpp)); `ClassDB::_instantiate_internal` falls back to `compat_classes` when a class is unknown ([class_db.cpp](https://github.com/godotengine/godot/blob/4.7-stable/core/object/class_db.cpp)), and `get_resource_type` applies `get_compatibility_remapped_class` (resource_format_text.cpp). Only 3.x→4.0 renames exist; no 4.x→4.y entries.
- **Property renames: nothing.** The loader calls `resource->set(assign, value)` without checking the result; `Object.set`: "If the property does not exist or the given `value`'s type doesn't match, nothing happens" (Object page) — so a renamed, removed or re-typed property's value is **silently dropped** and disappears on the next save. There is no `FormerlySerializedAs`. The mechanism available is `_set(property, value)` returning `true` for a legacy name (Object page); it is not documented as a migration recipe. Whole-project 3→4 migration is textual rewriting by the Project Converter from `RenamesMap3To4` tables (`class_renames`, `gdscript_properties_renames`, `csharp_properties_renames`, `project_settings_renames`, `builtin_types_renames`, …) ([renames_map_3_to_4.h](https://github.com/godotengine/godot/blob/4.7-stable/editor/project_upgrade/renames_map_3_to_4.h)).
- **Unknown types are preserved**: when `ClassDB::instantiate(type)` fails and missing-resource creation is enabled, the loader creates a `MissingResource`, `set_original_class(type)`, `set_recording_properties(true)` while reading; the saver writes recorded properties back (`pi.usage & PROPERTY_USAGE_STORAGE || missing_resource_properties.has(pi.name)`) and the original class name; a `MissingResource` value in a live parent is parked in `META_MISSING_RESOURCES` metadata and restored on save if the live value is null (resource_format_text.cpp; [missing_resource.h](https://github.com/godotengine/godot/blob/4.7-stable/core/io/missing_resource.h)). A missing *script* file yields a placeholder `Resource` tagged `__load_path__` (tools builds) — whether the script's properties survive a resave is decided in `Object::set_script` (not read; **unverified**). A script that fails to *compile* keeps values on a placeholder instance (§5).
- Because defaults are stripped on save (§4), changing a script's default retroactively changes old files; there is no stored "schema version" for script-defined types (nothing like `EngineBuild` or `serializedVersion` is written for script properties — absence in the saver code).

### Unity

- `[FormerlySerializedAs("oldName")]` "rename a field without losing its serialized value. This is an Editor-only attribute" ([FormerlySerializedAsAttribute](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/serialization/formerlyserializedasattribute)); not supported at runtime (how-unity-uses). Missing/extra/re-typed fields silently defaulting or dropping is not stated on a 6000.3 page (**unverified** as a quote); best-practices only says to serialize "the smallest possible set of data … to maintain backwards compatibility". `ISerializationCallbackReceiver` is the custom hook (documented for unsupported types; migration use is extrapolation).
- `[SerializeReference]` missing types: "Unity replaces the instance with null, but the serialized information is preserved"; `ManagedReferenceMissingType { assemblyName, className, namespaceName, referenceId, serializedData }` "can aid in migrating data to new types"; restored on domain reload if the type returns ([ManagedReferenceMissingType](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/managedreferencemissingtype); 2022 blog). Moved/renamed classes: `[MovedFrom(autoUpdateAPI, sourceNamespace, sourceAssembly, sourceClassName)]` — "Serialization by reference of plain C# classes needs to be informed of classes being renamed"; with `autoUpdateAPI == false` renames are honoured "*ONLY* by the serialization system" ([UpdatedFromAttribute.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Runtime/Export/Scripting/APIUpdating/UpdatedFromAttribute.cs)). Engine types carry `serializedVersion:` in YAML; script blocks do not (YAML scene example). The API Updater rewrites scripts/DLLs for `UnityUpgradable`-marked APIs ([API Updater](https://docs.unity.com/en-us/engine/current/manual/upgrade-guides/apiupdater)).

### Unreal

- **Three version layers**: engine version (assets from a newer engine "do not appear in the Content Browser, and their references are treated as null"); engine object version (`EUnrealEngineObjectUE5Version`, "The engine refuses to load any package with a version higher than its own"); **object-level custom versions** keyed by `FGuid`: register with a global `FCustomVersionRegistration(GUID, LatestVersion, "Name")`, call `Ar.UsingCustomVersion(GUID)` in `Serialize`, branch on `Ar.CustomVer(GUID)` (returns -1 if never recorded) — e.g. `if (Ar.CustomVer(FFrameworkObjectVersion::GUID) < FFrameworkObjectVersion::WheelOffsetIsFromWheel) bDeprecatedSpringOffsetMode = true;` ([Versioning of Assets and Packages](https://dev.epicgames.com/documentation/en-us/unreal-engine/versioning-of-assets-and-packages-in-unreal-engine?application_version=5.6), body stamped 5.0.3; [FCustomVersion](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/FCustomVersion?application_version=5.6); [FCustomVersionRegistration](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/FCustomVersionRegistration?application_version=5.6)). Per-package versions live in `FPackageFileSummary::CustomVersionContainer`; `FPackageFileVersion` = UE4 + UE5 file versions ([FPackageFileVersion](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/FPackageFileVersion?application_version=5.6)).
- **Tagged property serialisation** tolerates shape changes: `FPropertyTag { Name, Type, TypeName, StructName, StructGuid, EnumName, InnerType, ValueType, Size, ArrayIndex, PropertyGuid, … }` "A tag describing a class property, to aid in serialization" ([FPropertyTag](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FPropertyTag?application_version=5.6)); `SerializeTaggedProperties` "using property tags to handle mismatches"; "Added properties get CDO defaults on load, and removed ones are ignored" (Object handling). Type changes of structs: `ICppStructOps::SerializeFromMismatchedTag` "Serializes the struct from a different property tag" opted in via `TStructOpsTypeTraits` ([ICppStructOps](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/UScriptStruct/ICppStructOps?application_version=5.6)); a plain property whose type changed without a hook is dropped (**inferred**).
- **Core Redirects** (`DefaultEngine.ini [CoreRedirects]`): `+ClassRedirects=(OldName="/Script/MyModule.MyOldClass",NewName="/Script/MyModule.MyNewClass")`, `+StructRedirects`, `+EnumRedirects=(…,ValueChanges=(("NumberTwo","LetterB")))`, `+FunctionRedirects`, `+PropertyRedirects=(OldName="MyOldActor.OldIntProperty",NewName="MyNewActor.NewIntProperty")`, `+PackageRedirects=(…,Removed=true)`; "Renamed properties without a redirect don't migrate their data"; resave then delete the redirect ([Core Redirects](https://dev.epicgames.com/documentation/en-us/unreal-engine/core-redirects-in-unreal-engine); [FCoreRedirects](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/CoreUObject/FCoreRedirects?application_version=5.6)). Gameplay tags have their own `GameplayTagRedirects`.
- Deprecation idiom: `_DEPRECATED` suffix + `#if WITH_EDITORONLY_DATA`, migrated once in `PostLoad` ("Converted on PostLoad", C7 engine examples; C7 [sparse class data](https://dev.epicgames.com/documentation/unreal-engine/sparse-class-data-in-unreal-engine)); `UE_DEPRECATED(Version, "message")` for code.

### Bevy

- Nothing built in: no version field in asset files (only `meta_format_version: "1.0"` in `.meta`); renames/removals are serde's `#[serde(alias)]`, `#[serde(rename)]`, `#[serde(default)]`, `#[serde(skip)]`. Reflect-serialised files key on type paths, so renaming a type or crate renames the key; `#[type_path = "my_crate"]` pins it; `#[reflect(skip_serializing)]` hides a field from files (derive Reflect page; meta.rs).

### Flax

- JSON is tolerant: `DESERIALIZE_MEMBER`/`DeserializeIfExists` skip missing keys; unknown keys are ignored. Every JSON asset carries `EngineBuild`, surfaced as `ISerializeModifier::EngineBuild` "Number of engine build when data was serialized. Useful to upgrade data from the older storage format." ([ISerializeModifier.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Serialization/ISerializeModifier.h); [C++ serialization](https://docs.flaxengine.com/manual/scripting/cpp/serialization.html)).
- Documented recipes ([Refactoring and renaming](https://docs.flaxengine.com/manual/scripting/advanced/refactoring-renaming.html)): renamed field → `[JsonProperty("PlayerSpeed")] public float Speed;`; moved/removed field → `[Serialize, Obsolete, NoUndo] private float WalkableRadius { get => throw…; set { Surface.WalkRadius = value; ContentDeprecated.Mark(); } }` (C++: `API_PROPERTY(Attributes="Serialize, Obsolete, NoUndo")` + `MARK_CONTENT_DEPRECATED()`); `ContentDeprecated.Mark` makes the editor resave in the new format. Binary assets: `BinaryAssetUpgrader : IAssetUpgrader` with `{CurrentVersion, TargetVersion, UpgradeHandler}` steps ([BinaryAssetUpgrader.h](https://github.com/FlaxEngine/FlaxEngine/blob/1.13.7014.1/Source/Engine/Content/Upgraders/BinaryAssetUpgrader.h)); chaining **unverified**. A `TypeName` that no longer resolves yields `Instance == null` silently; no type-rename map found (**unverified**).

### Stride

- `[AssetFormatVersion(name, version, minUpgradableVersion)]` stored per dependency as `SerializedVersion: {Stride: 2.0.0.0}` (Asset.cs; [AssetFormatVersionAttribute.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/AssetFormatVersionAttribute.cs)); `[AssetUpgrader(name, startMinVersion, targetVersion, typeof(Upgrader))]` (`AllowMultiple`) with `IAssetUpgrader.Upgrade(context, dependencyName, currentVersion, targetVersion, YamlMappingNode, assetFile)` — upgrades run on the **YAML DOM before typed deserialisation** (`dynamic asset = new DynamicYamlMapping(yamlAssetNode)`), then `SetSerializableVersion` and `~Base`/`~BaseParts` ([AssetUpgraderAttribute.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/AssetUpgraderAttribute.cs); [IAssetUpgrader.cs](https://github.com/stride3d/stride/blob/releases/4.4.1/sources/assets/Stride.Core.Assets/IAssetUpgrader.cs); AssetUpgraderBase.cs). Member rename without upgrader: `[DataAlias("OldName")]` ("Alias will be ignored during builds and at runtime"); type tag rename: `DataContract.Alias` (Serialization manual).

### O3DE

- `Class<T>()->Version(n, &Converter)` "Add version control to the structure with optional converter. If not controlled a version of 0 is assigned."; `VersionConverter = bool(*)(SerializeContext&, DataElementNode&)` operating on the element tree: `rootElement.GetVersion()`, `RemoveElementByName(AZ_CRC("m_events"))`, `AddElementWithData(sc, "m_eventMap", eventMap)`, `FindElement`, `GetChildData`, `Convert` ("if the new type has sub-elements … you must add those sub-elements after calling convert") ([Versioning serialized data](https://docs.o3de.org/docs/user-guide/programming/components/reflection/serialization-context/versioning/); SerializeContext.h). Declarative: `->NameChange(4, 5, "MyData", "Data")`, `->TypeChange<int, float>("MyData", 4, 5, converter)` ("Type changes apply before name changes"); `ClassDeprecate(name, uuid, converter)` "on load any instances will be silently dropped"; ObjectStream `FILTERFLAG_IGNORE_UNKNOWN_CLASSES` vs `FILTERFLAG_STRICT`; JSON load reports per-field outcomes `{Success, Skipped, DefaultsUsed, TypeMismatch, Missing, Invalid, Catastrophic}` (same pages; [ObjectStream.h](https://github.com/o3de/o3de/blob/2605.0/Code/Framework/AzCore/AzCore/Serialization/ObjectStream.h)).

### Pattern (versioning)

- Strength ranks: **Unreal** (custom versions per subsystem + tagged properties + ini redirects for class/struct/enum/property/package) and **O3DE** (per-class version + converter on the element tree + `NameChange`/`TypeChange`/`ClassDeprecate`) > **Stride** (per-package format version + DOM upgraders + `DataAlias`) > **Flax** (engine build stamp + obsolete-setter recipe) > **Unity** (`FormerlySerializedAs`, `MovedFrom`, missing-type preservation; no version stamp for script data) > **Godot** and **Bevy** (nothing for field renames; Godot has class-rename compat and unknown-type preservation).
- Every engine's loader is name-keyed and tolerant by default (missing → default, extra → dropped); the difference is whether the drop is *silent* (Godot, Unity, Flax, Bevy with `serde(default)`) or *reported/preservable* (O3DE result codes, Unity `ManagedReferenceMissingType`, Godot `MissingResource` for whole types, Unreal `IsKnownMissing` redirects).
- Version stamps are either **per file** (Flax `EngineBuild`, Stride `SerializedVersion{dep: ver}`, Unreal package + custom-version container) or **per type instance** (O3DE `version="N"`, Unity `serializedVersion:` on engine types). The engines with the strongest stories put the *upgrade hook next to the type definition* (O3DE `Version(n, converter)`, Stride `[AssetUpgrader]`, Unreal `Serialize` + custom version) and run it before or during typed deserialisation.

## Surprises and contradictions with the map's Notes

1. **Godot's file does not name the script class as its type.** `type=` is the native base (`Resource`), the script is an `ext_resource` reference (uid + path), and `script_class` is an editor index hint that `load()` never reads. "Godot's inheritance is class inheritance" holds for the *type system*, but the *file* is "native class + script handle + property bag". A Fenrir file that names a game type neutrally would be closer to Flax (`TypeName` from one C++/C# registry) or Unreal (`/Script/Module.Class`) than to Godot.
2. **Godot has no field-versioning at all** and silently drops unknown/renamed properties on load (and therefore on the next save). The engine the user likes for inheritance is the weakest on migration; the gap is filled only by the 3→4 Project Converter's textual rename tables.
3. **Unity names the type by GUID, not by name**, which breaks the moment a class moves assembly; the map's "files name types language-neutrally" is the opposite of Unity's choice and matches Flax/Unreal/O3DE.
4. **Diff-against-default is the majority rule**, so the map's existing per-field defaults in api.json are an asset, not a nicety: five of seven engines need exactly that table to write and read files. The cost is that a changed default rewrites history (Unreal documents it).
5. **Inheritance costs the reflection layer nothing in any engine**: the base relation is *data* (Flax `BaseTypeHandle`, O3DE `AZ_RTTI` bases, Unreal `SuperIndex`, Godot `get_base_script`), and polymorphic assignment is checked by an is-a query, not by layout. The map's worry that "C++ structs with members on both base and derived are not standard-layout, so describe-api cannot describe them" is a describe-api constraint, not an engine-pattern one; Flax's generator describes exactly such classes (`API_CLASS` on a C++ class hierarchy) and Bevy/O3DE show that flat composition (enums, `$type`-tagged values) gives the same file-level polymorphism without class inheritance.
6. **O3DE's default asset UUID is a path hash** — moving a file changes its identity unless the opt-in metadata system is on. A stable-id design must decide who owns id creation (sidecar vs header) before the first file exists; Godot's 4.4 `.uid` retrofit cost a re-save of every project.
7. **Hot reload of a data asset is either in-place (`copy_from` + signal) or replace-and-notify**; both need the type to be re-instantiable from a property bag, and both require that holders hold a handle (Godot `Ref<Resource>` to the same object, O3DE `Asset<T>` that is re-pointed).
8. **No engine serialises "parts" for data assets**; composition shows up as nested typed values (Godot sub_resources, Unreal `Instanced`, Unity `SerializeReference`, Stride tags, O3DE `$type`) inside a class. Bevy is the only one with no class model, and it has no file-level type at all.
