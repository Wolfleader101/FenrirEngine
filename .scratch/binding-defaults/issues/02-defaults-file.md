# 02: Iris.Bindings and describe-api: a `defaults` key names the SDK's names once

**What to build:** A binding configuration's top-level `defaults` names one `<Name>.binding-defaults.toml` holding SDK names; a binding states only what differs from it (spec: "A defaults file", decisions 1, 2, 6, 9, 10, 11).

- **`BindingConfig.cs`**: reads `defaults` (a path relative to the configuration, suffix `.binding-defaults.toml` checked as `.binding.toml` is, the file must exist), parses the file with the same `Reader`, and refuses any key outside the allowed set (the spec's table: `[csharp]` the nine SDK names, `pointer-type`, `usings`; `[cpp] includes`; `[registration]` `extension`, the eight `make-*`, `includes`; `[tests] includes`, `component`; `[natives] context`, `attribute`, `make`, `zero-outputs`; `[bound-types]`) with `<defaults>: '<key>' is not a key a defaults file may state (a binding's own)`. Merging: a scalar the binding states replaces the default; a list the binding states is appended after the default's entries. A binding restating a default byte for byte (a scalar, a list entry, or a `[bound-types]` entry equal in every field) fails: `<path>: '<key>' is already the default from <defaults>; delete it`. The merged configuration is what the rest of the tool sees; `BindingConfig` gains `Defaults` (the file's path, or null) for diagnostics. A defaults file has no `defaults` and no `uses`. `[natives]` `attribute`, `make`, `zero-outputs` are now satisfied from either place; `context` is accepted from either but still only describe-api reads it.
- **`tools/describe-api/src/Natives.cs`**: `NativesSelection.Read` takes `context` from the binding, else from the file its `defaults` names (reading that one key and nothing else); the diagnostic for a missing context names both files. A test in `tools/describe-api/tests/DescribeTests.cs` reads a configuration whose `context` is in its defaults file.
- **`packages/FenrirScripting/api/FenrirScripting.binding-defaults.toml`** (new, owned by FenrirScripting, commented as the one place the SDK's names live): `[csharp]` the six component, event and union names, the three resource names, `usings = ["Fenrir.Scripting"]`; `[registration] includes = ["FenrirScripting/ComponentRegistry.hpp", "FenrirScripting/ScriptingExtension.hpp", "FenrirScripting/ZeroingOutputs.hpp"]`, `extension`, the four `make-*`, `make-scene-resource`; `[tests] includes = ["ScriptingProbe.hpp"]`, `component = "Fenrir::ScriptingProbe::Component(app.scripting)"` (with a comment that `setup` declares `app`); `[natives]` `context`, `attribute`, `make`, `zero-outputs`. `[bound-types]` waits for ticket 03.
- **Seven bindings** (all but FenrirMath's) gain `defaults = ".../FenrirScripting.binding-defaults.toml"` and lose every key the file now gives, including the `FenrirScripting/*.hpp` lines of `[registration] includes`, `"Fenrir.Scripting"` from `usings`, `"ScriptingProbe.hpp"` from `[tests] includes` and `[tests] component`. FenrirMath's binding states no `defaults` (its mirrors cannot `using Fenrir.Scripting`).
- **Two writer facts stop depending on the configuration**, so the defaults can supply a name without changing a binding's output: the registration sets `extension.resources` when the lists hold a resource, not when a factory is configured (`RegistrationConfig.HasResources` goes), and the generated `using`s after the system ones are sorted ordinal and never name the file's own namespace. The regeneration's only changes are those two canonicalisations (five files), the defaults test's includes with `ScriptingProbe.hpp` first (six files), and Assets's registration gaining `FenrirScripting/ComponentRegistry.hpp`, which the defaults list for every registration; a second run is a no-op.
- **The fixture**: `tests/Fixture/Host.binding-defaults.toml` with the `Host::` names; `Fixture.binding.toml` names it and is trimmed the same way; `Uses/Common.binding.toml` names nothing.
- **README**: a "Defaults" section (the key, the file, the allowed keys, replace-or-append, the restating refusal, which keys each tool reads: describe-api `sources` and `context`, Iris.Bindings the rest); `packages/Iris/docs/natives-description.md`'s `context` row gains "or the binding's defaults file". ADR-0042's consequence "a binding's own configuration (namespace, which C# type stands for each bound type, the few field renames) lives with the binding" gains one sentence: the SDK's names live once, in a FenrirScripting-owned defaults file every binding names.
- **Tests** (`tests/BindingTests.cs`): the fixture generates the same bytes with its names in the defaults file; a scalar override wins; a list is appended after the defaults'; a restated scalar, list entry and `[tests] component` are each refused naming the file; a defaults file stating `namespace`, `source` or `names` is refused; a missing file and a wrong suffix are refused; a defaults file stating `defaults` is refused.
