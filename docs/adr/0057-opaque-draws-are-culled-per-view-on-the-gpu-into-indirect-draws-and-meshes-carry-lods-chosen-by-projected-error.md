# Opaque draws are culled per view on the GPU into indirect draws, and meshes carry LODs chosen by projected error

ADR-0051 left instancing unculled: "No per-instance culling yet. Revisit with GPU culling, through indirect draws." It showed up in a frame. LightingDemo's asteroid ring drew 100k full-detail rocks (3.3k to 6.8k triangles each) at 136 ms a frame in Release on an RTX 5080, the GPU fully busy and the CPU idle; every copy, on screen or not, goes through `DepthPrepass` and `Opaque`, and the shadow passes (ADR-0050) each draw them again. The demo now simplifies its rock meshes by hand at spawn, at about 9 ms. Culling and levels of detail are the structural answers, done on the GPU as Unreal's GPU Scene, Unity's GPU Resident Drawer and Bevy's GPU preprocessing do. This amends ADR-0051, ADR-0021 (what a mesh holds) and ADR-0049 (the stage list). Settled in a grilling session on 2026-11-03.

## Where the line is

**The renderer decides, each frame, about what it was given; the game decides what to give it.** What follows from "there is a camera, some meshes and a GPU" is the renderer's, because it is the same in every game and no game can do it better: not drawing what is outside a view or behind something, not drawing more triangles than pixels, not issuing a draw per copy, not shading with lights that cannot reach a pixel. What depends on the shape of the world or on gameplay is the game's: what exists right now (streaming), how the world is cut up (a grid, a quadtree, an octree, cells and portals), what a far-off forest is replaced with (proxies, impostors), what is loaded at what resolution. An arena shooter has no answer to those because it has no such question; a voxel engine's answer is a grid of chunks; an interior's is rooms. An engine that picks one picks the game. So the renderer keeps no spatial structure of its own and no notion of a level, and gives the game the pieces instead: an entity's world bounds, the frustum maths it culls with (`Math::Frustum`, public, in FenrirMath, and `Renderer::GetFrustum`), `visible`, asset revisions, and tools in FenrirAssets such as `GenerateLods`, which are optional. Its opinions are about how to draw, and each can be switched off.

Culling is two levels for this reason. The CPU culls entities by their world bounds, which a chunked world gets for free by making its chunks or cells entities, at whatever size suits it; the GPU culls copies, over a flat list, because a compute pass over a million boxes is cheap and a tree is what the GPU does worst.

## Culling

- **Every opaque and masked draw is culled on the GPU, per view**, after a coarse cull on the CPU: a lone item, a merged run or an instance list whose world bounds (a list's are the union of its copies', computed when it is uploaded) are outside the view is left out of that view's candidates. On the GPU, a run of merged items, an instance list's copies, and a lone item (a run of one) all go through one compute pass per view that writes the survivors. Transparent items stay direct draws, culled on the CPU by their world bounds, which keeps ADR-0019's back-to-front sort.
- **A view is what a pass draws from:** a camera, each cascade of the sun, each shadowed spot light, and each shadowed point light, which culls against its range sphere and draws all six faces from one result. `DepthPrepass` and `Opaque` share their camera's result, so they draw exactly the same copies at the same detail, which `Opaque`'s equality depth test needs (ADR-0049). The passes run in a new `Cull` stage, first in ADR-0049's stage list, open to user passes like every other stage: a compute pass that must run before the frame (a particle simulation, say) belongs there.
- **Bounds are the mesh's local box, tested twice.** Each record of the draw buffer carries its mesh's local AABB. The pass first tests the sphere derived from it (the box's centre under the copy's full transform, its half-diagonal scaled by the largest axis scale), one dot product per plane, which keeps every visible copy and some off-screen ones; a copy that passes then has the box's eight corners transformed and tested, and is kept if they are not all outside one plane. A lone or merged item's record carries its box under its own world matrix already applied, so the shader's transform is the identity; a skinned item's box is its skinned bounds (ADR-0035). The CPU's coarse cull and transparent cull use the same `Math::Frustum` and the same corner test, so one set of unit tests is the oracle for both.
- **The survivors reach the shader through an indirection buffer.** Set 3 binding 3 holds one entry per drawn instance: the record it reads and, for an instance list, the copy. `CurrentDraw()` in `Fenrir/Draw.glsl` reads the entry at the draw's base instance plus its instance index, which `FenrirDrawIndex()` already computes per backend, and composes as before. User shaders that read only `CurrentDraw()` need no change. The palette keeps binding 2, so it stays the third storage block GL numbers.
- **Each run draws through indirect commands.** The renderer writes a template per run and level of detail (index count, first index, base vertex, and the base instance where its survivors start, with no instances) and copies it over the view's command buffer before the cull; the pass counts survivors into it with atomics, so the order of copies within a run varies frame to frame, which an opaque pass with a prepass does not show, and tests compare sets. Work groups never straddle runs: a group table, written with the templates, maps each group to its run, so one dispatch culls a whole view. Each run is then one multi-draw of one command per level of detail.
- **The graphics device gains indirect draws** (ADR-0016): an `Indirect` buffer usage, an `IndirectRead` resource usage that backends derive barriers from, and `CmdDrawIndexedIndirect { buffer, offset, drawCount, stride }`, which the GL backend replays with `glMultiDrawElementsIndirect` and the null backend records and checks. Vulkan's `vkCmdDrawIndexedIndirect` has the same command layout.
- **`RendererConfig::gpuCulling` turns culling off for comparison**, as `automaticInstancing` turns merging off: the pass still runs and still writes the indirection, but accepts every candidate at full detail, so there is one drawing path. `RendererStats::instances` stays the candidates submitted, which the CPU knows; `instancesDrawn` is what the GPU drew, read back from the most recent frame that has left flight, usually two behind.

## Occlusion

- **Copies behind other copies are culled in two phases against a depth pyramid**, per camera, on by default (`RendererConfig::occlusionCulling`). What was visible last frame is drawn first into `DepthPrepass`; the pyramid is built from that depth; everything else inside the frustum is tested against the pyramid level whose texels cover its screen rectangle, and what shows is drawn after. Both phases' survivors are what `Opaque` draws, and the pyramid is built again from the complete depth for whatever reads it after. Visibility is a bit per candidate per camera, kept while the frame's candidates keep their order.
- **The pyramid is shared with screen-space reflections** (ADR-0056): one per camera, RG32F holding the nearest and the farthest depth of each texel's footprint, built by fragment passes into its mips since the device has no storage images, and made for a camera when either reflections or occlusion wants it. Occlusion reads the farthest depth; reflections read the nearest.
- **Shadow views do not occlusion cull.** A caster hidden from the light still shadows nothing, but a pyramid per shadow view is not worth building until a scene says so.

## Levels of detail

- **A mesh carries its levels of detail as extra index lists over its own vertices.** `MeshData` gains `lods`: each a list of indices into the same streams and its simplification error, in the mesh's local units, coarser and with a larger error each. They share the vertex buffer, so a run's levels are commands into one index buffer and differ only in their first index and count, with no rebinding. A skinned mesh's levels share its skin.
- **The pass picks one level per surviving copy by projected error:** the coarsest level whose error, projected at the copy's distance from the camera, is below `RendererConfig::lodErrorPixels` (one pixel by default). This is a projected size test that needs no hand-set distances, and it is the same for every mesh; there is no per-mesh or per-renderer override, since a mesh that must keep detail simply ships without the coarse levels. Shadow views choose by the camera, not the light, so a copy casts with the detail it is seen at and does not shadow itself; a far copy's shadow near the camera has a coarse silhouette, which the shadow filter hides.
- **A copy smaller than `RendererConfig::minProjectedPixels` is not drawn at all**: a level past the last, chosen by the same projection of the copy's radius. Off by default (0), since what is too small to matter depends on the game.
- **Levels are generated by meshoptimizer** (MIT), a submodule of FenrirAssets: `GenerateLods` simplifies a mesh into a chain, keeping attribute seams, with the error meshoptimizer reports scaled to local units. The engine imports glTF and FBX at load and has no cooked asset format, so levels are made at load by the app that wants them; a cooked format is its own ADR, and when it comes, this is what it cooks.

## Not yet

- **GPU-written instance lists**, a user pass in `Cull` writing a list's copies and count for the cull to read. It changes what an asset's revision means, so it is its own ADR.
- **Cluster or meshlet culling and continuous LOD** (Nanite's approach), mesh shaders, GPU-written draw lists of whole items (the CPU still resolves materials and pipelines), LOD cross-fading, and occlusion culling of shadow views.

## Considered

- **CPU culling of copies.** 100k copies a view, and as many again per shadow view, is the CPU work this ADR moves off it, and it would need the copies' transforms back on the CPU every frame. Lone items are culled on the CPU as entities, then go down the GPU path with everything else, which keeps one way to draw.
- **An octree or BVH in the renderer.** It would help only the CPU side, which culls entities, and how many entities there are and how they are grouped is the game's choice; the game that needs a tree over its chunks writes one over `Renderer::GetWorldBounds`, shaped for its world.
- **Spheres only.** Looser for anything long and thin: a tree, a lamp post, a building; the box test wants the same record data and costs a few lines, so both are done.
- **A prefix sum instead of atomics**, for a deterministic order within a run. A second dispatch and barrier per view, to fix an order nothing depends on.
- **One mesh asset per level.** It leaves the renderer to pair meshes it cannot tell belong together, and costs a vertex buffer bind per level.
- **Distance thresholds per mesh.** They depend on the mesh's size and the field of view, and have to be set by hand; projected error does not.
- **Occlusion gated on a measurement.** Every GPU-driven renderer ships it, the neon city and Sponza will show it, and the pyramid is built for reflections anyway.
