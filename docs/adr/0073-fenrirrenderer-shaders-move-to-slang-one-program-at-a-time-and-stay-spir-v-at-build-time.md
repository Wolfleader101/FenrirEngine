# FenrirRenderer's shaders move to Slang, one program at a time, and stay SPIR-V compiled at build time

ADR-0018 made every shader GLSL 460, compiled at build time by our own `FenrirShaderCompiler` to SPIR-V that OpenGL 4.6 loads directly, and rejected Slang "for now": its OpenGL support was documented as limited, D3D12 still went through DXC, and it was a large shared library. Those three facts still hold (`.scratch/fenrir-renderer/research/slang-migration.md`, read 2026-11-03 to 2026-11-19 against Slang v2026.20 and `main` @ `6b94df2f`). What has changed is what is known about the cost. A prototype compiled all 71 of the engine's GLSL stages through Slang, ran the tool's own `GlRewrite` on the result unchanged, and found the GL path works, with four traps that each have a fix. Meanwhile the shader code grew from a few hundred lines to 5,900: fifteen shared includes, three compute programs, a `#define` key set of eighteen, and `builtin:2d` at 32 variants. The shared includes are the reason to move: `Fenrir/Lighting.glsl` is a 424-line convention ("fill a `FenrirSurface`, call `FenrirLitColour`") that no compiler checks, every stage of every variant re-parses it, and ADR-0057 depends on a binding-order rule the preprocessor cannot enforce. Slang gives modules, interfaces and one reflection API for every target, and emits HLSL, Metal and WGSL from the same source, so a second backend (ADR-0016) needs no SPIRV-Cross. This supersedes ADR-0018, and amends ADR-0024, ADR-0048, ADR-0051, ADR-0056 and ADR-0057.

## The decision

- **Slang is the shader language.** Every shader, the engine's, a user's or a UI overlay's, is written in Slang and compiled at build time to SPIR-V, which stays the only shader input the graphics device accepts. ADR-0018's decisions on SPIR-V, on compiling at build time and never at runtime, on the shader container, on `fenrir_add_shaders` and on declared layouts with a reflected material set (ADR-0024) stand unchanged.
- **The move is gradual, program by program, with two front ends for its length.** `FenrirShaderCompiler` compiles `.slang` stages through Slang beside the `.vert`, `.frag` and `.comp` stages it compiles through glslang. Both go through the same reflection model, `GlRewrite` and container, so a program may mix a GLSL vertex stage with a Slang fragment stage. Each program moves when it is ready, and is held to its golden images and pixel probes before the next one moves. glslang leaves when the last GLSL stage does. Slang never compiles the existing GLSL: its GLSL mode is where the prototype's traps live (a dropped `gl_Layer` write, no `invariant`, a refused `mat4(mat3)`), and it would change every program's compiler at once.
- **Slang is a pinned prebuilt release, fetched at configure time, never a submodule built from source.** A source build needs Python 3, the repository's git tags, several minutes, and by default downloads DXC, slang-llvm, Dawn and Tint; using it through `add_subdirectory` is undocumented. ADR-0052 already fetches large assets at configure time, and this uses the same mechanism: the release archive for the host (Windows x86_64, Linux x86_64), checked by hash, under the build directory. Only `FenrirShaderCompiler` links `slang` (the `slang-compiler` shared library), `PRIVATE`, as ADR-0010 asks: no engine target, test or demo links it, and no public header names it.
- **Reflection comes from Slang's program layout, not from the SPIR-V.** Slang strips a resource a stage declares but never reads. `GlBindingOf` numbers a binding by its index among its set's bindings of its kind *in the variant*, so a stripped palette would move ADR-0057's indirection buffer one GL point down. SPIRV-Reflect leaves the tool with glslang. Every binding, block member, runtime-array record size and vertex input the container holds is read from Slang's layout, which lists every declared parameter whether or not the code uses it, so the container's bindings describe what is declared, as glslang's did. The renderer's fixed sets stay declared in C++ and checked against that reflection in debug builds (ADR-0018, ADR-0024).
- **Matrices are column-major in memory, by the compiler's flag.** The tool compiles with `-matrix-layout-row-major`, which, for Slang's SPIR-V, decorates matrix members `ColMajor` as glslang did. Slang's default reads every matrix the C++ side uploads transposed. The flag is set in the tool, never per shader, and the tool refuses a `row_major` qualifier in source.
- **SPIR-V 1.0 stays the GL output, and the tool completes it.** `ARB_gl_spirv` names SPIR-V 1.0, and Slang's 1.0 output is documented as experimental: it leaves out `SPV_KHR_shader_draw_parameters` for `DrawParameters`, and `ShaderViewportIndexLayerEXT` with its extension for a vertex-stage `Layer` write. `GlRewrite` adds each, as it already rewrites builtins and descriptor sets, and the tool runs `spirv-val` on every GL copy in its tests. Moving GL to a newer SPIR-V version waits for a driver test on NVIDIA, AMD, Intel and Mesa, and is a revisit condition below.
- **Rules move from glslang's AST to Slang's reflection, and keep their messages.** Every resource names its set and binding with `[vk::binding(b, set)]`, or the build fails; no push constants (an entry-point `uniform` parameter is one); at most eight bindings of a kind in a set; every vertex input and stage output has a `[vk::location]`. The instance index is read only through `Fenrir.Draw`'s `CurrentDraw()`, which takes `SV_VulkanInstanceID` (the raw `InstanceIndex`; Slang's `SV_InstanceID` already subtracts the base instance, so it would be subtracted twice on GL), and the tool refuses either semantic in any other module. `invariant` position stays a rule of ADR-0049's equal depth test: the tool adds `Invariant` to the vertex stage's `Position` output in every mesh program's SPIR-V, since Slang has no spelling for it.
- **Material defaults are attributes.** `#pragma fenrir default(name, values…)` (ADR-0024) becomes `[FenrirDefault(x, y, z, w)]` on a `MaterialParams` field and `[FenrirDefaultTexture("white" | "black" | "normal")]` on a texture, read back through Slang's user-attribute reflection with ADR-0024's checks kept: unknown member, value count, stages disagreeing, non-parameter types. GLSL stages keep the pragma until they are ported.
- **Variants stay `#define` keys, every combination built offline.** Slang keeps `-D` and `#ifdef`, the container is unchanged, and the renderer's key picking (ADR-0024) is untouched. Link-time constants and specialization constants are not used: the prototype could not link the former through `slangc`, and the latter are what ADR-0018 deferred. Where a key changes a module (`POINT_SHADOW` in `Fenrir.Draw`, `SKINNED` in `Fenrir.Skinning`), the key is a session-wide macro, so the module compiles once per variant as the include did.
- **Includes become modules under `Fenrir.`, one per include, and the engine ships their source.** `Fenrir/Lighting.glsl` becomes `Fenrir.Lighting`, imported with `import Fenrir.Lighting;`. The include directory stays where it is and becomes the module search path, so `fenrir_add_shaders`' `INCLUDE_DIRECTORIES` keeps its meaning. `FenrirSurface` becomes a struct with `FenrirLitColour` as a method; an `IFenrirMaterial` interface is not introduced here (see "Not yet"). Precompiled `.slang-module` files are not shipped: they tie users to one Slang build.
- **The container format does not change.** A stage keeps its GL copy and its unrewritten SPIR-V; `ShaderContainerVersion` stays 1; the C# side (`Fenrir.Assets.Shaders`) sees the same parameters, types and defaults.
- **User GLSL shaders stay accepted until the last built-in is ported, then one release more.** `fenrir_add_shaders` takes both kinds the whole time, and the GLSL includes are kept in step with the modules while any built-in uses them. Their removal is the last ticket, and the README names the date.

## Consequences

- **Build cost.** Configure downloads a 60 to 90 MB archive once per machine, and CI's Windows image does too. The tool loads a 25 MB shared library at build time. Nothing changes in the engine's link or its shipped size.
- **Goldens are checked, not kept bit-identical.** Slang's SPIR-V orders instructions differently and strips what is unused, so each ported program is held to ADR-0049's CIEDE2000 tolerance and the GL probes' tolerances, not to identical bytes. A ported program that fails its goldens is a ticket's failure, never a tolerance change.
- **Two compilers in the tool for months**, with two sets of must-fail fixtures and two rule checkers. The GLSL path is frozen: no new rule, option or include is added to it.
- **Slang's user attributes are documented as experimental.** If they change shape, the defaults are the one thing that breaks, and the fallback is a `FenrirDefault` function the tool evaluates from the module's reflection instead.
- **Later backends change the tool, not the shaders.** D3D12 gets HLSL from Slang (then DXC), Metal MSL and WebGPU WGSL, each a target the tool adds to the container; or SPIRV-Cross from Slang's SPIR-V, which the prototype showed works too. Which is the new backend's ADR.
- **Docs.** `GLOSSARY.md`'s "FenrirShaderCompiler" and "Shader variant", the renderer README's "User shaders" and "Materials and built-in shaders", `cmake/FenrirShaders.cmake`'s header and every shader's header comment change as each program moves.

## Considered options

- **A big-bang port.** Rejected: every program changes compiler and language at once, so a wrong-pixel trap shows as dozens of golden failures with nothing to bisect by, and it blocks every other renderer change while it lands.
- **Slang compiling the existing GLSL in place, converting syntax later.** Rejected: the GLSL front end is where the prototype's traps are, and it still changes every program's compiler at once.
- **Slang for new code only, GLSL includes kept.** Rejected as an end state: every shared concept would exist twice and drift. It is this ADR's first few tickets, time-boxed.
- **Staying on GLSL.** The honest alternative. Rejected because the include set has become a language-sized convention that nothing checks, and a second backend would need SPIRV-Cross for HLSL and MSL and still have no modules.
- **Slang as a submodule built from source**, as glslang is. Rejected: Python, tags, generators, downloads and a long first build for every clone, and undocumented as `add_subdirectory`.
- **Link-time constants or specialization constants for variants.** Deferred: the preprocessor keys work, the container is unchanged, and the renderer picks keys by name. Revisit with the variant count.
- **Reflection kept on SPIRV-Reflect over Slang's SPIR-V.** Rejected: the stripped-resource case gives a wrong GL binding with no error, and Slang names block types `SLANG_ParameterGroup_…`.

## Not yet

An `IFenrirMaterial` or `ISurface` interface a user shader implements instead of filling a struct; link-time specialization; a newer SPIR-V version on GL; shipped precompiled modules; hot reload (ADR-0018's child-process plan still holds, with `.slang` files); Slang's HLSL, Metal and WGSL targets in the container; `ParameterBlock<T>` for the material set.

## When to revisit

If a GL driver rejects SPIR-V the tool completed (take SPIR-V 1.3 after a driver test, or ADR-0018's SPIRV-Cross-to-GLSL fallback, which works on Slang's SPIR-V too); if Slang's user attributes change (the function fallback above); if a program passes 64 variants (link-time or specialization constants); when the second backend is designed (which target each gets).
